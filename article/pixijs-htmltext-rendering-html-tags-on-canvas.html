PixiJS HTMLText: Rendering HTML Tags on Canvas

The HTMLText class in PixiJS provides a solution for rendering styled, rich text directly onto an HTML5 canvas by parsing standard HTML and CSS. This article explains the purpose of HTMLText, breaks down the technical mechanism behind how it converts markup into canvas-compatible textures using SVG foreign objects, and discusses key performance trade-offs when integrating web-styled text into a WebGL rendering pipeline.

What is the HTMLText Class?

PixiJS includes native text classes such as Text and BitmapText. While the standard Text class relies on the Canvas 2D API (fillText) and applies uniform styling across an entire block, HTMLText supports inline HTML tags such as <b>, <i>, <br>, and <span style="...">.

This enables developers to construct complex typographic layouts—such as varying font weights, inline colors, and custom line heights—within a single object, avoiding the need to manually position and align multiple distinct text instances.

How HTMLText Renders Directly Inside the Canvas

Because Canvas 2D and WebGL contexts cannot natively interpret or render DOM elements, PixiJS uses browser standards to convert HTML into an image format that the canvas can display.

  1. SVG ForeignObject Wrapping: When you pass HTML to an HTMLText instance, PixiJS constructs an SVG document containing a <foreignObject> tag. The user-provided HTML and accompanying CSS rules are placed directly inside this element.
  2. Data Serialization: The constructed SVG string is serialized and converted into a base64 Data URI or an Object URL using a Blob.
  3. Native Rasterization: The URL is assigned to the src attribute of an offscreen HTML Image element. The browser's native layout and rendering engine processes the SVG and its inner HTML, rasterizing the vector shapes and web fonts into pixel data.
  4. Texture Upload to Canvas: Once the image loads, PixiJS draws the image onto a hidden, offscreen <canvas> element. This canvas serves as the source for a standard PixiJS Texture, which is then uploaded to the GPU and rendered via WebGL as a 2D quad/sprite on the stage.

Performance and Implementation Considerations

While HTMLText simplifies multi-style text rendering, the underlying conversion process introduces specific behavioral and performance factors:

  • Asynchronous Rendering: The process of converting SVG into an image and waiting for the browser to decode it is asynchronous. Text changes will not appear immediately in the current frame; there is a slight delay before the texture is ready.
  • Texture Memory Overhead: Each HTMLText object requires a unique offscreen canvas and GPU texture. Frequent text updates force the browser to continually reconstruct SVG structures, rasterize images, and upload new textures to the GPU, which can degrade performance.
  • Optimal Usage: HTMLText is suited for static or infrequently updated content such as dialogues, tooltips, instructional screens, and rich UI panels. For dynamic, frequently updated text (like HUD scoreboards or timers), standard BitmapText or Text remains the optimal choice.
