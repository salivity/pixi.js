Polygon Collision in Pixi.js Using SAT

This article provides an overview of the Separating Axis Theorem (SAT) and explains how to implement it for precise convex polygon collision detection in Pixi.js applications. You will learn the core mathematical principles behind SAT, how to calculate projecting axes and intervals, and how to integrate custom SAT collision checks directly into a Pixi.js update loop.

What is the Separating Axis Theorem (SAT)?

The Separating Axis Theorem (SAT) states that two convex shapes do not overlap if there exists an axis onto which the two shapes' projections do not overlap. Conceptually, if you shine a light from an angle and cast shadows of two 2D objects onto a flat line, and you can find an angle where there is an empty space between their shadows, the shapes are definitely not touching.

Because SAT relies on testing projections, it is exclusively suitable for convex polygons (polygons where all interior angles are less than 180 degrees). Concave shapes must be decomposed into multiple convex polygons before applying SAT.

Mathematical Foundations of SAT

To check for a collision between two convex polygons using SAT, follow these mathematical steps:

  1. Identify the Axes to Test:
    The candidate axes are the normal vectors (perpendicular lines) of every edge on both polygons. For a polygon with edges formed by vertices \(A\) and \(B\), the edge vector is: \[\vec{E} = (B_x - A_x, B_y - A_y)\] The normal axis is perpendicular to that edge: \[\vec{N} = (-\vec{E}_y, \vec{E}_x)\]

  2. Project Vertices onto the Axis:
    For every vertex \(V\) of a polygon, calculate the scalar projection onto axis \(\vec{N}\) using the dot product: \[\text{projection} = V_x \cdot N_x + V_y \cdot N_y\]

  3. Determine the Interval:
    Find the minimum and maximum projection values for each polygon: \[[\min_A, \max_A] \quad \text{and} \quad [\min_B, \max_B]\]

  4. Check for Overlap:
    Compare the intervals. If \(\max_A < \min_B\) or \(\max_B < \min_A\), there is a separating axis, which means the polygons do not collide. You can exit early. If all tested axes produce an overlap, the polygons are colliding.

Implementing SAT in Pixi.js

Pixi.js is a rendering library rather than a physics engine. While it provides classes like PIXI.Polygon and PIXI.Graphics, it does not include built-in polygon-to-polygon collision resolution. SAT bridges this gap.

1. Core SAT Collision Helper

The following JavaScript implementation defines an SAT test between two arrays of { x, y } vertices:

function getNormals(vertices) {
  const normals = [];
  for (let i = 0; i < vertices.length; i++) {
    const p1 = vertices[i];
    const p2 = vertices[(i + 1) % vertices.length];
    const edge = { x: p2.x - p1.x, y: p2.y - p1.y };
    // Normal perpendicular to edge: (-y, x)
    const normal = { x: -edge.y, y: edge.x };
    // Normalize the vector
    const length = Math.hypot(normal.x, normal.y);
    normals.push({ x: normal.x / length, y: normal.y / length });
  }
  return normals;
}

function projectPolygon(axis, vertices) {
  let min = axis.x * vertices[0].x + axis.y * vertices[0].y;
  let max = min;

  for (let i = 1; i < vertices.length; i++) {
    const dot = axis.x * vertices[i].x + axis.y * vertices[i].y;
    if (dot < min) min = dot;
    if (dot > max) max = dot;
  }

  return { min, max };
}

function checkSATCollision(polygonA, polygonB) {
  const axes = [...getNormals(polygonA), ...getNormals(polygonB)];

  for (const axis of axes) {
    const projA = projectPolygon(axis, polygonA);
    const projB = projectPolygon(axis, polygonB);

    // If shadows do not overlap on this axis, no collision
    if (projA.max < projB.min || projB.max < projA.min) {
      return false;
    }
  }

  return true;
}

2. Integrating with Pixi.js Graphics

To use this function with Pixi.js objects, extract the global (transformed) positions of the vertices:

import * as PIXI from 'pixi.js';

const app = new PIXI.Application();
await app.init({ width: 800, height: 600 });
document.body.appendChild(app.canvas);

// Helper to convert local points into world coordinates
function getWorldVertices(graphic, localPoints) {
  return localPoints.map(p => graphic.toGlobal(p));
}

// Define shapes
const pointsA = [{ x: 0, y: -40 }, { x: 40, y: 40 }, { x: -40, y: 40 }];
const polyA = new PIXI.Graphics().poly(pointsA).fill(0x3498db);
polyA.position.set(200, 200);

const pointsB = [{ x: -30, y: -30 }, { x: 30, y: -30 }, { x: 30, y: 30 }, { x: -30, y: 30 }];
const polyB = new PIXI.Graphics().poly(pointsB).fill(0xe74c3c);
polyB.position.set(240, 210);

app.stage.addChild(polyA, polyB);

// Render loop check
app.ticker.add(() => {
  polyA.rotation += 0.01;

  const worldA = getWorldVertices(polyA, pointsA);
  const worldB = getWorldVertices(polyB, pointsB);

  const isColliding = checkSATCollision(worldA, worldB);

  polyA.tint = isColliding ? 0x2ecc71 : 0x3498db;
});

Using toGlobal ensures translation, rotation, and scaling applied to Pixi display objects are accounted for when projecting vertices, maintaining accurate collision detection during rendering.
