EventBoundary Hit Testing and Events in Pixi.js

Pixi.js utilizes the EventBoundary class as the core engine for translating native DOM pointer inputs into its internal scene graph events. This article explores how EventBoundary performs recursive spatial hit testing against display objects, constructs event propagation paths, and manages the capture and bubbling phases of synthetic federated pointer events.

The Role of EventBoundary

In Pixi.js (introduced natively in v7 to replace the legacy InteractionManager), the EventBoundary sits between low-level input listeners (like the canvas DOM element) and the scene graph. When the browser fires a native PointerEvent, MouseEvent, or TouchEvent, the input system wraps the native event and passes it to an EventBoundary instance configured on the root stage.

The EventBoundary handles two primary responsibilities:

  1. Identifying which display object resides under the pointer coordinates (hit testing).
  2. Dispatching a FederatedPointerEvent through the display hierarchy using standard W3C DOM event propagation mechanics.

The Hit Testing Pipeline

Hit testing identifies the topmost interactive target at a specific global coordinate \((x, y)\). The EventBoundary.hitTest(x, y) method resolves this by recursively traversing the scene graph from the root container down to individual leaves.

1. Pruning and Interactive State

Before performing geometric calculations, EventBoundary prunes non-qualifying branches:

  • eventMode Check: Pixi.js evaluates the object’s eventMode. If set to 'none', the object and all its children are ignored. If set to 'passive', children may be tested, but the object itself cannot be a target. If set to 'auto', 'static', or 'dynamic', the object is considered a candidate for receiving events.
  • Visibility and Renderability: Objects where visible is false, renderable is false, or alpha is effectively zero are skipped unless explicitly configured to receive events.
  • Masks and Culling: If an object has a mask, EventBoundary checks whether the point falls within the mask. If it fails, the object and its descendants are discarded.

2. Traversal Order

EventBoundary traverses children in reverse render order (from highest z-index / last drawn child to lowest). This ensures that objects rendered visually on top receive the hit test first, avoiding unnecessary checks on obscured elements beneath them.

3. Spatial Evaluation (containsPoint)

For candidate display objects, EventBoundary transforms the global coordinate into the object's local coordinate space using the inverse world transform matrix:

  • Custom hitArea: If a hitArea (such as a PIXI.Rectangle, PIXI.Circle, or PIXI.Polygon) is defined, Pixi checks if the local coordinate lies inside this shape.
  • Default Geometry: Without a custom hitArea, Pixi delegates to the object's own containsPoint(point) implementation, which evaluates textures, graphics geometries, or vector paths against the point.

The first leaf or container that returns true from its hit test is returned as the event target.

Event Construction and Propagation

Once the hit target is identified, the EventBoundary creates a FederatedPointerEvent. This event mimics standard DOM event behavior, providing properties like target, currentTarget, clientX, clientY, global, local, stopPropagation(), and stopImmediatePropagation().

Building the Propagation Path

The EventBoundary constructs a propagation path array containing the target object and all of its ancestors up to the root container: [Target, Parent, Grandparent, ..., Root]

Dispatch Phases

The EventBoundary dispatches the event through three sequential phases:

  1. Capture Phase: The event travels downward from the root container toward the target. Listeners registered with { capture: true } execute during this phase.
  2. Target Phase: The event reaches the target object itself, firing handlers bound directly to that node.
  3. Bubble Phase: If the event is configured to bubble (such as pointerdown, pointerup, or pointertap), the event reverses direction and travels upward from the target’s immediate parent back to the root. Any non-capture listeners along this path execute unless event.stopPropagation() is invoked.

State Management and Boundary Transitions

Beyond point-and-click dispatching, EventBoundary tracks continuous pointer states across frames:

  • Pointer Over/Out and Enter/Leave: The boundary maintains a reference to the previously hovered target for each active pointer ID. When the cursor moves, EventBoundary computes the lowest common ancestor between the old target and the new target. It then dispatches pointerout and pointerleave events up the leaving branch, followed by pointerover and pointerenter events down the entering branch.
  • Cursor Synchronization: During hit testing, EventBoundary detects the cursor style assigned to the active target and updates the root canvas cursor accordingly.
  • Pointer Tracking: By tracking individual pointer IDs, EventBoundary supports multi-touch interactions, correctly handling concurrent dragging, pressing, and releasing across different display objects simultaneously.
