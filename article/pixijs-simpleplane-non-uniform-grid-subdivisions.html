PixiJS SimplePlane Non-Uniform Grid Subdivisions

This article examines whether the SimplePlane class in Pixi.js can be configured with non-uniform grid subdivisions. It details the default grid generation behavior, explains why native configuration parameters do not support irregular spacing out of the box, and provides concrete methods for modifying vertex data or using alternative mesh structures to achieve a non-uniform subdivision layout.

Native Support in SimplePlane

By default, the Pixi.js SimplePlane does not support non-uniform grid subdivisions through its constructor or standard configuration properties. The constructor signature accepts texture, verticesX, and verticesY:

const plane = new PIXI.SimplePlane(texture, verticesX, verticesY);

When SimplePlane initializes, its internal _refresh() or geometry build method calculates vertex positions and texture coordinates (UVs) uniformly across the width and height of the texture. It divides the space evenly by (verticesX - 1) along the X-axis and (verticesY - 1) along the Y-axis. There are no built-in arguments to define arbitrary column widths or row heights.

Achieving Non-Uniform Subdivisions

Although the initial generation is strictly uniform, you can achieve a non-uniform grid using two primary techniques: manually modifying the SimplePlane vertex buffer, or building a custom PIXI.Mesh.

1. Manually Modifying the Vertex and UV Buffers

After instantiating a SimplePlane, you have direct access to its underlying geometry buffers. You can rewrite the vertex positions and UV coordinates to match your desired non-uniform spacing.

  • Vertex Positions: Access the position buffer via plane.geometry.getAttribute('aVertexPosition'). The .data property contains a flat Float32Array of [x0, y0, x1, y1, ...].
  • UV Coordinates: Access the texture mapping via plane.geometry.getAttribute('aTextureCoord'). If your non-uniform grid needs to distort or properly map the texture to irregular spacing, update this buffer's .data array as well.
  • Commit Updates: After modifying the array values, set the buffer's update flag so the WebGL context re-uploads the data:
const posAttr = plane.geometry.getAttribute('aVertexPosition');
const uvAttr = plane.geometry.getAttribute('aTextureCoord');

// Iterate and manually reposition vertices according to your non-uniform scale
posAttr.data[0] = customX;
posAttr.data[1] = customY;

// Flag buffers for GPU re-upload
posAttr.update();
uvAttr.update();

2. Using a Custom PIXI.Mesh

If your grid requires permanent, complex, or non-uniform subdivisions from the start, bypassing SimplePlane in favor of a standard PIXI.Mesh with a custom PIXI.MeshGeometry is generally the cleaner architecture.

With PIXI.Mesh, you supply your own arrays for positions, UVs, and triangle indices:

  • Define the non-uniform grid points in standard JavaScript arrays.
  • Generate the triangle index array connecting adjacent vertices into quad pairs.
  • Pass the buffers into a new PIXI.MeshGeometry(positions, uvs, indices).
  • Create the mesh via new PIXI.Mesh(geometry, shaderOrMaterial).

Summary

SimplePlane does not have a native setting or constructor option for non-uniform grid subdivisions; it strictly divides planes into evenly distributed rows and columns. However, because Pixi.js exposes raw geometry buffers, you can achieve non-uniform layouts either by post-processing the aVertexPosition and aTextureCoord buffers of a SimplePlane, or by constructing a custom PIXI.Mesh.
