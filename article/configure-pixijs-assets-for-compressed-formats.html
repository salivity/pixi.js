Configure PixiJS Assets for Compressed Formats

This guide explains how to configure the Pixi.js Assets manager to detect hardware capabilities and serve GPU-compressed texture formats like ASTC, BCn, ETC, or modern web formats like WebP and AVIF. By configuring detection parsers and structured asset manifests, Pixi.js automatically evaluates client GPU extensions and loads the most efficient texture available, with seamless fallbacks for unsupported devices.

1. Enable Compressed Texture Support

To handle GPU-native formats such as KTX or DDS containers holding BCn, ETC, or ASTC textures, ensure that the compressed texture package is included in your project. In full Pixi.js bundles, compressed texture extensions are often included, but in modular setups, install and register @pixi/compressed-textures:

npm install @pixi/compressed-textures

Import and register the parsers to ensure Pixi.js registers detection rules and decoding capabilities:

import { extensions } from 'pixi.js';
import { 
    loadKTX, 
    loadDDS, 
    detectCompressed
} from '@pixi/compressed-textures';

extensions.add(loadKTX, loadDDS, detectCompressed);

Once added, Pixi.js inspects the underlying WebGL context for supported extensions (such as WEBGL_compressed_texture_s3tc, WEBGL_compressed_texture_astc, or WEBGL_compressed_texture_etc).

2. Configure Format Preferences in Assets.init

When initializing the Assets cache, define your preference order using Assets.init(). Pixi.js uses this list to break ties when multiple compatible formats are provided:

import { Assets } from 'pixi.js';

await Assets.init({
    preferences: {
        preferWorkers: true,
        preferCreateImageBitmap: true,
        // Order formats from highest priority to lowest priority
        formats: ['astc', 'bc3', 'etc2', 'webp', 'png']
    }
});

Pixi.js cross-references this formats array against the formats supported by the current device's hardware.

3. Supply Multi-Format Assets

To enable automatic selection, provide the loader with multiple format alternatives for a single asset key. You can achieve this using an array in Assets.load or via an asset manifest.

Using Assets.load Directly

Pass an array of URLs. Pixi.js will pick the first format in the list that the device supports:

// Provide formats in preferred order or rely on Assets.init preferences
const texture = await Assets.load([
    'textures/character.astc.ktx',
    'textures/character.s3tc.ktx',
    'textures/character.webp',
    'textures/character.png'
]);

Using an Asset Manifest

For larger projects, create an asset manifest where an asset alias points to multiple file formats under a single entry:

const manifest = {
    bundles: [
        {
            name: 'game-screen',
            assets: [
                {
                    alias: 'background',
                    src: [
                        'assets/bg.astc.ktx',
                        'assets/bg.bc7.ktx',
                        'assets/bg.etc2.ktx',
                        'assets/bg.webp',
                        'assets/bg.png'
                    ]
                }
            ]
        }
    ]
};

// Initialize the manifest
await Assets.init({ manifest });

// Load the bundle
const bundle = await Assets.loadBundle('game-screen');

// Retrieve the texture via its alias
const backgroundTexture = bundle.background;

4. How Format Matching Operates

When Assets.load evaluates an array of candidate URLs:

  1. Detection: Registered detectors (like detectCompressed, detectWebp, and detectAvif) run during initialization to query browser and WebGL capabilities.
  2. Filtering: Pixi.js strips out any URLs containing format extensions the system cannot decode.
  3. Resolution: If multiple valid formats remain, Pixi.js selects the one with the highest priority according to the formats preference array configured during Assets.init.
  4. Fallback: If no compressed GPU format is supported, the loader cascades down to WebP or standard raster formats (PNG/JPEG).
