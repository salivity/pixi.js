How to Cull Off-Screen Objects in Pixi.js

This article provides a comprehensive guide on implementing off-screen culling in Pixi.js to boost rendering performance and achieve stable frame rates. By determining which display objects reside outside the current camera viewport and disabling their rendering, you can drastically reduce draw calls and GPU workload in scenes with large worlds or dense sprite counts.

Why Off-Screen Culling Matters

By default, Pixi.js processes display objects in your scene graph even if they are located outside the visible screen. While WebGL clips pixels outside the viewport automatically, the CPU still expends time calculating scene-graph transformations, updating vertex buffers, and submitting draw calls. Setting an off-screen object's renderable property to false instructs Pixi.js to skip that object during the render pass, eliminating unnecessary CPU and GPU overhead.

Implementing a Basic Viewport Bounds Check

The most direct way to cull objects is to define the boundaries of your camera viewport and check each object's position against those boundaries inside your application's update ticker.

// Define the visible camera boundaries
const viewport = {
    left: camera.x,
    top: camera.y,
    right: camera.x + app.screen.width,
    bottom: camera.y + app.screen.height
};

// Check and cull objects in the update loop
app.ticker.add(() => {
    // Update viewport position if camera moves
    viewport.left = camera.x;
    viewport.top = camera.y;
    viewport.right = camera.x + app.screen.width;
    viewport.bottom = camera.y + app.screen.height;

    for (let i = 0; i < objects.length; i++) {
        const obj = objects[i];
        
        // Axis-Aligned Bounding Box (AABB) intersection check
        const isVisible = 
            obj.x + obj.width > viewport.left &&
            obj.x < viewport.right &&
            obj.y + obj.height > viewport.top &&
            obj.y < viewport.bottom;

        // Toggle renderable instead of visible to preserve transform calculations
        obj.renderable = isVisible;
    }
});

Using renderable = false is preferred over visible = false if you still need position or matrix updates to process while the object is off-screen.

Optimizing Bounds Calculations

Using getBounds() inside a continuous render loop can hurt performance because it recalculates global matrices for every target. To maximize frame rates:

  1. Use Local Dimensions: For standard sprites, calculate culling using simple coordinates and fixed dimensions (obj.x, obj.y, obj.width, obj.height) rather than running obj.getBounds().
  2. Add a Buffer Zone: Expand the camera's bounding box slightly (padding by 50 to 100 pixels) to prevent objects from popping into existence abruptly at the edge of the screen.

Scaling with Spatial Partitioning

Iterating over thousands of individual objects every frame creates a CPU bottleneck (\(O(n)\) complexity). For large-scale applications, organize your display objects using a spatial partitioning system such as a Quadtree, a uniform spatial grid, or a library like pixi-cull.

With spatial hashing, you divide your world space into discrete cells. When the camera moves, you query only the cells overlapping the camera's viewport and toggle the visibility of the objects contained within those specific cells, reducing the number of bounding checks from thousands to just a few dozen per frame.
