Multi-Texture Uniforms in Pixi.js Fragment Shaders

This guide demonstrates how to bind and sample multiple texture uniforms within a custom Pixi.js fragment shader. By configuring custom uniforms with PIXI.Texture objects and declaring corresponding sampler2D uniforms in GLSL, you can blend, mask, or manipulate several textures simultaneously in real time.

1. The Fragment Shader Code

In WebGL and Pixi.js, textures are accessed inside shaders as sampler2D types. In a standard Pixi.js filter, the input sprite's texture is provided automatically as uSampler. To use additional textures, declare extra uniform sampler2D variables.

// fragment.glsl
varying vec2 vTextureCoord;

// Default input texture from Pixi.js
uniform sampler2D uSampler;

// Custom secondary textures
uniform sampler2D uTextureTwo;
uniform sampler2D uDisplacementMap;

void main(void) {
    // Sample the primary texture
    vec4 baseColor = texture2D(uSampler, vTextureCoord);

    // Sample the secondary textures
    vec4 secondColor = texture2D(uTextureTwo, vTextureCoord);
    vec4 mapColor = texture2D(uDisplacementMap, vTextureCoord);

    // Example operation: Blend baseColor and secondColor using red channel of the map
    vec4 finalColor = mix(baseColor, secondColor, mapColor.r);

    gl_FragColor = finalColor;
}

2. Setting Up Pixi.js Uniforms

Pixi.js abstracts WebGL texture binding units. When you pass a PIXI.Texture into a custom filter's uniform dictionary, Pixi.js automatically manages texture units (such as gl.TEXTURE0, gl.TEXTURE1, etc.) and sets the uniform integer values under the hood.

import * as PIXI from 'pixi.js';

// 1. Load the required textures
const primaryTexture = PIXI.Texture.from('assets/base.png');
const secondaryTexture = PIXI.Texture.from('assets/overlay.png');
const mapTexture = PIXI.Texture.from('assets/map.png');

// 2. Define the uniform map
const uniforms = {
    uTextureTwo: secondaryTexture,
    uDisplacementMap: mapTexture,
};

// 3. Create the custom filter
const customFilter = new PIXI.Filter(null, fragmentShaderSource, uniforms);

// 4. Apply the filter to a container or sprite
const sprite = new PIXI.Sprite(primaryTexture);
sprite.filters = [customFilter];
app.stage.addChild(sprite);

3. Handling Separate UV Coordinates

When working with multiple textures of different sizes or textures coming from a spritesheet/texture atlas, sampling both with vTextureCoord can produce misaligned or distorted results.

To sample a secondary texture using its own UV space, pass normalized texture matrices or UV bounds into the shader:

const uniforms = {
    uTextureTwo: secondaryTexture,
    // Pass the texture's internal frame coordinates
    uTextureTwoUV: [
        secondaryTexture.frame.x / secondaryTexture.baseTexture.width,
        secondaryTexture.frame.y / secondaryTexture.baseTexture.height,
        secondaryTexture.frame.width / secondaryTexture.baseTexture.width,
        secondaryTexture.frame.height / secondaryTexture.baseTexture.height,
    ]
};

Adjust the coordinate mapping in the shader:

uniform vec4 uTextureTwoUV;

vec2 getSecondaryUV(vec2 coord) {
    return uTextureTwoUV.xy + (coord * uTextureTwoUV.zw);
}

void main(void) {
    vec2 secondaryCoord = getSecondaryUV(vTextureCoord);
    vec4 secondColor = texture2D(uTextureTwo, secondaryCoord);
    // ...
}

4. Updating Textures Dynamically

To replace or update a bound texture after initialization, directly modify the uniform property on the filter instance:

customFilter.uniforms.uTextureTwo = PIXI.Texture.from('assets/new_overlay.png');

Pixi.js will detect the update and bind the new WebGL texture unit in the next render cycle. Ensure all textures are loaded or have their dimensions resolved prior to initial rendering to prevent WebGL warnings regarding incomplete textures.
