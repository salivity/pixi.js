Pixi.js Geometry addAttribute and addIndex Explained

In Pixi.js, the Geometry class serves as the bridge between raw vertex data and GPU shader programs, allowing developers to create custom meshes and shapes. This article provides a focused explanation of the addAttribute and addIndex methods on a Pixi.js Geometry instance, detailing how they define vertex attributes and element order to control hardware-accelerated rendering.

The addAttribute Method

The addAttribute method defines and registers a custom vertex attribute on the Geometry object. In graphics rendering, an attribute represents per-vertex data—such as 2D/3D positions, texture coordinates (UVs), vertex colors, or normal vectors—that is passed directly into a vertex shader.

When you call addAttribute, you supply:

  • id (String): The attribute variable name that matches the attribute defined in your vertex shader (for example, aVertexPosition or aTextureCoord).
  • buffer (Buffer | Array): The raw data container (typically a Float32Array or an instance of Pixi's Buffer) that holds the values for all vertices.
  • size (Number, optional): The number of components per vertex attribute. For example, a 2D position (x, y) requires a size of 2, while an RGBA color requires 4. Defaults to 2.
  • normalized (Boolean, optional): Whether fixed-point data values should be normalized to a standard range when accessed. Defaults to false.
  • type (Number, optional): The WebGL data type of each component in the array (e.g., PIXI.TYPES.FLOAT).
  • stride (Number, optional): The byte offset between consecutive attributes in interleaved arrays.
  • start (Number, optional): The byte offset of the first element in the buffer.

By using addAttribute, Pixi.js configures the WebGL vertex array state, instructing the GPU exactly how many bytes to read per vertex and where to find them in memory.

The addIndex Method

The addIndex method attaches an index buffer to the Geometry instance, transforming the rendering pipeline to use indexed drawing (gl.drawElements instead of gl.drawArrays).

An index buffer is an array of integer pointers—usually formatted as a Uint16Array or Uint32Array—that references individual vertices defined by your attributes.

Key benefits and behaviors of addIndex:

  • Reduces Data Duplication: When rendering connected primitive shapes (such as a quad composed of two triangles), multiple triangles inevitably share the same vertices. Instead of duplicating position and UV data for every vertex, addIndex allows shared vertices to be defined once and referenced multiple times by their indices.
  • Defines Winding and Topology: The sequence of numbers in the index buffer dictates the exact order in which vertices are assembled into primitive shapes, directly controlling triangle construction and face winding.

The method accepts an existing PIXI.Buffer or a typed array (like Uint16Array) representing the indices.

Summary of Roles

While addAttribute constructs the physical layout and properties of each vertex point in memory, addIndex dictates the connection map that tells the GPU how to connect those points into geometric primitives. Together, these two methods form the foundation for building any custom mesh or dynamic procedural geometry within Pixi.js.
