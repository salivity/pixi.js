How PixiJS Handles Premultiplied Alpha on GPU Upload

PixiJS relies heavily on premultiplied alpha (PMA) to ensure accurate color blending, prevent dark halo artifacts during bilinear texture filtering, and maintain high performance across rendering pipelines. When uploading image resources to the GPU, PixiJS checks the format of the asset and instructs the underlying WebGL or WebGPU context whether to multiply RGB channels by the alpha channel during the pixel transfer. This article explains the mechanisms PixiJS uses to manage texture upload flags, handle diverse source data types, and avoid double-premultiplication.

Why PixiJS Requires Premultiplied Alpha

In standard straight-alpha (unassociated) rendering, transparent pixels with zero alpha often store arbitrary RGB values, usually black (0, 0, 0, 0). When GPU hardware applies linear texture filtering or mipmapping, it interpolates the color channels independently of the alpha channel, pulling the black color into adjacent semi-transparent pixels and creating dark outlines.

PixiJS uses premultiplied alpha rendering by default because it allows the hardware to blend correctly using the standard blend function (ONE, ONE_MINUS_SRC_ALPHA). This setup ensures smooth antialiasing, seamless sprite tinting, and predictable compositing across layered render passes.

The WebGL Pixel Store Pipeline

During texture initialization in WebGL, PixiJS interfaces directly with the gl.pixelStorei API. The primary flag governing this behavior is gl.UNPACK_PREMULTIPLY_ALPHA_WEBGL.

When uploading a texture to the GPU using gl.texImage2D or gl.texSubImage2D:

  • If gl.UNPACK_PREMULTIPLY_ALPHA_WEBGL is set to true, the WebGL implementation automatically multiplies the red, green, and blue components by the alpha component as pixels are copied to GPU memory.
  • If set to false, the GPU memory receives the raw, unmultiplied color channels directly.

PixiJS dynamically toggles this state before invoking texture upload calls to prevent leaking global state across different asset types.

Alpha Modes Configuration

PixiJS defines explicit alpha configurations through its texture resource system. Internally, a base texture tracks its alpha behavior via an alphaMode property:

  • Unpack / Premultiply on Upload: Instructs PixiJS to enable gl.UNPACK_PREMULTIPLY_ALPHA_WEBGL = true. The browser converts straight-alpha image pixels into premultiplied data on the fly during upload.
  • Premultiplied (PMA): Indicates that the source image data has already been premultiplied (for instance, via a build step, pre-render canvas, or texture packer). PixiJS leaves gl.UNPACK_PREMULTIPLY_ALPHA_WEBGL = false to prevent multiplying the alpha twice.
  • No Premultiplied Alpha: Tells PixiJS to keep the source in straight alpha format and disables GPU-side premultiplication during upload. Custom shaders are then expected to handle color and alpha associations manually.

Source-Specific Upload Handling

Different image formats and elements require different upload routines:

DOM Image Elements (HTMLImageElement)

Standard web image formats like PNG and JPEG are decoded by the browser into straight alpha in host memory. When an HTMLImageElement or ImageBitmap is uploaded, PixiJS detects the source and enables the unpack premultiplication flag so the transformation occurs natively on the GPU upload thread without CPU overhead.

Canvases (HTMLCanvasElement)

A 2D canvas context in HTML5 is premultiplied by default. When PixiJS uploads canvas data, it recognizes this internal representation and bypasses the UNPACK_PREMULTIPLY_ALPHA_WEBGL step, avoiding the washed-out or over-darkened appearance that occurs with double multiplication.

Typed Arrays and Raw Buffers

When uploading raw pixel data via Float32Array or Uint8Array, browsers do not consistently support driver-level unpack premultiplication across all formats. PixiJS sets the unpack flag to false for raw buffer uploads. If premultiplication is required for raw buffers, developers must premultiply the array in software before upload or run a compute/fragment pass on the GPU.

Compressed Textures

Compressed formats (such as BC3, ETC2, or ASTC) bypass standard pixel-store parameters entirely. gl.pixelStorei(gl.UNPACK_PREMULTIPLY_ALPHA_WEBGL, ...) has no effect on compressed texture uploads (gl.compressedTexImage2D). PixiJS assumes that compressed textures containing an alpha channel were already premultiplied during the offline compression step.
