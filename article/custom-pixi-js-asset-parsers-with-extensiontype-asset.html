Custom Pixi.js Asset Parsers with ExtensionType.Asset

This guide explains how to extend Pixi.js's asset management system by creating and injecting custom asset parsers using ExtensionType.Asset. Modern Pixi.js versions utilize an extensible asset loading pipeline that allows developers to intercept, download, and parse proprietary or unsupported file formats into native resources. By following the steps below, you will learn the required parser interface lifecycle and how to register your custom pipeline into the global loader.

Understanding the Asset Parser Pipeline

The Pixi.js Assets pipeline processes assets through distinct stages defined within a loader parser object:

  1. test: Evaluates the URL or file extension to determine if this parser handles the given asset.
  2. load (optional): Defines how raw data is retrieved from the network (e.g., fetching as a Blob, ArrayBuffer, or plain text). If omitted, standard loaders handle fetching.
  3. testParse (optional): Checks whether the loaded raw content matches the parser requirements prior to parsing.
  4. parse: Transforms the raw loaded data into a usable object (such as a Texture, Container, or custom data structure).
  5. unload (optional): Handles cleanup and resource deallocation when Assets.unload() is called.

Implementing a Custom Parser

To inject a custom parser, define an object that conforms to the LoaderParser interface and attach an extension property configured with ExtensionType.Asset.

Below is an example of a custom parser designed to handle .customdata binary or text files:

import { extensions, ExtensionType, LoaderParser, Loader } from 'pixi.js';

interface CustomAssetData {
    id: string;
    parsedValues: number[];
}

export const customAssetParser: LoaderParser<CustomAssetData> = {
    extension: {
        type: ExtensionType.Asset,
        name: 'customAssetParser',
        priority: 10, // Higher numbers run earlier in the pipeline
    },

    // Step 1: Detect if this parser should handle the URL
    test(url: string): boolean {
        return url.endsWith('.customdata');
    },

    // Step 2: Fetch the raw data
    async load(url: string, asset?: any, loader?: Loader): Promise<string> {
        const response = await fetch(url);
        if (!response.ok) {
            throw new Error(`Failed to load asset: ${url}`);
        }
        return await response.text();
    },

    // Step 3: Test loaded raw data if needed
    async testParse(data: string): Promise<boolean> {
        return typeof data === 'string' && data.startsWith('CUSTOM_HEADER');
    },

    // Step 4: Transform raw data into your application structure
    async parse(data: string): Promise<CustomAssetData> {
        const lines = data.split('\n').slice(1); // Remove header
        const parsedValues = lines.map((line) => parseFloat(line)).filter(Boolean);

        return {
            id: 'generated-id',
            parsedValues,
        };
    },

    // Step 5: Clean up memory when unloaded
    async unload(asset: CustomAssetData): Promise<void> {
        asset.parsedValues.length = 0;
    },
};

Registering and Using the Extension

Inject the parser pipeline into Pixi.js before initializing your application or loading any assets. Use the extensions.add API to register it globally:

import { Assets, extensions } from 'pixi.js';
import { customAssetParser } from './customAssetParser';

// Register the custom asset pipeline
extensions.add(customAssetParser);

async function init() {
    // Pixi.js automatically routes matching files to your parser
    const data = await Assets.load<CustomAssetData>('assets/level-1.customdata');

    console.log(data.parsedValues);

    // Clean up using the custom unload method
    await Assets.unload('assets/level-1.customdata');
}

init();

Parser Priority and Execution Order

If multiple parsers match the same file extension, you can control the execution order by providing a numeric priority within the extension metadata:

extension: {
    type: ExtensionType.Asset,
    name: 'overrideTextureParser',
    priority: 50, // Runs before default loaders (standard default is 0)
}

Setting a high priority ensures your custom pipeline intercepts the asset before native Pixi.js parsers (such as standard image or JSON loaders) process it.
