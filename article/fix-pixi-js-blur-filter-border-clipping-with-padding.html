Fix Pixi.js Blur Filter Border Clipping with Padding

When applying a blur filter to display objects in Pixi.js, developers frequently encounter harsh, rectangular edges where the soft blur suddenly cuts off. This article explains the technical cause behind this visual border clipping—rooted in how Pixi.js allocates bounding boxes for render textures—and demonstrates how configuring the filter's padding property resolves the issue by allocating sufficient rendering space for the blur's outward pixel spread.

What Causes Visual Border Clipping?

Visual clipping occurs because of how Pixi.js handles filter rendering through temporary off-screen framebuffers.

When you apply a filter to a display object (such as a Sprite, Graphics, or Container), Pixi.js does not render it directly to the screen. Instead, it performs the following steps:

  1. Calculates the geometric bounding box (AABB) of the target object.
  2. Allocates a temporary WebGL render texture sized exactly to those bounds.
  3. Renders the object into this texture.
  4. Executes the filter's fragment shader across that texture.
  5. Draws the final result onto the main canvas.

A blur effect functions via a convolution kernel (such as a Gaussian or box blur) that samples neighboring pixels and spreads colors outward. Because a blur inherently expands beyond the original visual footprint of an object, pixels near the boundary attempt to bleed into non-existent space. The temporary render texture is strictly bounded to the original dimensions of the geometry, causing the outward-spreading pixels to hit the edge of the texture and clip abruptly, resulting in a distinct visual seam.

How Filter Padding Resolves the Issue

The padding property on a Pixi.js filter defines an extra margin (in pixels) added around the target object's bounding box when generating its temporary render texture.

import { BlurFilter, Sprite } from 'pixi.js';

const sprite = Sprite.from('asset.png');

// Create the blur filter
const blurFilter = new BlurFilter();
blurFilter.strength = 8;

// Apply padding to accommodate the spread
blurFilter.padding = 20;

sprite.filters = [blurFilter];

When padding is set, Pixi.js expands the dimensions of the off-screen render texture uniformly on all sides:

  • Extended Canvas Space: Adding padding increases the width and height of the temporary texture by padding * 2.
  • Zero Alpha Margins: The extra space initially contains fully transparent pixels (alpha: 0).
  • Unrestricted Falloff: The blur shader can sample and spread pixels into this transparent buffer, allowing the Gaussian curve to decay naturally to absolute zero opacity before it reaches the boundaries of the texture.

Determining the Correct Padding Value

The necessary padding depends on the strength and quality of the blur:

  • Direct Correlation to Strength: A higher strength or blur value spreads pixels further, requiring a proportionally larger padding value. A good baseline is setting padding slightly higher than the filter's strength * 2.
  • Auto-Padding Caveat: While some built-in Pixi.js filters attempt to calculate default padding automatically based on their parameters, manual adjustments are frequently necessary when combining multiple passes, applying custom shaders, or scaling parent containers dynamically.
  • Performance Consideration: Keep padding as small as visually acceptable. Overly large padding values allocate unnecessarily large render textures, which increases GPU memory usage and consumes extra fill-rate during the rendering pipeline.
