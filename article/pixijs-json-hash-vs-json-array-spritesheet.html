PixiJS JSON Hash vs JSON Array Spritesheet

When working with spritesheets in PixiJS, texture packing tools like TexturePacker typically export data in either JSON Hash or JSON Array format. The primary difference between these two formats lies in how frame definitions are structured within the JSON file: JSON Hash stores frames as key-value pairs inside an object, whereas JSON Array stores them as a sequential list of objects. While PixiJS natively supports and parses both formats seamlessly, understanding their structural differences, serialization nuances, and performance implications will help you choose the right format for your development workflow.

Data Structure Differences

The structural distinction between the two formats determines how frame metadata is accessed and represented in the exported file:

  • JSON Hash: In this format, the frames property is a single JavaScript object (a hash map). The key for each entry is the original filename or identifier, and the value is the frame data (dimensions, coordinates, trimming, and pivot data).
{
  "frames": {
    "character_idle.png": {
      "frame": { "x": 0, "y": 0, "w": 32, "h": 32 },
      "rotated": false,
      "trimmed": false,
      "spriteSourceSize": { "x": 0, "y": 0, "w": 32, "h": 32 },
      "sourceSize": { "w": 32, "h": 32 }
    }
  },
  "meta": { ... }
}
  • JSON Array: In this format, the frames property is an array of objects. Because arrays do not use named keys, each frame object explicitly includes a filename property alongside its coordinates and dimensions.
{
  "frames": [
    {
      "filename": "character_idle.png",
      "frame": { "x": 0, "y": 0, "w": 32, "h": 32 },
      "rotated": false,
      "trimmed": false,
      "spriteSourceSize": { "x": 0, "y": 0, "w": 32, "h": 32 },
      "sourceSize": { "w": 32, "h": 32 }
    }
  ],
  "meta": { ... }
}

File Size and Redundancy

JSON Hash produces slightly smaller uncompressed file sizes than JSON Array. Because JSON Array must explicitly define the "filename" key for every single sprite in the sheet, it introduces redundant characters. In large spritesheets containing hundreds or thousands of individual frames, this redundancy noticeably increases the uncompressed file size. When compressed (via gzip or Brotli over HTTP), this difference becomes minimal, but JSON Hash remains the more concise representation.

Frame Ordering and Animations

  • JSON Array maintains a strict, deterministic sequence by nature of being an indexed array. If your game pipeline relies on the exact order in which frames were defined during export without relying on alphabetical sorting, JSON Array guarantees that order.
  • JSON Hash relies on object keys. In JavaScript, non-numeric object keys are typically traversed in insertion order in modern runtimes, but hash maps are inherently conceptualized as unordered collections. PixiJS overcomes this by sorting frame keys alphabetically or numerically when constructing animated sprites, meaning you do not lose animation sequencing when using JSON Hash as long as your frame names contain ordered suffixes (e.g., run_01.png, run_02.png).

PixiJS Internal Handling

PixiJS’s Spritesheet class standardizes both inputs upon loading. Regardless of which format you supply to the loader, PixiJS generates an internal textures dictionary where textures are mapped by their frame names.

When parsing a JSON Array, PixiJS must iterate through the array and read the filename property of each entry to populate its internal texture map. When parsing a JSON Hash, PixiJS can read the keys directly. While the internal parsing time difference is negligible in most real-world scenarios, JSON Hash maps more directly to how PixiJS organizes textures in memory.

Conclusion and Best Practice

For PixiJS development, JSON Hash is the industry standard and the recommended option. It aligns directly with PixiJS's key-based texture lookup system, eliminates repetitive "filename" keys to keep file size down, and is the default target format for PixiJS export presets in tools such as TexturePacker. Use JSON Array only if you have custom pipeline tools that explicitly require array-based iteration before passing assets to the engine.
