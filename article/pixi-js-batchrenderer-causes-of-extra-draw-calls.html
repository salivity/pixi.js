Pixi.js BatchRenderer: Causes of Extra Draw Calls

The Pixi.js BatchRenderer is designed to optimize WebGL performance by aggregating consecutive 2D display objects into single draw calls. However, whenever the renderer encounters an object requiring a state change that WebGL cannot handle mid-draw, or when hardware and buffer capacities are reached, it must flush the current batch and issue a new draw call. Understanding these internal triggers allows developers to structure their scene graphs efficiently, avoid unnecessary draw calls, and maintain optimal rendering frame rates.

Exceeding Maximum Texture Units

Pixi.js allows multiple unique textures to be bound within the same batch. The renderer queries the GPU for gl.MAX_TEXTURE_IMAGE_UNITS (typically 8 to 32 depending on the device).

  • The BatchRenderer maintains an internal list of unique base textures assigned to the current draw call.
  • When a display object requires a texture that is not already in the current batch's texture array, the renderer attempts to register it.
  • If the number of unique textures reaches the device’s limit, the renderer flushes the existing batch to reset the bound texture slots before processing the new object.

Vertex and Index Buffer Capacity

The BatchRenderer allocates fixed-size geometry buffers in system memory before pushing them to WebGL:

  • Vertex Buffer Overflow: The internal vertex buffer has a maximum limit (defaulting to 16,384 vertices or indices depending on Pixi version and settings). If an incoming object’s vertices would exceed this remaining buffer capacity, a flush occurs.
  • Index Limit (16-bit Indices): When running in environments or configurations constrained to 16-bit integer indices (Uint16Array), a single batch cannot reference more than 65,535 vertices. Exceeding this boundary triggers an immediate batch break.

Blend Mode Transitions

WebGL blend operations (gl.blendFunc and gl.blendEquation) are global pipeline states applied per draw call:

  • Every display object in Pixi.js has a blendMode property (e.g., NORMAL, ADD, MULTIPLY).
  • When the BatchRenderer encounters an object with a blend mode different from the currently batched blend mode, it cannot combine them.
  • It flushes all previously queued geometry under the active blend mode, changes the WebGL blend state, and starts a new batch for the incoming object.

Custom Shaders and Material Changes

Batched objects are rendered using a standardized multi-texture batch shader.

  • If a display object relies on a custom shader or program, it cannot use the generic batch shader.
  • The renderer immediately breaks the batch, issues a draw call for preceding items, binds the custom shader program, renders the specialized object, and resets back to the batch shader for subsequent items.

Masks and Filters

Masks and filters interrupt the linear flow of the render pipeline:

  • Alpha/Graphics Masks: Applying a stencil mask or custom rendering mask requires switching render targets or modifying stencil buffer states, forcing an immediate flush of any queued items.
  • Filters: Applying a Filter requires Pixi.js to divert rendering to a separate RenderTexture (framebuffer). Queued items rendered before the filtered object must be drawn first, the filtered object is processed in isolation, and the batch resumes afterward.

Interleaved Non-Batchable Objects

When display objects that do not inherit from the standard batchable pipeline (such as custom WebGL meshes, legacy graphics objects without batching enabled, or custom render callbacks) are placed between standard sprites, the batch breaks. The renderer must execute the custom draw call independently, breaking continuity and requiring separate draw calls before and after the foreign object.
