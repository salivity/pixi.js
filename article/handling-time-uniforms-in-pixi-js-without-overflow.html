Handling Time Uniforms in Pixi.js Without Overflow

Managing time-based uniforms in Pixi.js shaders can lead to visual stuttering and precision artifacts when elapsed time values grow too large for WebGL's standard 32-bit floating-point precision. This article explains why floating-point overflow occurs in WebGL shaders and details the standard techniques to prevent it—primarily by wrapping cyclic intervals in JavaScript before passing values to the GPU, splitting timestamps into high and low components, and bounding cumulative deltas inside Pixi.js ticker loops.

The Cause of Shader Precision Loss

WebGL fragment shaders commonly use single-precision 32-bit floats (highp float), which allocate 23 bits for the mantissa. This yields approximately 7 decimal digits of precision.

When you continuously increment a uniform like uTime += delta or pass raw values from performance.now(), the absolute magnitude of the number grows. As the integer part increases, the available precision for the fractional part shrinks. Within a few hours or even minutes, calculations such as sin(uTime) or procedural noise algorithms lose fractional precision, resulting in visible animation stepping, jitter, or frozen effects.

The Solution: Modulo Wrapping in JavaScript

The most reliable approach to prevent precision degradation is to constrain the time uniform in JavaScript before uploading it to the GPU.

If your shader relies on periodic functions like sin(), cos(), or looping noise, wrap the time variable by its repeating cycle:

import * as PIXI from 'pixi.js';

const app = new PIXI.Application();
await app.init({ width: 800, height: 600 });

const filter = new PIXI.Filter({
    gl: {
        vertex: PIXI.Filter.defaultVertexSrc,
        fragment: `
            precision highp float;
            in vec2 vTextureCoord;
            out vec4 finalColor;
            uniform sampler2D uTexture;
            uniform float uTime;

            void main() {
                vec2 uv = vTextureCoord;
                uv.x += sin(uv.y * 10.0 + uTime) * 0.02;
                finalColor = texture(uTexture, uv);
            }
        `
    },
    resources: {
        timeUniforms: {
            uTime: { value: 0.0, type: 'f32' }
        }
    }
});

// Define the cycle length (e.g., 2 * PI for trigonometric functions)
const CYCLE = Math.PI * 2.0;
let accumulatedTime = 0;

app.ticker.add((ticker) => {
    // Add delta in seconds
    accumulatedTime += ticker.deltaMS / 1000;

    // Keep accumulatedTime within [0, CYCLE)
    if (accumulatedTime >= CYCLE) {
        accumulatedTime %= CYCLE;
    }

    filter.resources.timeUniforms.uniforms.uTime = accumulatedTime;
});

Using the modulo operator in JavaScript rather than the GLSL mod() function is critical. If a large float is sent to the GPU, precision is already lost before the shader's mod() function executes.

Handling Non-Periodic Time Variables

For effects like continuous procedural terrain scrolling or unbounded directional flow, you cannot simply wrap time at a small boundary like \(2\pi\). Use one of the following two strategies instead:

1. Shift Offsets Rather Than Time

Instead of advancing an unbounded time value, compute spatial offsets in JavaScript and wrap them by the repeating texture or domain size:

const DOMAIN_SIZE = 1024.0;
let offset = 0;

app.ticker.add((ticker) => {
    offset = (offset + ticker.deltaMS * 0.1) % DOMAIN_SIZE;
    filter.resources.timeUniforms.uniforms.uOffset = offset;
});

2. Two-Part Float Representation (High/Low)

When absolute large values with high fractional precision are strictly necessary, split the time into an integer component (seconds) and a fractional component:

let startTime = performance.now();

app.ticker.add(() => {
    const now = (performance.now() - startTime) / 1000;
    const timeInt = Math.floor(now);
    const timeFrac = now - timeInt;

    filter.resources.timeUniforms.uniforms.uTimeInt = timeInt;
    filter.resources.timeUniforms.uniforms.uTimeFrac = timeFrac;
});

In the shader:

uniform float uTimeInt;
uniform float uTimeFrac;

float getTime(float scale) {
    return mod(uTimeInt, scale) + uTimeFrac;
}

Summary Checklist

  1. Never pass raw performance.now() or unbounded cumulative frames to a shader uniform.
  2. Apply wrapping logic using JavaScript's modulo arithmetic before setting uniform values.
  3. Match your modulo cycle period to the mathematical period of your shader's core algorithm.
  4. Shift local coordinates or domain offsets directly instead of passing an ever-increasing global time scalar.
