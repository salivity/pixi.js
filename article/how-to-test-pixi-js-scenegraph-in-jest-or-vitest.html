How to Test Pixi.js Scenegraph in Jest or Vitest

Testing Pixi.js scenegraph logic in headless environments allows you to verify node hierarchies, coordinate transformations, and display object states without running a browser or compiling WebGL shaders. By pairing Node-based test runners like Jest or Vitest with DOM and Canvas mocks, you can isolate container logic, spatial calculations, and lifecycle events rapidly in continuous integration pipelines.

The Challenge of Headless Pixi.js Testing

Pixi.js depends on browser globals, primarily window, document, and the HTMLCanvasElement interface. When running under Node.js via Jest or Vitest, these APIs do not exist natively. Attempting to instantiate Pixi objects directly will result in errors regarding missing canvas contexts or window references.

Testing the scenegraph does not require actual pixel rendering. It requires verifying transforms, hierarchy propagation (parent/children), bounds, and custom container behavior. The goal is to provide just enough environment mocking for Pixi's math and tree systems to function properly.

Setting Up the Test Environment

Both Jest and Vitest require a browser-like environment (such as jsdom or happy-dom) along with canvas mocking libraries to satisfy Pixi's initialization routines.

Vitest Setup

Install the required mock packages:

npm install -D vitest jsdom vitest-canvas-mock

Configure vitest.config.ts:

import { defineConfig } from 'vitest/config';

export default defineConfig({
  test: {
    environment: 'jsdom',
    setupFiles: ['./vitest.setup.ts'],
    threads: false, // Ensures mocks run reliably across tests
  },
});

Create ./vitest.setup.ts:

import 'vitest-canvas-mock';

Jest Setup

Install the Jest equivalents:

npm install -D jest jest-environment-jsdom jest-canvas-mock

Configure jest.config.js:

module.exports = {
  testEnvironment: 'jsdom',
  setupFiles: ['jest-canvas-mock'],
};

Testing Scenegraph Transformations

In an interactive Pixi.js application, the rendering loop automatically calls updateTransform() on the root container every frame. In a headless unit test, the ticker is not running, so you must explicitly call updateTransform() to update global coordinates and world matrices before asserting bounds or global positions.

Here is an example test verifying nested positioning and transformations:

import { Container, Point } from 'pixi.js';
import { describe, it, expect } from 'vitest'; // or '@jest/globals'

describe('Scenegraph Transformation Logic', () => {
  it('correctly calculates global positions for nested containers', () => {
    const root = new Container();
    const parent = new Container();
    const child = new Container();

    root.addChild(parent);
    parent.addChild(child);

    // Apply local transforms
    parent.position.set(100, 50);
    child.position.set(25, 25);

    // Manually trigger matrix updates
    root.updateTransform();

    // Verify global coordinate calculation
    const globalPos = child.toGlobal(new Point(0, 0));
    expect(globalPos.x).toBe(125);
    expect(globalPos.y).toBe(75);
  });

  it('updates visibility inheritance down the tree', () => {
    const parent = new Container();
    const child = new Container();

    parent.addChild(child);
    parent.visible = false;

    // Local visibility remains true, but rendered state evaluates to false
    expect(child.visible).toBe(true);
    expect(parent.renderable).toBe(true);
    
    parent.updateTransform();
    expect(parent.worldVisible).toBe(false);
  });
});

Mocking Textures and Sprites

If your scenegraph tests involve Sprite instances rather than pure Container nodes, Pixi will attempt to validate texture dimensions. Avoid loading external image assets during unit tests by using empty or programmatically generated textures.

import { Sprite, Texture } from 'pixi.js';
import { describe, it, expect } from 'vitest';

describe('Sprite Hierarchy', () => {
  it('assigns dimensions without loading image assets', () => {
    // Texture.EMPTY provides a safe 0-size texture without triggering WebGL uploads
    const sprite = new Sprite(Texture.EMPTY);
    
    sprite.width = 100;
    sprite.height = 100;
    
    expect(sprite.width).toBe(100);
    expect(sprite.height).toBe(100);
  });
});

Best Practices for Headless Pixi Tests

  1. Avoid new Application(): Instantiating the full application spins up a WebGL/WebGPU context and a ticker. When testing scenegraph structure, instantiate only the specific Container subclasses you need.
  2. Call updateTransform() explicitly: Any assertion relying on toGlobal(), toLocal(), getBounds(), or worldTransform requires a prior call to updateTransform() on the highest common ancestor.
  3. Clean up listeners and children: Ensure containers remove event listeners or children during test cleanup (container.destroy({ children: true })) to avoid memory retention between test suites.
