Pass Structured Buffers to Pixi.js WGSL Shaders

Passing structured data buffers to WebGPU shaders in Pixi.js v8 allows you to send complex data models—such as particle arrays, lighting parameters, or matrix collections—directly to WGSL compute and fragment shaders. This article provides a direct guide to structuring WGSL memory layouts, initializing typed buffers in Pixi.js, configuring BufferUsage flags for uniform and storage buffers, and binding those resources to custom fragment filters and compute pipelines.

1. Memory Alignment and WGSL Struct Layout

WGSL enforces strict byte-alignment rules for structured data (both uniform and storage buffers). When matching JavaScript typed arrays to WGSL structs:

  • f32, i32, u32: 4 bytes (align: 4)
  • vec2<f32>: 8 bytes (align: 8)
  • vec3<f32>: 16 bytes (align: 16)
  • vec4<f32>: 16 bytes (align: 16)
  • Structs inside arrays must be aligned to multiples of 16 bytes.
// WGSL Struct Definition
struct ItemData {
    position: vec2<f32>, // 8 bytes (offset 0)
    scale: f32,          // 4 bytes (offset 8)
    padding: f32,        // 4 bytes (offset 12, ensures 16-byte struct size)
    color: vec4<f32>,    // 16 bytes (offset 16)
};

// Storage buffer binding (Compute or Fragment)
@group(0) @binding(0) var<storage, read> items: array<ItemData>;

2. Creating the Structured Buffer in Pixi.js

Pixi.js manages WebGPU buffers via the Buffer class. Populate a Float32Array matching your WGSL struct's byte offsets, then create the buffer with appropriate usage flags:

import { Buffer, BufferUsage } from 'pixi.js';

const ITEM_COUNT = 100;
const FLOATS_PER_ITEM = 8; // 32 bytes total per item (8 * 4 bytes)
const bufferData = new Float32Array(ITEM_COUNT * FLOATS_PER_ITEM);

for (let i = 0; i < ITEM_COUNT; i++) {
    const offset = i * FLOATS_PER_ITEM;
    // position (vec2)
    bufferData[offset + 0] = Math.random() * 800;
    bufferData[offset + 1] = Math.random() * 600;
    // scale (f32)
    bufferData[offset + 2] = 1.0;
    // padding
    bufferData[offset + 3] = 0.0;
    // color (vec4)
    bufferData[offset + 4] = 1.0; // r
    bufferData[offset + 5] = 0.5; // g
    bufferData[offset + 6] = 0.2; // b
    bufferData[offset + 7] = 1.0; // a
}

// Create the Pixi.js Buffer
const structuredBuffer = new Buffer({
    data: bufferData,
    usage: BufferUsage.STORAGE | BufferUsage.COPY_DST,
});
  • For uniform buffers, use BufferUsage.UNIFORM | BufferUsage.COPY_DST.
  • For storage buffers (read/write in compute, or read-only in fragment), use BufferUsage.STORAGE.

3. Binding to a Fragment Shader via Filter

To pass your structured buffer to a fragment shader, use a custom Filter with a WGSL shader program:

import { Filter, GlProgram, GpuProgram } from 'pixi.js';

const wgslFragmentSource = `
    struct ItemData {
        position: vec2<f32>,
        scale: f32,
        padding: f32,
        color: vec4<f32>,
    };

    @group(0) @binding(1) var<storage, read> items: array<ItemData>;

    @fragment
    fn mainFragment(
        @location(0) uv: vec2<f32>
    ) -> @location(0) vec4<f32> {
        let firstItem = items[0];
        return firstItem.color;
    }
`;

const gpuProgram = GpuProgram.from({
    fragment: {
        source: wgslFragmentSource,
        entryPoint: 'mainFragment',
    },
});

const customFilter = new Filter({
    gpuProgram,
    resources: {
        items: structuredBuffer,
    },
});

// Apply to any Pixi Container/Sprite
sprite.filters = [customFilter];

4. Binding to a Compute Shader

Compute shaders allow high-performance calculations on structured buffers. You can bind read/write buffers to execute compute passes:

import { WebGPUSystem } from 'pixi.js';

const computeSource = `
    struct ItemData {
        position: vec2<f32>,
        scale: f32,
        padding: f32,
        color: vec4<f32>,
    };

    @group(0) @binding(0) var<storage, read_write> items: array<ItemData>;

    @compute @workgroup_size(64)
    fn mainCompute(@builtin(global_invocation_id) id: vec3<u32>) {
        let index = id.x;
        if (index >= arrayLength(&items)) {
            return;
        }
        items[index].position.x += 1.0;
    }
`;

// Execution via WebGPU device wrapper
const device = renderer.gpu.device;
const computeModule = device.createShaderModule({ code: computeSource });

const bindGroupLayout = device.createBindGroupLayout({
    entries: [{
        binding: 0,
        visibility: GPUShaderStage.COMPUTE,
        buffer: { type: 'storage' },
    }],
});

const computePipeline = device.createComputePipeline({
    layout: device.createPipelineLayout({ bindGroupLayouts: [bindGroupLayout] }),
    compute: { module: computeModule, entryPoint: 'mainCompute' },
});

const bindGroup = device.createBindGroup({
    layout: bindGroupLayout,
    entries: [{
        binding: 0,
        resource: { buffer: structuredBuffer.gpuBuffer },
    }],
});

// Dispatch compute work
const commandEncoder = device.createCommandEncoder();
const passEncoder = commandEncoder.beginComputePass();
passEncoder.setPipeline(computePipeline);
passEncoder.setBindGroup(0, bindGroup);
passEncoder.dispatchWorkgroups(Math.ceil(ITEM_COUNT / 64));
passEncoder.end();
device.queue.submit([commandEncoder.finish()]);

5. Updating Structured Data at Runtime

When your structured data changes, write directly to the local typed array and inform Pixi.js to mark the buffer for upload:

// Modify the data
bufferData[0] = 350.0; // Update first item's x-coordinate

// Queue buffer update to GPU
structuredBuffer.update();

Pixi.js manages the underlying queue.writeBuffer call on the subsequent render cycle, ensuring the WGSL shader receives the updated values.
