Query WebGPU Limits and Features in Pixi.js

PixiJS v8 introduces first-class support for WebGPU alongside WebGL, allowing applications to leverage modern GPU capabilities for high-performance 2D rendering. When building advanced graphical pipelines, shaders, or compute workloads, understanding the target hardware's constraints is essential. This article explains how to access the underlying WebGPU adapter and device through the PixiJS API to query supported limits and features directly.

Accessing the WebGPU Device System

In PixiJS v8, the WebGPURenderer encapsulates WebGPU context management inside its gpu system (GpuDeviceSystem). To inspect the hardware's capabilities, you must initialize PixiJS with the WebGPU renderer preference and wait for asynchronous initialization to complete.

import { Application } from 'pixi.js';

const app = new Application();

await app.init({
    preference: 'webgpu',
    width: 800,
    height: 600,
});

Once initialized, verify that the active renderer is indeed using WebGPU by checking app.renderer.type or inspecting app.renderer.gpu.

Inspecting Adapter and Device References

The app.renderer.gpu system exposes references to both the native GPUAdapter and the active GPUDevice:

const gpuSystem = app.renderer.gpu;

// The native WebGPU adapter represents the physical hardware
const adapter = gpuSystem.adapter;

// The native WebGPU device represents the active logical connection
const device = gpuSystem.device;

Querying Hardware Limits

WebGPU enforces limits on various operational parameters, such as maximum texture dimensions, buffer binding sizes, and compute workgroup capacities.

You can inspect the maximum theoretical limits supported by the physical hardware via adapter.limits, or view the limits allocated to the current runtime session via device.limits. Both return a standard GPUSupportedLimits object.

// Query specific limits from the adapter
console.log('Max 2D Texture Dimension:', adapter.limits.maxTextureDimension2D);
console.log('Max Bind Groups:', adapter.limits.maxBindGroups);
console.log('Max Buffer Size:', adapter.limits.maxBufferSize);
console.log('Max Compute Workgroup Size X:', adapter.limits.maxComputeWorkgroupSizeX);

// Iterate through all supported limits
for (const [limitName, limitValue] of Object.entries(adapter.limits)) {
    console.log(`${limitName}: ${limitValue}`);
}

Checking Supported Features

WebGPU features are optional hardware extensions—such as texture compression formats, 16-bit float types, or timestamp queries—that are not part of the baseline core specification.

Features are exposed as a GPUSupportedFeatures Set-like object via adapter.features and device.features.

// Check for specific feature support
const hasBC = adapter.features.has('texture-compression-bc');
const hasFloat32Filterable = adapter.features.has('float32-filterable');

console.log('Supports BC Texture Compression:', hasBC);
console.log('Supports Float32 Filtering:', hasFloat32Filterable);

// List all features enabled on the active device
device.features.forEach((feature) => {
    console.log(`Enabled Feature: ${feature}`);
});

Difference Between Adapter and Device Limits

When querying capabilities, note the distinction between adapter and device:

  • adapter.limits and adapter.features: Represent the absolute maximum capabilities of the client's underlying GPU.
  • device.limits and device.features: Represent the constraints requested and locked in during device creation. PixiJS requests specific features and default limits suitable for general rendering during app.init().

Accessing both properties allows you to either adapt runtime behavior to the current active device or check whether the hardware supports requesting a custom device reconfiguration.
