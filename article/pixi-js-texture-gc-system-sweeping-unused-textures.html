PixiJS TextureGCSystem: Sweeping Unused Textures

The TextureGCSystem in PixiJS is a core rendering subsystem responsible for automatically managing VRAM by identifying and removing unused GPU texture memory. As 2D rendering applications load, swap, and discard visual assets, texture data can quickly saturate GPU memory if not properly cleaned up. The TextureGCSystem mitigates memory leaks and prevents browser context loss by actively sweeping and deallocating unreferenced WebGL or WebGPU textures, balancing application performance with efficient resource consumption.

How the TextureGCSystem Works

Whenever a texture is rendered on the screen, PixiJS uploads its image data to the GPU and tracks its usage. The TextureGCSystem runs periodically during the render loop, maintaining an internal record of when textures were last bound or drawn.

Rather than relying on the JavaScript engine’s CPU-bound garbage collection—which cannot directly monitor or reclaim hardware video memory (VRAM)—the TextureGCSystem tracks texture lifespans directly on the rendering pipeline. If a texture is not used within a designated timeframe or number of frames, the system flags it as stale and purges the corresponding GPU texture resource (glTexture), freeing the associated VRAM.

Key Sweeping Modes

The garbage collector operates under distinct modes dictated by the application's configuration:

  • AUTO: The default mode. PixiJS automatically checks and sweeps textures at regular intervals based on frame counts or elapsed time.
  • MANUAL: Disables automated sweeping. Developers must explicitly trigger the garbage collection pass using renderer.textureGC.run(). This is particularly useful in performance-critical sections, such as during intense gameplay, allowing developers to defer memory cleanup to level transitions or loading screens.

Mechanics of Texture Unloading

When the TextureGCSystem sweeps a texture, it specifically targets the GPU representation:

  1. Idle Thresholds: The system monitors two primary parameters: maxIdle (the maximum number of frames or seconds a texture can go unused before being eligible for collection) and checkCountMax (the interval between collection passes).
  2. GPU Deallocation: When the threshold is reached for an unused texture, the system deletes the WebGL texture object from VRAM.
  3. CPU Persistence: Importantly, sweeping unloads the texture from the GPU without necessarily destroying the CPU-side BaseTexture or source data. If a purged texture is required again later, PixiJS automatically re-uploads it to the GPU upon the next render pass.

Performance Impact and Tuning

Improper garbage collection settings can cause performance stutter, known as texture thrashing. Thrashing occurs when textures are evicted too quickly, forcing PixiJS to continuously re-upload them to the GPU on subsequent frames. Developers can tune the TextureGCSystem by increasing maxIdle values for scenes with large asset varieties, or by toggling to manual mode to strictly control when cleanup pauses occur. By automating the reclamation of dormant VRAM, the TextureGCSystem provides a critical layer of stability for long-running PixiJS applications.
