Pixi.js: Mask a Container with an Active Filter

In Pixi.js, you can apply a mask to a container that also has an active filter applied. While assigning both properties directly to the same container is supported, the visual result depends on whether you want the mask to cut off the post-filter visual effects or apply the filter across the already-masked bounds. Achieving predictable rendering requires understanding the order of operations and, in most cases, using a nested container structure.

Direct Assignment vs. Execution Order

Pixi.js allows you to set both properties on a single object:

const container = new PIXI.Container();
container.filters = [new PIXI.BlurFilter()];
container.mask = maskGraphics;

When applied to the same container, Pixi.js typically renders the container's contents to a temporary framebuffer (render texture) for the filter pass, then applies the mask to that resulting texture. However, filters that expand the bounds of an object (such as BlurFilter, GlowFilter, or DropShadowFilter) can cause unexpected clipping or edge artifacts if the mask boundaries do not account for the filter's output area.

Recommended Approach: Container Nesting

To avoid edge artifacts and precisely control how the mask and filter interact, nest your containers based on your desired visual outcome.

1. Filter First, Mask Second (Clipping the Filter)

Use this structure when you want to contain the filter effects within a specific boundary (for example, keeping a glowing object strictly inside a window shape).

  • Child Container: Holds the display objects and the filters array.
  • Parent Container: Holds the child container and applies the mask.
// Create containers
const maskContainer = new PIXI.Container();
const filteredContent = new PIXI.Container();

// Add visual elements and filter to the child
filteredContent.addChild(mySprite);
filteredContent.filters = [new PIXI.BlurFilter()];

// Create and assign mask to the parent
const mask = new PIXI.Graphics();
mask.beginFill(0xffffff);
mask.drawRect(0, 0, 200, 200);
mask.endFill();

maskContainer.mask = mask;
maskContainer.addChild(mask);
maskContainer.addChild(filteredContent);

2. Mask First, Filter Second (Softening the Mask Edge)

Use this structure when you want the mask's hard edge to be affected by the filter (for example, applying a blur to both the object and the masked boundary).

  • Child Container: Holds the display objects and the mask.
  • Parent Container: Holds the child container and applies the filters array.
// Create containers
const filteredParent = new PIXI.Container();
const maskedContent = new PIXI.Container();

// Set up mask on the child
const mask = new PIXI.Graphics();
mask.beginFill(0xffffff);
mask.drawCircle(100, 100, 50);
mask.endFill();

maskedContent.mask = mask;
maskedContent.addChild(mask);
maskedContent.addChild(mySprite);

// Apply filter to parent
filteredParent.filters = [new PIXI.BlurFilter()];
filteredParent.addChild(maskedContent);

Key Considerations

  • Filter Padding: When masking a filtered container, ensure filter.padding is properly configured on filters that generate pixels outside the original bounds (like blurs or drop shadows). If the mask bounds are larger than the object bounds, insufficient padding will cause the filter to appear clipped into a rectangular box inside the mask.
  • Mask Types: Stencil masks (PIXI.Graphics) only support binary clipping (on or off). If you need smooth alpha masking combined with filters, use a PIXI.Sprite as the mask, which internally invokes Pixi's SpriteMaskFilter.
  • Performance: Combining filters and masks increases draw calls and requires multiple render texture swaps in the WebGL pipeline. Group static elements together and set container.cacheAsBitmap = true where possible to minimize runtime render overhead.
