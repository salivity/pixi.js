Multiple Uniform Buffers in Pixi.js WebGPU Shaders

Pixi.js v8 fully supports binding multiple uniform buffers simultaneously to a single custom WebGPU shader. By organizing separate sets of shader parameters into distinct UniformGroup instances, you can map them to separate bind points and buffer allocations in WebGPU. This article explains how WebGPU bindings work in Pixi.js, how to configure WGSL shader code to accept multiple uniform buffers, and how to construct the corresponding JavaScript resources.

How Pixi.js Handles Uniform Buffers in WebGPU

In Pixi.js v8's WebGPU pipeline, uniform buffers are represented by the UniformGroup class. Each UniformGroup is backed by its own GPU buffer. When writing a custom WGSL shader, you can define multiple struct declarations and assign each to a specific binding point.

Pixi.js maps uniform groups passed via the shader's resources object directly to the corresponding WebGPU bind groups. Pixi automatically assigns resources to @group(0) by default for custom draw calls, incrementing the @binding(n) index for each separate resource provided.

Defining the WGSL Shader

In your WGSL source code, declare multiple structs and bind them using separate @binding decorators under @group(0).

// WGSL Vertex & Fragment Shader

struct GlobalUniforms {
    uProjectionMatrix: mat3x3<f32>,
    uWorldTransformMatrix: mat3x3<f32>,
};

struct MaterialUniforms {
    uColor: vec4<f32>,
    uIntensity: f32,
};

// Bind first uniform buffer to binding 0
@group(0) @binding(0) var<uniform> globals: GlobalUniforms;

// Bind second uniform buffer to binding 1
@group(0) @binding(1) var<uniform> material: MaterialUniforms;

@vertex
fn mainVertex(@location(0) aPosition: vec2<f32>) -> @builtin(position) vec4<f32> {
    let position = globals.uProjectionMatrix * globals.uWorldTransformMatrix * vec3<f32>(aPosition, 1.0);
    return vec4<f32>(position.xy, 0.0, 1.0);
}

@fragment
fn mainFragment() -> @location(0) vec4<f32> {
    return material.uColor * material.uIntensity;
}

Creating and Binding Multiple UniformGroups in Pixi.js

To supply data to the WGSL shader, create a distinct UniformGroup for each buffer and assign them to the shader's resources object using keys that match the binding names or sequential binding indices.

import { Shader, UniformGroup, Mesh, Geometry } from 'pixi.js';

// 1. Create the first uniform buffer (globals)
const globalUniforms = new UniformGroup({
    uProjectionMatrix: { value: new Float32Array(9), type: 'mat3x3<f32>' },
    uWorldTransformMatrix: { value: new Float32Array(9), type: 'mat3x3<f32>' },
});

// 2. Create the second uniform buffer (material parameters)
const materialUniforms = new UniformGroup({
    uColor: { value: [1.0, 0.5, 0.2, 1.0], type: 'vec4<f32>' },
    uIntensity: { value: 1.5, type: 'f32' },
});

// 3. Define the custom shader with both uniform buffers
const shader = Shader.from({
    gpu: {
        vertex: {
            entryPoint: 'mainVertex',
            source: wgslSourceCode,
        },
        fragment: {
            entryPoint: 'mainFragment',
            source: wgslSourceCode,
        },
    },
    resources: {
        globals: globalUniforms,
        material: materialUniforms,
    },
});

// 4. Attach shader to a Mesh or custom geometry
const mesh = new Mesh({
    geometry: customGeometry,
    shader: shader,
});

Managing Buffer Updates Independently

Using multiple uniform buffers allows you to update frequently changing properties without re-uploading static data to the GPU:

  • Static Buffers: Data that rarely changes (such as material configurations or lighting constants) can remain untouched in its own buffer.
  • Dynamic Buffers: Frequently modified data (such as transforms or frame-based timers) can be updated by modifying group.uniforms.property = newValue and setting group.update() on only that specific UniformGroup.

By leveraging separate UniformGroup objects in Pixi.js, you reduce CPU-to-GPU data transmission overhead while maintaining clean, modular WGSL code.
