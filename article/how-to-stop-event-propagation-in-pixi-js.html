How to Stop Event Propagation in Pixi.js

This guide explains how to prevent event bubbling in Pixi.js using the stopPropagation method. By default, interactive pointer events in a Pixi.js scene graph bubble up from the target child object to its ancestors. Calling stopPropagation() within an active event listener halts this traversal, ensuring that parent containers do not process the same interaction event.

Understanding Event Bubbling in Pixi.js

Pixi.js features an event system (the Federated Events API) modeled closely after the standard DOM event model. When a user interacts with a DisplayObject—such as clicking or tapping a Sprite or Container—the event begins at the root, traverses down to the target during the capture phase, and then bubbles back up through the parent hierarchy.

If both a child object and its parent container have event listeners attached to the same event type (such as pointerdown), clicking the child triggers the child's listener first, followed immediately by the parent's listener.

Using event.stopPropagation()

To prevent an event from bubbling up to parent containers, call stopPropagation() directly on the FederatedPointerEvent object passed to your callback function.

import { Application, Container, Graphics } from 'pixi.js';

const app = new Application({ width: 800, height: 600 });
document.body.appendChild(app.view);

// Create a parent container
const parentContainer = new Container();
parentContainer.eventMode = 'static'; // or 'passive' / 'auto'

// Create a background for the parent to receive hits
const parentBg = new Graphics();
parentBg.beginFill(0x34495e);
parentBg.drawRect(0, 0, 300, 300);
parentBg.endFill();
parentContainer.addChild(parentBg);

// Create a child element inside the container
const childButton = new Graphics();
childButton.beginFill(0xe74c3c);
childButton.drawRect(50, 50, 100, 100);
childButton.endFill();
childButton.eventMode = 'static';
parentContainer.addChild(childButton);

app.stage.addChild(parentContainer);

// Parent listener
parentContainer.on('pointerdown', () => {
    console.log('Parent container clicked!');
});

// Child listener with stopPropagation
childButton.on('pointerdown', (event) => {
    // Stop the event from bubbling up to parentContainer
    event.stopPropagation();
    
    console.log('Child button clicked!');
});

In the example above, clicking directly on childButton logs "Child button clicked!" to the console. Because event.stopPropagation() is invoked, the parentContainer listener will not execute. Clicking anywhere else inside parentBg will still trigger the parent's listener as expected.

stopPropagation() vs. stopImmediatePropagation()

Pixi.js provides two methods for halting event dispatch:

  • event.stopPropagation(): Stops the event from traveling further up the display hierarchy (to parents). Other listeners attached to the same target object will still run.
  • event.stopImmediatePropagation(): Stops the event from bubbling to parent objects and prevents any remaining event listeners attached to the current target object from firing.
