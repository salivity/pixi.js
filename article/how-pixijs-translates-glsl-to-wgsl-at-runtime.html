How PixiJS Translates GLSL to WGSL at Runtime

PixiJS bridges the gap between WebGL and WebGPU by enabling developers to write standard GLSL shaders that seamlessly execute on modern WebGPU backends. To achieve this without requiring external offline compilation tools or shipping massive binary compilers, PixiJS utilizes a lightweight runtime transpilation pipeline. This system parses GLSL code on the fly, reorganizes resources to match WebGPU requirements, decouples texture samplers, restructures loose uniforms into uniform buffer objects, and translates built-in variables and functions directly into valid WebGPU Shading Language (WGSL).

Lightweight AST and Token-Based Parsing

Rather than bundling heavy WebAssembly-based compilers like Naga or SPIRV-Cross, PixiJS uses a purpose-built, JavaScript-native parser designed specifically for 2D and 2.5D graphics shaders. At runtime, the shader code is parsed into tokens and mapped to a lightweight Abstract Syntax Tree (AST). This allows PixiJS to analyze function declarations, variable types, entry points, and input/output interfaces with minimal memory overhead and near-instant compilation times in the browser thread.

Decoupling Textures and Samplers

In GLSL, a sampler2D represents both the texture data and the sampling state (filtering, wrapping) within a single object. WGSL, adhering to modern GPU architecture, strictly separates textures and samplers into distinct bindings: texture_2d<f32> and sampler.

During runtime translation, PixiJS detects all sampler2D declarations in the GLSL source and splits each one into two separate WGSL resource bindings:

  • A texture resource binding (@binding(n) var uTexture: texture_2d<f32>;)
  • A sampler resource binding (@binding(n + 1) var uSampler: sampler;)

The translator simultaneously rewrites texture sampling calls, converting functions like texture2D(uTexture, vUv) into WGSL's textureSample(uTexture, uSampler, vUv).

Packing Loose Uniforms into Uniform Buffer Objects (UBOs)

WebGL allows "loose" uniforms scattered across the shader (such as individual uniform mat3 uMatrix; or uniform vec4 uColor; declarations). WebGPU requires all non-texture uniforms to be aggregated into Uniform Buffer Objects defined inside structured blocks.

PixiJS scans the GLSL source for standalone uniform variables, extracts their types, and synthesizes a corresponding WGSL struct:

struct GlobalUniforms {
    uMatrix: mat3x3<f32>,
    uColor: vec4<f32>,
};
@group(0) @binding(0) var<uniform> globalUniforms: GlobalUniforms;

References within the shader body are then prefixed to read from this newly created struct (e.g., transforming uColor into globalUniforms.uColor), ensuring byte alignment compatibility.

Structuring Attributes and Varyings

GLSL shaders handle inputs and outputs via top-level attribute (or in) and varying (or out) declarations. WGSL requires inputs and outputs to be encapsulated inside explicitly typed structs annotated with location attributes.

PixiJS restructures these variables into:

  • An input vertex struct marked with @location(n) annotations.
  • A vertex-to-fragment intermediary struct (VertexOutput) containing interpolated values.
  • Built-in position mappings, redirecting gl_Position to an output decorated with @builtin(position).

Function and Syntax Conversion

PixiJS performs deterministic replacement of GLSL primitives, types, and intrinsic math functions to their WGSL equivalents:

  • Type Conversion: Translates vector and matrix types (e.g., vec2 to vec2<f32>, mat4 to mat4x4<f32>).
  • Precision Qualifiers: Strips WebGL-specific qualifiers (precision mediump float;, highp, etc.) that are unsupported in WGSL.
  • Intrinsic Mapping: Maps functions such as mix() to WGSL equivalents, adjustments for atan() parameter orders, and replaces discard statements with WGSL's discard control flow syntax.
  • Coordinate Correction: WebGPU uses a coordinate system where normalized device coordinates for depth run from 0.0 to 1.0 (unlike WebGL's -1.0 to 1.0). The PixiJS translation layer applies a coordinate transformation to the vertex position output to maintain visual consistency across both backends.
