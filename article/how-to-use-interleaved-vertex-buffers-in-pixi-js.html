How to Use Interleaved Vertex Buffers in Pixi.js

This article explains how Pixi.js supports interleaved vertex data structures inside a single Buffer instance to improve GPU memory layout and rendering performance. By combining multiple vertex attributes—such as positions, texture coordinates, and colors—into a single contiguous array, developers can minimize buffer binding overhead and maximize GPU cache locality. Pixi.js facilitates this through its core Geometry, Buffer, and Attribute architecture by allowing developers to explicitly define strides and byte offsets for multiple attributes pointing to the same shared buffer.

Understanding Interleaved Buffers

In standard vertex buffer configurations, attributes are often stored in separate arrays (one for positions, one for UVs, and one for colors). An interleaved buffer combines all of these attributes into a single flat array where each vertex's components are stored consecutively:

[X, Y, U, V, R, G, B, A,  X, Y, U, V, R, G, B, A, ...]

Grouping these values together optimizes memory access patterns on the GPU because reading one attribute automatically pulls adjacent vertex attributes into the GPU cache.

Core Pixi.js Classes

Pixi.js provides low-level WebGL and WebGPU abstractions:

  1. Buffer: Wraps a typed array (such as Float32Array or Uint8Array) containing raw vertex data.
  2. Geometry: Manages the mesh's vertex and index data, linking shaders to specific buffer segments.
  3. addAttribute: A method on Geometry that maps a specific shader attribute to a designated section of a Buffer.

Configuring Stride and Offset in Pixi.js

Pixi.js allows interleaved buffers by accepting stride and start (offset) parameters within the geometry.addAttribute() method.

The signature for adding an attribute is:

geometry.addAttribute(id, buffer, size, normalized, type, stride, start);
  • id: The attribute variable name used in the custom vertex shader (e.g., aPosition, aUV).
  • buffer: The shared Buffer instance containing the interleaved data.
  • size: The number of components per vertex for this attribute (e.g., 2 for a 2D position vector).
  • normalized: Whether the data should be normalized (false by default).
  • type: The WebGL data type (defaults to float).
  • stride: The total byte distance between consecutive vertices.
  • start: The byte offset where this attribute begins within each vertex.

Implementation Example

The following code demonstrates defining an interleaved buffer holding 2D position coordinates and 2D texture coordinates for three vertices forming a triangle:

import { Geometry, Buffer, Mesh, Shader, Program } from 'pixi.js';

// Layout per vertex:
// [posX, posY, u, v]
// 4 float values per vertex * 4 bytes per float = 16 bytes stride
const vertexData = new Float32Array([
    //  X,     Y,     U,   V
    -100,  -100,   0.0, 0.0, // Vertex 1
     100,  -100,   1.0, 0.0, // Vertex 2
       0,   100,   0.5, 1.0  // Vertex 3
]);

// Step 1: Create the single buffer
const vertexBuffer = new Buffer(vertexData);

// Step 2: Define stride and offsets (in bytes)
const BYTES_PER_FLOAT = Float32Array.BYTES_PER_ELEMENT; // 4 bytes
const STRIDE = 4 * BYTES_PER_FLOAT;                    // 16 bytes total
const POSITION_OFFSET = 0;                             // Starts at byte 0
const UV_OFFSET = 2 * BYTES_PER_FLOAT;                 // Starts at byte 8

// Step 3: Create the geometry and map attributes to the same buffer
const geometry = new Geometry();

geometry.addAttribute(
    'aPosition',       // Shader attribute name
    vertexBuffer,      // Shared buffer
    2,                 // Size (X, Y)
    false,             // Normalized
    undefined,         // Type (defaults to FLOAT)
    STRIDE,            // 16 bytes stride
    POSITION_OFFSET    // 0 bytes offset
);

geometry.addAttribute(
    'aUV',             // Shader attribute name
    vertexBuffer,      // Shared buffer
    2,                 // Size (U, V)
    false,             // Normalized
    undefined,         // Type (defaults to FLOAT)
    STRIDE,            // 16 bytes stride
    UV_OFFSET          // 8 bytes offset
);

Mixing Data Types

To further optimize memory usage, developers can combine multiple typed views over an underlying ArrayBuffer. For example, positions can use 32-bit floats while vertex colors use 8-bit unsigned integers:

const vertexCount = 3;
const strideInBytes = 12; // 8 bytes for 2 floats (pos) + 4 bytes for 4 uint8s (color)
const arrayBuffer = new ArrayBuffer(vertexCount * strideInBytes);

const floatView = new Float32Array(arrayBuffer);
const uint8View = new Uint8Array(arrayBuffer);

// Populate position (float32) and color (uint8)
// Vertex 0: Pos(0, 0), Color(255, 0, 0, 255)
floatView[0] = 0.0;
floatView[1] = 0.0;
uint8View[8] = 255;
uint8View[9] = 0;
uint8View[10] = 0;
uint8View[11] = 255;

const sharedBuffer = new Buffer(arrayBuffer);
const mixedGeometry = new Geometry();

mixedGeometry.addAttribute('aPosition', sharedBuffer, 2, false, undefined, strideInBytes, 0);
mixedGeometry.addAttribute('aColor', sharedBuffer, 4, true, 5121 /* UNSIGNED_BYTE */, strideInBytes, 8);

By explicitly specifying offsets and stride intervals, Pixi.js passes the correct parameters directly to the underlying gl.vertexAttribPointer calls, enabling full hardware-accelerated interleaved vertex arrays.
