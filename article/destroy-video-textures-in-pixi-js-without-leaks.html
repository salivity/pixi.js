Destroy Video Textures in Pixi.js Without Leaks

Managing video memory in Pixi.js requires disposing of both WebGL GPU resources and the underlying HTML5 DOM element. Failing to clean up both sides results in persistent memory leaks, dangling network connections, or audio continuing to play in the background. This guide provides a direct, step-by-step approach to fully destroying a Pixi.js video texture, its sprite, and the associated <video> element.

Why Video Textures Cause Memory Leaks

A video texture in Pixi.js depends on two primary components:

  1. The Pixi.js Texture and BaseTexture: Holds the WebGL texture reference inside GPU memory.
  2. The HTMLVideoElement: Decodes media, streams frames, and resides in browser CPU/RAM memory.

Calling standard sprite disposal methods alone will often leave the native <video> element running or cached in memory, continuing to buffer data and consume cycles.

Step-by-Step Cleanup Procedure

To cleanly remove a video texture, perform the cleanup in reverse order of creation: stop the media, unload the source, destroy the WebGL textures, and remove the sprite.

1. Stop and Unload the HTMLVideoElement

Retrieve the underlying video element via the texture's baseTexture.resource.source. Pause it, remove the source URL, and call .load() to force the browser to release the media buffer.

const baseTexture = videoSprite.texture.baseTexture;
const videoElement = baseTexture.resource?.source;

if (videoElement instanceof HTMLVideoElement) {
    videoElement.pause();
    videoElement.removeAttribute('src'); // Clear attribute
    videoElement.src = '';              // Empty source property
    videoElement.load();                 // Force browser to unload media buffer
    videoElement.remove();               // Remove from DOM if appended
}

2. Destroy the Texture and BaseTexture

Call .destroy(true) on the texture to ensure that the texture and its underlying BaseTexture are both flagged for GPU deallocation.

// Passing true destroys the BaseTexture alongside the Texture
videoSprite.texture.destroy(true);

3. Destroy the Sprite and Remove from the Stage

Finally, remove the sprite from the stage hierarchy and destroy the display object.

if (videoSprite.parent) {
    videoSprite.parent.removeChild(videoSprite);
}

// Destroy the sprite (children and texture cleanup)
videoSprite.destroy({
    children: true,
    texture: true,
    baseTexture: true
});

Complete Reusable Cleanup Function

Here is an all-in-one cleanup function compatible with Pixi.js v6 and v7:

function disposeVideoSprite(sprite) {
    if (!sprite) return;

    // 1. Clean up HTML5 Video Element
    const texture = sprite.texture;
    if (texture && texture.baseTexture) {
        const source = texture.baseTexture.resource?.source;
        if (source instanceof HTMLVideoElement) {
            source.pause();
            source.removeAttribute('src');
            source.src = '';
            source.load();
            if (source.parentNode) {
                source.parentNode.removeChild(source);
            }
        }
    }

    // 2. Remove from display hierarchy
    if (sprite.parent) {
        sprite.parent.removeChild(sprite);
    }

    // 3. Destroy sprite and GPU textures
    sprite.destroy({
        children: true,
        texture: true,
        baseTexture: true
    });
}

Common Traps to Avoid

  • Relying Solely on sprite.destroy(): By default, sprite.destroy() without explicit arguments does not aggressively unload the base video resource or stop playback on the native element.
  • Retaining Event Listeners: If you attached custom listeners to the HTMLVideoElement (such as timeupdate or ended), remove them via removeEventListener before nullifying references.
  • Global Texture Cache: If the texture was loaded using PIXI.Texture.from('video.mp4'), it was added to PIXI.utils.TextureCache. Call PIXI.Texture.removeFromCache(texture) to remove the reference so the garbage collector can reclaim the object.
