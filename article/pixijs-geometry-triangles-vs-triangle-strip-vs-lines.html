PixiJS Geometry: TRIANGLES vs TRIANGLE_STRIP vs LINES

In Pixi.js, rendering custom shapes with PIXI.Geometry and PIXI.Mesh relies on WebGL drawing modes to instruct the GPU on how to connect raw vertex positions. The three primary topology types—gl.TRIANGLES, gl.TRIANGLE_STRIP, and gl.LINES—control whether vertices are assembled as isolated polygons, continuous mesh ribbons, or simple line segments. This article provides a clear breakdown of how each draw mode interprets vertex buffers, their performance implications, and when to use each in your rendering pipeline.

gl.TRIANGLES

gl.TRIANGLES processes vertices in discrete, independent triplets. For every three sequential vertex points provided in your vertex array (or index buffer), the GPU renders one complete triangle.

  • Assembly Logic: Vertices (v0, v1, v2) create the first triangle, (v3, v4, v5) create the second, and so on.
  • Vertex Formula: If you supply \(N\) vertices, the GPU will render \(N / 3\) independent triangles. Vertices must be supplied in multiples of three; any remaining vertices are discarded.
  • Best Use Cases:
    • Complex, non-linear geometries such as 2D game characters, irregular polygons, or UI panels with interior holes.
    • Meshes imported from standard 3D/2D modeling software where faces are arranged arbitrarily.
  • Consideration: Without an index buffer (PIXI.Buffer assigned as an index), gl.TRIANGLES requires duplicating vertex data for adjacent triangles that share edges, leading to higher memory consumption.

gl.TRIANGLE_STRIP

gl.TRIANGLE_STRIP optimizes vertex reuse by chaining adjacent triangles together. After defining the initial triangle with three vertices, every single subsequent vertex generates an additional triangle using the previous two vertices.

  • Assembly Logic:
    • Triangle 1: (v0, v1, v2)
    • Triangle 2: (v1, v2, v3)
    • Triangle 3: (v2, v3, v4)
    • The GPU automatically alternates the vertex winding order to ensure all triangles share a consistent normal (face orientation).
  • Vertex Formula: Supplying \(N\) vertices yields \(N - 2\) connected triangles (for \(N \ge 3\)).
  • Best Use Cases:
    • Continuous, linear geometry such as ropes (PIXI.SimpleRope), dynamic trails, ribbons, terrain strips, and bendable curves.
    • Simple rectangular quads (a 4-vertex strip produces a 2-triangle quad).
  • Consideration: gl.TRIANGLE_STRIP requires significantly less vertex data than unindexed gl.TRIANGLES. However, constructing disjoint surfaces within a single draw call requires using degenerate triangles (zero-area triangles) to bridge gaps.

gl.LINES

gl.LINES bypasses polygon rasterization entirely, drawing isolated two-point line segments instead of filled surfaces.

  • Assembly Logic: Vertices are read in isolated pairs. Points (v0, v1) produce the first line segment, and (v2, v3) produce the second.
  • Vertex Formula: Supplying \(N\) vertices produces \(N / 2\) line segments. An odd trailing vertex is ignored.
  • Best Use Cases:
    • Debug visualizations, such as rendering collision bounds, bone skeletons, and velocity vectors.
    • Wireframe overlays and technical grid displays.
  • Consideration: WebGL implementations strictly limit the stroke width of gl.LINES (often restricted to 1 pixel across major browsers and operating systems). For variable line thickness or styled borders, render filled geometry using gl.TRIANGLE_STRIP or gl.TRIANGLES instead.
