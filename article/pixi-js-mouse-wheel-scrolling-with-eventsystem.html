Pixi.js Mouse Wheel Scrolling with EventSystem

Pixi.js handles mouse wheel scrolling through its modern EventSystem, a core plugin introduced in Pixi.js v7 to replace the legacy InteractionManager. The system captures native browser wheel events on the canvas, translates them into cross-platform Pixi-specific events via hit testing, and bubbles them through the display hierarchy using a standard DOM-like event flow. This setup allows developers to implement zoom, scroll, and pan behaviors directly on individual display objects or global stage containers.

DOM Listening and Event Interception

The EventSystem attaches a native event listener to the canvas element (view or canvas) configured during renderer initialization. When a user scrolls, the browser triggers a standard DOM WheelEvent. Pixi’s EventSystem intercepts this event and routes it to an internal EventBoundary, which manages the logic for hit detection, coordinates, and dispatching.

Hit Testing and Target Resolution

Before dispatching the event, the EventBoundary checks the coordinates of the cursor:

  1. Coordinate Conversion: The native client coordinates (clientX, clientY) are mapped to the renderer's internal coordinate space (screen and global points).
  2. Hit Detection: The EventBoundary traverses the display tree to locate the topmost DisplayObject or Container under the pointer that has an active eventMode (such as 'static' or 'dynamic').
  3. Target Assignment: If an interactive object sits directly beneath the cursor, it becomes the primary target of the event. If no interactive object is hit, the event targets the root stage.

Normalization via FederatedWheelEvent

Pixi.js wraps the raw DOM event into a FederatedWheelEvent. This object normalizes inconsistent browser behaviors across platforms while appending rendering context data. Key properties accessible on a FederatedWheelEvent include:

  • deltaX, deltaY, and deltaZ: The scroll distances along each axis.
  • deltaMode: Indicates the unit of scroll measurements (pixels, lines, or pages).
  • global: A Point object representing the global coordinate of the wheel event relative to the renderer.
  • client / screen: Viewport-based coordinates from the native event.
  • originalEvent: A direct reference to the native browser WheelEvent for accessing raw properties.

Propagation: Capture and Bubble

Pixi.js implements the W3C event flow model, meaning the FederatedWheelEvent traverses through three phases:

  1. Capture Phase: The event travels downward from the root stage through parent containers until it reaches the target.
  2. Target Phase: The event executes on the target object.
  3. Bubble Phase: The event bubbles back up the display hierarchy through the parent containers.

Developers can intercept the event at any level or call event.stopPropagation() to prevent ancestor containers from reacting to the wheel interaction.

Implementation Example

To receive wheel events, display objects must have their eventMode set, and an event listener must be registered for the 'wheel' event type:

import { Application, Container, Graphics } from 'pixi.js';

const app = new Application();
await app.init({ width: 800, height: 600 });
document.body.appendChild(app.canvas);

const box = new Graphics()
    .rect(0, 0, 100, 100)
    .fill(0xff0000);

box.position.set(350, 250);

// Enable interaction
box.eventMode = 'static';
box.cursor = 'pointer';

// Listen for wheel events
box.on('wheel', (event) => {
    // Prevent the default browser page scroll if necessary
    event.preventDefault();

    // Adjust scale based on deltaY (zooming)
    const zoomFactor = event.deltaY < 0 ? 1.1 : 0.9;
    box.scale.x *= zoomFactor;
    box.scale.y *= zoomFactor;
});

app.stage.addChild(box);

Managing Browser Scroll Behavior

Because the canvas is embedded inside the HTML document, mouse wheel actions within Pixi.js can also trigger native window scrolling. To stop the web page from scrolling while interacting with Pixi objects, event.preventDefault() can be invoked on the federated event, or autoPreventDefault can be enabled on the EventSystem configuration via app.renderer.events.autoPreventDefault = true.
