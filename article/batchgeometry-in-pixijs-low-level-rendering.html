BatchGeometry in PixiJS Low-Level Rendering

This article explores the fundamental role of the BatchGeometry class within the low-level WebGL rendering pipeline of PixiJS. It covers how BatchGeometry coordinates dynamic vertex and index data, enables high-performance draw call batching, and interacts with the batch rendering system to maximize 2D rendering throughput.

In PixiJS, minimizing WebGL draw calls is critical to maintaining high frame rates. The BatchGeometry class serves as the specialized data container that enables this optimization. It extends the standard Geometry class to aggregate the geometry of multiple independent 2D display objects—such as sprites, meshes, and graphics—into unified vertex and index buffers that can be rendered in a single draw call.

Vertex Buffer Aggregation

Instead of allocating separate vertex buffers for every sprite or visual element, the rendering pipeline uses BatchGeometry to manage contiguous blocks of memory. As the batch system iterates over renderable objects, it writes their vertex attributes directly into the arrays managed by BatchGeometry. These attributes typically include:

  • Positions: 2D screen coordinates \((x, y)\).
  • Texture Coordinates (UVs): Normalized mapping coordinates \((u, v)\).
  • Colors/Alpha: Packed 32-bit RGBA tint and opacity values.
  • Texture Indices: Identifiers indicating which WebGL texture unit contains the object's texture.

By packing these attributes sequentially, BatchGeometry allows the GPU to process hundreds or thousands of quads consecutively without switching buffer bindings.

Pre-allocated Index Buffers

A primary architectural advantage of BatchGeometry is its handling of index buffers. Most 2D elements rendered in PixiJS are quads constructed from two triangles (requiring 6 indices for 4 vertices). Rather than recalculating and uploading index arrays every frame, BatchGeometry maintains a pre-populated, static index buffer patterned specifically for quads (\(0, 1, 2, 0, 2, 3\), shifted for each subsequent quad). This design eliminates the CPU overhead of generating index data in real time and allows PixiJS to scale the index buffer dynamically if the batch size increases.

Multi-Texture Coordination

BatchGeometry directly supports PixiJS’s multi-texture batching mechanism. Because modern GPUs support binding multiple textures simultaneously, BatchGeometry includes the texture index as a per-vertex attribute. When the shader runs, it reads this attribute to sample from the correct texture unit. BatchGeometry facilitates this by aligning buffer strides and attribute pointers so the vertex shader can route geometry to the correct texture sampler without flushing the batch.

WebGL Execution

At the rendering stage, BatchGeometry binds its attributes to the target WebGL context via a single Vertex Array Object (VAO) where supported. Once the batch system finishes gathering objects up to its maximum capacity, it issues a single gl.drawElements call referencing BatchGeometry's populated buffers. Once drawn, the geometry's buffer pointers reset, making it ready to collect the next batch of renderables with minimal memory allocation overhead.
