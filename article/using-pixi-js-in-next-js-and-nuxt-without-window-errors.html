Using Pixi.js in Next.js and Nuxt Without Window Errors

Integrating Pixi.js into server-side rendering (SSR) frameworks like Next.js and Nuxt often triggers the dreaded ReferenceError: window is not defined. This article explains why this error occurs when evaluating Pixi.js on the server and provides direct, practical solutions to properly load and mount Pixi.js strictly on the client side in both Next.js and Nuxt applications.

Why the Error Happens

Pixi.js is a client-side 2D rendering engine that relies directly on browser-specific APIs, such as window, document, and WebGL context providers (HTMLCanvasElement). When Next.js or Nuxt compiles a page on the server using Node.js, these browser APIs do not exist in the runtime environment. If Pixi.js is imported or initialized top-level in a component, Node.js attempts to access window, resulting in an immediate crash.

To fix this, you must defer the importation and execution of Pixi.js until the component has mounted in the browser.

Solution 1: Integrating with Next.js

Next.js provides two primary ways to bypass server-side evaluation: next/dynamic and the useEffect hook.

Method A: Using next/dynamic (Recommended for standalone canvas components)

Create your Pixi component in a separate file (e.g., components/PixiCanvas.tsx), then import it dynamically with SSR disabled in your parent page or component.

// components/PixiCanvas.tsx
'use client';

import { useEffect, useRef } from 'react';
import * as PIXI from 'pixi.js';

export default function PixiCanvas() {
  const containerRef = useRef<HTMLDivElement>(null);

  useEffect(() => {
    if (!containerRef.current) return;

    const app = new PIXI.Application();

    // Async initialization for Pixi v8 (or synchronous for v7)
    const initPixi = async () => {
      await app.init({ width: 600, height: 400, backgroundColor: 0x1099bb });
      containerRef.current?.appendChild(app.canvas);

      const graphics = new PIXI.Graphics();
      graphics.rect(50, 50, 100, 100);
      graphics.fill(0xffffff);
      app.stage.addChild(graphics);
    };

    initPixi();

    return () => {
      app.destroy(true, { children: true });
    };
  }, []);

  return <div ref={containerRef} />;
}

Import it in your page using next/dynamic:

// app/page.tsx or pages/index.tsx
import dynamic from 'next/dynamic';

const PixiCanvas = dynamic(() => import('@/components/PixiCanvas'), {
  ssr: false,
});

export default function Page() {
  return (
    <main>
      <h1>Pixi.js in Next.js</h1>
      <PixiCanvas />
    </main>
  );
}

Method B: Dynamic Import Inside useEffect

If you prefer to keep everything in a single component without next/dynamic, import the library dynamically inside useEffect, which only executes in the browser:

'use client';

import { useEffect, useRef } from 'react';

export default function PixiInline() {
  const containerRef = useRef<HTMLDivElement>(null);

  useEffect(() => {
    let app: any;

    const loadPixi = async () => {
      const PIXI = await import('pixi.js');
      app = new PIXI.Application();

      await app.init({ width: 600, height: 400 });
      containerRef.current?.appendChild(app.canvas);
    };

    loadPixi();

    return () => {
      if (app) app.destroy(true, { children: true });
    };
  }, []);

  return <div ref={containerRef} />;
}

Solution 2: Integrating with Nuxt 3

Nuxt provides built-in mechanisms to isolate client-only code: the .client.vue component suffix, the <ClientOnly> component, and dynamic imports within the onMounted lifecycle hook.

Method A: Using the .client.vue Suffix

Create a component named PixiCanvas.client.vue. Nuxt automatically detects the .client suffix and excludes the file from server-side builds.

<!-- components/PixiCanvas.client.vue -->
<template>
  <div ref="pixiContainer"></div>
</template>

<script setup lang="ts">
import { ref, onMounted, onBeforeUnmount } from 'vue';
import * as PIXI from 'pixi.js';

const pixiContainer = ref<HTMLDivElement | null>(null);
let app: PIXI.Application | null = null;

onMounted(async () => {
  if (!pixiContainer.value) return;

  app = new PIXI.Application();
  await app.init({ width: 600, height: 400, backgroundColor: 0x1099bb });

  pixiContainer.value.appendChild(app.canvas);
});

onBeforeUnmount(() => {
  if (app) {
    app.destroy(true, { children: true });
  }
});
</script>

Method B: Using onMounted with Dynamic Import

If you do not want to use file suffixing, import Pixi dynamically inside Vue’s onMounted hook:

<!-- components/PixiDynamic.vue -->
<template>
  <ClientOnly>
    <div ref="pixiContainer"></div>
  </ClientOnly>
</template>

<script setup lang="ts">
import { ref, onMounted, onBeforeUnmount } from 'vue';

const pixiContainer = ref<HTMLDivElement | null>(null);
let app: any = null;

onMounted(async () => {
  const PIXI = await import('pixi.js');
  
  app = new PIXI.Application();
  await app.init({ width: 600, height: 400 });

  if (pixiContainer.value) {
    pixiContainer.value.appendChild(app.canvas);
  }
});

onBeforeUnmount(() => {
  if (app) {
    app.destroy(true, { children: true });
  }
});
</script>

Essential Cleanup Practices

WebGL contexts are limited per browser tab. Failing to properly clean up your Pixi application can cause memory leaks and context loss when navigating between pages in SPA mode. Always invoke app.destroy(true, { children: true }) inside the component cleanup lifecycle (return () => {} in React's useEffect or onBeforeUnmount in Vue).
