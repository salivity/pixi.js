Difference Between inputClamp and inputSize in PixiJS

When developing custom fragment filters in Pixi.js, inputSize and inputClamp are two built-in vec4 uniform vectors that handle texture coordinate calculations and render boundary management. The primary difference is that inputSize provides dimension metrics and inverse texel sizes for coordinate transformations, while inputClamp defines the valid coordinate bounds to prevent sampling artifacts and texture bleeding caused by Pixi.js's internal texture pooling system.

What is inputSize?

The inputSize uniform provides resolution data regarding the input filter texture. It is a vec4 structured as follows:

  • inputSize.x: The width of the input filter area in pixels.
  • inputSize.y: The height of the input filter area in pixels.
  • inputSize.z: The inverse width (1.0 / width), representing the horizontal size of a single texel in normalized UV coordinates (0.0 to 1.0).
  • inputSize.w: The inverse height (1.0 / height), representing the vertical size of a single texel in normalized UV coordinates (0.0 to 1.0).

Common Use Cases for inputSize

  • Convolution and Blur Offsets: Shaders that sample adjacent pixels (such as Gaussian blurs, drop shadows, or edge-detection filters) multiply an offset step by inputSize.zw to calculate the exact distance to neighboring texels.
  • Aspect Ratio Adjustments: Calculating normalized circular shapes, radial gradients, or aspect-correct noise requires scaling coordinates using inputSize.xy.

What is inputClamp?

The inputClamp uniform defines the normalized UV boundaries of the actual object being filtered. It is a vec4 structured as:

  • inputClamp.xy: The minimum UV coordinates (top-left) of the valid render region.
  • inputClamp.zw: The maximum UV coordinates (bottom-right) of the valid render region.

Pixi.js reuses WebGL render textures from a shared pool to optimize GPU memory. Consequently, the input texture passed to a filter is often larger than the target display object, meaning the target content occupies only a specific sub-rectangle.

If a shader samples outside this sub-rectangle—which frequently happens with displacement, distortion, or multi-tap blur filters—it may sample blank space or leftover pixel data from other pooled draws, leading to visible edge bleeding and visual artifacts.

Common Use Cases for inputClamp

  • Boundary Clamping: Whenever a shader offsets texture coordinates, clamping the calculated UV coordinate prevents edge artifacts: 
    vec2 clampedCoord = clamp(displacedCoord, inputClamp.xy, inputClamp.zw);
vec4 color = texture2D(uSampler, clampedCoord);

Key Differences Summary

Feature inputSize inputClamp
Component Format (width, height, 1.0/width, 1.0/height) (minX, minY, maxX, maxY)
Primary Role Pixel dimensions and texel step calculation. Texture boundary restriction.
Shader Purpose Determining coordinate scales and pixel distances. Preventing edge bleeding on multi-tap or displaced samples.
Typical Operation Multiplied with pixel offsets (using .zw). Applied via the GLSL clamp() function.
