Configuring WebGPU Color Write Masks in PixiJS

This article provides an overview of how Pixi.js handles color write masks to isolate specific RGBA channels during a WebGPU render pass. You will learn about the role of the underlying WebGPU GPUColorWrite flags, how Pixi.js maps render states to WebGPU pipelines, and the implementation details required to restrict drawing operations to targeted color channels.

WebGPU Color Write Masks Fundamentals

In WebGPU, channel masking is controlled at the pipeline level rather than as dynamic render pass state. The writeMask property belongs to the GPUColorTargetState dictionary within a render pipeline’s descriptor. It uses a bitwise flag system defined by the global GPUColorWrite constants:

  • GPUColorWrite.RED (0x1)
  • GPUColorWrite.GREEN (0x2)
  • GPUColorWrite.BLUE (0x4)
  • GPUColorWrite.ALPHA (0x8)
  • GPUColorWrite.ALL (0xF)

When a fragment shader outputs a color, the GPU applies this bitmask to determine which components of the fragment are written into the target texture attachment. Unset channels remain untouched, retaining their existing values in the framebuffer.

Pixi.js Architecture and Pipeline Management

Pixi.js v8 introduced a unified rendering architecture supporting both WebGL and WebGPU backends. Unlike WebGL, which permits dynamic switching of color masks at any point via gl.colorMask(r, g, b, a), WebGPU requires color mask states to be baked directly into the immutable GPURenderPipeline.

To handle this, the Pixi.js WebGPU renderer abstracts state tracking through its pipeline management systems:

  1. State Representation: Pixi.js maintains a render state object tracking blending, depth testing, culling, and color write operations.
  2. Pipeline Caching: The WebGPU backend (WebGPUPipelineSystem) hashes the active shader program, blend modes, geometry layout, and color write mask states to retrieve or asynchronously compile an appropriate GPURenderPipeline.
  3. Attachment Binding: During a render pass, the pipeline bound via GPUCommandEncoder.beginRenderPass() enforces the mask whenever draw calls are issued.

Configuring Masks in Pixi.js

To isolate specific channels in Pixi.js when rendering via WebGPU, the configuration is applied through custom materials, custom GpuProgram instances, or low-level render pass controls.

1. Setting the Mask on Custom Shaders and Pipelines

When defining custom shaders using Shader or GpuProgram, you specify color target states within the pipeline descriptor override. This explicitly defines the writeMask passed to the underlying device.createRenderPipeline():

import { Shader, GpuProgram } from 'pixi.js';

// Define which channels to write to (e.g., Red and Alpha only)
const writeMask = GPUColorWrite.RED | GPUColorWrite.ALPHA;

const gpuProgram = GpuProgram.from({
    vertex: { source: vertexShaderWGSL, entryPoint: 'main' },
    fragment: { source: fragmentShaderWGSL, entryPoint: 'main' },
    gpuOptions: {
        targets: [
            {
                format: 'bgra8unorm', // Target texture format
                writeMask: writeMask, // Channel isolation mask
            }
        ]
    }
});

const customShader = new Shader({ gpuProgram });

2. Modifying Render Passes and Pipeline States

For custom rendering systems or render-to-texture operations:

  1. Query Target Configuration: Retrieve the render target's texture format (commonly bgra8unorm or rgba8unorm).
  2. Combine Flags: Combine the required bitwise values from GPUColorWrite to block unwanted channels. For example, to isolate the green channel, assign writeMask = GPUColorWrite.GREEN.
  3. Pipeline Construction: When Pixi.js evaluates the draw call, its pipeline manager detects the modified target state and issues the WebGPU pipeline creation descriptor containing:
targets: [{
    format: targetTextureFormat,
    writeMask: GPUColorWrite.GREEN,
    blend: blendState,
}]

Execution in the Render Pass

Once the pipeline is configured with the isolated channel mask, Pixi.js executes the draw commands through the standard WebGPU render pass workflow:

  1. The WebGPUColorMaskSystem or pipeline state manager generates a pipeline hash including the specific writeMask.
  2. The pass encoder sets the pipeline via renderPassEncoder.setPipeline(pipeline).
  3. When vertices and fragments are processed, the GPU filters the fragment stage output. Any component omitted from the writeMask is discarded before writing to the render target's color buffer, preserving existing target channel data throughout the render pass.
