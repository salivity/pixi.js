Measure Pixi.js Frame Time with WebGPU Timestamps

This article details how to accurately measure GPU frame execution times in Pixi.js by utilizing WebGPU timestamp queries. Because standard JavaScript timers like performance.now() only measure CPU execution time and do not account for asynchronous GPU command processing, relying on native GPU hardware timestamps is essential for true render profiling. Below, you will find the architectural requirements, configuration steps, and implementation code required to extract nanosecond-precise render timings in modern Pixi.js applications.

Understanding WebGPU Timestamps

Standard profiling tools measure the time it takes the CPU to queue draw commands, not the time the GPU takes to execute them. WebGPU provides a dedicated query mechanism (timestamp-query) that logs hardware-level execution timestamps at specific stages within a command buffer.

Note: Due to security restrictions (such as mitigation against Spectre-like timing attacks), modern browsers require specific flags enabled—such as --disable-dawn-features=disallow_unsafe_apis in Chrome or enabling Developer Tools experiments—to access timestamp queries.

Step 1: Requesting the Timestamp Query Feature

To use timestamp queries in Pixi.js (version 8+), you must configure the underlying WebGPURenderer to request the timestamp-query feature when initializing the GPU device.

import { Application } from 'pixi.js';

const app = new Application();

await app.init({
    width: 800,
    height: 600,
    preference: 'webgpu',
    powerPreference: 'high-performance',
    gpu: {
        requiredFeatures: ['timestamp-query']
    }
});

Step 2: Creating Query Sets and Buffers

You need a GPUQuerySet configured for timestamps, a destination buffer on the GPU to hold the resolved values, and a readback buffer mapped to CPU memory to retrieve the results.

const device = app.renderer.gpu.device;

// Check if feature is available on the device
if (!device.features.has('timestamp-query')) {
    throw new Error('timestamp-query is not supported or enabled on this system.');
}

// 2 queries: one before the render, one after
const querySet = device.createQuerySet({
    type: 'timestamp',
    count: 2
});

const queryResolveBuffer = device.createBuffer({
    size: 2 * BigInt64Array.BYTES_PER_ELEMENT,
    usage: GPUBufferUsage.QUERY_RESOLVE | GPUBufferUsage.COPY_SRC
});

const readbackBuffer = device.createBuffer({
    size: 2 * BigInt64Array.BYTES_PER_ELEMENT,
    usage: GPUBufferUsage.COPY_DST | GPUBufferUsage.MAP_READ
});

Step 3: Writing Timestamps Around Frame Execution

WebGPU allows timestamps to be written directly into a command encoder or a compute/render pass. To measure the full rendering overhead of a frame in Pixi.js, you can execute a custom command encoder pass that bookmarks the timestamps immediately before and after the scene draws.

async function measureRenderPass() {
    const encoder = device.createCommandEncoder();

    // Write start timestamp (index 0)
    encoder.writeTimestamp(querySet, 0);
    device.queue.submit([encoder.finish()]);

    // Render the Pixi.js stage
    app.render();

    // Write end timestamp (index 1) and resolve queries
    const resolveEncoder = device.createCommandEncoder();
    resolveEncoder.writeTimestamp(querySet, 1);
    
    // Resolve the query set to the GPU buffer
    resolveEncoder.resolveQuerySet(querySet, 0, 2, queryResolveBuffer, 0);
    
    // Copy the resolved 64-bit values to the readable buffer
    resolveEncoder.copyBufferToBuffer(
        queryResolveBuffer, 
        0, 
        readbackBuffer, 
        0, 
        2 * BigInt64Array.BYTES_PER_ELEMENT
    );

    device.queue.submit([resolveEncoder.finish()]);

    // Read the values back to JavaScript
    await readbackBuffer.mapAsync(GPUMapMode.READ);
    const arrayBuffer = readbackBuffer.getMappedRange();
    const timestamps = new BigInt64Array(arrayBuffer.slice());
    readbackBuffer.unmap();

    // Calculate duration in nanoseconds, then convert to milliseconds
    const nanoseconds = Number(timestamps[1] - timestamps[0]);
    const milliseconds = nanoseconds / 1_000_000;

    return milliseconds;
}

Continuous Profiling Considerations

Querying timestamps on every single frame by immediately mapping buffers can introduce CPU stalls due to synchronization waits. For real-time profiling during production or testing:

  1. Ring Buffers: Implement a circular buffer system with multiple sets of resolve and readback buffers so you can process frame \(N\) while the GPU resolves frame \(N-2\).
  2. Sampling: Capture metrics over intervals (e.g., once every 30 or 60 frames) rather than mapping buffers on every render tick.
  3. Disjoint Queries: Ensure your application accounts for potential system resets or disjoint states where hardware clock frequencies change dynamically between frames.
