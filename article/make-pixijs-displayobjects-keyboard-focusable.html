Make PixiJS DisplayObjects Keyboard Focusable

This guide explains how to make PixiJS DisplayObject instances accessible and navigable using the keyboard Tab key. By leveraging the built-in PixiJS AccessibilityManager, you can automatically create an HTML DOM overlay over your WebGL or Canvas elements, enabling native browser focus states, screen reader support, and standard keyboard interaction.

1. Ensure the Accessibility Manager Is Active

PixiJS includes an accessibility plugin that creates a hidden HTML layer over the canvas containing standard DOM elements mapped to your display objects. In most standard builds (PixiJS v7 and v8), the accessibility manager initializes automatically. If you are using a custom bundle, make sure @pixi/accessibility is imported and registered.

You can verify or activate it on your application instance:

app.renderer.accessibility.active = true;

2. Configure the DisplayObject Properties

To make any DisplayObject (such as a Sprite, Graphics, or Container) focusable via the Tab key, you must enable interaction and configure its accessibility properties.

import { Graphics } from 'pixi.js';

const button = new Graphics();
button.beginFill(0x3498db);
button.drawRoundedRect(0, 0, 150, 50, 8);
button.endFill();

// 1. Enable interaction (eventMode in v7+, interactive in v6 and below)
button.eventMode = 'static';
button.cursor = 'pointer';

// 2. Enable accessibility
button.accessible = true;

// 3. Set accessibility metadata
button.accessibleTitle = 'Submit Action';
button.accessibleType = 'button'; // Can be 'button', 'link', etc.
button.accessibleHint = 'Activates the primary form submission';

// 4. Add to the stage
app.stage.addChild(button);

When accessible = true is set, PixiJS generates a native HTML <button> or <div> placed directly over the coordinates of your DisplayObject. When the user presses Tab, the browser shifts focus to this DOM element.

3. Handle Keyboard Activation

Once an object receives focus, users expect to trigger it using the Enter or Space keys. PixiJS automatically dispatches interaction events when the underlying accessible DOM element is triggered:

function onActivate() {
    console.log('DisplayObject activated via click or keyboard!');
}

// Works for both pointer clicks and keyboard 'Enter'/'Space' when focused
button.on('pointertap', onActivate);

4. Visualizing the Focus State

While the browser tracks focus on the invisible DOM layer, you must provide visual feedback on the canvas so keyboard users know which element is currently selected.

Listen to the focus and blur events directly on the DisplayObject:

const focusRing = new Graphics();
focusRing.lineStyle(3, 0xffffff);
focusRing.drawRoundedRect(-4, -4, 158, 58, 10);
focusRing.visible = false;
button.addChild(focusRing);

// Show visual ring on keyboard focus
button.on('focus', () => {
    focusRing.visible = true;
});

// Hide visual ring when focus is lost
button.on('blur', () => {
    focusRing.visible = false;
});

5. Controlling Tab Order (tabIndex)

By default, the tab order follows the scene graph hierarchy and the order in which accessible objects are added to the stage. If you need a specific navigation sequence, define the accessibleTabIndex property:

firstButton.accessibleTabIndex = 1;
secondButton.accessibleTabIndex = 2;

Setting accessibleTabIndex = -1 will remove an item from the sequential keyboard navigation while still allowing it to remain programmatically focusable or detectable by screen readers.
