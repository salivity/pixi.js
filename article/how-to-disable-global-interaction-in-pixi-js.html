How to Disable Global Interaction in Pixi.js

Disabling user input during cutscenes, transitions, or loading screens is essential for preventing accidental inputs and maintaining state integrity in Pixi.js applications. This guide explains how to disable interactions globally across your entire scene using Pixi.js's built-in event system properties, DOM-level pointer handling, and invisible blocker layers.

Method 1: Disabling interactiveChildren on the Stage

The most idiomatic way within Pixi.js to freeze user interactions is to disable event processing on the root container (app.stage). Setting interactiveChildren to false prevents the event system from traversing the display list and firing events on child display objects.

// Disable all interactions across the stage
app.stage.interactiveChildren = false;

// Re-enable interactions once the cutscene or loading ends
app.stage.interactiveChildren = true;

In Pixi.js v7 and v8, you can also set the eventMode property directly on the stage:

// Disables interaction on the stage and all descendants
app.stage.eventMode = 'none';

// Restore default interactive behavior
app.stage.eventMode = 'passive'; // or 'auto' depending on your setup

Method 2: Disabling Pointer Events on the Canvas Element

If you want a lightweight approach that completely bypasses the Pixi.js event loop without altering the display hierarchy states, you can disable pointer events on the HTML <canvas> element via CSS.

// Disable inputs completely at the DOM level
app.canvas.style.pointerEvents = 'none';

// Re-enable inputs
app.canvas.style.pointerEvents = 'auto';

(Note: In Pixi.js v7 and earlier, use app.view instead of app.canvas.)

This approach ensures the browser drops all mouse, touch, and pointer events before they ever reach the Pixi.js renderer, saving CPU cycles during heavy loading routines.

Method 3: Using an Invisible Fullscreen Blocker

If you need certain background tasks or animations to remain interactive while blocking general gameplay interactions, an overlay blocker is the most flexible approach. Create a transparent Container or Graphics object positioned on the topmost rendering layer to consume all incoming pointer events.

// Create a fullscreen hit area blocker
const blocker = new PIXI.Graphics();
blocker.rect(0, 0, app.screen.width, app.screen.height);
blocker.fill({ color: 0x000000, alpha: 0 }); // Transparent

// Set the eventMode to consume events
blocker.eventMode = 'static';
blocker.cursor = 'default';

// Add to the top of the scene during transitions
app.stage.addChild(blocker);

// Remove the blocker to restore interaction
app.stage.removeChild(blocker);

This method is particularly useful when transitions include custom skip buttons or loading dialogs, as you can position those interactive elements above the blocker while keeping the underlying game world non-interactive.
