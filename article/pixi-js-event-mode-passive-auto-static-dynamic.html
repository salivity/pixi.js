PixiJS eventMode: passive, auto, static, dynamic

In PixiJS v7 and later, the EventSystem replaces the legacy boolean interactive property with eventMode, providing granular control over how display objects participate in hit-testing and event bubbling. Choosing the correct mode between 'passive', 'auto', 'static', and 'dynamic' is essential for optimizing rendering performance, managing pointer events, and ensuring accurate hit detection in complex scenes.

'auto'

'auto' is the default eventMode for display objects. Under this setting, PixiJS determines interaction based on whether the object has registered event listeners. If the object has no listeners, it acts transparently—passing hit-testing down to its children without emitting events on itself. If event listeners (such as pointerdown or click) are added to the object, PixiJS treats it as interactive, functioning similarly to 'static'.

'passive'

'passive' designates that an object should never trigger interaction events on itself, but it allows hit-testing to traverse through to its children. This mode is best suited for organizational containers, layers, or parent wrappers that do not require user interaction themselves but contain buttons or other interactive elements. Using 'passive' prevents unnecessary hit calculations on the parent while maintaining interactivity for nested items.

'static'

'static' marks an object as interactive, meaning it actively receives and handles pointer events such as clicks, taps, and drags. It is optimized for elements that do not move constantly, such as UI buttons, stationary game assets, or static dialogue windows. When an object is set to 'static', PixiJS assumes its position and dimensions remain relatively stable, allowing the hit-testing pipeline to optimize event dispatching based on mouse and touch movements.

'dynamic'

'dynamic' is designed for interactive objects that animate, move, or change size continuously. In standard static hit-testing, an event typically triggers only when the pointer moves over an object. If an object moves under a stationary mouse cursor, a static mode might not detect the collision immediately. Setting eventMode = 'dynamic' forces PixiJS to evaluate hit-testing for the object on every frame or tick, ensuring accurate detection for moving targets, flying projectiles, or scrolling game worlds. Because of this continuous evaluation, 'dynamic' has the highest performance overhead and should only be used when necessary.

Summary Comparison

  • auto: Adapts automatically; acts passive if no listeners are attached, or interactive if listeners exist.
  • passive: Does not trigger events on itself, but checks its children.
  • static: Always interactive; optimized for UI and non-moving objects.
  • dynamic: Always interactive; continuously updates hit bounds for moving or animating objects.
