How Pixi.js Mask Affects getBounds Calculations

In Pixi.js, managing spatial dimensions through bounding boxes is a core requirement for collision detection, UI layout, and viewport culling. However, using the mask property alongside getBounds() frequently produces unexpected results for developers. This article explains how Pixi.js evaluates display objects when masks are applied, why masked objects retain their full dimensions during bounds calculations, and how to reliably determine the true visible area of masked content.

The Default Behavior: Masks Are Ignored

When you call getBounds() on a Container or DisplayObject, Pixi.js calculates the smallest rectangle that encompasses all of the object's vertices and visible children in global coordinates. By design, the mask property is completely disregarded during this process.

If you apply a 100x100 pixel Graphics mask to an 800x600 pixel Sprite, calling sprite.getBounds() will still return a rectangle of 800x600 pixels. The mask does not truncate, clip, or resize the bounding box returned by the masked object.

Why getBounds Does Not Account for Masks

The separation between masks and bounding calculations is an intentional performance choice rooted in the Pixi.js rendering architecture:

  1. Rendering vs. Scene Graph: In Pixi.js, masks are GPU rendering directives handled during the WebGL render pass (using stencil buffers, scissors, or custom shaders). They dictate which pixels are drawn to the screen, not the structural dimensions of the scene graph.
  2. CPU Performance Overhead: Dynamically calculating geometric intersections between complex shapes (such as polygonal or bezier curve masks) and child display hierarchies during getBounds() calls would introduce significant CPU overhead, negatively impacting frame rates.

Masks Within the Display List

A common side effect occurs when the mask object itself is added to the display hierarchy. If you add the mask as a child via container.addChild(maskObject), its geometry will be included in the container's getBounds() calculation along with the other children. To prevent the mask's geometry from expanding the container's bounds, assign the mask strictly to the mask property (container.mask = maskObject) without adding it as a rendered child of that container, or ensure it is added to an external parent.

Calculating the True Visible Bounding Box

Because getBounds() does not automatically clip dimensions to the mask, obtaining the actual visible screen area requires manually intersecting the target object's bounds with the mask's bounds.

You can compute the visible rectangle by retrieving both bounding boxes and finding their overlapping region:

function getVisibleBounds(displayObject) {
    const objectBounds = displayObject.getBounds();

    if (!displayObject.mask) {
        return objectBounds;
    }

    const maskBounds = displayObject.mask.getBounds();

    const x0 = Math.max(objectBounds.x, maskBounds.x);
    const y0 = Math.max(objectBounds.y, maskBounds.y);
    const x1 = Math.min(objectBounds.x + objectBounds.width, maskBounds.x + maskBounds.width);
    const y1 = Math.min(objectBounds.y + objectBounds.height, maskBounds.y + maskBounds.height);

    if (x1 <= x0 || y1 <= y0) {
        // No visible intersection
        return new PIXI.Rectangle(0, 0, 0, 0);
    }

    return new PIXI.Rectangle(x0, y0, x1 - x0, y1 - y0);
}

This intersection provides the precise rectangular area visible to the user, ensuring that UI positioning and hit-testing accurately reflect masked elements.
