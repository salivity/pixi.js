Compute Post-Processing in PixiJS WebGPU

Implementing compute-based image post-processing with storage textures in PixiJS enables high-performance visual effects that leverage modern WebGPU capabilities. While standard PixiJS post-processing uses traditional fragment shaders via the Filter system, compute shaders allow arbitrary memory reads, shared workgroup memory, and direct writes to storage textures. This guide covers how to access the underlying WebGPU device, configure read and write storage textures, dispatch a WGSL compute shader pass, and integrate the final output back into the PixiJS rendering loop.

1. Initialize PixiJS with WebGPU

To use compute shaders and storage textures, ensure the application initializes using the WebGPU renderer preference.

import { Application, RenderTexture, Sprite } from 'pixi.js';

const app = new Application();
await app.init({
    width: 800,
    height: 600,
    preference: 'webgpu'
});
document.body.appendChild(app.canvas);

// Verify WebGPU is active
if (app.renderer.type !== 'webgpu') {
    throw new Error('WebGPU is not supported or not active.');
}

2. Set Up Textures and Storage Targets

Compute post-processing requires a source texture (the rendered scene) and an output storage texture. WebGPU storage textures require the GPUTextureUsage.STORAGE_BINDING flag, along with GPUTextureUsage.TEXTURE_BINDING if you plan to sample them afterward.

const device = app.renderer.gpu.device;
const width = app.screen.width;
const height = app.screen.height;

// 1. PixiJS render target for rendering the initial scene
const sceneRenderTarget = RenderTexture.create({ width, height });

// 2. Native WebGPU storage texture for compute output
const storageTexture = device.createTexture({
    size: [width, height],
    format: 'rgba8unorm',
    usage: 
        GPUTextureUsage.STORAGE_BINDING | 
        GPUTextureUsage.TEXTURE_BINDING | 
        GPUTextureUsage.COPY_SRC
});

3. Write the WGSL Compute Shader

Compute shaders read pixel data, process it, and write the output into a storage texture using coordinates derived from the global invocation ID.

@group(0) @binding(0) var inputTexture: texture_2d<f32>;
@group(0) @binding(1) var outputTexture: texture_storage_2d<rgba8unorm, write>;

@compute @workgroup_size(16, 16)
fn main(@builtin(global_invocation_id) id: vec3<u32>) {
    let dims = textureDimensions(inputTexture);
    if (id.x >= dims.x || id.y >= dims.y) {
        return;
    }

    let coords = vec2<i32>(id.xy);
    let color = textureLoad(inputTexture, coords, 0);

    // Example: Grayscale and invert post-processing effect
    let gray = dot(color.rgb, vec3<f32>(0.299, 0.587, 0.114));
    let inverted = vec3<f32>(1.0 - gray);

    textureStore(outputTexture, coords, vec4<f32>(inverted, color.a));
}

4. Build the Compute Pipeline and Bind Group

Compile the compute shader, create the pipeline, and construct the bind group that connects the scene texture and the storage texture.

const shaderModule = device.createShaderModule({
    code: `/* WGSL code from Step 3 */`
});

const computePipeline = device.createComputePipeline({
    layout: 'auto',
    compute: {
        module: shaderModule,
        entryPoint: 'main'
    }
});

function createComputeBindGroup(sourceGpuTexture) {
    return device.createBindGroup({
        layout: computePipeline.getBindGroupLayout(0),
        entries: [
            {
                binding: 0,
                resource: sourceGpuTexture.createView()
            },
            {
                binding: 1,
                resource: storageTexture.createView()
            }
        ]
    });
}

5. Execute the Compute Pass in the Render Loop

To apply the post-processing every frame:

  1. Render your PixiJS scene into the offscreen sceneRenderTarget.
  2. Extract the underlying GPUTexture from the PixiJS texture source.
  3. Open a WebGPU command encoder to dispatch the compute workgroups.
  4. Draw the processed storage texture to the screen.
// Wrap the storage texture into a PixiJS external texture for display
const outputPixiTexture = RenderTexture.from({
    resource: storageTexture,
    width,
    height
});
const screenSprite = new Sprite(outputPixiTexture);

app.ticker.add(() => {
    // Step A: Render the scene to the off-screen target
    app.renderer.render({
        container: sceneContainer,
        target: sceneRenderTarget,
        clear: true
    });

    // Step B: Get the native texture from Pixi's GPU representation
    const sourceGpuTexture = app.renderer.texture.getGpuSource(sceneRenderTarget.source).texture;
    const bindGroup = createComputeBindGroup(sourceGpuTexture);

    // Step C: Dispatch Compute Commands
    const commandEncoder = device.createCommandEncoder();
    const passEncoder = commandEncoder.beginComputePass();
    passEncoder.setPipeline(computePipeline);
    passEncoder.setBindGroup(0, bindGroup);

    const workgroupCountX = Math.ceil(width / 16);
    const workgroupCountY = Math.ceil(height / 16);
    passEncoder.dispatchWorkgroups(workgroupCountX, workgroupCountY);
    passEncoder.end();

    device.queue.submit([commandEncoder.finish()]);

    // Step D: Render the resulting storage texture to the main screen
    app.renderer.render({
        container: screenSprite,
        clear: true
    });
});

Summary of Key Considerations

  • Texture Usage Flags: PixiJS render textures must include TEXTURE_BINDING so they can be read by textureLoad inside the compute shader.
  • Workgroup Sizing: Standard 2D image processing workgroup dimensions of 16x16 or 8x8 optimize GPU thread occupancy. Always include boundary checks in the WGSL shader to avoid out-of-bounds writes.
  • Synchronization: WebGPU command queues execute linearly per submission. Ensure compute passes finish writing to the storage texture before reading from it in subsequent draw calls.
