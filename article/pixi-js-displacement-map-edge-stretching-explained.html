Pixi.js Displacement Map Edge Stretching Explained

Edge stretching artifacts when using displacement maps in Pixi.js occur primarily because the displacement shader samples texture coordinates beyond the boundaries of the target sprite or filter area, triggering WebGL's default edge-clamping behavior. When a displacement offset pulls a pixel coordinate past the edge of the texture, the GPU duplicates the outermost pixel row or column across the displaced area instead of rendering transparency or wrapping content. This guide explains the core technical causes behind this visual artifact—including texture wrap modes, filter bounding boxes, and displacement scale values—and how these factors interact within Pixi.js's rendering pipeline.

WebGL Texture Clamping (CLAMP_TO_EDGE)

The primary culprit behind edge stretching is the default texture wrap mode used in WebGL and Pixi.js: CLAMP_TO_EDGE.

Displacement filters work by reading red and green color channels from a displacement map to determine how many pixels to offset the UV coordinates of the target sprite. When an offset pushes a UV coordinate outside the standard [0.0, 1.0] range:

  • With CLAMP_TO_EDGE, any coordinate less than 0.0 is treated as 0.0, and any coordinate greater than 1.0 is treated as 1.0.
  • The GPU continuously samples the exact border pixels of the sprite for all out-of-bounds offsets.
  • If the sprite has opaque pixels touching its border, those pixels are smeared outward across the displaced region, creating continuous horizontal or vertical streaks.

Filter Area Constraints and Missing Padding

Pixi.js renders filters to off-screen framebuffers sized to match the bounding box of the display object. By default, this filter area tightly wraps the sprite's dimensions.

When a displacement map displaces pixels near the edges of this bounding box:

  • The displaced pixels are pushed outside the rendered filter texture.
  • Pixi.js does not automatically expand the render target to accommodate the displacement distance unless specified.
  • The edges of the filter texture clip or clamp against the boundaries of the internal render target, producing hard cutoffs or stretched lines along the bounding rectangle.

High Displacement Scale Values

The scale property on a DisplacementFilter determines the maximum distance (in pixels) that coordinates can be shifted.

When scale values are set high relative to the sprite size, the UV offsets easily exceed the texture bounds. Even if a sprite has a small amount of transparent padding within its original asset, a large displacement scale will shift the opaque content past that transparent buffer, forcing the shader to sample the clamped border pixels.

Non-Neutral Displacement Map Edges

Displacement maps rely on neutral values—typically mid-gray (rgba(128, 128, x, x)) in normalized [0.5, 0.5] color space—to represent zero offset.

If the displacement map texture does not fade to neutral gray at its borders:

  • Pixels along the perimeter of the sprite are subjected to continuous directional shifting.
  • The edges are aggressively pulled outward or inward rather than remaining stationary.
  • If the displacement texture's own wrap mode is clamped, the displacement vector itself remains stuck at a high offset along the perimeter, worsening the visual smear.

How to Prevent Edge Stretching

Understanding the underlying causes highlights the direct remedies within Pixi.js:

  1. Increase Filter Padding: Assign a padding value to the filter or sprite (e.g., filter.padding = 50;). This expands the internal render texture beyond the sprite's visual bounds, giving displaced pixels room to move without hitting the frame boundary.
  2. Add Transparent Margins to Assets: Ensure the source sprite contains transparent pixel borders so that clamped coordinates read rgba(0, 0, 0, 0) instead of opaque colors.
  3. Set Displacement Texture Wrap Modes: If using a tiling displacement texture, set displacementSprite.texture.baseTexture.wrapMode = PIXI.WRAP_MODES.REPEAT so the displacement pattern tiles seamlessly rather than clamping at its own edges.
  4. Feather the Displacement Map: Ensure the displacement map fades to rgb(128, 128, 128) near the borders so displacement smoothly falls off to zero at the edges of the display object.
