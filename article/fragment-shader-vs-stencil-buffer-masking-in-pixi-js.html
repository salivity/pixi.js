Fragment Shader vs Stencil Buffer Masking in Pixi.js

Masking in Pixi.js can be achieved through two primary techniques: hardware-level stencil buffer masking and custom fragment shader masking (often utilized via filter masks). While stencil masking relies on the GPU's fixed-function pipeline to perform binary, pass-or-fail pixel visibility tests based on vector geometry, fragment shader masking operates at the per-pixel level across color channels. Understanding the architectural differences between these two methods allows developers to choose the right balance between visual fidelity, such as soft edges and gradients, and rendering performance.

Operating Mechanism

The stencil buffer functions as an auxiliary hardware buffer alongside the color and depth buffers. When Pixi.js applies a stencil mask, it draws the masking geometry into this buffer, setting an integer value for every covered pixel. When the masked object is subsequently rendered, the GPU performs a stencil test: pixels are drawn only where the stencil value matches the mask criteria. This is a fixed-function hardware operation that does not evaluate pixel colors or textures.

In contrast, a custom fragment shader handles masking programmatically by treating the mask and the target content as image inputs (textures). Pixi.js typically renders the target display object and the mask graphic to off-screen Framebuffer Objects (FBOs). These textures are passed as uniforms (sampler2D) into the custom shader. The shader executes a fragment program for every pixel, manually calculating visibility by sampling the mask’s color or alpha channel and multiplying it against the target content's values:

varying vec2 vTextureCoord;
uniform sampler2D uSampler;
uniform sampler2D uMask;

void main(void) {
    vec4 color = texture2D(uSampler, vTextureCoord);
    vec4 mask = texture2D(uMask, vTextureCoord);
    gl_FragColor = color * mask.a;
}

Visual Precision and Alpha Support

The most significant visual difference lies in the handling of transparency:

  • Stencil Buffer: Operates as a 1-bit binary cutoff. A pixel is either completely visible or completely discarded. It cannot natively produce semi-transparent masks, soft edges, or anti-aliased transitions. Edge pixels appear sharp and potentially aliased.
  • Fragment Shader: Supports full 8-bit (or higher) alpha precision per pixel. Because the mask values are interpolated and read as floating-point numbers from 0.0 to 1.0, shaders support smooth alpha gradients, feathered edges, dynamic dissolves, and texture-based masks like PNGs with complex transparency.

Memory Overhead and Pipeline Cost

Stencil masks are memory-efficient because they utilize the existing canvas context's stencil buffer without allocating additional render textures. However, they introduce pipeline state changes and break Pixi.js's automatic batching system, forcing the renderer to split draw calls when writing to and reading from the stencil buffer.

Fragment shader masking incurs higher memory and fill-rate overhead. Rendering the content and the mask to separate FBOs requires extra VRAM allocation and context switching costs. For mobile or fill-rate-limited devices, sampling multiple full-screen or large-area textures inside a fragment shader can degrade frame rates if overused.

Selection Criteria

Use the stencil buffer when clipping user interfaces, scrolling viewports, or simple geometric windows where hard boundaries are acceptable and memory overhead must be minimized.

Opt for a custom fragment shader mask when the visual design demands soft drop-offs, texture-driven cutouts, animated reveal transitions, or multi-channel blending that cannot be defined by simple vector geometry.
