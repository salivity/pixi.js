PixiJS: Ignore Clicks Outside Masked Areas

In Pixi.js, applying a visual mask to a display object hides its rendering outside the designated shape, but it does not inherently constrain the object's interaction boundaries. Consequently, pointer events and hit tests continue to trigger across the object's entire unmasked bounds. This guide details how to resolve this behavior and ensure clicks outside the mask pass through to underlying elements using custom hit areas and containsPoint overrides.

Why Pixi.js Masks Allow Outside Clicks

Pixi.js handles rendering and interactions using two separate pipelines. Masks rely on stencil buffers or scissor rectangles during the WebGL render pass to clip pixels visually. However, the event system (such as @pixi/events or the legacy InteractionManager) uses geometric bounding boxes and hit test logic rather than pixel-level render data. Because the mask does not automatically clip the interaction bounds, user inputs on masked-out areas still register as valid interactions.

Solution 1: Override containsPoint

The most flexible solution for dynamic or arbitrarily shaped masks is overriding the target object's containsPoint method. By verifying that a pointer coordinate resides within both the display object and its assigned mask, you can instantly reject clicks outside the visible region.

const container = new PIXI.Container();
container.eventMode = 'static'; // Or interactive = true in Pixi v6 and below

const mask = new PIXI.Graphics();
mask.beginFill(0xffffff);
mask.drawCircle(100, 100, 50);
mask.endFill();

container.mask = mask;

// Override containsPoint to account for the mask
container.containsPoint = function (point) {
    // If a mask exists, the point must be inside the mask
    if (this.mask && !this.mask.containsPoint(point)) {
        return false;
    }
    
    // Otherwise, check the default hit test logic
    return PIXI.Container.prototype.containsPoint.call(this, point);
};

When using this approach, any pointer event outside the mask returns false, allowing the event to penetrate to any interactive objects positioned below.

Solution 2: Assign an Explicit hitArea

If the mask uses a fixed geometric primitive—such as a rectangle, circle, or polygon—the simplest and most performant solution is assigning a matching hitArea directly to the masked element.

const sprite = PIXI.Sprite.from('texture.png');
sprite.eventMode = 'static';

// Define the mask
const mask = new PIXI.Graphics();
mask.drawRect(0, 0, 200, 150);
sprite.mask = mask;

// Match the hit area to the mask dimensions
sprite.hitArea = new PIXI.Rectangle(0, 0, 200, 150);

When a hitArea is assigned, Pixi.js bypasses its default bounds calculations and only tests pointer coordinates against the defined shape.

Solution 3: Masking Containers with Multiple Children

For complex containers with multiple interactive children, apply the containsPoint check to the parent container, or disable interactions on children that fall outside the viewport.

function applyMaskedHitTesting(targetContainer, maskGraphics) {
    targetContainer.mask = maskGraphics;
    
    targetContainer.containsPoint = function (point) {
        if (!maskGraphics.containsPoint(point)) {
            return false;
        }
        return PIXI.Container.prototype.containsPoint.call(this, point);
    };
}

If children inside the container must remain individually interactive, attach the modified containsPoint logic to each interactive child or use a custom hit-testing function during event propagation to ensure that coordinates are tested against the parent mask's local transform space.
