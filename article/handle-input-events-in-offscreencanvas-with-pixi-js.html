Handle Input Events in OffscreenCanvas with Pixi.js

Running Pixi.js in a Web Worker using OffscreenCanvas significantly improves rendering performance by isolating WebGL operations from main thread UI bottlenecks. However, because Web Workers have no direct access to the Document Object Model (DOM), Pixi.js cannot automatically detect user inputs such as clicks, touches, or cursor movements. This guide details how to capture user input events on the main DOM thread, serialize their payloads, forward them via postMessage, and inject them into Pixi.js's internal event system inside the worker.

The Challenge of Worker-Based Inputs

Pixi.js uses an EventSystem that binds directly to the rendering <canvas> element on the DOM to process federated events (pointerdown, pointermove, etc.). When rendering with OffscreenCanvas, the canvas context is transferred out of the DOM. Because workers lack access to event targets like window and document, you must establish an event proxy mechanism that bridges the main thread and the worker.

Step 1: Capture and Serialize Events on the Main Thread

On the main thread, the original <canvas> element remains in the DOM even after calling transferControlToOffscreen(). Attach event listeners directly to this placeholder canvas to listen for pointer, mouse, and wheel events.

Because native DOM Event objects cannot be cloned directly across the Web Worker boundary, you must extract only the required properties into a plain JavaScript object:

// main.js
const canvas = document.getElementById('renderCanvas');
const offscreen = canvas.transferControlToOffscreen();
const worker = new Worker('worker.js', { type: 'module' });

// Transfer canvas ownership to the worker
worker.postMessage({ type: 'init', canvas: offscreen }, [offscreen]);

// Define the input events you need to forward
const eventTypes = [
  'pointerdown',
  'pointerup',
  'pointermove',
  'pointerover',
  'pointerout',
  'wheel'
];

eventTypes.forEach((type) => {
  canvas.addEventListener(type, (event) => {
    // Extract canvas bounding rectangle to compute relative coordinates
    const rect = canvas.getBoundingClientRect();

    worker.postMessage({
      type: 'input-event',
      eventData: {
        type: event.type,
        // Calculate offset coordinates relative to the canvas
        clientX: event.clientX,
        clientY: event.clientY,
        offsetX: event.clientX - rect.left,
        offsetY: event.clientY - rect.top,
        pointerId: event.pointerId,
        pointerType: event.pointerType,
        button: event.button,
        buttons: event.buttons,
        deltaX: event.deltaX || 0,
        deltaY: event.deltaY || 0,
      }
    });
  });
});

Step 2: Ingest Events in the Worker

Inside the worker, initialize the Pixi.js Application. When receiving a serialized event via self.onmessage, forward it to the Pixi.js EventSystem using its synthetic event handlers.

Pixi.js exposes its event management via app.renderer.events. Depending on the event type received, invoke the corresponding method on the event manager:

// worker.js
import { Application } from 'pixi.js';

let app;

self.onmessage = async (e) => {
  const { type, canvas, eventData } = e.data;

  if (type === 'init') {
    app = new Application();
    await app.init({
      canvas: canvas,
      width: 800,
      height: 600,
    });
    return;
  }

  if (type === 'input-event' && app) {
    handleWorkerEvent(eventData);
  }
};

function handleWorkerEvent(eventData) {
  const events = app.renderer.events;
  if (!events) return;

  // Construct a minimal object mimicking a PointerEvent or WheelEvent
  const fakeEvent = {
    ...eventData,
    preventDefault: () => {},
    stopPropagation: () => {},
  };

  // Route to the appropriate Pixi EventSystem handler
  switch (eventData.type) {
    case 'pointerdown':
      events.onPointerDown(fakeEvent);
      break;
    case 'pointerup':
      events.onPointerUp(fakeEvent);
      break;
    case 'pointermove':
      events.onPointerMove(fakeEvent);
      break;
    case 'pointerover':
      events.onPointerOver(fakeEvent);
      break;
    case 'pointerout':
      events.onPointerOut(fakeEvent);
      break;
    case 'wheel':
      events.onWheel(fakeEvent);
      break;
  }
}

Step 3: Handling Coordinate Scaling

If the canvas resolution differs from its displayed CSS dimensions, mouse coordinates sent using clientX and clientY will misalign with objects on the stage.

To resolve this, calculate the scaling factor on the main thread and normalize the positions before transmission:

const rect = canvas.getBoundingClientRect();
const scaleX = canvas.width / rect.width;
const scaleY = canvas.height / rect.height;

const normalizedOffsetX = (event.clientX - rect.left) * scaleX;
const normalizedOffsetY = (event.clientY - rect.top) * scaleY;

Pass normalizedOffsetX and normalizedOffsetY as both clientX/clientY and offsetX/offsetY in the serialized payload to ensure Pixi's hit-testing functions accurately map clicks to stage display objects.

Step 4: Disabling Automatic Default Prevention

Because worker messages are processed asynchronously, calls to event.preventDefault() inside the worker thread cannot cancel native browser behaviors (such as scrolling or text selection). You must configure the main thread canvas using CSS touch-action: none; to suppress unwanted browser touch behaviors directly in the DOM, rather than relying on Pixi.js's built-in event suppression.
