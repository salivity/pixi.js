Preload Fallback PNG Textures in PixiJS

Compressed textures such as KTX2, Basis, or DDS significantly reduce GPU memory usage and improve rendering performance, but older hardware and unsupported browsers may fail to parse them. PixiJS handles asset management through its robust Assets pipeline, allowing developers to detect capabilities, serve prioritized formats, and gracefully fall back to standard PNG images. This guide details how to configure the PixiJS asset manager to prioritize compressed textures while automatically preloading PNG fallbacks when format detection or loading fails.

Using Asset Manifests for Automatic Format Fallbacks

The most efficient way to manage texture fallbacks in PixiJS (v7 and v8) is through an asset manifest. When you define multiple formats under the same asset key or bundle, the Assets resolver evaluates which format the client's hardware supports based on initialized texture parsers. If a compressed texture extension is not supported, PixiJS loads the PNG alternative automatically.

First, initialize the compressed texture extensions, then define your manifest:

import { Application, Assets } from 'pixi.js';
import '@pixi/compressed-textures'; // Enables KTX, DDS, and Basis detection

await Assets.init({
    manifest: {
        bundles: [
            {
                name: 'game-assets',
                assets: [
                    {
                        alias: 'character',
                        src: [
                            'assets/character.ktx2',
                            'assets/character.png'
                        ]
                    },
                    {
                        alias: 'background',
                        src: [
                            'assets/background.dds',
                            'assets/background.png'
                        ]
                    }
                ]
            }
        ]
    }
});

// Load the bundle; PixiJS evaluates formats in order and picks the first supported file
const bundle = await Assets.loadBundle('game-assets');

By providing an array of strings in the src property, PixiJS checks each file against its registered format parsers. If the browser lacks WebGL support for the compressed format, it skips that format and downloads the standard PNG instead.

Programmatic Fallback with try/catch

If your assets are dynamically resolved or loaded individually without a predefined manifest, you can implement a safe loading wrapper using standard asynchronous error handling. This ensures that even if a network request fails or transcoding generates an error, the application falls back to a PNG texture.

import { Assets, Texture } from 'pixi.js';

async function loadTextureWithFallback(alias, compressedUrl, fallbackUrl) {
    // Check if the asset has already been loaded or cached
    if (Assets.cache.has(alias)) {
        return Assets.get(alias);
    }

    try {
        // Attempt to load the primary compressed texture
        return await Assets.load({
            alias,
            src: compressedUrl
        });
    } catch (error) {
        console.warn(`Failed to load compressed texture (${compressedUrl}). Loading PNG fallback.`);
        
        // Remove failed entry from cache before attempting fallback
        Assets.unload(alias).catch(() => {});

        // Preload and return the fallback PNG
        return await Assets.load({
            alias,
            src: fallbackUrl
        });
    }
}

// Usage
const backgroundTexture = await loadTextureWithFallback(
    'bg',
    'assets/textures/bg.ktx2',
    'assets/textures/bg.png'
);

Ensuring Proper Transcoder Initialization

When working with formats like KTX2 or Basis, failures often occur before the network stage if the WebAssembly transcoders are missing or improperly configured. Ensure your transcoder worker paths are initialized prior to asset loading:

import { Assets } from 'pixi.js';

// Configure transcoders if using KTX2 / Basis
await Assets.init({
    preferences: {
        preferWorkers: true,
    }
});

If the environment cannot instantiate the required WebAssembly modules or Web Workers, standardizing your asset definitions with array-based src paths ensures that the load phase bypasses the unsupported formats instantly, keeping application startup fast and error-free.
