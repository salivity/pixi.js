How to Share Geometry Across Meshes in Pixi.js

This article explains how to instantiate a single Geometry instance and share it across multiple distinct Mesh objects in Pixi.js. By decoupling buffer definitions from display objects, you can significantly reduce GPU memory usage and optimize rendering workflows while retaining independent transformations, shaders, or material properties for each mesh.

Understanding Mesh and Geometry Decoupling

In Pixi.js, a Mesh is a display object that pairs structural vertex data with visual styling. It relies on two main components:

  • Geometry: Holds vertex buffers, index buffers, UV mappings, and custom attributes.
  • Shader or MeshMaterial: Defines the appearance, textures, and uniform data.

Because Geometry does not store position, rotation, scale, or rendering state, one instance can serve as the data source for an unlimited number of Mesh instances.

Step-by-Step Implementation

1. Define the Shared Geometry

Create the Geometry instance once by populating it with vertex positions, texture coordinates (UVs), and index data.

import * as PIXI from 'pixi.js';

// Define standard quad vertices (two triangles)
const positions = new Float32Array([
    -50, -50,
     50, -50,
     50,  50,
    -50,  50
]);

const uvs = new Float32Array([
    0, 0,
    1, 0,
    1, 1,
    0, 1
]);

const index = new Uint16Array([
    0, 1, 2,
    0, 2, 3
]);

// Create the shared geometry instance
const sharedGeometry = new PIXI.Geometry()
    .addAttribute('aVertexPosition', positions, 2)
    .addAttribute('aTextureCoord', uvs, 2)
    .addIndex(index);

2. Create Meshes Referencing the Same Geometry

Pass the same sharedGeometry reference into each PIXI.Mesh constructor. Each mesh can have its own material or share a material as needed.

const texture = PIXI.Texture.from('path/to/texture.png');

// Create distinct materials or reuse one
const material1 = new PIXI.MeshMaterial(texture);
const material2 = new PIXI.MeshMaterial(texture);

// Create distinct Mesh instances using the same Geometry
const meshA = new PIXI.Mesh(sharedGeometry, material1);
const meshB = new PIXI.Mesh(sharedGeometry, material2);

// Position each mesh independently
meshA.position.set(100, 200);
meshA.rotation = 0.5;

meshB.position.set(300, 200);
meshB.scale.set(1.5);

// Add both meshes to the stage
app.stage.addChild(meshA);
app.stage.addChild(meshB);

Key Considerations

Dynamic Vertex Updates

If you update the buffer data of sharedGeometry (such as modifying vertex coordinates via getBuffer('aVertexPosition').update()), every mesh referencing this geometry will reflect those changes on the next render frame.

Memory Management and Destruction

Pixi.js display objects can destroy their underlying resources when removed. When sharing geometries, avoid destroying the geometry prematurely:

// Remove and destroy only the display object and its material, preserving the geometry
meshA.destroy({
    children: true,
    texture: false,
    baseTexture: false
});

// Explicitly destroy the shared geometry only when no meshes require it
sharedGeometry.destroy();
