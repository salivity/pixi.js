How to Dispose of Pixi.js Filters Properly

Properly disposing of filter instances in Pixi.js is essential to prevent GPU memory leaks and maintain steady frame rates in WebGL applications. This article covers the exact steps needed to detach a filter from a display object, invoke its built-in destruction lifecycle, release associated uniforms and custom textures, and ensure the JavaScript garbage collector can reclaim the memory.

1. Remove the Filter from the Display Object

Before destroying a filter, you must detach it from the target display object's filters array. Leaving a destroyed filter in the active render pipeline will trigger rendering errors.

To remove a specific filter:

// Remove a specific filter from a container
container.filters = container.filters.filter(f => f !== myFilter);

// If the array is empty, set it to null to disable filter rendering passes completely
if (container.filters.length === 0) {
    container.filters = null;
}

Setting container.filters = null completely skips the filter rendering pass for that object, saving unnecessary draw calls.

2. Call the destroy() Method on the Filter

Pixi.js filter instances inherit from PIXI.Filter and provide a .destroy() method. Calling this method cleans up internal WebGL shader programs and releases uniform buffers tied to the GPU context.

myFilter.destroy();

After calling destroy(), nullify any local references to the filter instance in your application code so the JavaScript garbage collector can collect the object:

myFilter = null;

3. Clean Up Associated Textures

Some complex filters (such as DisplacementFilter) rely on secondary sprites or textures. Pixi.js does not automatically destroy external textures passed into a filter because they might be shared across other elements in your application.

If the texture or sprite was created exclusively for that filter, you must dispose of it manually:

// Example with a DisplacementFilter
const displacementSprite = new PIXI.Sprite(customTexture);
const displacementFilter = new PIXI.DisplacementFilter(displacementSprite);

// Cleanup:
container.filters = null;

// Destroy the filter
displacementFilter.destroy();

// Destroy the sprite and its underlying texture
displacementSprite.destroy({
    children: true,
    texture: true,
    baseTexture: true
});

Full Lifecycle Pattern

To ensure complete memory cleanup, implement a standard disposal routine:

function disposeFilter(targetDisplayObject, filterInstance, customTexture = null) {
    // 1. Detach from the display object
    if (targetDisplayObject.filters) {
        targetDisplayObject.filters = targetDisplayObject.filters.filter(f => f !== filterInstance);
        if (targetDisplayObject.filters.length === 0) {
            targetDisplayObject.filters = null;
        }
    }

    // 2. Destroy optional associated resources
    if (customTexture) {
        customTexture.destroy(true);
    }

    // 3. Destroy the filter program on the GPU
    filterInstance.destroy();
}

Following this sequence ensures that shader programs are unlinked, GPU memory buffers are cleared, and references are severed from both the rendering pipeline and the JavaScript runtime.
