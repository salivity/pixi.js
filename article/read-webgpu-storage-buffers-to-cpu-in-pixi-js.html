Read WebGPU Storage Buffers to CPU in Pixi.js

Reading simulation results from structured storage buffers back to the CPU in Pixi.js requires leveraging the WebGPU backend introduced in Pixi.js v8. This process entails configuring a storage buffer with transfer capabilities, binding it to a compute pipeline, and copying the simulation results into a staging buffer mapped for CPU reading. This guide details how to configure Pixi.js WebGPU buffers, dispatch compute commands, and retrieve your data asynchronously.

1. Initialize Pixi.js with WebGPU Support

To work with compute shaders and structured storage buffers, the Pixi.js Application must be initialized with the WebGPU renderer preference.

import { Application } from 'pixi.js';

const app = new Application();
await app.init({
    width: 800,
    height: 600,
    preference: 'webgpu',
});

if (app.renderer.type !== 'webgpu') {
    throw new Error('WebGPU is required for compute storage buffers.');
}

2. Create the Storage Buffer

A structured storage buffer in WebGPU holds arbitrary data (such as particle positions, velocities, or grid data). In Pixi.js, instantiate a Buffer containing typed array data. The underlying GPU buffer must include both STORAGE and COPY_SRC usage flags so its contents can be copied out after compute operations.

import { Buffer, BufferUsage } from 'pixi.js';

const elementCount = 1000;
const data = new Float32Array(elementCount * 4); // Example: 4 floats per element (vec4)

// Initialize data
for (let i = 0; i < data.length; i++) {
    data[i] = Math.random();
}

const storageBuffer = new Buffer({
    data: data,
    usage: BufferUsage.STORAGE | BufferUsage.COPY_SRC | BufferUsage.COPY_DST,
});

3. Bind the Buffer in a Compute Pipeline

WebGPU manages resource bindings via bind groups. Access Pixi’s underlying WebGPU device via app.renderer.gpu.device to create compute pipelines and bind groups.

const device = app.renderer.gpu.device;

// WGSL compute shader
const computeCode = `
struct Particle {
    pos: vec4<f32>,
};

@group(0) @binding(0) var<storage, read_write> particles: array<Particle>;

@compute @workgroup_size(64)
fn main(@builtin(global_invocation_id) global_id: vec3<u32>) {
    let index = global_id.x;
    if (index >= arrayLength(&particles)) {
        return;
    }
    // Simple simulation logic
    particles[index].pos.x += 0.01;
}
`;

const shaderModule = device.createShaderModule({ code: computeCode });

const computePipeline = device.createComputePipeline({
    layout: 'auto',
    compute: {
        module: shaderModule,
        entryPoint: 'main',
    },
});

// Access the underlying GPUBuffer managed by Pixi.js
// Ensure Pixi uploads the buffer to the GPU first
app.renderer.buffer.updateBuffer(storageBuffer);
const gpuBuffer = storageBuffer.gpuBuffer;

const bindGroup = device.createBindGroup({
    layout: computePipeline.getBindGroupLayout(0),
    entries: [
        {
            binding: 0,
            resource: { buffer: gpuBuffer },
        },
    ],
});

4. Dispatch the Compute Pass

Record and execute the compute pass using the WebGPU command encoder.

const commandEncoder = device.createCommandEncoder();
const passEncoder = commandEncoder.beginComputePass();

passEncoder.setPipeline(computePipeline);
passEncoder.setBindGroup(0, bindGroup);
passEncoder.dispatchWorkgroups(Math.ceil(elementCount / 64));
passEncoder.end();

device.queue.submit([commandEncoder.finish()]);

5. Copy and Read Back Data to the CPU

WebGPU does not allow direct CPU reading from buffers with active STORAGE usage. You must copy the data into a temporary staging buffer created with MAP_READ and COPY_DST flags, map the staging buffer into CPU memory, and extract the values.

async function readBackStorageBuffer(device, sourceGpuBuffer, byteLength) {
    // 1. Create a staging buffer
    const stagingBuffer = device.createBuffer({
        size: byteLength,
        usage: GPUBufferUsage.MAP_READ | GPUBufferUsage.COPY_DST,
    });

    // 2. Encode the copy command
    const copyEncoder = device.createCommandEncoder();
    copyEncoder.copyBufferToBuffer(
        sourceGpuBuffer,
        0,
        stagingBuffer,
        0,
        byteLength
    );
    device.queue.submit([copyEncoder.finish()]);

    // 3. Map the staging buffer for read access
    await stagingBuffer.mapAsync(GPUMapMode.READ);

    // 4. Copy the mapped range into a local TypedArray
    const copyArrayBuffer = stagingBuffer.getMappedRange();
    const results = new Float32Array(copyArrayBuffer.slice(0));

    // 5. Unmap and destroy the staging buffer
    stagingBuffer.unmap();
    stagingBuffer.destroy();

    return results;
}

// Usage
const results = await readBackStorageBuffer(device, gpuBuffer, data.byteLength);
console.log('Readback results:', results);

Performance Considerations

  • Asynchronous Stalls: mapAsync introduces latency as the CPU waits for GPU execution to complete. Avoid reading back data every frame; instead, only fetch state when synchronization or persistence is required.
  • Buffer Reuse: If periodic readbacks are necessary, maintain a dedicated, reusable staging buffer rather than allocating and destroying a new staging buffer on every frame.
