3D Perspective Projection in Pixi.js Using Matrices

This article provides a direct guide on projecting a 2D Pixi.js stage or container into simulated 3D perspective using matrix transformations. While Pixi.js is built primarily as a 2D rendering engine using affine transforms, you can simulate depth and perspective by understanding homogeneous coordinates, applying perspective division, and injecting non-affine projective matrices into custom meshes or shaders.

The Limitation of Pixi.js 2D Matrices

By default, Pixi.js uses PIXI.Matrix for object transformations. This represents a 2D affine transformation matrix structured as:

\[\begin{bmatrix} a & c & tx \\ b & d & ty \\ 0 & 0 & 1 \end{bmatrix}\]

Affine matrices can handle translation, rotation, scale, and skew, but they maintain parallel lines. They cannot produce perspective foreshortening, where objects appear smaller and converge toward a vanishing point as depth (\(Z\)) increases.

Mathematical Concept: Perspective Division

To project a 3D coordinate \((X, Y, Z)\) onto a 2D screen \((x', y')\), you must apply perspective projection:

\[x' = \frac{X \cdot d}{Z + d}\] \[y' = \frac{Y \cdot d}{Z + d}\]

Where \(d\) represents the distance from the camera to the projection plane (focal length).

In matrix form, perspective requires homogeneous coordinates where the bottom row of a \(3 \times 3\) projective matrix (homography) contains non-zero elements:

\[\begin{bmatrix} x_{out} \\ y_{out} \\ w \end{bmatrix} = \begin{bmatrix} m_{00} & m_{01} & m_{02} \\ m_{10} & m_{11} & m_{12} \\ p_x & p_y & 1 \end{bmatrix} \begin{bmatrix} x_{in} \\ y_{in} \\ 1 \end{bmatrix}\]

After multiplication, the final 2D coordinates are obtained through perspective division:

\[x' = \frac{x_{out}}{w}, \quad y' = \frac{y_{out}}{w}\]

Implementation Approaches in Pixi.js

Because standard PIXI.Container instances only support 2D affine transforms, you must implement perspective projection using either vertex meshes or custom shaders.

1. Projecting Vertices with PIXI.SimpleMesh

The cleanest native way to apply a 3D projection to a 2D element without external plugins is by manipulating the vertex buffer of a PIXI.SimpleMesh.

// Define a simple 3D point transformation function
function project3D(x, y, z, focalLength, originX, originY) {
    const distance = z + focalLength;
    if (distance <= 0) return { x: 0, y: 0 }; // Behind camera
    
    const scale = focalLength / distance;
    return {
        x: (x - originX) * scale + originX,
        y: (y - originY) * scale + originY
    };
}

// Setup a plane mesh with a texture
const texture = PIXI.Texture.from('surface.png');
const width = 400;
const height = 400;

// Quad vertices: [x0, y0, x1, y1, x2, y2, x3, y3]
const rawVertices = [
    0, 0,
    width, 0,
    width, height,
    0, height
];

const uvs = [
    0, 0,
    1, 0,
    1, 1,
    0, 1
];

const indices = [0, 1, 2, 0, 2, 3];

const mesh = new PIXI.SimpleMesh(texture, new Float32Array(rawVertices), new Float32Array(uvs), new Uint16Array(indices));
app.stage.addChild(mesh);

// Apply a tilt transformation around the X-axis (Pitch)
function updatePerspective(pitchAngleRad, focalLength) {
    const cos = Math.cos(pitchAngleRad);
    const sin = Math.sin(pitchAngleRad);
    const originY = height / 2;
    const originX = width / 2;

    const projected = [];

    for (let i = 0; i < rawVertices.length; i += 2) {
        const localX = rawVertices[i];
        const localY = rawVertices[i + 1] - originY;

        // Rotate in 3D around X axis
        const y3D = localY * cos;
        const z3D = localY * sin;

        // Perspective divide
        const point = project3D(localX, y3D + originY, z3D, focalLength, originX, originY);
        projected.push(point.x, point.y);
    }

    mesh.verticesBuffer.update(new Float32Array(projected));
}

// Tilt the plane 45 degrees backward with a focal length of 300
updatePerspective(Math.PI / 4, 300);

2. Using a Projective Homography Shader

If you need entire containers with complex nested elements projected into 3D, you can apply a custom PIXI.Filter containing a projective matrix.

  1. Vertex Shader: Passes through normalized UVs.
  2. Fragment Shader: Multiplies the output pixel coordinates by the inverse homography matrix to sample the original 2D texture.
// Fragment Shader
varying vec2 vTextureCoord;
uniform sampler2D uSampler;
uniform mat3 uInverseMatrix;

void main(void) {
    // Convert 2D UV coordinate to homogeneous coordinate
    vec3 homogeneousCoord = uInverseMatrix * vec3(vTextureCoord, 1.0);
    
    // Perspective division
    vec2 projectedCoord = homogeneousCoord.xy / homogeneousCoord.z;

    // Discard fragments outside the projected plane
    if (projectedCoord.x < 0.0 || projectedCoord.x > 1.0 || 
        projectedCoord.y < 0.0 || projectedCoord.y > 1.0) {
        discard;
    }

    gl_FragColor = texture2D(uSampler, projectedCoord);
}

In the JavaScript layer, calculate the \(3 \times 3\) transformation matrix representing the rotation and camera perspective, invert it, and upload it to the filter uniform as a flat array of 9 elements.

Subdividing Meshes to Avoid Texture Warping

When using simple quad meshes (SimpleMesh with 4 vertices), affine texture interpolation across two triangles can cause a visible diagonal seam (affine texture mapping artifact). To produce a smooth, mathematically accurate perspective across a large plane, subdivide the mesh into an \(N \times N\) grid of smaller quads and apply the projection to each vertex. This minimizes linear interpolation error and creates a realistic 3D perspective effect across the Pixi.js stage.
