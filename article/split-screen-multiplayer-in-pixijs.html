Split-Screen Multiplayer in PixiJS

Setting up split-screen multiplayer in PixiJS is entirely possible by creating two distinct viewport containers, applying rectangular masks to divide the canvas, and dynamically shifting each container's position or pivot to follow individual players. Because PixiJS does not feature a built-in "Camera" class, virtual cameras are constructed using standard display containers that encapsulate the game world and project distinct visual perspectives side by side.

The Virtual Camera Concept in PixiJS

In PixiJS, a camera is achieved by transforming a Container. By altering a container’s pivot or position, you change which portion of the game world is visible on the screen.

To create a split-screen system, you divide the screen into separate viewports (for example, horizontal or vertical halves). Each viewport requires:

  1. A Viewport Container: Houses the visual representation of the game world for that specific player.
  2. A Mask: Constrains the viewport rendering to its designated screen area (e.g., left half for Player 1, right half for Player 2).
  3. A Tracking Mechanism: Updates the container’s position/pivot each frame based on the assigned player's coordinates.

Implementation Steps

1. Define Viewport Bounds and Masks

Create two separate Graphics rectangles representing the boundary of each screen segment. These act as masks to prevent visuals from bleeding across the partition.

const halfWidth = app.screen.width / 2;
const height = app.screen.height;

// Player 1 Mask (Left half)
const mask1 = new PIXI.Graphics();
mask1.beginFill(0xffffff);
mask1.drawRect(0, 0, halfWidth, height);
mask1.endFill();

// Player 2 Mask (Right half)
const mask2 = new PIXI.Graphics();
mask2.beginFill(0xffffff);
mask2.drawRect(halfWidth, 0, halfWidth, height);
mask2.endFill();

2. Create the Viewport Containers

Construct a viewport container for each player. Attach the masks to these containers and set their screen positions.

// Viewport 1
const viewport1 = new PIXI.Container();
viewport1.mask = mask1;
viewport1.position.set(0, 0);

// Viewport 2
const viewport2 = new PIXI.Container();
viewport2.mask = mask2;
viewport2.position.set(halfWidth, 0);

app.stage.addChild(viewport1, viewport2, mask1, mask2);

3. Manage the Shared World

You can either mirror display objects between viewports or render the primary world into separate containers. For full split-screen behavior, each viewport typically contains its own cloned hierarchy or shares visual references where each viewport acts as a separate scene graph viewing the same logical data.

const world1 = new PIXI.Container();
const world2 = new PIXI.Container();

viewport1.addChild(world1);
viewport2.addChild(world2);

// Populate world1 and world2 with game elements (maps, players, items)

4. Update Cameras in the Game Loop

Inside the main ticker, update the pivot of each world container to center on its respective player. Offset the pivot by half of the viewport's dimensions so the player remains centered within their specific half of the screen.

app.ticker.add(() => {
    // Center Viewport 1 on Player 1
    world1.pivot.x = player1.x - (halfWidth / 2);
    world1.pivot.y = player1.y - (height / 2);

    // Center Viewport 2 on Player 2
    world2.pivot.x = player2.x - (halfWidth / 2);
    world2.pivot.y = player2.y - (height / 2);
});

Alternative: Using RenderTextures

If duplicating the scene graph inside two separate containers creates performance overhead, you can use RenderTexture.

  1. Create a single worldContainer holding all game assets.
  2. Create two RenderTexture instances, each matching the resolution of one half of the screen.
  3. Position the worldContainer to focus on Player 1, render it to the first RenderTexture, reposition it for Player 2, and render it to the second.
  4. Assign these textures to two stationary sprites on the main stage.

Performance Optimization

  • Frustum Culling: PixiJS renders all display objects within a container unless instructed otherwise. Implement bounding-box checks so that objects outside a player's visible half are marked with visible = false before that camera renders.
  • Scissor Rectangles: PixiJS supports scissor-test masking on graphics masks. Ensure your masking rectangles do not trigger expensive stencil buffers by using standard unrotated rectangles.
