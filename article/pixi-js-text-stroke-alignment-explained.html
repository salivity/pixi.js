Pixi.js Text Stroke Alignment Explained

Pixi.js renders standard typography using the HTML5 Canvas 2D API, which does not provide native parameters for inner, outer, or centered stroke alignment. Instead, Pixi.js manages stroke appearance by controlling the draw order of the fill and stroke passes, effectively defaulting to an outer stroke appearance. Understanding how this rendering order works allows developers to work around engine limitations and achieve specific alignment effects like centered or inner strokes.

The Default Behavior: Emulated Outer Stroke

When configuring a PIXI.TextStyle, you define stroke (the color) and strokeThickness (the stroke width). Under the hood, Pixi.js renders text to an offscreen canvas using CanvasRenderingContext2D.strokeText() and CanvasRenderingContext2D.fillText().

The standard Canvas API always centers strokes along the path of a glyph—meaning half of the stroke width extends outward, and the other half extends inward into the body of the glyph. However, Pixi.js executes the stroke operation before the fill operation:

  1. context.strokeText() draws the stroke centered along the glyph outlines.
  2. context.fillText() draws the glyph fill directly on top of the stroke.

Because the fill layer completely covers the inner half of the stroke, only the outward-expanding half remains visible. This creates an emulated outer stroke. To achieve a specific visual outer border, you must set strokeThickness to twice the desired visual width.

Achieving Center Stroke

Because Pixi.js overwrites the inner half of the stroke with the fill, a standard text object cannot natively display a true centered stroke where both the inner and outer halves are visible over the fill.

To achieve a center stroke:

  • No Fill: If fill is omitted or fully transparent, the full centered stroke will be visible, leaving the interior of the glyphs hollow.
  • Layering Two Text Objects: Create two identical PIXI.Text instances positioned at the exact same coordinates. The bottom instance provides the fill without a stroke, and the top instance provides the stroke without a fill (or with a semi-transparent fill). This places the entire stroke path on top of the text, giving you an equal, centered stroke distribution over and around the glyphs.

Achieving Inner Stroke

Neither Canvas 2D nor Pixi.js natively supports inner strokes for text typography. An inner stroke requires the stroke to only be visible within the boundary of the glyphs, leaving the outer bounds untouched.

To create an inner stroke in Pixi.js, you must implement specialized workarounds:

  • Masking: Use the text itself as a mask over a larger stroked version of the same text. The mask clips away the outer half of the stroke, restricting the visible stroke to the inside of the glyph boundaries.
  • Blend Modes and Canvas Context Overrides: By rendering the text on an isolated canvas and using composite operations such as source-atop, you can force the stroke to draw strictly inside the existing alpha boundaries of the filled text.

Stroke Alignment in Bitmap and SDF Text

If you use PIXI.BitmapText with Signed Distance Field (SDF or MSDF) fonts instead of standard canvas-based PIXI.Text, stroke rendering is handled entirely within WebGL fragment shaders.

In an SDF shader, distance values determine whether a fragment is inside, on the edge, or outside a glyph. While standard Pixi.js SDF shaders emulate the same outer-stroke behavior as standard text, developers can modify or write custom SDF fragment shaders to shift the distance threshold, allowing true mathematical inner, centered, or outer stroke alignment with zero performance overhead.
