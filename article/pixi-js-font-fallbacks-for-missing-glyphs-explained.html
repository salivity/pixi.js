Pixi.js Font Fallbacks for Missing Glyphs Explained

Pixi.js handles font fallback cascades differently depending on the text implementation used: standard Text (Canvas-based), HTMLText, or BitmapText. While Canvas and HTML text implementations defer character-level fallback directly to the browser's underlying text engine using CSS-like cascades, pre-rendered solutions like BitmapText cannot automatically fall back to system fonts for missing glyphs without explicit configuration or dynamic generation.

PIXI.Text and Canvas Font Cascades

For standard PIXI.Text objects, Pixi.js does not implement an internal font shaper or glyph rasterizer. Instead, it renders text onto an off-screen HTML5 Canvas using the 2D rendering context (CanvasRenderingContext2D) and converts the result into a GPU texture.

Fallback cascades in PIXI.Text are controlled by passing an array of font names or a comma-separated string to the fontFamily style property:

const style = new PIXI.TextStyle({
    fontFamily: ['CustomFont', 'Helvetica', 'Arial', 'sans-serif'],
    fontSize: 24,
});

Pixi.js assigns this list directly to the canvas context's ctx.font property. From that point, the browser's native font resolution engine takes over. When the browser renders the string:

  1. It looks for the requested glyph in the first font (CustomFont).
  2. If the glyph is absent, it steps down the cascade to the next font in the array (Helvetica).
  3. If no listed font contains the glyph, it falls back to system defaults designated by the generic family (sans-serif).

Because the browser manages this at the individual glyph level, a single text string can seamlessly mix glyphs from your custom font with fallback glyphs for missing characters, such as non-Latin scripts, emojis, or specialized symbols.

PIXI.BitmapText Limitations

PIXI.BitmapText operates on a completely different pipeline designed for high performance. It renders text by mapping characters directly to coordinates within a pre-baked texture atlas (generated via tools like BMFont, ShoeBox, or dynamically at runtime).

Because PIXI.BitmapText bypasses the browser's canvas text pipeline:

  • No Automatic Native Fallbacks: If a glyph is missing from the bitmap font atlas, Pixi.js cannot query the operating system or browser for a substitute font.
  • Missing Glyph Behavior: By default, Pixi.js will either ignore the character, render a replacement character (if configured), or leave blank spacing.
  • Multi-Font Support: To achieve a fallback effect in bitmap text, you must register multiple bitmap fonts and manually configure fallbacks, or merge multiple font character sets into the texture atlas during your build process.

PIXI.HTMLText and CSS Rules

PIXI.HTMLText converts HTML and CSS markup into an image via SVG foreignObject or HTML canvas integration. Font fallback cascades in PIXI.HTMLText mirror standard web page behavior:

const htmlText = new PIXI.HTMLText({
    text: '<span style="font-family: CustomFont, sans-serif;">Hello 世界</span>',
});

The browser handles the cascade identically to any standard DOM element, applying fallback fonts specifically to individual missing glyphs within the styled node.

PixiJS v8 Unified Text System

In PixiJS v8, text handling is unified under a consolidated Text object that accepts different renderMode values (canvas, html, or bitmap). Despite the unified API:

  • Setting renderMode: 'canvas' or renderMode: 'html' continues to leverage the browser's native glyph fallback system.
  • Setting renderMode: 'bitmap' retains the physical restriction of requiring all rendered glyphs to exist within the assigned bitmap texture assets.

Ensuring Reliable Fallbacks

To ensure font fallbacks render predictably in Pixi.js:

  1. Preload Custom Fonts: Ensure custom WebFonts are fully loaded via the native document.fonts.load() API before instantiating PIXI.Text. If a custom font is not fully loaded, Pixi will render the canvas immediately using the fallback font, caching that texture on the GPU until explicitly re-rendered.
  2. Always Supply Generic Families: Always end your fontFamily arrays with generic CSS font families (sans-serif, serif, or monospace) to prevent platform-specific layout breaks when missing glyphs occur.
