How PixiJS Uses WebGL Stencil Buffer for Masking

Pixi.js utilizes the WebGL stencil buffer to execute high-performance vector masking by treating the buffer as a hardware-level pixel filter. Instead of relying on expensive render-to-texture passes or fragment shader sampling, Pixi.js taps directly into the GPU's fixed-function pipeline. By rendering vector geometry directly into the stencil buffer with color writes disabled, it writes a reference pattern that dictates exactly which pixels of subsequent display objects are permitted to render to the screen.

The Role of the WebGL Stencil Buffer

In WebGL, the stencil buffer is an 8-bit integer buffer attached to the canvas framebuffer, alongside the color and depth buffers. It provides per-pixel integer storage (typically values from 0 to 255) that acts as a mask.

During standard rasterization, the GPU checks the value in the stencil buffer against a defined reference value using a comparison function (such as equal, not equal, or greater than). Pixi.js’s MaskSystem controls this pipeline state to isolate the rendering of complex, non-rectangular vector paths.

Phase 1: Configuring the Graphics Pipeline

When a masked display object is encountered during rendering, Pixi.js pushes the mask onto its internal mask stack and configures the WebGL context:

  1. Enable Stencil Testing: Pixi.js activates stencil operations by executing gl.enable(gl.STENCIL_TEST).
  2. Disable Color and Depth Writes: Since the mask geometry only needs to establish bounds rather than display color, Pixi.js disables color channel updates via gl.colorMask(false, false, false, false) and depth writes with gl.depthMask(false). This drastically improves rendering throughput.

Phase 2: Drawing the Vector Mask Geometry

Pixi.js then draws the PIXI.Graphics object designated as the mask.

Because vector graphics consist of arbitrary geometry, Pixi.js triangulates paths, polygons, and bezier curves into raw triangle meshes. As these triangles are rasterized, Pixi.js configures gl.stencilOp and gl.stencilFunc.

For standard single-level masks:

  • gl.stencilFunc(gl.ALWAYS, currentLevel, 0xFF) tells the GPU that every rasterized pixel of the mask passes the test.
  • gl.stencilOp(gl.KEEP, gl.KEEP, gl.REPLACE) updates the stencil buffer pixel values to match the current mask level (for example, a reference value of 1).

Complex vector fill rules (such as Even-Odd or Non-Zero winding) are managed by adjusting how the stencil buffer values increment, decrement, or invert as overlapping triangles rasterize over the same pixel coordinate.

Phase 3: Rendering the Masked Target

Once the geometry has been written to the stencil buffer:

  1. Re-enable Color Channels: gl.colorMask(true, true, true, true) is called so that content pixels are written to the screen again.
  2. Set the Comparison Rule: Pixi.js calls gl.stencilFunc(gl.EQUAL, currentLevel, 0xFF) and gl.stencilOp(gl.KEEP, gl.KEEP, gl.KEEP). This tells the GPU that subsequent draw calls must only write colors to the frame where the stencil buffer value equals the reference level.
  3. Render Masked Content: The children of the masked container (sprites, meshes, or text) are drawn normally. Pixels that fall outside the vector boundary fail the stencil test and are discarded immediately by the GPU before blending or color calculation occurs.

Phase 4: Managing Nested Masks and Cleanup

Pixi.js handles hierarchical or nested masks by incrementing the stencil reference value with each layer:

  • When a child mask is applied inside a parent mask, the new vector geometry is rendered using a stencil test that requires the parent level to already be present. Passing fragments increment the buffer to the next integer level (currentLevel + 1).
  • Because the stencil buffer is 8-bit, Pixi.js supports nesting up to 255 levels deep without needing offscreen buffers.
  • Once the masked container completes its draw call, Pixi.js executes a "pop" phase. It disables color writes again and redraws the mask geometry using gl.stencilOp(gl.KEEP, gl.KEEP, gl.DECR) or clear passes to restore the stencil buffer to its previous state.

By executing masking directly through WebGL stencil tests, Pixi.js avoids memory allocations for secondary framebuffers, prevents texture sampling overhead, and preserves sharp, anti-aliased vector boundaries at arbitrary screen resolutions.
