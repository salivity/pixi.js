Integrating Rapier 2D Physics with Pixi.js

This article provides a technical overview of coupling the Rapier.js 2D WebAssembly physics engine with the Pixi.js rendering pipeline. It covers fundamental setup, the synchronization of Pixi’s ticker with Rapier’s simulation step, coordinate and unit conversion between physics meters and screen pixels, and a complete code implementation pattern for continuous rendering.

Core Architecture and Unit Mapping

Rapier.js runs using WebAssembly and operates within the metric system (meters, kilograms, seconds), whereas Pixi.js renders coordinates directly in screen pixels. Directly using pixel values in physics simulations results in floating-point inaccuracies and unnatural, sluggish movement.

To integrate the two, you must establish a Pixels-Per-Meter (PPM) scaling factor:

  • Scaling Constant: Define a ratio, typically between 30 and 100 pixels per meter (e.g., const PPM = 50).
  • Position Translation: Multiply Rapier positions by PPM to assign Pixi sprite coordinates: pixiSprite.x = body.translation().x * PPM.
  • Rotation Translation: Pixi.js and Rapier 2D both calculate rotation in radians, allowing direct assignment: pixiSprite.rotation = body.rotation().
  • Coordinate Axes: Pixi’s origin (0,0) rests at the top-left corner, increasing downwards. You can configure Rapier’s gravity vector downward along the Y-axis (e.g., { x: 0.0, y: 9.81 }) so that positive Y maps naturally to downward screen movement.

The Integration Loop

Pixi.js features an internal rendering loop powered by PIXI.Ticker. Integrating Rapier requires updating the physics simulation inside this ticker before updating the visual properties of Pixi display objects.

  1. Step the World: Advance Rapier's simulation using world.step(). For deterministic physics, you can supply an event queue or use a fixed time-step accumulator.
  2. Synchronize Entities: Iterate through linked pairs of Rapier rigid bodies and Pixi display objects, updating the graphics to match the rigid body’s latest state.
  3. Render: Pixi automatically draws the updated display objects at the end of the tick.

Minimal Implementation Example

import * as PIXI from 'pixi.js';
import RAPIER from '@dimforge/rapier2d-compat';

async function main() {
    // 1. Initialize Rapier WASM and Pixi Application
    await RAPIER.init();
    
    const app = new PIXI.Application();
    await app.init({ width: 800, height: 600, backgroundColor: 0x1a1a1a });
    document.body.appendChild(app.canvas);

    const PPM = 50; // 50 pixels = 1 meter

    // 2. Setup Rapier World (downward gravity)
    const gravity = new RAPIER.Vector2(0.0, 9.81);
    const world = new RAPIER.World(gravity);

    // 3. Create Ground (Static Body)
    const groundBodyDesc = RAPIER.RigidBodyDesc.fixed().setTranslation(400 / PPM, 550 / PPM);
    const groundBody = world.createRigidBody(groundBodyDesc);
    const groundColliderDesc = RAPIER.ColliderDesc.cuboid(300 / PPM, 10 / PPM);
    world.createCollider(groundColliderDesc, groundBody);

    // Pixi Ground Graphic
    const groundGraphic = new PIXI.Graphics()
        .rect(-300, -10, 600, 20)
        .fill(0x444444);
    groundGraphic.x = 400;
    groundGraphic.y = 550;
    app.stage.addChild(groundGraphic);

    // 4. Create a Dynamic Box
    const boxBodyDesc = RAPIER.RigidBodyDesc.dynamic()
        .setTranslation(400 / PPM, 100 / PPM)
        .setRotation(Math.PI / 6);
    const boxBody = world.createRigidBody(boxBodyDesc);
    const boxColliderDesc = RAPIER.ColliderDesc.cuboid(25 / PPM, 25 / PPM).setRestitution(0.7);
    world.createCollider(boxColliderDesc, boxBody);

    // Pixi Box Graphic
    const boxGraphic = new PIXI.Graphics()
        .rect(-25, -25, 50, 50)
        .fill(0xff3300);
    app.stage.addChild(boxGraphic);

    // Pair container for synchronization
    const actors = [{ body: boxBody, view: boxGraphic }];

    // 5. The Update/Render Loop
    app.ticker.add((ticker) => {
        // Step the Rapier physics world forward
        world.step();

        // Update Pixi positions to match Rapier's simulation
        for (const actor of actors) {
            const position = actor.body.translation();
            actor.view.x = position.x * PPM;
            actor.view.y = position.y * PPM;
            actor.view.rotation = actor.body.rotation();
        }
    });
}

main();

Advanced Considerations

  • Fixed Timestep Accumulation: By default, calling world.step() directly inside ticker.add() causes physics to advance based on variable frame rates, which can lead to inconsistencies. Implementing a fixed-delta accumulator (e.g., stepping at a rigid 1/60s) stabilizes collision resolution regardless of screen refresh rates.
  • Object Pooling & Disposal: When removing entities, ensure clean removal from both systems: call world.removeRigidBody(body) in Rapier and graphic.destroy() in Pixi.js to avoid memory leaks across the JavaScript-WASM bridge.
