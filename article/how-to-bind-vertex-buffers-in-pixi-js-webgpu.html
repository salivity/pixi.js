How to Bind Vertex Buffers in Pixi.js WebGPU

This article provides an overview of how Pixi.js manages and binds vertex buffers to WebGPU pipeline states during rendering. You will learn how the engine abstracts WebGPU's strict pipeline interfaces, how Pixi.js geometry layouts map to low-level GPU vertex buffer layouts, and the exact sequence in which the render pipeline and vertex buffers are bound to the render pass encoder.

The Relationship Between Buffers and Pipelines in WebGPU

In native WebGPU, a render pipeline (GPURenderPipeline) requires a pre-defined layout (GPUVertexBufferLayout) that describes the structure of incoming vertex data, including stride, step mode, and attribute offsets. When drawing, the render pass encoder must explicitly bind both the compiled pipeline state via setPipeline() and the actual data sources via setVertexBuffer() matching the expected slot indices.

Pixi.js abstracts this process primarily through its v8 architecture using two main internal subsystems: the Pipeline System (GpuPipelineSystem) and the Geometry System (GpuGeometrySystem).

1. Defining the Vertex Layout

In Pixi.js, you define geometry attributes using the Geometry class. Each attribute specifies its format (such as float32x2), its buffer source, stride, and offset:

import { Geometry, Buffer } from 'pixi.js';

const vertexBuffer = new Buffer({
    data: new Float32Array([-0.5, -0.5, 0.5, -0.5, 0.0, 0.5]),
    usage: BufferUsage.VERTEX | BufferUsage.COPY_DST,
});

const geometry = new Geometry({
    attributes: {
        aPosition: {
            buffer: vertexBuffer,
            format: 'float32x2',
            stride: 8,
            offset: 0,
        },
    },
});

Pixi.js parses this high-level structure and automatically creates a native GPUVertexBufferLayout descriptor.

2. Creating the Pipeline State

When a draw call is initiated for a mesh or batch, Pixi.js needs a GPURenderPipeline. The GpuPipelineSystem checks its internal cache for an existing pipeline matching:

  • The active shader program (GpuProgram).
  • The current blend, stencil, and depth states.
  • The GPUVertexBufferLayout derived from the Geometry instance.

If a cached pipeline exists, it is reused. Otherwise, Pixi.js compiles a new GPURenderPipeline via the WebGPU device, baking the vertex buffer layout directly into the pipeline state descriptor.

3. Binding During the Render Pass

Once the pipeline is resolved, Pixi.js handles the command encoding in the active render pass:

  1. Pipeline Binding: The render pass encoder receives the pipeline via passEncoder.setPipeline(gpuPipeline). This configures the GPU's fixed-function state and informs it how vertex buffer memory will be formatted.
  2. Buffer Synchronization: The GpuBufferSystem ensures that any dirty vertex data in the Buffer object is uploaded to its corresponding native GPUBuffer.
  3. Vertex Buffer Binding: The GpuGeometrySystem iterates through each buffer assigned to the geometry. It executes: 
    passEncoder.setVertexBuffer(slotIndex, gpuBuffer, offset, size);
    The slotIndex corresponds directly to the location defined in the pipeline's vertex buffer layout.
  4. Draw Execution: Pixi.js issues passEncoder.draw() or passEncoder.drawIndexed(), consuming the bound vertex buffers through the active pipeline state.

By separating the static layout definition within the Geometry from the low-level encoding, Pixi.js ensures that vertex buffers are bound to WebGPU pipeline states efficiently with minimal redundant state changes.
