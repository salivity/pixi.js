Freeze a Container Transform in PixiJS

In PixiJS, child display objects automatically inherit position, rotation, and scale from their parent containers through the scene graph hierarchy. This article demonstrates how to decouple a child Container from this inheritance pipeline by overriding its transform updates, allowing you to completely freeze its position on the screen or ignore its parent's transformations while retaining local movement.

Understanding the Transform Pipeline

By default, PixiJS calculates global rendering positions using the updateTransform() method. During each render pass, a parent container computes its worldTransform matrix and passes it down to each child:

child.updateTransform();

Inside this call, the child multiplies its localTransform matrix by the parent's worldTransform matrix. To prevent parent adjustments from altering the child, you must intercept this calculation.

Method 1: Completely Freezing the World Transform

If you want a container to remain entirely static in world space regardless of any changes to its parent (or its own local properties), you can override its updateTransform method to do nothing.

  1. Position the child container at its intended coordinates.
  2. Render the scene once or manually invoke updateTransform() to calculate the initial matrix.
  3. Replace the updateTransform function with an empty implementation.
import * as PIXI from 'pixi.js';

const parent = new PIXI.Container();
const child = new PIXI.Container();

parent.addChild(child);

// Set initial position
child.position.set(100, 100);

// Force the initial transform calculation
child.updateTransform();

// Freeze the transform completely
child.updateTransform = function () {
    // No-op: prevents worldTransform from being recalculated
};

Even if parent.position, parent.scale, or parent.rotation changes, child.worldTransform remains frozen at its initial values.

Method 2: Ignoring the Parent While Retaining Local Transforms

If you need the child to remain controllable independently—moving relative to the global screen space rather than its parent—override updateTransform to substitute the parent’s transform with PIXI.Transform.IDENTITY.

import * as PIXI from 'pixi.js';

const parent = new PIXI.Container();
const child = new PIXI.Container();

parent.addChild(child);

// Override updateTransform to bypass parent transform
child.updateTransform = function () {
    // Update local matrix from child's position, scale, rotation, and skew
    this.transform.updateLocalTransform();

    // Multiply local transform by an identity matrix instead of parent.worldTransform
    this.transform.updateTransform(PIXI.Transform.IDENTITY);

    // Update children if this container has nested objects
    for (let i = 0, j = this.children.length; i < j; ++i) {
        this.children[i].updateTransform();
    }
};

With this implementation, mutating the parent container has zero effect on the child, but modifying child.x, child.rotation, or other local properties functions as if the child were attached directly to the root stage.

Restoring Default Transform Behavior

To unfreeze the container and reconnect it to its parent's transform hierarchy, restore the original prototype method:

delete child.updateTransform;

Deleting the instance-level method causes the container to fall back to PIXI.Container.prototype.updateTransform, instantly re-enabling parental transform inheritance.
