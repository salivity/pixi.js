How to Seek Video Textures Dynamically in PixiJS

Seeking to a specific timestamp in a video texture dynamically is fully supported in Pixi.js. Because Pixi.js relies on standard HTML5 <video> elements under the hood to drive its video textures, dynamic seeking is accomplished by directly manipulating the underlying media element's currentTime property and triggering a texture update. This article explains how to access the underlying video resource, alter its playback position dynamically via code, and handle texture updates cleanly during rendering.

Accessing the Underlying HTML5 Video Element

When you instantiate a video texture using Pixi.js, the engine wraps a standard HTML5 <video> element inside its texture management system. To control playback, jump to a timestamp, or pause at a specific frame, you interact directly with this DOM element.

Depending on the version of Pixi.js you are using, the path to the HTML5 video element differs slightly:

  • PixiJS v7 and earlier: The video element is accessed through texture.baseTexture.resource.source.
  • PixiJS v8: The video element is accessed via texture.source.resource.

How to Seek to a Specific Timestamp

To dynamically jump to a given time, set the currentTime attribute of the underlying video element to the desired value in seconds.

Here is a practical implementation for PixiJS:

import * as PIXI from 'pixi.js';

// Create a Pixi Application
const app = new PIXI.Application();
await app.init({ width: 800, height: 600 });
document.body.appendChild(app.canvas);

// Load the video texture
const texture = await PIXI.Assets.load('path/to/video.mp4');

// Create a sprite from the texture
const videoSprite = new PIXI.Sprite(texture);
app.stage.addChild(videoSprite);

// Retrieve the HTML5 video element (PixiJS v8 syntax)
const videoElement = texture.source.resource;

/**
 * Dynamically seeks to a specific timestamp in seconds.
 * @param {HTMLVideoElement} video 
 * @param {number} targetTimeInSeconds 
 */
function seekToTimestamp(video, targetTimeInSeconds) {
    // Ensure the video is loaded enough to seek
    if (video.readyState >= 1) { // HAVE_METADATA or higher
        video.currentTime = targetTimeInSeconds;
    } else {
        video.addEventListener('loadedmetadata', () => {
            video.currentTime = targetTimeInSeconds;
        }, { once: true });
    }
}

// Example: Seek to 12.5 seconds dynamically
seekToTimestamp(videoElement, 12.5);

Handling Texture Updates on Seek

When a video is playing, Pixi.js automatically synchronizes the texture with each new frame using its internal ticker. However, if the video is paused and you are using it purely as a dynamically scrubbed sequence, the WebGL texture may not automatically refresh immediately upon setting currentTime.

To ensure the sprite displays the newly sought frame:

  1. Listen for the native HTML5 seeked event on the video element.
  2. Manually notify Pixi.js to refresh the GPU texture resource.
videoElement.addEventListener('seeked', () => {
    // In PixiJS v8
    texture.source.update();

    // In PixiJS v7
    // texture.baseTexture.update();
});

Key Considerations for Smooth Seeking

  • Keyframe Density: Browsers seek between video keyframes (I-frames). If you require precise, frame-by-frame scrubbing without latency, encode the source video with a short keyframe interval (GOP size) or use an intra-frame-only codec like Apple ProRes or Motion JPEG.
  • Preloading: Ensure the video's preload attribute is set to auto or buffer sufficient data before seeking forward, otherwise the video element will trigger a network fetch and pause rendering while buffering.
  • CORS Configuration: If the video source is hosted on a separate domain, ensure the server provides appropriate Access-Control-Allow-Origin headers, and set crossOrigin = "anonymous" on the video element before loading it into Pixi.js to avoid tainted canvas security errors.
