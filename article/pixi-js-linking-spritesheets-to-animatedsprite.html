Pixi.js: Linking Spritesheets to AnimatedSprite

In Pixi.js, the Spritesheet class bridges the gap between raw texture atlases and playable animations by parsing metadata and organizing individual frames into ordered texture arrays. This article explains how a spritesheet's JSON data structure is processed by the Spritesheet class to populate the animations object, and how that data is subsequently ingested by the AnimatedSprite class to produce fluid animations.

The JSON Data Structure

The linkage begins in the atlas data file, typically generated by tools like TexturePacker. A valid Pixi.js spritesheet JSON file contains two critical objects: frames and animations.

{
  "frames": {
    "enemy_run_01.png": { "frame": { "x": 0, "y": 0, "w": 32, "h": 32 } },
    "enemy_run_02.png": { "frame": { "x": 32, "y": 0, "w": 32, "h": 32 } }
  },
  "animations": {
    "enemy_run": ["enemy_run_01.png", "enemy_run_02.png"]
  },
  "meta": {
    "image": "spritesheet.png",
    "size": { "w": 64, "h": 32 }
  }
}

The frames object defines the boundary coordinates of each individual image on the base image, while the animations object groups specific frame keys into arrays designated by an animation name.

Processing via the Spritesheet Class

When Pixi's Assets loader or the manual spritesheet.parse() method processes the asset, the Spritesheet class performs the following internal operations:

  1. Texture Creation: It crops the base texture according to the rectangle coordinates defined in each frames entry, instantiating a standalone Texture for each frame and mapping them by key in the spritesheet.textures dictionary.
  2. Animation Mapping: The class checks the JSON for the animations property. For each array key listed (e.g., "enemy_run"), it iterates through the string names, retrieves the matching Texture references from its newly created textures dictionary, and compiles them into a sequential JavaScript array (Texture[]).
  3. Storage: The resulting arrays are stored within the spritesheet.animations property as key-value pairs, where the key is the animation identifier and the value is the array of Texture instances.

Passing Textures to AnimatedSprite

The AnimatedSprite constructor requires an array of textures or frame objects to determine what to render over time. Because spritesheet.animations directly stores textures in this format, an instance is created by referencing the animation key:

const sheet = PIXI.Assets.get('spritesheetData');
const runAnimation = new PIXI.AnimatedSprite(sheet.animations['enemy_run']);

runAnimation.animationSpeed = 0.16;
runAnimation.play();
app.stage.addChild(runAnimation);

Frame Updating Mechanics

Once initialized, the AnimatedSprite does not maintain an active coupling with the Spritesheet instance itself. Instead, it relies solely on the array of Texture objects handed to it during instantiation.

On each tick of Pixi's shared ticker, the AnimatedSprite increments an internal frame counter governed by its animationSpeed. When the counter reaches the threshold for the next frame, the class sets its internal _texture property to the corresponding index in the provided sheet.animations array, seamlessly cycling through the textures extracted by the spritesheet.
