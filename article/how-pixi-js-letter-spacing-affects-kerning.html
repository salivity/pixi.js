How PixiJS Letter Spacing Affects Kerning

The letterSpacing property in PixiJS modifies the horizontal distance between text characters, but its effect on font kerning calculations depends entirely on whether you are rendering standard PIXI.Text or PIXI.BitmapText. While kerning adjusts the variable space between specific pairs of adjacent glyphs based on font design, letterSpacing applies a uniform offset across all characters. In standard Canvas-rendered text, applying manual letter spacing often disables or bypasses natural pair kerning entirely, whereas in bitmap fonts, it acts as an additive value that preserves the underlying kerning table metrics.

Kerning Mechanics in Standard PIXI.Text

Standard text rendering in PixiJS relies on the HTML5 Canvas 2D rendering context. Natural typographic kerning is calculated automatically by the browser's font engine when rendering entire strings together (for instance, reducing the space between "A" and "V").

When letterSpacing is set to 0, PixiJS delegates the rendering of text fragments directly to the canvas engine using methods like fillText(). This approach allows the browser's native text shaper to read the font's OpenType/TrueType kerning pairs (GPOS or kern tables) and render accurately kerned text.

When a non-zero letterSpacing value is assigned in PIXI.TextStyle, PixiJS historically overrides standard whole-string rendering to ensure exact cross-browser pixel spacing. To apply this spacing:

  1. PixiJS splits the string into individual glyphs or code points.
  2. Each glyph is measured and positioned sequentially along the x-axis.
  3. The formula for the next character's position is: \[\text{Position}_{n+1} = \text{Position}_n + \text{Width}(\text{Glyph}_n) + \text{letterSpacing}\]

Because characters are measured and drawn in isolation rather than as a continuous string, the browser engine cannot evaluate contextual glyph pairs. Consequently, native kerning calculations are lost, and only the glyph’s isolated advance width plus the letterSpacing value determines the final position.

Kerning Calculations in PIXI.BitmapText

Unlike canvas-based text, PIXI.BitmapText uses pre-rendered texture atlases paired with font descriptor files (such as BMFont XML or JSON). These descriptor files explicitly store the glyph metrics, advance widths, and specific kerning pairs.

In BitmapText, kerning calculations are not overridden by letterSpacing; instead, letterSpacing is additive:

  1. PixiJS retrieves the base horizontal advance value (xAdvance) for the current glyph from the font metrics.
  2. It queries the font's kerning dictionary using the character code of the previous glyph and the current glyph to retrieve the kerning offset: \[\text{KerningOffset} = \text{getKerning}(\text{Glyph}_{n-1}, \text{Glyph}_n)\]
  3. The letterSpacing value is then added directly into the horizontal offset calculation: \[\text{Advance} = \text{xAdvance} + \text{KerningOffset} + \text{letterSpacing}\]

Because BitmapText handles glyph placement manually through its own layout engine, proportional kerning relationships remain intact regardless of how large or small the letterSpacing value is.

Visual Implications

Applying positive letterSpacing increases the uniform tracking across the string. As letter spacing increases, the visual impact of pair kerning diminishes because the relative proportion of the kerning adjustment becomes negligible compared to the total whitespace between letters.

Conversely, applying negative letterSpacing pulls glyphs closer together. In PIXI.BitmapText, characters with negative kerning pairs (like "To" or "Wa") will collapse into each other faster than pairs without kerning adjustments. In standard PIXI.Text, the collapse will be completely uniform across all glyphs due to the absence of pair-specific calculations.
