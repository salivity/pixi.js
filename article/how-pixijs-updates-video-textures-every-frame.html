How PixiJS Updates Video Textures Every Frame

PixiJS delivers smooth video playback by wrapping the native HTML5 <video> element inside a specialized VideoResource that synchronizes with the browser's rendering pipeline. By leveraging modern frame-timing APIs, maintaining a dirty-flagging mechanism, and efficiently uploading decoded frames directly to WebGL texture memory using gl.texSubImage2D, PixiJS ensures that video textures stay synchronized with the display refresh rate without unnecessary CPU or GPU overhead.

The VideoResource Abstraction

At the core of video handling in PixiJS is the VideoResource class, which extends the base Resource architecture. When you create a video texture using PIXI.Texture.from('video.mp4'), PixiJS creates an underlying HTMLVideoElement and binds it to a VideoResource.

This resource acts as the bridge between the browser’s media decoding pipeline and the WebGL renderer. Instead of generating new textures on every frame—which would quickly consume GPU memory and trigger garbage collection stalls—the VideoResource reuses the same GPU texture allocation, updating its contents in-place.

Frame Synchronization with requestVideoFrameCallback

To achieve stutter-free playback, PixiJS must know precisely when a new video frame is ready for rendering. Older rendering techniques polled the video element's currentTime on every tick, which frequently resulted in redundant texture uploads or dropped frames due to clock drift between the video framerate and display refresh rate.

Modern PixiJS implementations utilize the native HTMLVideoElement.requestVideoFrameCallback() (rVFC) API when available:

  • Hardware-Synchronized Callbacks: The browser notifies PixiJS the exact moment a new frame is decoded and presented by the media compositor.
  • Metadata Access: The callback provides precise metadata, such as presentation timestamps and processing duration, ensuring optimal synchronization.
  • Ticker Fallback: In environments where rVFC is not supported, PixiJS falls back to listening to the native timeupdate event combined with Pixi’s internal Ticker, verifying frame changes by comparing the element's currentTime.

The Dirty Flag and Ticker System

PixiJS avoids expensive operations by utilizing an internal invalidation pattern:

  1. Detection: When requestVideoFrameCallback fires or a time discrepancy is detected, the VideoResource marks its parent BaseTexture as "dirty" by calling baseTexture.update().
  2. Flagging: Calling update() increments the dirtyId of the BaseTexture.
  3. Lazy Execution: The actual frame is not uploaded immediately; it waits until PixiJS executes its main render pass via the render loop (Ticker). If an object using the video texture is outside the visible viewport or culled, PixiJS skips the upload entirely.

GPU Upload via texSubImage2D

When the render pass encounters a dirty video texture, the TextureSystem uploads the updated pixel data from the HTML5 video element directly to the existing WebGL texture on the GPU.

Instead of calling gl.texImage2D—which allocates new texture storage—PixiJS uses gl.texSubImage2D. This WebGL command replaces the pixel contents of the existing memory buffer directly from the <video> element source. Because modern browsers handle internal hardware decoding and zero-copy transfers between media players and WebGL contexts, gl.texSubImage2D allows the GPU to stream video frames with minimal CPU intervention.

Automatic Lifecycle and Playback Handling

PixiJS also manages edge cases to prevent playback bottlenecks:

  • Auto-pausing: If the video is paused, seeking, or buffering, PixiJS stops queueing texture updates, eliminating unnecessary render work.
  • Auto-resizing: When video metadata loads, the VideoResource detects the native dimensions (videoWidth and videoHeight) and updates the texture frame coordinates automatically, preventing display distortion.
  • Premultiplied Alpha: Video textures typically default to treating alpha channels correctly for WebGL blending, ensuring clean integration with other graphical elements in the scene graph.
