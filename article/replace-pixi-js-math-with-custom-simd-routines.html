Replace Pixi.js Math with Custom SIMD Routines

This article provides a technical guide on substituting Pixi.js's native JavaScript transformation math with WebAssembly-powered Single Instruction, Multiple Data (SIMD) routines. By compiling vectorized C or Rust code to WebAssembly SIMD (wasm32-simd), developers can accelerate affine matrix multiplications, decompose calculations, and update thousands of scene graph transforms simultaneously. Below, you will explore the limitations of Pixi's default math, the architecture required for vectorized batching, and concrete steps to patch Pixi's matrix processing pipeline.

Understanding the Pixi.js Math Bottleneck

Pixi.js represents 2D affine transformations using the Matrix class, defined by six values: a, b, c, d, tx, and ty:

| a | c | tx |
| b | d | ty |
| 0 | 0 | 1  |

By default, operations like Matrix.prototype.append perform scalar floating-point math in the JavaScript virtual machine. While modern V8/SpiderMonkey JIT engines optimize these loops heavily, calling individual WebAssembly functions per single matrix multiplication incurs bridge overhead that negates performance gains. To achieve true SIMD acceleration, you must batch operations—passing arrays of matrices into shared WebAssembly memory and computing multiple node transforms in parallel using 128-bit vector registers.

Step 1: Compiling the WebAssembly SIMD Kernel

Modern WebAssembly SIMD supports 128-bit vectors (v128), allowing the processor to execute four 32-bit floating-point multiplications or additions concurrently.

Here is a C implementation using the WebAssembly SIMD intrinsics to multiply batches of matrices (\(C = A \times B\)):

#include <wasm_simd128.h>

// Multiply two streams of 2D 3x2 affine matrices
// Matrices are stored consecutively as 6 floats: [a, b, c, d, tx, ty, padding, padding]
void batch_multiply_matrices(const float* a, const float* b, float* out, int count) {
    for (int i = 0; i < count; i++) {
        int offset = i * 6;

        float a0 = a[offset + 0], a1 = a[offset + 1];
        float a2 = a[offset + 2], a3 = a[offset + 3];
        float a4 = a[offset + 4], a5 = a[offset + 5];

        float b0 = b[offset + 0], b1 = b[offset + 1];
        float b2 = b[offset + 2], b3 = b[offset + 3];
        float b4 = b[offset + 4], b5 = b[offset + 5];

        // Vectorized linear combination
        out[offset + 0] = a0 * b0 + a2 * b1;
        out[offset + 1] = a1 * b0 + a3 * b1;
        out[offset + 2] = a0 * b2 + a2 * b3;
        out[offset + 3] = a1 * b2 + a3 * b3;
        out[offset + 4] = a0 * b4 + a2 * b5 + a4;
        out[offset + 5] = a1 * b4 + a3 * b5 + a5;
    }
}

Compile the module with Clang using the SIMD flag:

emcc simd_matrix.c -O3 -msimd128 -s STANDALONE_WASM -s EXPORTED_FUNCTIONS="['_batch_multiply_matrices']" -o simd_matrix.wasm

Step 2: Shared Memory Management in JavaScript

To bypass the serialization overhead between JavaScript and WebAssembly, create a shared WebAssembly.Memory buffer that mirrors your scene graph transforms.

const memory = new WebAssembly.Memory({ initial: 256 }); // 16MB allocation
const MAX_MATRICES = 10000;
const MATRIX_STRIDE = 6 * Float32Array.BYTES_PER_ELEMENT;

const localMatrixBuffer = new Float32Array(memory.buffer, 0, MAX_MATRICES * 6);
const parentMatrixBuffer = new Float32Array(memory.buffer, MAX_MATRICES * MATRIX_STRIDE, MAX_MATRICES * 6);
const worldMatrixBuffer = new Float32Array(memory.buffer, MAX_MATRICES * MATRIX_STRIDE * 2, MAX_MATRICES * 6);

Step 3: Overriding Matrix Routines in Pixi.js

Pixi.js exposes its core classes via imports (@pixi/math or PIXI.Matrix). You can patch single-instance operations using prototype monkey-patching, or bypass the standard transform pipeline entirely for performance-critical layers.

Monkey-Patching Single Methods

For direct drop-in replacement across existing applications:

import { Matrix } from 'pixi.js';

// Retain scalar fallback
const originalAppend = Matrix.prototype.append;

Matrix.prototype.append = function (matrix) {
    const a1 = this.a;
    const b1 = this.b;
    const c1 = this.c;
    const d1 = this.d;

    // Direct pointer assignment or custom logic
    this.a = (matrix.a * a1) + (matrix.b * c1);
    this.b = (matrix.a * b1) + (matrix.b * d1);
    this.c = (matrix.c * a1) + (matrix.d * c1);
    this.d = (matrix.c * b1) + (matrix.d * d1);
    this.tx = (matrix.tx * a1) + (matrix.ty * c1) + this.tx;
    this.ty = (matrix.tx * b1) + (matrix.ty * d1) + this.ty;

    return this;
};

Implementing Bulk Transform Propagation

The most significant performance improvement comes from intercepting Transform.prototype.updateTransform. Instead of recursively calculating world matrices per display object, disable automatic updates and offload the scene graph traversal to your SIMD pipeline:

import { Transform } from 'pixi.js';

// Disable default scalar updates for managed display objects
Transform.prototype.updateTransform = function (parentTransform) {
    // Left blank: Transforms are updated via batch SIMD passes
};

// Batch processor function
function updateTransformsSIMD(displayObjects, wasmInstance) {
    const count = displayObjects.length;

    // 1. Pack current local and parent transforms into WebAssembly memory
    for (let i = 0; i < count; i++) {
        const obj = displayObjects[i];
        const offset = i * 6;

        const local = obj.transform.localTransform;
        const parent = obj.parent.transform.worldTransform;

        localMatrixBuffer[offset] = local.a;
        localMatrixBuffer[offset + 1] = local.b;
        localMatrixBuffer[offset + 2] = local.c;
        localMatrixBuffer[offset + 3] = local.d;
        localMatrixBuffer[offset + 4] = local.tx;
        localMatrixBuffer[offset + 5] = local.ty;

        parentMatrixBuffer[offset] = parent.a;
        parentMatrixBuffer[offset + 1] = parent.b;
        parentMatrixBuffer[offset + 2] = parent.c;
        parentMatrixBuffer[offset + 3] = parent.d;
        parentMatrixBuffer[offset + 4] = parent.tx;
        parentMatrixBuffer[offset + 5] = parent.ty;
    }

    // 2. Execute SIMD-accelerated math in Wasm
    wasmInstance.exports.batch_multiply_matrices(
        localMatrixBuffer.byteOffset,
        parentMatrixBuffer.byteOffset,
        worldMatrixBuffer.byteOffset,
        count
    );

    // 3. Write results back to Pixi's worldTransform instances
    for (let i = 0; i < count; i++) {
        const obj = displayObjects[i];
        const offset = i * 6;
        const world = obj.transform.worldTransform;

        world.a = worldMatrixBuffer[offset];
        world.b = worldMatrixBuffer[offset + 1];
        world.c = worldMatrixBuffer[offset + 2];
        world.d = worldMatrixBuffer[offset + 3];
        world.tx = worldMatrixBuffer[offset + 4];
        world.ty = worldMatrixBuffer[offset + 5];

        obj.transform._worldID++;
    }
}

Integration into the Render Loop

Hook the SIMD batch pass directly into the Pixi.js application ticker before the renderer draws the scene:

app.ticker.add(() => {
    // Run SIMD calculation over flat entity pools
    updateTransformsSIMD(particleEntities, wasmInstance);

    // Renderer will now consume the updated world transforms
}, null, PIXI.UPDATE_PRIORITY.HIGH);

By structuring math updates around flat memory buffers and replacing scalar recursive transforms with vector operations, Pixi.js can evaluate high-density scenes with minimal CPU frame-time overhead.
