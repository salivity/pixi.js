Responsive Anchor UI Layouts in Pixi.js

Building responsive, anchor-based user interfaces in Pixi.js requires decoupling your UI logic from fixed coordinate spaces and recalculating positions relative to screen boundaries whenever the canvas dimensions change. This guide explains how to set up an adaptive rendering canvas, implement an anchor-point positioning system (such as top-left, center, or bottom-right), handle dynamic screen resize events, and apply scale factors to ensure crisp, accessible interfaces across diverse devices and aspect ratios.

Configuring the Pixi.js Application for Resizing

To support multiple resolutions, initialize the Application so that the renderer automatically resizes with the browser window or its parent container.

import { Application } from 'pixi.js';

const app = new Application();

await app.init({
    resizeTo: window,
    resolution: window.devicePixelRatio || 1,
    autoDensity: true,
    antialias: true,
});

document.body.appendChild(app.canvas);

Setting resolution: window.devicePixelRatio and autoDensity: true ensures that graphics remain sharp on high-DPI displays without distorting the layout coordinates.

Defining the Anchor Layout Concept

Unlike standard game objects positioned in world coordinates, UI elements typically stick to a reference point on the screen (the anchor) plus a fixed offset in pixels.

Common anchor points include:

  • Top-Left (0, 0): Ideal for player avatars, pause buttons, or status indicators.
  • Top-Right (1, 0): Ideal for settings menus, currency displays, and close buttons.
  • Bottom-Left (0, 1): Ideal for chat windows or virtual joysticks.
  • Bottom-Right (1, 1): Ideal for action buttons or inventory toggles.
  • Center (0.5, 0.5): Ideal for modal dialogues, popups, and pause screens.

Implementing an Anchor-Based Component

To build an anchor system, attach layout metadata directly to UI containers or manage them via an explicit layout manager.

import { Container } from 'pixi.js';

class UIElement extends Container {
    constructor(options = {}) {
        super();
        this.anchorX = options.anchorX ?? 0; // 0 = Left, 0.5 = Center, 1 = Right
        this.anchorY = options.anchorY ?? 0; // 0 = Top, 0.5 = Center, 1 = Bottom
        this.offsetX = options.offsetX ?? 0; // Distance in pixels from the anchor
        this.offsetY = options.offsetY ?? 0;
    }

    updateLayout(screenWidth, screenHeight) {
        this.x = screenWidth * this.anchorX + this.offsetX;
        this.y = screenHeight * this.anchorY + this.offsetY;
    }
}

If the element itself needs to center internally on its anchor position (such as a modal window or a centered button), adjust the element's pivot:

// Center the container's pivot so its center aligns with its (x, y) coordinates
element.pivot.set(element.width / 2, element.height / 2);

Creating a Centralized Layout Manager

Maintain an array of responsive elements and update their positions whenever the canvas dimensions change.

class UIManager {
    constructor(app) {
        this.app = app;
        this.elements = [];

        // Listen for screen resize events
        this.app.renderer.on('resize', (width, height) => {
            this.resize(width, height);
        });
    }

    add(element) {
        this.elements.push(element);
        this.app.stage.addChild(element);
        // Position immediately with current dimensions
        element.updateLayout(this.app.screen.width, this.app.screen.height);
    }

    remove(element) {
        const index = this.elements.indexOf(element);
        if (index !== -1) {
            this.elements.splice(index, 1);
            this.app.stage.removeChild(element);
        }
    }

    resize(width, height) {
        for (const element of this.elements) {
            element.updateLayout(width, height);
        }
    }
}

Managing Scale Across Screen Densities

Positioning elements with anchors prevents them from falling off-screen, but elements may appear too large on mobile screens or too small on ultra-wide desktop monitors. To resolve this, calculate a dynamic UI scale based on a reference resolution:

function getScaleFactor(currentWidth, currentHeight, designWidth = 1920, designHeight = 1080) {
    const scaleX = currentWidth / designWidth;
    const scaleY = currentHeight / designHeight;
    
    // Choose Math.min to preserve aspect ratio without clipping
    return Math.min(scaleX, scaleY);
}

// Applying scale to UI layers
function updateUIScaling(uiContainer, width, height) {
    const scale = getScaleFactor(width, height);
    uiContainer.scale.set(scale);
}

Combine anchoring with scale factors by scaling your parent UI container, then positioning child elements using the scaled coordinate boundaries:

const scaledWidth = app.screen.width / uiContainer.scale.x;
const scaledHeight = app.screen.height / uiContainer.scale.y;

element.updateLayout(scaledWidth, scaledHeight);

Example Usage

const uiManager = new UIManager(app);

// Top-Right Settings Button
const settingsButton = new UIElement({
    anchorX: 1,
    anchorY: 0,
    offsetX: -50,
    offsetY: 20
});
uiManager.add(settingsButton);

// Centered Modal Window
const modal = new UIElement({
    anchorX: 0.5,
    anchorY: 0.5,
    offsetX: 0,
    offsetY: 0
});
modal.pivot.set(modal.width / 2, modal.height / 2);
uiManager.add(modal);

This modular pattern isolates coordinate calculations, prevents manual position tracking inside individual components, and keeps interfaces consistent across arbitrary viewports and screen orientations.
