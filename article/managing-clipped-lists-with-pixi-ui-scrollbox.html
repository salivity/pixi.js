Managing Clipped Lists with @pixi/ui ScrollBox

This article provides an overview of how the ScrollBox component from @pixi/ui implements clipped scrolling lists within PixiJS applications. It examines the internal display hierarchy, the use of hardware-accelerated masking for visual clipping, interaction handling for drag and wheel gestures, and dynamic layout calculations for updating scrollbar dimensions.

Display Container Hierarchy

The ScrollBox component achieves scrolling and clipping by separating the component into a structured hierarchy of display objects:

  1. Root Container: The outer ScrollBox instance, which defines the visible viewport dimensions (width and height) and holds all sub-elements.
  2. Mask Geometry: A PIXI.Graphics rectangular instance that strictly matches the dimensions of the visible viewport.
  3. Content Container: An internal container that holds the list items. The mask is applied to this container, ensuring that any child item positioned outside the designated viewport area is excluded from rendering.
  4. Scrollbar Tracks and Thumbs: UI graphics positioned along the edges of the root container to reflect scrolling progress and provide interactive control.

Hardware Masking and Clipping

Visual clipping in ScrollBox relies on PixiJS's masking pipeline. When you set the viewport bounds of the ScrollBox, an internal rectangular mask is created and assigned:

contentContainer.mask = maskGraphics;

PixiJS evaluates this mask during the render pass. Depending on the renderer settings and device capabilities, PixiJS uses either a scissor test or the stencil buffer to discard fragments outside the mask boundaries. Because the clipping is performed at the GPU level, list items can freely shift their coordinates without requiring manual visibility culling or clipping math per element, maintaining high rendering performance even with dense display trees.

Interaction and Coordinate Manipulation

Scrolling is managed through interaction events attached to the root container or global stage, capturing pointerdown, pointermove, pointerup, and wheel events.

When a user drags within the viewport or spins the mouse wheel:

  • The component computes the input delta along the active axis (horizontal, vertical, or bidirectional).
  • The x or y coordinates of the internal content container are shifted by this delta.
  • The new position is clamped to prevent scrolling beyond content limits: \[\text{minPosition} = \text{viewportSize} - \text{contentSize}\] \[\text{maxPosition} = 0\]
  • If configured, an elastic damping or "bounce" algorithm allows temporary over-scrolling before smoothly tweening the content back into valid bounds.

Dynamic Layout and Scrollbar Synchronization

ScrollBox automatically tracks the dimensions of its children to maintain correct clipping boundaries:

  • Bounds Calculation: Whenever an item is added via addItem() or the content changes, ScrollBox calculates the aggregate bounding box using contentContainer.getLocalBounds().
  • List Positioning: Items can be automatically laid out sequentially using configurable padding and spacing, arranging them in vertical stacks, horizontal rows, or grids.
  • Scrollbar Resizing: The ratio of the viewport size to the total content size determines the length of the scrollbar thumb: \[\text{ThumbSize} = \text{TrackSize} \times \left( \frac{\text{ViewportSize}}{\text{ContentSize}} \right)\]
  • Indicator Tracking: As the content coordinates change, the scrollbar thumb's position is updated proportionally across the track, giving visual feedback of the current scroll offset.
