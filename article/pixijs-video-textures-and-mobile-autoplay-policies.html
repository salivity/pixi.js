PixiJS Video Textures and Mobile Autoplay Policies

Using video textures in PixiJS on mobile devices often results in blank or frozen textures due to strict browser autoplay policies on iOS Safari and Android Chrome. Modern mobile browsers block programmatic media playback with audio to conserve user bandwidth and prevent intrusive experiences. To reliably display video textures in PixiJS, developers must either satisfy automated background playback requirements using muted inline attributes or defer playback until a qualifying user interaction triggers the media pipeline.

Mobile Autoplay Restrictions Affecting PixiJS

Mobile WebKit (iOS) and Blink (Android) enforce strict playback constraints on the underlying HTML5 <video> elements powering PixiJS textures:

  • Gesture Requirement: Videos containing audio tracks cannot call .play() programmatically without an explicit user gesture (such as touchstart, touchend, or click).
  • Fullscreen Hijack: iOS Safari automatically forces videos to play in native fullscreen mode unless explicitly instructed not to, which breaks WebGL canvas integration.
  • Power and Data Saving: Mobile operating systems pause or reject video playback when the device is in low-power mode or when the tab loses focus.

When a policy is violated, the video’s play() method returns a rejected Promise. Consequently, the video texture fails to update its underlying WebGL texture buffer, rendering as transparent, black, or an empty frame in the PixiJS stage.

Solution 1: Muted Inline Playback (For Backgrounds and Visuals)

If the video does not require sound, mobile browsers allow immediate autoplay as long as the HTML video element meets specific criteria before binding it to PixiJS.

Create the DOM video element manually and set its properties before creating the PixiJS texture:

const video = document.createElement('video');

video.muted = true;
video.defaultMuted = true;
video.setAttribute('playsinline', '');
video.setAttribute('webkit-playsinline', '');
video.autoplay = true;
video.loop = true;
video.src = 'path/to/video.mp4';

// Ensure CORS allows WebGL texturing
video.crossOrigin = 'anonymous';

// Bind to PixiJS
const texture = PIXI.Texture.from(video);
const sprite = new PIXI.Sprite(texture);
app.stage.addChild(sprite);

// Explicitly handle playback initialization
video.play().catch((error) => {
    console.warn('Autoplay was prevented:', error);
});

Key attributes required:

  • muted and defaultMuted = true: Satisfies zero-volume autoplay conditions.
  • playsinline and webkit-playsinline: Keeps the video inside the WebGL pipeline rather than launching native fullscreen players on iOS.

Solution 2: User Gesture Unlock (For Audio-Enabled Videos)

If your video texture requires audible sound, you must unlock playback using a direct user input event on the canvas or an overlay UI element.

  1. Display a Pre-interaction State: Render a static poster frame or a "Tap to Start" prompt inside PixiJS.
  2. Bind the Gesture: Listen for a pointerdown event on the PixiJS application view or stage.
  3. Execute Playback: Call play() on the underlying source video inside the event handler.
const texture = PIXI.Texture.from('path/to/video.mp4');
const videoSource = texture.baseTexture.resource.source;

// Configure inline display
videoSource.setAttribute('playsinline', '');
videoSource.setAttribute('webkit-playsinline', '');

// Wait for explicit touch or click
app.view.addEventListener('pointerdown', () => {
    if (videoSource.paused) {
        videoSource.play().then(() => {
            console.log('Video playing successfully with audio.');
        }).catch((err) => {
            console.error('Playback failed:', err);
        });
    }
}, { once: true });

Best Practices for Video Textures

  • Preload Metadata: Ensure the video metadata is loaded before reading dimensions to avoid rendering zero-sized textures.
  • Clean Up Video Sources: When destroying a PixiJS video texture, pause the HTML video element, set its src to an empty string, and call video.load() to release mobile hardware decoders and memory.
  • Handle Sleep and Visibility Changes: Listen to document.visibilitychange to pause video playback when the user switches tabs, and resume safely when returning to prevent desynchronization with the PixiJS render loop.
