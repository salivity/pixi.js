How Pixi.js hitTest Finds Frontmost Target

This article provides an overview of how Pixi.js determines which interactive display object lies directly beneath a pointer coordinate. It covers the depth-first, reverse-order traversal algorithm implemented by Pixi.js's event boundary system, the conditions required for a child to qualify as a valid target, and the pruning techniques used to bypass non-interactive branches for optimal performance.

Reverse-Order Depth-First Traversal

Pixi.js renders display objects using the painter's algorithm: children located at higher indices within a Container.children array are rendered over children with lower indices. To determine which object is physically in front at a given screen coordinate, the hitTest logic reverses this order during hit testing.

When testing a container, the traversal iterates backwards from children.length - 1 down to 0. By checking the last rendered child first, Pixi.js ensures that visual layering matches interaction priority, identifying the top-most visual element immediately.

The search executes as a depth-first search (DFS). When the search encounters a nested Container, it dives directly into that child's subtree—again checking from the highest index to the lowest—before moving to earlier siblings in the parent container.

Candidate Validation and Branch Pruning

Before testing points against specific geometry, Pixi.js evaluates several flags on the container and its children to skip unnecessary calculations. A branch or object is pruned if it fails any of the following criteria:

  • Visibility and Renderability: If an object has visible = false or renderable = false, it is ignored, along with all of its descendants.
  • Alpha Threshold: In scenarios involving render textures or specific hit conditions, objects with an alpha value of zero may be disregarded depending on the interaction configuration.
  • Interactive Children: If a container has interactiveChildren = false, Pixi.js evaluates the container itself (if it is interactive) but skips testing any of its child elements.
  • Event Mode: Under Pixi's modern event system, the eventMode property dictates responsiveness. Elements set to 'none' are skipped entirely, while elements set to 'passive' pass events through to objects behind them without becoming direct targets.

Point Testing and Masks

Once a candidate passes the pruning phase, the global screen coordinates are mapped into the candidate's local coordinate space using its inverted world transform matrix.

  1. Mask Verification: If the candidate has a mask, Pixi.js tests whether the coordinate falls inside the mask bounds. If it falls outside, the candidate is discarded.
  2. HitArea or Bounds Check: If the object defines a custom hitArea (such as a PIXI.Rectangle or PIXI.Polygon), the local point is checked against that shape using hitArea.contains(x, y). If no hitArea is specified, Pixi.js calculates the local bounds of the visual asset (such as a Sprite or Graphics geometry) to verify if the coordinate intersects the rendered content.

Target Resolution and Early Termination

Because the traversal operates from front to back, the first interactive object that successfully passes both coordinate transformation and containment tests is guaranteed to be the frontmost target.

Once a valid hit occurs at the lowest level of the active branch, the recursive search terminates immediately. The hit object is returned as the event target, preventing Pixi.js from performing expensive geometry checks on any display objects positioned behind it.
