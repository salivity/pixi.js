Pixi.js: worldTransform vs. localTransform

In Pixi.js, rendering objects accurately depends on understanding coordinate spaces and transformation matrices. Every DisplayObject contains both a localTransform and a worldTransform, which represent 3x3 affine transformation matrices. The fundamental difference between them is their frame of reference: localTransform calculates an object's position, scale, rotation, and skew relative strictly to its direct parent, whereas worldTransform calculates these properties relative to the root stage, determining where the object actually appears on the screen.

Understanding localTransform

The localTransform property represents an object’s transformation relative to its parent container.

  • Derivation: It is derived directly from the object's local spatial properties, including position (x, y), scale, rotation, skew, and pivot.
  • Independence: Changing the position, scale, or rotation of an ancestor container does not alter a child’s localTransform. If a sprite is positioned at x: 20, y: 20, its localTransform will reflect an offset of (20, 20), regardless of where its parent is placed in the scene.
  • Scope: It operates strictly in the parent object's local coordinate space.

Understanding worldTransform

The worldTransform property represents the final, cumulative transformation matrix applied to the object after factoring in the entire scene hierarchy.

  • Derivation: It is computed by multiplying the parent's worldTransform by the current object's localTransform.
  • Dependency: Any modification to an ancestor container (such as moving, rotating, or scaling the parent or grandparent) directly changes the child’s worldTransform.
  • Scope: It operates in the global coordinate space of the root canvas/stage. This is the matrix Pixi.js passes to the GPU or canvas 2D context to render the object in its final screen position.

Summary of Key Differences

Feature localTransform worldTransform
Reference Frame Direct parent container Root stage (global/screen space)
Source Data Object's x, y, scale, rotation, pivot Parent's worldTransform combined with local values
Parent Influence Unaffected by parent transformations Completely dependent on parent transformations
Rendering Role Intermediate mathematical step Direct matrix used for screen rendering and drawing

Practical Example

Consider a Container positioned at (100, 100) on the stage, containing a child Sprite positioned at (25, 25):

  • Sprite's localTransform: Translates by (25, 25). It only accounts for the offset inside the container.
  • Sprite's worldTransform: Translates by (125, 125). It combines the container's position and the sprite's local offset to determine the final screen coordinate.

When to Use Which

Use localTransform when you need to inspect or modify how an element is oriented relative to its siblings and parent container.

Use worldTransform when dealing with global interactions across different branches of the scene graph, such as global collision detection, positioning UI elements over in-game objects, or mapping screen coordinates to objects via methods like toGlobal() and toLocal(). Note that worldTransform is updated during the render pass via updateTransform(), so if you modify an object's position and need its updated world position immediately, you must call parent.updateTransform() or displayObject.getBounds() first.
