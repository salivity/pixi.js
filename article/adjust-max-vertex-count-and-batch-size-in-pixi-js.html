Adjust Max Vertex Count and Batch Size in Pixi.js

In Pixi.js, batching combines multiple 2D objects into single WebGL draw calls to maximize rendering performance. By default, the batcher allocates a buffer sized for a specific number of quads, but you can adjust this limit to accommodate heavier vertex requirements or reduce memory overhead. This guide explains how to configure the maximum vertex count and batch size across different versions of Pixi.js, as well as the technical trade-offs of adjusting these values.

Pixi.js v6 and v7: Replacing the Default Batch Plugin

In Pixi.js v6 and v7, the default 2D batching system is handled by the BatchRenderer. The internal vertex capacity is determined by the defaultBatchSize property within BatchPluginFactory, which represents the maximum number of quads processed in a single batch (default is usually 4,096 quads, equal to 16,384 vertices).

To adjust the batch size globally, generate a new batch renderer with your desired capacity and register it under the 'batch' plugin name before initializing the Application or Renderer.

import * as PIXI from 'pixi.js';

// Define the custom quad capacity (e.g., 8192 quads = 32,768 vertices)
const customBatchSize = 8192;

// Create a new batch renderer class with the custom size
const CustomBatchRenderer = PIXI.BatchPluginFactory.create({
    defaultBatchSize: customBatchSize
});

// Register it to override the default batch renderer
PIXI.extensions.add({
    name: 'batch',
    type: PIXI.ExtensionType.RendererPlugin,
    ref: CustomBatchRenderer
});

// Initialize your application as usual
const app = new PIXI.Application({
    width: 800,
    height: 600,
});

If you are using an older Pixi.js v5 or v6 setup using PIXI.Renderer.registerPlugin, you can register it like this:

PIXI.Renderer.registerPlugin('batch', CustomBatchRenderer);

Pixi.js v8: Pipe Architecture and Batcher Limits

Pixi.js v8 completely rewrote the internal rendering engine using a modular pipe architecture. In v8, geometry batching is managed by the Batcher class.

Unlike previous versions with fixed compile-time plugin generation, the v8 Batcher dynamically manages vertex and index allocation, but you can still override batch settings via custom batch pipe configurations or by modifying the Batcher instance defaults.

import { Batcher, Application } from 'pixi.js';

// Adjust the default vertex and index capacity
Batcher.defaultOptions = {
    ...Batcher.defaultOptions,
    maxVertices: 65535, // Adjust vertex limit per batch
};

const app = new Application();
await app.init({
    width: 800,
    height: 600,
});

Technical Considerations When Changing Batch Size

  • 16-bit Index Buffer Limits: By default, standard WebGL 1.0/2.0 implementations often use 16-bit unsigned integers (Uint16Array) for element index buffers (gl.UNSIGNED_SHORT). This limits the maximum number of unique vertices in a single batch to 65,535. Setting a batch size higher than 16,383 quads (which totals 65,532 vertices) will require 32-bit indices (OES_element_index_uint), which may not be supported on low-end hardware.
  • CPU-to-GPU Upload Times: Increasing batch size reduces the total number of draw calls, but it increases the time spent uploading vertex buffers to the GPU in a single chunk. If your application rarely fills large buffers, a high batch size wastes CPU memory.
  • Texture Paging Limits: A batch breaks not only when the vertex limit is reached, but also when the number of bound textures exceeds the GPU's MAX_TEXTURE_IMAGE_UNITS limit. Increasing vertex capacity will not prevent batch breaks caused by referencing too many unique sprite textures.
