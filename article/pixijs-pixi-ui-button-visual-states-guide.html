PixiJS @pixi/ui Button Visual States Guide

This article provides an overview of how the Button component in @pixi/ui manages hover, down, and disabled visual states in Pixi.js applications. It covers the underlying interaction model, how event hooks trigger visual transitions, the role of the enabled property for disabled handling, and how extended components like FancyButton streamline state management with declarative configurations.

The Button Architecture in @pixi/ui

The base Button class in @pixi/ui acts as a state controller that wraps a standard Pixi.js Container (such as a Sprite or Graphics object). Rather than hardcoding visual rendering directly into the component, Button binds to Pixi's interaction system (eventMode and pointer events) and emits internal state signals. You can either manually react to these signals to mutate the button's appearance or use the bundled FancyButton class, which handles visual switching automatically.

Handling the Hover State

The hover state represents the moment an input device's pointer enters and remains within the button's hit area.

  • Pointer Event Binding: When initialized, Button listens to pointerover and pointerout events on its target view.
  • Signals and Callbacks: Entering the view triggers the onHover signal, while exiting triggers onOut.
  • Visual Updates: In standard Button usage, you hook into these events to modify properties like tint, scale, or child visibility:
const button = new Button(view);

button.onHover.connect(() => {
    view.tint = 0xdddddd;
});

button.onOut.connect(() => {
    view.tint = 0xffffff;
});

Handling the Down (Pressed) State

The down state reflects an active click or touch press prior to release.

  • Interaction Tracking: The button captures pointerdown and checks for matching releases via pointerup or pointerupoutside.
  • Signals and Callbacks: Pressing the button dispatches onDown, while releasing the press dispatches onUp (and onPress if the pointer was released inside the original hit area).
  • Visual Feedback: A typical implementation applies an offset or a slight downscale to mimic depth:
button.onDown.connect(() => {
    view.scale.set(0.95);
});

button.onUp.connect(() => {
    view.scale.set(1.0);
});

Handling the Disabled State

The disabled state prevents user interaction while giving clear visual feedback that the action is unavailable.

  • The enabled Property: The Button component features an enabled boolean property.
  • Input Suppression: When enabled is set to false, the component automatically disables interactive events on the underlying container (setting its eventMode to 'none' or blocking internal event processing). Signals like onPress, onDown, and onHover will no longer fire.
  • Visual Representation: You can react to changes in the enabled property to adjust the view's appearance, commonly by reducing opacity or applying a grayscale filter:
button.enabled = false;
view.alpha = 0.5;

Declarative Visual States with FancyButton

To avoid manually writing listener callbacks for every state change, @pixi/ui provides the FancyButton component. It extends Button and accepts dedicated display objects for each visual state:

  • defaultView: The resting, idle appearance.
  • hoverView: Displayed automatically when pointer hover is detected.
  • pressedView: Displayed when the button is actively pressed.
  • disabledView: Displayed when button.enabled = false.

When the state changes, FancyButton toggles the visible property of these corresponding views and can automatically trigger predefined animations (such as scaling or tint transitions) configured in its constructor options.
