How to Benchmark Shader Filter Passes in Pixi.js

Measuring the execution time of individual shader filter passes in Pixi.js requires profiling the GPU directly rather than relying on standard CPU timestamps like console.time or performance.now(). Because WebGL commands are queued and executed asynchronously by the browser and the GPU driver, standard JavaScript timing functions only measure the time it takes to push draw calls to the buffer. To capture the true GPU execution time of an individual filter pass, you must hook into Pixi's internal filter pipeline and utilize the WebGL 2 timer query extension.

The Limitation of Standard Timers

Using performance.now() around a Pixi.js render call only records CPU execution time:

// Inaccurate: Measures CPU dispatch time, not GPU rendering time
const start = performance.now();
renderer.render(stage);
const end = performance.now();

While calling gl.finish() forces the CPU to wait until the GPU completes its commands, doing so stalls the entire rendering pipeline and introduces severe synthetic latency, skewing benchmark accuracy.

Using WebGL 2 Disjoint Timer Queries

The standard method for measuring GPU draw time without stalling the pipeline is the EXT_disjoint_timer_query_webgl2 extension. This extension allows you to place asynchronous timing queries before and after WebGL draw commands.

First, verify that your WebGL context supports the extension:

const gl = app.renderer.gl;
const ext = gl.getExtension('EXT_disjoint_timer_query_webgl2');

if (!ext) {
    console.error('EXT_disjoint_timer_query_webgl2 not supported');
}

Hooking into the Pixi.js Filter System

Pixi.js executes filter passes inside the FilterSystem class (renderer.filter). You can measure individual passes by overriding or wrapping the applyFilter method, which is invoked once for each pass of a filter.

Here is an implementation that monkey-patches renderer.filter.applyFilter to measure the duration of every pass:

function setupPassBenchmarking(renderer) {
    const gl = renderer.gl;
    const ext = gl.getExtension('EXT_disjoint_timer_query_webgl2');

    if (!ext) {
        throw new Error('GPU timer queries are not supported on this browser/device.');
    }

    const originalApplyFilter = renderer.filter.applyFilter;
    const activeQueries = [];

    renderer.filter.applyFilter = function(filter, input, output, clearMode) {
        // Create and start a GPU timer query
        const query = gl.createQuery();
        gl.beginQuery(ext.TIME_ELAPSED_EXT, query);

        // Execute the original filter pass
        originalApplyFilter.call(this, filter, input, output, clearMode);

        // Stop the query
        gl.endQuery(ext.TIME_ELAPSED_EXT);

        // Store query metadata to poll later
        activeQueries.push({
            query,
            filterName: filter.constructor.name,
            timestamp: performance.now()
        });
    };

    // Poll for results asynchronously without blocking rendering
    function pollQueries() {
        for (let i = activeQueries.length - 1; i >= 0; i--) {
            const item = activeQueries[i];
            const available = gl.getQueryParameter(item.query, gl.QUERY_RESULT_AVAILABLE);
            const disjoint = gl.getParameter(ext.GPU_DISJOINT_EXT);

            if (available && !disjoint) {
                const timeElapsedNs = gl.getQueryParameter(item.query, gl.QUERY_RESULT);
                const timeElapsedMs = timeElapsedNs / 1_000_000;
                
                console.log(`[Pass] ${item.filterName}: ${timeElapsedMs.toFixed(3)} ms`);
                
                gl.deleteQuery(item.query);
                activeQueries.splice(i, 1);
            } else if (disjoint) {
                // Timing data is invalid due to a GPU context reset or stall
                gl.deleteQuery(item.query);
                activeQueries.splice(i, 1);
            }
        }
        requestAnimationFrame(pollQueries);
    }

    requestAnimationFrame(pollQueries);
}

// Initialize benchmarking
setupPassBenchmarking(app.renderer);

Isolating Multi-Pass Filters

Some complex filters (such as BlurFilter or custom convolution filters) execute multiple sub-passes sequentially. To benchmark sub-passes individually:

  1. Identify the internal passes within the filter's apply method. For instance, BlurFilter delegates to separate horizontal and vertical passes (BlurFilterPass).
  2. Pass identifiers (such as uniforms or loop indices) to distinguish between passes:
renderer.filter.applyFilter = function(filter, input, output, clearMode) {
    const isHorizontal = filter.uniforms?.uPassDirection === 0;
    const passLabel = `${filter.constructor.name} (${isHorizontal ? 'H' : 'V'})`;

    const query = gl.createQuery();
    gl.beginQuery(ext.TIME_ELAPSED_EXT, query);

    originalApplyFilter.call(this, filter, input, output, clearMode);

    gl.endQuery(ext.TIME_ELAPSED_EXT);

    activeQueries.push({ query, label: passLabel });
};

Browser Security Flags and Considerations

Due to side-channel timing attack mitigations (such as Spectre), browsers place restrictions on timer precision:

  • Chrome: If EXT_disjoint_timer_query_webgl2 returns null, launch Chrome with the following flag for local profiling: 
    chrome.exe --enable-features=enable-webgl-timer-queries
  • Firefox: Navigate to about:config and set webgl.enable-privileged-extensions to true.
  • Resolution Clamping: Even when enabled, values may be rounded to intervals of 1 to 5 microseconds. Ensure you benchmark under a steady rendering load over many frames to calculate a statistically significant average.
