GlProgram vs GpuProgram in Pixi.js

Pixi.js v8 introduces a reactive multi-backend architecture capable of running on both WebGL and WebGPU through a unified rendering interface. Central to this design are the GlProgram and GpuProgram classes, which encapsulate GPU shader logic tailored to each backend. This article breaks down the primary differences between GlProgram and GpuProgram, explaining their target APIs, shading language requirements, resource binding systems, and how Pixi.js integrates them to deliver cross-backend shader support.

Target Rendering Backends

The most fundamental difference between the two classes is the graphics API they target:

  • GlProgram is designed specifically for the WebGL and WebGL 2.0 renderers. It compiles and manages shaders using the traditional OpenGL pipeline.
  • GpuProgram is built specifically for the WebGPU renderer. It interfaces directly with the WebGPU rendering pipeline and handles modern GPU primitives.

Shading Languages

Because WebGL and WebGPU use different shader specifications, GlProgram and GpuProgram consume different shading languages:

  • GlProgram uses GLSL (OpenGL Shading Language): It requires separate vertex and fragment shader strings written in GLSL (typically GLSL ES 3.0 or 1.0 depending on WebGL support).
  • GpuProgram uses WGSL (WebGPU Shading Language): It accepts WGSL source code, combining vertex and fragment entry points within a single WGSL module or through separate designated code blocks.

Resource Binding and Pipelines

The underlying architectures of WebGL and WebGPU manage data buffers and state differently, leading to distinct internal handling within each class:

  • Uniforms and Attributes in GlProgram: WebGL handles uniforms by setting individual uniform locations or using Uniform Buffer Objects (UBOs) in WebGL 2. GlProgram maps directly to a compiled WebGLProgram, handling uniform location lookups, attribute indices, and sampler units typical of the state-machine-driven OpenGL pipeline.
  • Bind Groups and Layouts in GpuProgram: WebGPU requires explicit pipeline layouts and bind groups. GpuProgram structures bindings (buffers, textures, samplers) into group indices compatible with WebGPU's modern pipeline configuration, significantly reducing CPU overhead during draw calls.

Unified Shader Integration

In application code, developers rarely interact with GlProgram or GpuProgram in isolation. Instead, Pixi.js provides a unified Shader class that can accept instances of both classes simultaneously.

When creating a custom shader, you can supply both a glProgram and a gpuProgram to the same Shader definition. Pixi.js will automatically evaluate the active rendering backend at runtime:

  • If the browser or device initializes the WebGPU backend, Pixi.js executes the GpuProgram.
  • If the system falls back to WebGL, Pixi.js runs the GlProgram instead.

This abstraction allows applications to maintain broad compatibility with older devices via GlProgram while fully leveraging the performance improvements and reduced driver overhead of GpuProgram on modern hardware.
