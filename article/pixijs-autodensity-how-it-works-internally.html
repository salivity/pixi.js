PixiJS autoDensity: How It Works Internally

When configured in a PixiJS application, the autoDensity: true setting automatically synchronizes the canvas element's CSS dimensions with its internal rendering resolution. By bridging the gap between physical device pixels and CSS display pixels, this property prevents the canvas from visually expanding or blurring on high-DPI (Retina) displays without requiring manual CSS calculations.

The Problem: Physical Pixels vs. CSS Pixels

An HTML <canvas> element possesses two distinct sets of dimensions:

  1. Drawing Buffer Dimensions (width and height attributes): The internal coordinate space specifying how many physical pixels the GPU draws to.
  2. Display Dimensions (style.width and style.height): The external size of the element on the web page, measured in CSS pixels.

When you configure PixiJS with a resolution greater than 1 (such as window.devicePixelRatio), PixiJS scales up the canvas's drawing buffer so that visuals remain sharp on dense screens. However, by default, the browser treats each unit in the drawing buffer as a CSS pixel. If an 800x600 stage is given a resolution of 2, the drawing buffer expands to 1600x1200 pixels. Without explicit CSS styling, the canvas renders at twice its intended visual size on screen.

The Internal Mechanics of autoDensity

Internally, PixiJS delegates canvas management to its ViewSystem (or the underlying renderer system). The autoDensity boolean directly alters how this system handles canvas sizing during initialization and inside the renderer.resize() method.

When autoDensity is enabled, PixiJS executes the following operations under the hood:

1. Resolution Scaling

PixiJS sets the internal drawing buffer to match the requested logical size multiplied by the resolution factor:

canvas.width = Math.round(screen.width * resolution);
canvas.height = Math.round(screen.height * resolution);

2. Automatic CSS Dimension Assignment

Immediately following the buffer calculation, the ViewSystem checks the autoDensity flag. If autoDensity is true, it writes directly to the canvas's inline style object:

canvas.style.width = `${screen.width}px`;
canvas.style.height = `${screen.height}px`;

By explicitly forcing the CSS width and height back down to the unscaled screen dimensions, the high-resolution internal buffer is compressed into the intended visual space on the page.

3. Continuous Synchronization via resize()

Whenever app.renderer.resize(width, height) is called, the renderer recalculates both internal render targets and re-evaluates the autoDensity condition. If active, it continuously updates canvas.style.width and canvas.style.height to match the newly passed logical dimensions.

What Happens When autoDensity Is false

When autoDensity is set to false (the default behavior in earlier versions), PixiJS completely ignores canvas.style.width and canvas.style.height.

As a result:

  • The canvas relies entirely on external CSS stylesheets or default browser rules.
  • If no external CSS overrides exist, the canvas visually stretches to match the internal pixel dimensions, breaking the intended page layout whenever resolution > 1.
  • Developers must manually calculate and assign canvas.style.width and canvas.style.height whenever the renderer is resized.

Enabling autoDensity: true eliminates this boilerplate by ensuring the DOM presentation size remains anchored to the logical scene size, while the GPU renders at the native hardware resolution.
