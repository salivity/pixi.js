Flipping UV Coordinates on a Pixi.js Texture

This article explains how to flip texture UV coordinates horizontally or vertically in Pixi.js without changing the scale property of a Sprite. You will learn how UV coordinates are structured within Pixi.js textures, how to clone a texture to prevent side effects on other sprites, and how to programmatically swap UV corner points or apply dihedral symmetries (groupD8) to invert the rendered image.

Why Avoid Inverting Sprite Scale?

Setting sprite.scale.x = -1 or sprite.scale.y = -1 is the common way to mirror a sprite, but it alters the transformation matrix of the entire display object. This inversion cascades down to all child display objects, reverses physics collider offsets, and complicates local coordinate calculations. Inverting the UV coordinates directly on the texture flips the visual content without altering the sprite's transform hierarchy.

Understanding Pixi.js UV Mapping

Pixi.js stores UV mapping in a TextureUvs object accessed via texture.uvs. The UV data is stored in a Float32Array named uvsFloat32 containing eight numbers representing four coordinate pairs:

  • (x0, y0): Top-Left
  • (x1, y1): Top-Right
  • (x2, y2): Bottom-Right
  • (x3, y3): Bottom-Left

Because multiple sprites often share the same Texture instance, you should always clone the texture before mutating its UV data.

Method 1: Manually Swapping UV Coordinates

To flip an image horizontally, swap the top-left and top-right coordinates, along with the bottom-left and bottom-right coordinates. To flip vertically, swap the top-left and bottom-left coordinates, along with the top-right and bottom-right coordinates.

import * as PIXI from 'pixi.js';

function getFlippedTexture(sourceTexture, flipX = false, flipY = false) {
    // Clone to avoid mutating the original texture used by other sprites
    const texture = sourceTexture.clone();
    
    // Ensure UVs are computed
    texture.updateUvs();

    const uvs = texture.uvs.uvsFloat32;

    // uvs format: [x0, y0, x1, y1, x2, y2, x3, y3]
    let x0 = uvs[0], y0 = uvs[1]; // Top-Left
    let x1 = uvs[2], y1 = uvs[3]; // Top-Right
    let x2 = uvs[4], y2 = uvs[5]; // Bottom-Right
    let x3 = uvs[6], y3 = uvs[7]; // Bottom-Left

    if (flipX) {
        // Swap left corners with right corners
        [x0, x1] = [x1, x0];
        [y0, y1] = [y1, y0];
        [x3, x2] = [x2, x3];
        [y3, y2] = [y2, y3];
    }

    if (flipY) {
        // Swap top corners with bottom corners
        [x0, x3] = [x3, x0];
        [y0, y3] = [y3, y0];
        [x1, x2] = [x2, x1];
        [y1, y2] = [y2, y1];
    }

    uvs[0] = x0; uvs[1] = y0;
    uvs[2] = x1; uvs[3] = y1;
    uvs[4] = x2; uvs[5] = y2;
    uvs[6] = x3; uvs[7] = y3;

    return texture;
}

// Usage:
const originalTexture = PIXI.Texture.from('character.png');
const flippedTexture = getFlippedTexture(originalTexture, true, false);

const sprite = new PIXI.Sprite(flippedTexture);
// sprite.scale remains (1, 1)

Note: Calling texture.updateUvs() again later on this cloned texture will reset the UV values back to their default layout based on frame and rotate.

Method 2: Using Pixi's Built-in Dihedral Group (groupD8)

Pixi.js features an internal math utility, PIXI.groupD8, to handle square rotations and reflections. Texture.rotate accepts groupD8 flags, which automatically recalibrate the UV coordinates upon calling texture.updateUvs().

import * as PIXI from 'pixi.js';

function createMirroredTexture(sourceTexture, flipX = false, flipY = false) {
    const texture = sourceTexture.clone();

    let rotation = texture.rotate || 0;

    if (flipX) {
        // Mirror horizontally using groupD8
        rotation = PIXI.groupD8.mirrorX(rotation);
    }

    if (flipY) {
        // Mirror vertically using groupD8
        rotation = PIXI.groupD8.mirrorY(rotation);
    }

    texture.rotate = rotation;
    texture.updateUvs();

    return texture;
}

// Usage:
const flippedTexture = createMirroredTexture(baseTexture, true, false);
const sprite = new PIXI.Sprite(flippedTexture);

Using groupD8 preserves changes across internal frame updates because the reflection state is stored directly within the texture's transformation definition rather than as raw array overrides.
