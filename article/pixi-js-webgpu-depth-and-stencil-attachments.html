Pixi.js WebGPU Depth and Stencil Attachments

This article provides a technical overview of how depth and stencil attachments are configured within WebGPU render passes in Pixi.js. It details the setup of custom RenderTarget instances, how WebGPU depth-stencil formats are selected, and the way Pixi.js maps high-level surface properties to low-level GPURenderPassDepthStencilAttachment descriptors, including load, store, and clear operations.

Enabling Depth and Stencil in RenderTarget

In Pixi.js (v8+), WebGPU render passes are governed by the RenderTargetSystem. Rather than requiring you to manually instantiate low-level WebGPU descriptors for every frame, Pixi.js manages attachments through the RenderTarget class.

To enable depth and stencil testing, you must configure a RenderTarget with the corresponding flags enabled:

import { RenderTarget } from 'pixi.js';

const renderTarget = new RenderTarget({
    width: 800,
    height: 600,
    depth: true,
    stencil: true,
});

Setting depth: true and stencil: true instructs Pixi's GpuRenderTargetSystem to allocate a depth-stencil texture alongside the primary color texture.

WebGPU Format Selection

Under the hood, Pixi.js determines the texture format for the depth-stencil attachment. By default, when both depth and stencil are requested, Pixi.js provisions a texture using the standard WebGPU format:

  • depth24plus-stencil8: Used when both depth and stencil buffers are active.
  • depth32float: Typically chosen if only high-precision depth is requested without a stencil buffer.
  • stencil8: Used if solely stencil operations are needed without depth.

Pixi's resource management handles the creation of the GPUTexture with GPUTextureUsage.RENDER_ATTACHMENT, and subsequently creates a GPUTextureView targeted for the render pass descriptor.

Construction of GPURenderPassDepthStencilAttachment

When the WebGPU renderer begins a pass with renderer.renderTarget.bind(renderTarget, clear), Pixi.js constructs the GPURenderPassDescriptor. The depthStencilAttachment property of this descriptor is populated with specific WebGPU instructions:

  1. view: The GPUTextureView created from the render target's depth-stencil texture.
  2. depthClearValue: Defaults to 1.0 (representing the far clipping plane).
  3. depthLoadOp: Configured as 'clear' if a clear flag is passed during the bind call, or 'load' if previous pass contents need to be preserved.
  4. depthStoreOp: Set to 'store' if the depth information needs to be read in later passes or discarded with 'discard' to optimize memory bandwidth when depth is transient.
  5. stencilClearValue: Defaults to 0.
  6. stencilLoadOp: Evaluated similarly to depth, switching between 'clear' and 'load'.
  7. stencilStoreOp: Set to 'store' or 'discard' depending on whether mask data persists beyond the active pass.

Execution in Custom Pipelines

If you are interacting directly with the underlying WebGPU rendering pipes or shaders via custom render pipelines, depth-stencil states must align with the attachment configuration.

When creating a GPURenderPipeline through Pixi.js, the depthStencil state must match the format of the bound RenderTarget:

const depthStencilState: GPUDepthStencilState = {
    format: 'depth24plus-stencil8',
    depthWriteEnabled: true,
    depthCompare: 'less',
};

If the format specified in your pipeline does not match the format of the attachment generated by the RenderTarget, the WebGPU device will throw a validation error during render pass execution. When rendering with Pixi's standard display tree, these states are automatically synchronized based on active masks and sorting filters.
