How Pixi.js Measures Text with Off-Screen Canvas

This article explains how Pixi.js calculates text dimensions prior to rendering by utilizing an off-screen HTML5 canvas and its 2D rendering context. Pixi.js evaluates font metrics, line breaks, and exact bounding boxes through internal measurement utilities before allocating WebGL textures. Understanding this process highlights how the engine efficiently handles word wrapping, determines accurate vertical baselines, and optimizes texture memory.

The Shared Off-Screen Canvas

Pixi.js creates a single, reusable off-screen HTML5 <canvas> element managed by its text measurement pipeline (primarily encapsulated in the TextMetrics class). Rather than creating and destroying DOM elements repeatedly, Pixi.js reuses this hidden 2D context across all Text objects.

When text measurements are required, Pixi.js synchronizes the off-screen context's font styling to match the target TextStyle:

context.font = textStyle.toFontString();

This step ensures that the font family, font size, weight, and style precisely mirror what will eventually be rendered.

Calculating Vertical Font Metrics

Standard CSS font sizes do not reliably convey the exact visual height, ascent, or descent of glyphs across different operating systems. To solve this, Pixi.js measures vertical metrics using either modern browser APIs or an internal pixel-scanning fallback.

Modern TextMetrics API

In modern environments, Pixi.js reads the advanced properties provided by the standard context.measureText() result. Specifically, it inspects:

  • actualBoundingBoxAscent and actualBoundingBoxDescent
  • fontBoundingBoxAscent and fontBoundingBoxDescent

These properties provide the exact distances from the baseline to the top and bottom of the font's bounding box.

Pixel-Scanning Fallback

When running in environments lacking full TextMetrics bounding box support, Pixi.js renders a test string (typically characters with extreme ascenders and descenders, such as |ÉqÅ) to the off-screen canvas. It then calls context.getImageData() to scan the raw pixel buffer:

  1. It scans rows from top to bottom to locate the highest non-transparent pixel (the font ascent).
  2. It scans rows from bottom to top to locate the lowest non-transparent pixel (the font descent).
  3. It combines these offsets to compute the total font height and baseline offset.

Because pixel reading with getImageData is computationally expensive, Pixi.js caches these font property calculations by font name and size to prevent repeated readbacks.

Measuring Horizontal Line Widths and Word Wrapping

Once vertical metrics are established, Pixi.js calculates the horizontal layout using context.measureText(string).width.

  1. Tokenization: Pixi.js breaks the raw text string into words, characters, or whitespace depending on the configured breakWords and wordWrap settings.
  2. Width Checking: The engine iteratively measures each token's width using measureText().
  3. Line Accumulation: If wordWrap is enabled, tokens are appended to the current line until adding another token exceeds wordWrapWidth. When a threshold is crossed, a line break is inserted.
  4. Letter Spacing: If custom letter spacing is defined in the TextStyle, Pixi.js calculates the width of each character individually and adds the spacing offset to the measured total.

Structuring the Output

The measurement pass compiles its findings into a TextMetrics instance containing:

  • text: The formatted text string (including inserted line breaks).
  • style: The applied TextStyle.
  • lines: An array of individual text lines.
  • lineWidths: An array storing the calculated width of each line.
  • lineHeight: The resolved vertical distance between consecutive baselines.
  • maxLineWidth: The width of the widest measured line.
  • fontProperties: The ascent, descent, and base height metrics.

Preparing the Final Render Target

After measurements are complete, Pixi.js dimensions the final rendering canvas using maxLineWidth and the total text block height (derived from lines.length and lineHeight).

By calculating these bounds on an off-screen context beforehand, Pixi.js ensures the primary canvas is allocated at the exact pixel dimensions required—accounting for resolution scaling and padding—without wasting GPU texture memory or causing glyph clipping during the WebGL upload phase.
