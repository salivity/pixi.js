PixiJS roundPixels: Sub-Pixel Snapping and Batching

In PixiJS, enabling roundPixels forces display objects to align strictly to integer screen coordinates, eliminating the blurriness caused by sub-pixel rendering while keeping sprite batching fully intact. This setting is particularly valuable for retro pixel-art games and crisp UI rendering, as it modifies vertex positions directly in the CPU-side geometry pipeline rather than requiring separate GPU passes or pipeline state changes.

Sub-Pixel Snapping

By default, PixiJS positions visual elements using floating-point coordinates. When a sprite sits on fractional coordinates (such as x: 10.5, y: 20.3), the GPU's texture sampler applies bilinear interpolation across the surrounding screen pixels. While this creates smooth animations, it causes sharp edges to appear soft, fuzzy, or blurred.

Setting roundPixels: true—either globally on the renderer or locally on a container or sprite—forces PixiJS to snap object coordinates to the nearest whole integer pixel during rendering calculations:

  • Visual Sharpness: Sprites and text retain 1:1 pixel fidelity without unwanted anti-aliasing artifacts along their borders.
  • Movement Trade-off: Slow-moving objects may exhibit visual jitter or stair-stepping instead of smooth linear motion, because coordinates must step across whole-pixel increments rather than sliding continuously across sub-pixels.

Effect on Batching

A common concern in WebGL rendering is whether enabling geometric modifiers breaks sprite batching and increases draw calls. In PixiJS, roundPixels has no negative impact on the batch renderer.

  1. CPU-Level Vertex Calculation: PixiJS applies pixel rounding during the vertex transformation phase (calculateVertices). The object’s world transform is evaluated, and the resulting quad positions are rounded to integer values before they are written into the shared vertex buffer.
  2. Uninterrupted Draw Calls: Because the rounding occurs strictly within the coordinate data rather than altering shaders, blend modes, or GPU uniforms, it does not require a pipeline flush. PixiJS packs the rounded vertices into the same batch buffer alongside other objects sharing the same base texture.
  3. Mixed Batching: Even in scenes where some elements have roundPixels: true and others have roundPixels: false, batching efficiency remains preserved. The batcher treats both simply as vertex positions inside the active batch buffer without triggering extra draw calls.

Performance Profile

Enabling roundPixels introduces a negligible CPU overhead because coordinates undergo mathematical rounding (typically via bitwise operations or Math.round) while the vertex buffer is assembled. However, this is offset by consistent GPU performance, as the total number of draw calls, state changes, and texture bindings remains identical to non-rounded rendering.
