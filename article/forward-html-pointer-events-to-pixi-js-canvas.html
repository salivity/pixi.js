Forward HTML Pointer Events to Pixi.js Canvas

When building web applications with Pixi.js, layering standard HTML/DOM elements on top of the WebGL canvas often intercepts clicks, touches, and mouse movements intended for the underlying scene. This guide explains how to forward these pointer interactions seamlessly from an overlying HTML UI layer directly into the Pixi.js canvas, covering both passive CSS-based passthrough and active JavaScript event re-dispatching.

Method 1: CSS Pointer Events (Passive Passthrough)

If your overlay container only hosts UI components (like HUD elements, buttons, or text) and you want empty space to automatically pass interactions through to Pixi.js, the most performant approach is using CSS.

Set the parent overlay to ignore pointer events, and explicitly re-enable them on interactive UI children:

/* The full-screen overlay container */
.ui-overlay {
  position: absolute;
  top: 0;
  left: 0;
  width: 100%;
  height: 100%;
  pointer-events: none; /* Let events fall through to the canvas */
}

/* Interactive elements inside the overlay */
.ui-overlay button,
.ui-overlay .interactive {
  pointer-events: auto; /* Re-enable clicks for actual UI components */
}

With this setup, any click or touch outside interactive elements reaches the Pixi.js canvas naturally without requiring JavaScript interception.

Method 2: Programmatic Event Forwarding

When an HTML element must handle an interaction itself (e.g., custom gestures, dragging, or logging) while simultaneously triggering the underlying Pixi.js scene, you must capture the DOM event and re-dispatch it to the Pixi canvas element.

Pixi.js (v7 and v8) listens directly to standard DOM pointer events on its view (or canvas) element via its internal EventSystem. Dispatching a synthetic PointerEvent to the canvas triggers Pixi's interaction pipeline.

Implementation

const overlayElement = document.getElementById('my-overlay-element');
const pixiCanvas = app.canvas; // In Pixi v7, use app.view

const forwardEvent = (event) => {
  // Prevent duplicate handling if event already targeted the canvas
  if (event.target === pixiCanvas) return;

  // Create a new PointerEvent with matching coordinates and properties
  const forwardedEvent = new PointerEvent(event.type, {
    bubbles: true,
    cancelable: true,
    view: window,
    clientX: event.clientX,
    clientY: event.clientY,
    screenX: event.screenX,
    screenY: event.screenY,
    pointerId: event.pointerId,
    pointerType: event.pointerType,
    isPrimary: event.isPrimary,
    button: event.button,
    buttons: event.buttons,
  });

  // Dispatch directly to the Pixi.js canvas
  pixiCanvas.dispatchEvent(forwardedEvent);
};

// Bind the relevant pointer event types
const eventTypes = ['pointerdown', 'pointermove', 'pointerup', 'pointercancel'];

eventTypes.forEach((type) => {
  overlayElement.addEventListener(type, forwardEvent);
});

Method 3: Direct Hit-Testing via Pixi's EventSystem

If you want to manually trigger Pixi interactions on specific display objects without dispatching native DOM events, you can convert client coordinates and query Pixi's event system directly:

overlayElement.addEventListener('pointerdown', (event) => {
  // 1. Get canvas-relative coordinates
  const rect = app.canvas.getBoundingClientRect();
  const x = event.clientX - rect.left;
  const y = event.clientY - rect.top;

  // 2. Query Pixi's event system for an interactive object at this point
  const hitObject = app.renderer.events.rootBoundary.hitTest(x, y);

  // 3. Manually emit Pixi events if a target is found
  if (hitObject) {
    hitObject.emit('pointerdown', {
      global: { x, y },
      target: hitObject,
    });
  }
});

Summary of Best Practices

  • Use Method 1 (CSS) whenever the UI overlay does not need to intercept clicks in blank areas. It incurs zero JavaScript overhead.
  • Use Method 2 (DOM Re-dispatching) when an HTML element needs to absorb the event visually or logically, but the Pixi.js canvas must still react to the standard pointer lifecycle (pointerdown, pointermove, pointerup).
