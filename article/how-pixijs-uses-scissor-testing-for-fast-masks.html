How PixiJS Uses Scissor Testing for Fast Masks

Scissor testing is a hardware-accelerated WebGL feature that restricts rendering strictly within a defined, axis-aligned rectangular region of the screen. Instead of using complex and performance-intensive stencil buffers or custom shader passes to clip visual elements, PixiJS leverages the native WebGL scissor test to implement rectangular masks. By converting rectangular mask coordinates into screen-space viewport bounds, PixiJS achieves fast, pixel-perfect clipping with virtually zero graphics memory overhead and minimal draw call penalties.

Understanding Scissor Testing

In standard graphics pipelines such as WebGL and OpenGL, scissor testing is a per-fragment operation executed during rasterization. When enabled via gl.enable(gl.SCISSOR_TEST), the graphics processor defines a box using gl.scissor(x, y, width, height).

Any pixel fragments generated outside these rectangular boundaries are discarded immediately before expensive fragment shading, blending, or depth testing take place. Because this culling occurs at the hardware level during the rasterization phase, it requires no additional render passes, textures, or auxiliary framebuffers, making it significantly faster than any alternative masking technique.

The Overhead of Traditional Masking

Masking arbitrary shapes typically relies on one of two techniques in WebGL:

  1. Stencil Masks: The engine renders the mask geometry to a stencil buffer, marks the valid pixels, and renders the masked content against the stencil values. This requires multiple state changes, interrupts geometry batching, and introduces GPU memory overhead for the stencil attachment.
  2. Sprite/Shader Masks: The engine renders the content and the mask into separate textures and composites them with a custom fragment shader, heavily consuming video memory and fill rate.

Both approaches force PixiJS to break its internal sprite batching pipeline, triggering additional draw calls and impacting frame rates when used extensively.

How PixiJS Optimizes Rectangular Masks

PixiJS includes an automated mask management system (MaskSystem) that determines the most efficient masking technique based on the shape of the mask. When an axis-aligned rectangle (such as a PIXI.Rectangle or an unrotated rectangular PIXI.Graphics object) is assigned as a mask, PixiJS routes it through its internal scissor pipeline instead of the stencil buffer.

The process functions through several steps:

  1. Coordinate Transformation: PixiJS calculates the world transform of the target display object and its mask. It maps the local coordinates of the rectangular mask to global WebGL screen-space coordinates.
  2. State Application: Before drawing the masked children, the renderer calls gl.enable(gl.SCISSOR_TEST) and updates gl.scissor() with the calculated screen-space boundaries.
  3. Batch Preservation: Because scissor testing operates as a simple WebGL state change rather than an offscreen render pass or stencil geometry draw, PixiJS can frequently preserve its active sprite batch, avoiding costly context switches.
  4. Scissor Intersection Handling: If rectangular masks are nested inside one another, PixiJS calculates the geometric intersection of the parent and child rectangles in screen space, applying the resulting overlapping area as the active scissor box.
  5. Restoration: Once the masked display objects finish rendering, PixiJS restores the previous scissor state or disables the scissor test entirely via gl.disable(gl.SCISSOR_TEST).

Performance Advantages

By substituting stencil operations with hardware scissor testing, PixiJS delivers three distinct performance benefits:

  • Lower Draw Call Count: Eliminates the pre-pass required to draw mask geometry to a buffer.
  • Preserved Geometry Batching: Sprites within a scissor mask can remain batched together with neighboring elements sharing the same texture atlas.
  • Reduced GPU Fill Rate: Discarding out-of-bounds fragments early in the raster stage saves GPU computational cycles that would otherwise be wasted processing invisible pixels.
