Update Texture Sub-Regions in Pixi.js

Updating a specific pixel region of an existing GPU texture without re-uploading the entire asset is possible in Pixi.js, though it is not the default behavior. Standard methods like texture.update() trigger a full CPU-to-GPU re-upload of the underlying image or canvas source. To modify only a designated sub-region and save bandwidth, you must either draw into a RenderTexture or tap directly into Pixi's low-level WebGL context using texSubImage2D.

Method 1: Using RenderTexture (GPU-Side Updates)

If your update originates from another display object, sprite, or graphical shape, using a RenderTexture is the cleanest approach. Instead of updating raw pixel arrays from the CPU, you can composite new elements directly onto the target texture on the GPU.

By disabling the auto-clear behavior during rendering, Pixi.js will leave existing pixels intact and draw only the specified region:

// Assume 'renderTexture' is an existing RenderTexture
const patchSprite = PIXI.Sprite.from('brush_stamp.png');
patchSprite.position.set(50, 50); // Target region coordinates

// Render the patch into the existing texture without clearing previous pixels
app.renderer.render(patchSprite, {
    renderTexture: renderTexture,
    clear: false
});

This approach avoids transferring raw pixel buffers across the PCIe bus, keeping operations entirely on the GPU.

Method 2: Using WebGL texSubImage2D (CPU-to-GPU Partial Uploads)

If you have raw pixel data in a typed array (such as a Uint8Array) or a small offscreen canvas that you need to push to a specific offset of a larger texture, you must use WebGL's native gl.texSubImage2D function. Pixi.js abstracts WebGL calls through its texture system, but you can bypass this abstraction safely.

Implementation Steps

  1. Bind the target Pixi texture to a WebGL texture unit using Pixi's texture system.
  2. Retrieve the active WebGLRenderingContext.
  3. Call gl.texSubImage2D to write the sub-region data.
function updateTextureRegion(renderer, baseTexture, x, y, width, height, pixelData) {
    const gl = renderer.gl;
    const glTexture = baseTexture._glTextures[renderer.CONTEXT_UID];

    if (!glTexture) {
        // The texture has not been initialized on the GPU yet
        renderer.texture.bind(baseTexture);
    }

    // Bind Pixi's GPU texture explicitly
    gl.bindTexture(gl.TEXTURE_2D, glTexture.texture);

    // Upload only the modified pixel rectangle
    gl.texSubImage2D(
        gl.TEXTURE_2D,
        0,                 // Level of detail (mip level)
        x,                 // X offset within the destination texture
        y,                 // Y offset within the destination texture
        width,             // Width of the sub-region
        height,            // Height of the sub-region
        gl.RGBA,           // Source format
        gl.UNSIGNED_BYTE,  // Source type
        pixelData          // ArrayBufferView or HTMLCanvasElement/ImageBitmap
    );
}

Critical Considerations

  • Mipmapping: If your base texture has mipmaps enabled, texSubImage2D only updates base level 0. You must manually call gl.generateMipmap(gl.TEXTURE_2D) after the update, or disable mipmaps (baseTexture.mipmap = PIXI.MIPMAP_MODES.OFF) on the texture to avoid visual artifacts when scaled down.
  • Context State: Avoid modifying texture parameters or rebinding without returning control, as Pixi.js maintains an internal cache of bound textures to minimize state changes.
  • PixiJS Version Differences: In PixiJS v7 and earlier, textures are accessed via baseTexture._glTextures. In PixiJS v8, the rendering pipeline relies on a unified WebGL/WebGPU abstraction layer (TextureSource), meaning direct WebGL calls require accessing the underlying device context via renderer.backend.gl.
