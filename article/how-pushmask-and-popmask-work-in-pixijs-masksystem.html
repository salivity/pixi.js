How pushMask and popMask Work in PixiJS MaskSystem

This article provides an in-depth look at the internal mechanics of the MaskSystem in PixiJS, focusing on the pushMask and popMask lifecycle. In PixiJS, masking isolates render regions to define visible boundaries for display objects. Internally, the MaskSystem coordinates mask application and removal through an internal state stack, delegating low-level operations to specialized subsystems like stencil, scissor, and sprite masking. By managing WebGL contexts and state reversions through push and pop routines, PixiJS ensures nested masks render correctly without manual shader or buffer state management.

The Role of the Mask Data Stack

At the heart of the MaskSystem is an internal stack, typically maintained as an array of MaskData objects. Whenever a display object with an assigned mask is encountered during the render pass, PixiJS does not immediately execute raw WebGL clipping. Instead, it encapsulates the mask's parameters, type, and target into a MaskData instance and pushes it onto the maskStack.

The stack structure allows PixiJS to support arbitrary levels of nesting. Because child elements can possess their own masks distinct from their parents, each entry on the stack preserves the preceding rendering state so it can be restored when traversing back up the scene graph.

The pushMask Execution Flow

When push(target, mask) or pushMask(maskData) is invoked, the MaskSystem executes a multi-step sequence:

  1. Detection and Normalization: The system detects whether the input mask is a Graphics object, a Sprite, or a pre-configured MaskData wrapper. If it is a raw display object, the system wraps it or retrieves its cached MaskData, resolving its specific mask type: SCISSOR, STENCIL, SPRITE, or COLOR.
  2. State Push: The resolved MaskData is appended to the internal maskStack. The MaskSystem tracks the current depth index, which directly influences GPU states like stencil buffer levels.
  3. Subsystem Delegation: Rather than executing GL commands directly, the MaskSystem delegates execution to the corresponding specialized system based on the mask type:
    • Scissor Masks: The system calculates the screen-space bounding box of the mask object. If nested within an existing scissor mask, it computes the intersection of the current rectangle and the parent rectangle, then applies gl.scissor via the ScissorSystem.
    • Stencil Masks: The StencilSystem configures gl.stencilFunc and gl.stencilOp. It renders the mask geometry directly to the stencil buffer, incrementing the stencil reference value. Subsequent draw calls for the masked object are configured to only pass where the stencil buffer matches this current reference level.
    • Sprite/Color Masks: The SpriteMaskFilter is bound. PixiJS reroutes rendering to a temporary render texture or prepares a custom filter pass where the alpha channel of the mask texture modulates the color output of the target container.

The popMask Execution Flow

Once the masked target and its children finish rendering, PixiJS calls pop(target) or popMask(). This operation unwinds the changes made during the corresponding push phase:

  1. Stack Retrieval: The MaskSystem pops the most recent MaskData off the maskStack.
  2. Subsystem Teardown: The mask's specific subsystem reverses its operations:
    • Scissor Masks: The previous scissor rectangle (if another scissor mask exists lower in the stack) is recalculated and restored. If the stack is empty, scissor testing (gl.disable(gl.SCISSOR_TEST)) is turned off.
    • Stencil Masks: The StencilSystem writes back over the mask geometry or updates the stencil test comparison reference to match the parent mask level. It decrements the active stencil level, disabling gl.STENCIL_TEST entirely if the stack returns to zero.
    • Sprite/Color Masks: The temporary filter pass completes, drawing the composited result back to the main framebuffer or previous render target, and detaching the custom mask filter.
  3. State Resynchronization: WebGL pipeline states—such as color masks, blend modes, and active framebuffers—are resynchronized to match the state expected by the outer container.

Handling Mask Types and Nested Complexity

The interplay between pushMask and popMask guarantees that different masking techniques can coexist. If a developer places a stencil mask inside a scissor mask, the MaskSystem handles the hierarchy cleanly: the outer scissor restricts the rasterization boundary, while the inner stencil restricts pixel rendering within that boundary. By abstracting GPU state changes into push and pop lifecycles, PixiJS maintains rendering accuracy and avoids state leakage between unrelated render tree nodes.
