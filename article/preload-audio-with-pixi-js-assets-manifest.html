Preload Audio with Pixi.js Assets Manifest

Managing game assets in modern Pixi.js applications is streamlined through the unified Assets manager. By integrating the @pixi/sound library, developers can define, bundle, and preload audio files alongside visual resources using a single, centralized manifest. This guide covers how to register audio loaders, configure a unified manifest, preload sound bundles asynchronously, and retrieve loaded sounds for playback.

1. Integrate the Pixi Sound Library

Pixi.js focuses purely on 2D rendering and does not natively decode audio formats in its core engine. To handle audio through the Assets system, you must install and import the official sound library:

npm install @pixi/sound

Importing @pixi/sound in your project automatically registers the audio loader extensions into the global Assets pipeline:

import { Application, Assets } from 'pixi.js';
import { sound } from '@pixi/sound';

Once imported, the Assets resolver recognizes standard audio extensions such as .mp3, .ogg, and .wav.

2. Define the Unified Manifest

A unified manifest organizes multiple asset types into structured bundles. You can specify audio assets alongside spritesheets, textures, and fonts inside the same configuration object.

const manifest = {
  bundles: [
    {
      name: 'game-screen',
      assets: [
        {
          alias: 'background-music',
          src: 'assets/audio/bgm.mp3',
        },
        {
          alias: 'laser-sfx',
          src: 'assets/audio/laser.wav',
        },
        {
          alias: 'hero-texture',
          src: 'assets/sprites/hero.png',
        }
      ]
    }
  ]
};

To support cross-browser compatibility, you can supply an array of formats for a single alias. Pixi's sound loader will automatically detect browser support and select the appropriate source:

{
  alias: 'explosion',
  src: ['assets/audio/explosion.ogg', 'assets/audio/explosion.mp3'],
}

3. Initialize and Load the Bundle

Initialize the Assets manager with your manifest, then load the target bundle using async/await. You can also attach a progress callback to monitor download status for loading screens.

async function loadGameAssets() {
  // Initialize the manifest
  await Assets.init({ manifest });

  // Load the bundle with a progress tracking callback
  const resources = await Assets.loadBundle('game-screen', (progress) => {
    console.log(`Loading: ${Math.round(progress * 100)}%`);
  });

  return resources;
}

4. Access and Play Preloaded Audio

When a bundle resolves, the audio assets are parsed into Sound instances. You can play them directly from the resolved resources object using their aliases, or access them globally using the @pixi/sound utility:

async function startGame() {
  const assets = await loadGameAssets();

  // Play directly from the loaded resources object
  assets['background-music'].play({ loop: true, volume: 0.5 });

  // Play using the global sound registry
  sound.play('laser-sfx', { volume: 0.8 });
}

5. Handling Browser Autoplay Restrictions

Modern web browsers block audio playback until the user interacts with the document. While Assets.loadBundle successfully downloads and decodes the audio files into memory in the background, ensure playback triggers only after an initial user interaction (such as a "Click to Start" button) to prevent muted playback warnings in the console.
