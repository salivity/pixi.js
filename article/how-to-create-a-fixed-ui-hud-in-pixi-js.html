How to Create a Fixed UI HUD in Pixi.js

Creating a Heads-Up Display (HUD) that remains static while the game camera scrolls or zooms requires separating your visual elements into distinct layers. In Pixi.js, the standard and most efficient approach is using multiple PIXI.Container instances: one dedicated to the moving game world and another dedicated to the fixed user interface. This article explains how to structure your scene graph, control camera movement, and maintain proper UI anchoring across different screen sizes.

1. Separate the Game World and the UI Layers

Instead of adding all sprites directly to app.stage, create two separate containers: one for the game world and one for the HUD. Add both containers to app.stage, ensuring the UI container is added last so it renders on top of the game world.

import * as PIXI from 'pixi.js';

const app = new PIXI.Application();
await app.init({ width: 800, height: 600 });
document.body.appendChild(app.canvas);

// Create separate containers
const worldContainer = new PIXI.Container();
const uiContainer = new PIXI.Container();

// Add them to the stage (order determines z-index)
app.stage.addChild(worldContainer);
app.stage.addChild(uiContainer);

2. Populate Each Container

Place all game objects—such as tilemaps, player characters, and enemies—inside worldContainer. Place all static elements—such as health bars, score counters, and minimaps—inside uiContainer.

// Add a game object to the world
const player = PIXI.Sprite.from('player.png');
worldContainer.addChild(player);

// Add a HUD element to the UI layer
const scoreText = new PIXI.Text({
    text: 'Score: 0',
    style: { fill: 0xffffff, fontSize: 24 }
});
scoreText.position.set(20, 20);
uiContainer.addChild(scoreText);

3. Move the World, Not the HUD

To simulate camera movement, adjust the position, scale, or pivot of worldContainer. Because uiContainer remains untouched at coordinates (0, 0), its children will stay locked to the screen viewport.

To follow a player, shift the worldContainer in the opposite direction of the player's movement:

app.ticker.add(() => {
    // Basic camera follow logic
    worldContainer.x = -player.x + app.screen.width / 2;
    worldContainer.y = -player.y + app.screen.height / 2;
});

Alternatively, you can use the pivot property of the worldContainer:

app.ticker.add(() => {
    worldContainer.pivot.x = player.x;
    worldContainer.pivot.y = player.y;
    worldContainer.position.x = app.screen.width / 2;
    worldContainer.position.y = app.screen.height / 2;
});

4. Anchoring UI Elements on Window Resize

While the HUD remains fixed relative to the top-left corner by default, responsive games require UI elements to align with other screen edges (e.g., top-right or bottom-center). When the canvas resizes, update the positions of those specific UI components:

function onResize() {
    // Keep an element anchored to the top-right corner
    healthBar.x = app.screen.width - healthBar.width - 20;
    healthBar.y = 20;

    // Keep an element anchored to the bottom-center
    actionToolbar.x = (app.screen.width - actionToolbar.width) / 2;
    actionToolbar.y = app.screen.height - actionToolbar.height - 10;
}

window.addEventListener('resize', onResize);

By decoupling world coordinates from viewport coordinates through container layering, your HUD maintains its fixed position without requiring manual position calculations each frame.
