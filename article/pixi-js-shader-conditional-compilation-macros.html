Pixi.js Shader Conditional Compilation Macros

Pixi.js fully supports conditional compilation preprocessor macros within its shaders through native WebGL GLSL directives. This article explains how WebGL processes directives like #ifdef, #if, and #define, and demonstrates how to dynamically inject these macros into Pixi.js vertex and fragment shaders to toggle features without incurring runtime performance penalties.

How Conditional Compilation Works in Pixi.js

Pixi.js compiles GLSL (OpenGL Shading Language) source code directly on the client GPU via the browser's WebGL context. Because GLSL includes a built-in C-style preprocessor, standard preprocessor directives function as expected within Pixi.js custom filters and shaders.

Commonly supported GLSL directives include:

  • #define
  • #undef
  • #ifdef / #ifndef
  • #if, #elif, #else, #endif
  • defined()

The preprocessor resolves these conditions before compiling the shader into GPU machine code. Code excluded by preprocessor checks is stripped entirely, meaning disabled features consume zero execution cycles and do not create runtime branch divergence.

Defining Macros Directly in Shader Code

For static behavior, macros can be written directly at the top of your fragment or vertex shader string:

#define ENABLE_BLOOM 1

precision mediump float;
varying vec2 vTextureCoord;
uniform sampler2D uSampler;

void main(void) {
    vec4 color = texture2D(uSampler, vTextureCoord);
    
    #if ENABLE_BLOOM
        color.rgb += vec3(0.2);
    #endif

    gl_FragColor = color;
}

Injecting Dynamic Macros in Pixi.js

Because Pixi.js accepts shaders as plain JavaScript strings, dynamic macros can be injected programmatically before the shader program is initialized.

To toggle features conditionally, prepend #define statements to your shader source:

import { Filter } from 'pixi.js';

const vertexShader = `...`; // Standard Pixi vertex shader
const baseFragmentShader = `
precision mediump float;
varying vec2 vTextureCoord;
uniform sampler2D uSampler;

void main(void) {
    vec4 color = texture2D(uSampler, vTextureCoord);

    #ifdef USE_GRAYSCALE
        float gray = dot(color.rgb, vec3(0.299, 0.587, 0.114));
        color.rgb = vec3(gray);
    #endif

    gl_FragColor = color;
}
`;

function createCustomFilter(enableGrayscale) {
    const macroPrefix = enableGrayscale ? '#define USE_GRAYSCALE\n' : '';
    const finalFragmentSrc = macroPrefix + baseFragmentShader;

    return new Filter(vertexShader, finalFragmentSrc);
}

const grayscaleFilter = createCustomFilter(true);
const defaultFilter = createCustomFilter(false);

Best Practices and Considerations

  1. Directive Placement: Ensure dynamically injected #define directives appear after any #version statement if targeting modern GLSL versions, but before the precision definitions and main function logic.
  2. Recompilation Cost: Changing a preprocessor macro requires creating a new shader program or recompiling an existing one. Avoid changing macros on every frame. For values that change continuously, use WebGL uniforms instead. Use preprocessor macros primarily for feature flags, quality profiles, or platform-specific optimizations.
