PixiJS Geometry Dispose and WebGL Buffer Cleanup

In PixiJS, calling the dispose method on a Geometry object initiates a targeted cleanup process that releases associated WebGL resources from GPU memory. Rather than immediately and aggressively deleting shared assets, dispose detaches the geometry's internal representations from the WebGL context, invalidates cached Vertex Array Objects (VAOs), and signals PixiJS's rendering subsystems to delete the underlying WebGL buffers via native WebGL API commands.

The Disposal Workflow

When geometry.dispose() is executed, the following pipeline clears the allocated WebGL buffers:

  1. Signal Dispatching via Events: The dispose() method triggers an internal 'dispose' event on the geometry instance. The PixiJS GeometrySystem listens for this event across all active renderer contexts.

  2. Vertex Array Object (VAO) Destruction: PixiJS manages WebGL Vertex Array Objects (VAOs) inside its GeometrySystem. When the dispose signal is received:

    • The renderer locates all cached VAO references tied to the geometry's unique ID (geometry.id).
    • The system calls gl.deleteVertexArray(vao) (or the respective WebGL extension method ext.deleteVertexArrayOES in WebGL 1) to destroy the state configurations stored on the GPU.
    • Internal reference maps tracking these VAOs are wiped to release CPU references.

  3. Buffer Dereferencing and Deallocation: A PixiJS Geometry is composed of multiple Attribute instances, each bound to an underlying Buffer (such as position, UV, or index buffers):

    • geometry.dispose() unbinds the attributes and notifies the BufferSystem.
    • For non-shared buffers or buffers explicitly destroyed, the BufferSystem retrieves the context-specific glBuffer (the native WebGL pointer) and executes gl.deleteBuffer(glBuffer).
    • Once gl.deleteBuffer executes, the WebGL implementation marks the VRAM allocation for deallocation, reducing GPU memory overhead immediately.

  4. Cache Invalidation: The renderer clears its internal binding states. If the disposed geometry or any of its associated buffers were currently bound in the WebGL context state cache, the GeometrySystem and BufferSystem reset their active pointers. This guarantees that subsequent draw calls will not attempt to write to or draw from stale WebGL memory addresses.

  5. Garbage Collection Enablement: By severing the links between the JavaScript Geometry instance, the Buffer wrappers, and the native WebGLBuffer references stored inside the context dictionaries, JavaScript's garbage collector can safely reclaim the CPU-side typed arrays (such as Float32Array or Uint16Array), completing total resource release across both CPU and GPU.
