PixiJS updateTransform Mathematical Operations Explained

The updateTransform method in PixiJS is the engine behind hierarchical scene graph positioning, converting local spatial properties like position, scale, rotation, and pivot into a final 2D affine transformation matrix for rendering. This article details the specific mathematical operations executed during this process, covering trigonometric evaluations for orientation and skew, linear offset calculations for pivots, and 3x3 matrix multiplications that cascade transformations down parent-child relationships.

1. 2D Affine Matrix Representation

PixiJS represents transformations using a 3x3 affine transformation matrix tailored for 2D space. Because the bottom row of an affine transform is always [0, 0, 1], PixiJS optimizes memory and computation by storing only the six dynamic values:

\[ \begin{bmatrix} a & c & tx \\ b & d & ty \\ 0 & 0 & 1 \end{bmatrix} \]

  • \(a\): Horizontal scale and cosine component of rotation.
  • \(b\): Vertical shear and sine component of rotation.
  • \(c\): Horizontal shear and negative sine component of rotation.
  • \(d\): Vertical scale and cosine component of rotation.
  • \(tx\): Horizontal translation (X position).
  • \(ty\): Vertical translation (Y position).

2. Trigonometric Evaluation for Rotation and Skew

When computing the local transformation matrix (localTransform), PixiJS evaluates sine and cosine functions against the object's rotation and skew properties.

If skew is zero, standard rotation math applies:

\[ \text{sr} = \sin(\text{rotation}), \quad \text{cr} = \cos(\text{rotation}) \]

When skew values are present, PixiJS calculates combined angles for the X and Y axes independently:

\[ a = \cos(\text{rotation} + \text{skew.y}) \cdot \text{scale.x} \] \[ b = \sin(\text{rotation} + \text{skew.y}) \cdot \text{scale.x} \] \[ c = -\sin(\text{rotation} - \text{skew.x}) \cdot \text{scale.y} \] \[ d = \cos(\text{rotation} - \text{skew.x}) \cdot \text{scale.y} \]

These operations compose rotation, skewing, and scaling into the four linear basis components of the matrix simultaneously.

3. Pivot Point Vector Offsets

The pivot point specifies the origin around which rotation and scaling occur. Mathematically, pivoting shifts the coordinate space before rotating/scaling and restores it afterward. PixiJS achieves this without a secondary matrix multiplication by applying the pivot directly to the translation components (\(tx\) and \(ty\)):

\[ tx = \text{position.x} - (\text{pivot.x} \cdot a + \text{pivot.y} \cdot c) \] \[ ty = \text{position.y} - (\text{pivot.x} \cdot b + \text{pivot.y} \cdot d) \]

This linear combination ensures that the pivot location is properly scaled and rotated relative to the object's anchor before being added to the world position.

4. Matrix Multiplication (Parent to Child Concatenation)

To calculate the object's worldTransform, PixiJS performs matrix multiplication between the parent node's worldTransform (\(P\)) and the current node's localTransform (\(L\)):

\[ W = P \times L \]

Expanding the matrix product for the six affine variables yields the following explicit arithmetic operations:

\[ W_a = L_a \cdot P_a + L_b \cdot P_c \] \[ W_b = L_a \cdot P_b + L_b \cdot P_d \] \[ W_c = L_c \cdot P_a + L_d \cdot P_c \] \[ W_d = L_c \cdot P_b + L_d \cdot P_d \] \[ W_{tx} = L_{tx} \cdot P_a + L_{ty} \cdot P_c + P_{tx} \] \[ W_{ty} = L_{tx} \cdot P_b + L_{ty} \cdot P_d + P_{ty} \]

5. Hierarchical Traversal

Once the current node's worldTransform is calculated, updateTransform recursively propagates this new matrix down through the display list. Each child node receives its parent's updated world matrix, repeating the matrix multiplication step until the entire active scene graph is mapped to absolute screen coordinates.
