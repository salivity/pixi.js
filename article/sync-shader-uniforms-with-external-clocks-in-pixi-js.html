Sync Shader Uniforms with External Clocks in Pixi.js

Synchronizing Pixi.js shader uniforms with external animation clocks allows you to coordinate complex WebGL visual effects with outside timing sources like GSAP, the Web Audio API, or global physics engines. Rather than relying on Pixi.js's internal ticker to advance time-dependent variables, you extract precise elapsed or normalized time values from your chosen external clock and pass them directly into your shader's uniform dictionary on every frame update.

Setting Up the Custom Shader

To control a shader’s playback from an external source, declare a uniform (commonly named uTime) inside your fragment or vertex shader. In Pixi.js, you instantiate a Filter or a Shader using this uniform:

const fragmentShader = `
precision mediump float;
varying vec2 vTextureCoord;
uniform sampler2D uSampler;
uniform float uTime;

void main(void) {
    vec2 uv = vTextureCoord;
    uv.x += sin(uv.y * 10.0 + uTime) * 0.05;
    gl_FragColor = texture2D(uSampler, uv);
}
`;

const waveFilter = new PIXI.Filter(null, fragmentShader, {
    uTime: 0.0,
});

sprite.filters = [waveFilter];

Synchronizing with GSAP

When using GSAP (GreenSock Animation Platform) as your master animation clock, use the gsap.ticker to update the uniform. This ensures that pausing, global time scaling, and frame drops handled by GSAP are mirrored accurately by the shader.

// Synchronizing via GSAP's global ticker
gsap.ticker.add((time, deltaTime, frame) => {
    // 'time' is the total elapsed time in seconds managed by GSAP
    waveFilter.uniforms.uTime = time;
});

If you need the shader tied to a specific GSAP timeline or tween instead of continuous time, tween a custom object or use the onUpdate callback:

const clock = { progress: 0 };

gsap.to(clock, {
    progress: Math.PI * 2,
    duration: 3,
    repeat: -1,
    ease: "none",
    onUpdate: () => {
        waveFilter.uniforms.uTime = clock.progress;
    }
});

Synchronizing with the Web Audio API

For audio-reactive visualizations, the browser's hardware-aligned AudioContext.currentTime serves as the most accurate master clock. Using Pixi's ticker to sample this external clock avoids drift between audio playback and the visual effects:

const audioContext = new (window.AudioContext || window.webkitAudioContext)();

PIXI.Ticker.shared.add(() => {
    // Direct hardware-driven time synchronization
    waveFilter.uniforms.uTime = audioContext.currentTime;
});

Best Practices for Seamless Synchronization

  1. Avoid Pixi Ticker Duplication: If your external framework already runs a main loop (such as Three.js, Phaser, or a custom RAF loop), stop Pixi’s shared ticker using PIXI.Ticker.shared.stop() and manually call app.render() after updating the uniforms in your external loop.
  2. Prevent Floating-Point Precision Loss: Over long sessions, a continuously increasing uTime uniform can cause floating-point precision issues in 32-bit GPU shaders, leading to stuttering. Modulo operations should be applied either on the CPU (time % 3600) or within the shader if continuous looping is required.
  3. Use Normalized Time for Bounded Animations: For transitions, pass a normalized value ranging from 0.0 to 1.0 rather than raw seconds. This decouples the visual logic inside the GLSL code from framerate variations and absolute time scaling.
