Sync Audio Timestamp with PixiJS AnimatedSprite

Synchronizing an AnimatedSprite to an audio track in PixiJS requires binding the animation frame directly to the playback time of the audio source rather than relying on the internal PixiJS ticker. This article explains how to disable automatic sprite playback, read real-time timestamps from an audio element or Web Audio context, and map those timestamps directly to the sprite's frames to prevent audio-visual drift.

The Drift Problem

By default, PIXI.AnimatedSprite updates its frame using its own internal timer and the shared PIXI.Ticker. However, browser rendering loops and audio hardware clocks run independently. Over time, slight variations in frame rate (requestAnimationFrame jitter, tab throttling, or garbage collection pauses) cause standard animations to fall out of sync with playing audio.

To achieve frame-accurate synchronization, the audio clock must act as the single source of truth, and the AnimatedSprite must be manually scrubbed to match that clock.

Step-by-Step Implementation

1. Disable Automatic Sprite Playback

Create the AnimatedSprite with the required textures, but do not call sprite.play(). Set autoUpdate to false or call sprite.stop() immediately after creation to prevent PixiJS from advancing frames automatically.

const frames = [/* array of PIXI.Texture objects */];
const animatedSprite = new PIXI.AnimatedSprite(frames);

// Prevent the sprite from advancing independently
animatedSprite.stop();
animatedSprite.autoUpdate = false;
app.stage.addChild(animatedSprite);

2. Map Timestamp to Frame Index

Determine the total duration of the animation sequence and how it aligns with the audio.

There are two primary methods to map the audio time to the frame index:

  • Fixed FPS Mapping: When an animation runs at a strict frame rate (e.g., 24 FPS) alongside the audio: \[\text{currentFrame} = \lfloor \text{currentTime} \times \text{FPS} \rfloor\]
  • Normalized Duration Mapping: When the animation span must match the entire duration of the audio clip: \[\text{currentFrame} = \left\lfloor \frac{\text{currentTime}}{\text{duration}} \times \text{totalFrames} \right\rfloor\]

3. Update the Sprite in the Render Loop

Attach an update listener to app.ticker. During each render pass, query the audio element's currentTime, calculate the corresponding frame, and set animatedSprite.gotoAndStop(frameIndex).

const audioElement = new Audio('path/to/audio.mp3');
const fps = 24;
const totalFrames = animatedSprite.totalFrames;

// Start playback
audioElement.play();

app.ticker.add(() => {
    if (audioElement.paused || audioElement.ended) {
        return;
    }

    // Calculate current frame index based on audio playback time
    const rawFrame = Math.floor(audioElement.currentTime * fps);

    // Clamp or loop the frame index to prevent out-of-bounds errors
    const targetFrame = rawFrame % totalFrames;

    // Direct assignment via gotoAndStop
    if (animatedSprite.currentFrame !== targetFrame) {
        animatedSprite.gotoAndStop(targetFrame);
    }
});

Handling Audio Latency and Precision

HTML5 Audio vs. Web Audio API

While standard HTMLMediaElement (<audio>) is simple, its currentTime property updates at a lower frequency (often 4 to 60 Hz depending on the browser). For high-precision requirements, such as rhythm games or tight lip-syncing:

  • Use the Web Audio API (AudioContext).
  • Reference audioContext.currentTime against an anchor timestamp recorded when the AudioBufferSourceNode.start() call was executed.
  • Calculate elapsed time via audioContext.currentTime - startTimestamp.

Handling Seeking and Pauses

Because frame selection is derived purely from audio.currentTime, actions like pausing, resuming, or scrubbing the audio track automatically reflect on the AnimatedSprite without requiring additional state logic. When the audio is scrubbed, the next tick updates the sprite to the exact matching frame immediately.
