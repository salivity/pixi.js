Fixing Pixi.js Jitter Far From the Origin

When display objects in Pixi.js travel far from the canvas coordinate origin (0, 0), they often exhibit visible stuttering, shaking, or jittering during movement. This article explains the technical mechanics behind this issue—primarily floating-point precision degradation in both the JavaScript runtime and WebGL shaders—and outlines practical architectural solutions, such as the floating origin pattern, to ensure smooth rendering across large coordinate spaces.

The Root Cause: Floating-Point Precision Degradation

The jitter observed in worldTransform matrices stems from the limitations of the IEEE 754 standard for floating-point arithmetic.

In JavaScript, numbers are stored as 64-bit double-precision floats. While this provides roughly 15 to 17 significant decimal digits, WebGL shaders typically process matrices and vertex positions using 32-bit single-precision floats (highp float), which only offer between 6 and 9 significant decimal digits.

As a display object moves further from (0, 0), the absolute magnitude of its coordinate values increases. Because floating-point numbers allocate a fixed number of bits to the significand (mantissa), larger numbers sacrifice precision in the fractional digits to represent the large integer portion.

When an object has a coordinate value of 1,000,000.0, the minimum incremental step that a 32-bit float can represent without rounding errors is significantly larger than when the coordinate is 1.0. When small sub-pixel translations (e.g., adding 0.1 per frame) are applied to these massive numbers, the values are truncated or rounded up unevenly.

How worldTransform Propagates the Issue

Pixi.js recalculates an object's worldTransform by concatenating the parent container's transform with the child's local transform:

\[\text{worldTransform} = \text{parent.worldTransform} \times \text{localTransform}\]

  1. JavaScript Matrix Multiplication: If a parent container acts as a camera and offsets the world by -1,000,000 while a child is positioned at +1,000,001, the calculation involves subtracting two massive numbers to yield a small screen coordinate (1). Rounding errors at this stage cause minor truncation.
  2. GPU Rasterization: Even if the JavaScript calculations retain acceptable precision, Pixi.js eventually converts the worldTransform matrix into a 32-bit Float32Array to pass to the GPU via uniform buffers. During vertex transformation, the GPU rounds vertex coordinates to the nearest representable 32-bit float, causing display objects to visually snap between discrete steps rather than translating smoothly.

Solutions to Eliminate Coordinate Jitter

1. Implement the Floating Origin Technique

Instead of allowing world coordinates to grow infinitely, use a floating origin (also known as origin rebasing). In this pattern, the player or active camera remains permanently near (0, 0) in Pixi's scene graph. When the camera moves, instead of moving the camera container across the world, you shift the entire world in the opposite direction or reset the origin dynamically whenever the camera moves beyond a predefined threshold.

2. Decouple Simulation Coordinates from Render Coordinates

Maintain your physics and game logic coordinates in an independent simulation layer using standard JavaScript 64-bit numbers. Compute the relative distance between an entity and the active camera before passing coordinates to Pixi.js:

// Good: Keep Pixi's local coordinates small
sprite.x = entity.worldX - camera.worldX;
sprite.y = entity.worldY - camera.worldY;

By ensuring that the coordinates assigned to Pixi.js DisplayObject properties (position.x, position.y) are always relative to the viewport, the values stay small, preserving sub-pixel precision and eliminating GPU rounding jitter.
