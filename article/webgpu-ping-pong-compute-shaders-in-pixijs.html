WebGPU Ping-Pong Compute Shaders in PixiJS

This article provides a comprehensive guide to implementing double-buffered ping-pong rendering techniques using WebGPU compute shaders in PixiJS v8. You will learn the mechanics behind alternating buffer states, how to configure WebGPU storage buffers and compute pipelines within PixiJS, and how to execute iterative GPU simulations—such as Conway’s Game of Life or particle physics—directly within the PixiJS render loop.

Understanding the Ping-Pong Technique

In GPU computing, a compute shader cannot safely read from and write to the same buffer or texture simultaneously without causing race conditions and undefined behavior. The ping-pong (or double-buffering) technique solves this by allocating two identical storage buffers: Buffer A and Buffer B.

  1. Step N: Buffer A acts as the read-only input, and Buffer B acts as the write-only storage output.
  2. Swap: The roles invert.
  3. Step N+1: Buffer B acts as the read-only input, and Buffer A acts as the write-only output.

This alternating pattern allows iterative simulations to run entirely on the GPU over sequential frames without transferring intermediate state data back to the CPU.

Initializing PixiJS with WebGPU

To utilize compute shaders, initialize a PixiJS Application explicitly requesting the WebGPU renderer:

import { Application, Buffer, BufferUsage } from 'pixi.js';

const app = new Application();
await app.init({
    width: 800,
    height: 600,
    preference: 'webgpu',
});
document.body.appendChild(app.canvas);

// Verify WebGPU context
const device = app.renderer.gpu?.device;
if (!device) {
    throw new Error('WebGPU is not supported or not enabled in this PixiJS instance.');
}

Defining the Compute Shader (WGSL)

Write the WGSL compute shader code. It accepts an input buffer for the previous state and an output buffer for the updated state.

const simulationShader = `
struct Particle {
    position: vec2<f32>,
    velocity: vec2<f32>,
};

@group(0) @binding(0) var<storage, read> inputState: array<Particle>;
@group(0) @binding(1) var<storage, read_write> outputState: array<Particle>;

@compute @workgroup_size(64)
void main(@builtin(global_invocation_id) id: vec3<u32>) {
    let index = id.x;
    if (index >= arrayLength(&inputState)) {
        return;
    }

    var p = inputState[index];
    
    // Update position based on velocity
    p.position += p.velocity;

    // Simple boundary collision
    if (p.position.x < 0.0 || p.position.x > 800.0) {
        p.velocity.x *= -1.0;
    }
    if (p.position.y < 0.0 || p.position.y > 600.0) {
        p.velocity.y *= -1.0;
    }

    outputState[index] = p;
}
`;

Creating Buffers and Bind Groups

Instantiate two identical WebGPU storage buffers and populate the primary buffer with initial data. Then, create two distinct bind groups to manage the swapped input and output states.

const PARTICLE_COUNT = 10000;
const particleSize = 4 * Float32Array.BYTES_PER_ELEMENT; // 4 floats: pos.x, pos.y, vel.x, vel.y
const bufferByteLength = PARTICLE_COUNT * particleSize;

// Generate initial particle data
const initialData = new Float32Array(PARTICLE_COUNT * 4);
for (let i = 0; i < PARTICLE_COUNT; i++) {
    initialData[i * 4 + 0] = Math.random() * 800; // x
    initialData[i * 4 + 1] = Math.random() * 600; // y
    initialData[i * 4 + 2] = (Math.random() - 0.5) * 4; // vx
    initialData[i * 4 + 3] = (Math.random() - 0.5) * 4; // vy
}

// Create Buffer A and Buffer B
const bufferUsage = GPUBufferUsage.STORAGE | GPUBufferUsage.COPY_DST | GPUBufferUsage.VERTEX;

const bufferA = device.createBuffer({
    size: bufferByteLength,
    usage: bufferUsage,
});
device.queue.writeBuffer(bufferA, 0, initialData);

const bufferB = device.createBuffer({
    size: bufferByteLength,
    usage: bufferUsage,
});

// Create compute pipeline
const shaderModule = device.createShaderModule({ code: simulationShader });
const computePipeline = device.createComputePipeline({
    layout: 'auto',
    compute: {
        module: shaderModule,
        entryPoint: 'main',
    },
});

// Create ping-pong bind groups
const bindGroupAtoB = device.createBindGroup({
    layout: computePipeline.getBindGroupLayout(0),
    entries: [
        { binding: 0, resource: { buffer: bufferA } },
        { binding: 1, resource: { buffer: bufferB } },
    ],
});

const bindGroupBtoA = device.createBindGroup({
    layout: computePipeline.getBindGroupLayout(0),
    entries: [
        { binding: 0, resource: { buffer: bufferB } },
        { binding: 1, resource: { buffer: bufferA } },
    ],
});

Executing the Ping-Pong Loop

Track the current buffer phase using a frame counter or a boolean flag. During every tick of PixiJS's ticker, dispatch the compute pass using the appropriate bind group before rendering occurs.

let pingPongStep = 0;

app.ticker.add(() => {
    // Determine which bind group to execute
    const isEvenFrame = pingPongStep % 2 === 0;
    const currentBindGroup = isEvenFrame ? bindGroupAtoB : bindGroupBtoA;

    // Encode compute pass
    const commandEncoder = device.createCommandEncoder();
    const passEncoder = commandEncoder.beginComputePass();
    
    passEncoder.setPipeline(computePipeline);
    passEncoder.setBindGroup(0, currentBindGroup);
    
    const workgroupCount = Math.ceil(PARTICLE_COUNT / 64);
    passEncoder.dispatchWorkgroups(workgroupCount);
    passEncoder.end();

    device.queue.submit([commandEncoder.finish()]);

    // Advance buffer toggle
    pingPongStep++;
});

Rendering the Ping-Pong Output

The resulting data from the active output buffer can be rendered directly using PixiJS custom geometry. Because both storage buffers were created with the GPUBufferUsage.VERTEX flag, you can wrap them as PixiJS Buffer instances and update the vertex attributes per frame:

import { Geometry, Mesh, Shader } from 'pixi.js';

// Setup PixiJS Buffers pointing to the GPU buffers
const pixiBufferA = new Buffer({
    data: new Float32Array(PARTICLE_COUNT * 4),
    usage: BufferUsage.VERTEX,
});
// Assign the underlying WebGPU buffers
pixiBufferA._gpuBuffer = bufferA;

const geometry = new Geometry({
    attributes: {
        aPosition: {
            buffer: pixiBufferA,
            stride: 16,
            offset: 0,
            format: 'float32x2',
        },
    },
});

// Update the geometry's buffer pointer dynamically in the ticker
app.ticker.add(() => {
    // Point geometry to the buffer written to in the compute pass
    const activeRenderBuffer = (pingPongStep % 2 !== 0) ? bufferB : bufferA;
    pixiBufferA._gpuBuffer = activeRenderBuffer;
});

By keeping computation and rendering operations within WebGPU memory, performance overhead is minimized, enabling complex mathematical simulations directly inside standard PixiJS scenes.
