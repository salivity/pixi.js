Pixi.js Compressed Texture Mipmap Generation

This article explains the behavior, limitations, and requirements of mipmap generation for hardware-compressed block textures in Pixi.js. Unlike standard uncompressed image formats like PNG or JPEG, hardware-compressed textures (such as BCn, ETC, ASTC, and PVRTC) cannot have mipmaps dynamically generated by the GPU at runtime. Consequently, Pixi.js relies strictly on pre-computed mipmaps packaged directly inside container files like KTX or DDS.

The WebGL Limitation on Compressed Mipmaps

Pixi.js operates on WebGL (or WebGPU in newer versions). In WebGL, runtime mipmap generation is handled via the command gl.generateMipmap(). The WebGL specification explicitly restricts this call to uncompressed color formats.

Because block-compressed textures compress pixels into fixed-size byte blocks (commonly 4x4 texels), the GPU rasterizer cannot arbitrarily downscale these blocks on the fly without decompressing, scaling, and re-compressing them. Re-compressing block data in real time is computationally prohibitive for mobile and desktop GPUs alike. Calling gl.generateMipmap() on a compressed texture format raises an INVALID_OPERATION WebGL error.

How Pixi.js Processes Compressed Textures

Because runtime generation is impossible, Pixi.js handles mipmaps for compressed formats through static asset loading:

  1. Container Parsing: When loading formats such as KTX, KTX2, or DDS via Pixi's compressed texture plugins or asset loaders, the parser reads the header data to check for pre-calculated mip levels.
  2. Sequential Upload: Pixi.js iterates through each pre-computed mip level present in the container file and uploads it sequentially to the GPU using gl.compressedTexImage2D().
  3. Sampler Configuration: If the container file contains a complete mip chain, Pixi.js configures the texture's minification filter to use mipmapping (such as LINEAR_MIPMAP_LINEAR for trilinear filtering).

Behavior When Mipmaps Are Absent

If an asset pipeline generates a compressed texture file containing only the base level (Level 0):

  • Pixi.js uploads only that single base level to video memory.
  • Pixi.js will not attempt to call gl.generateMipmap(), avoiding runtime WebGL errors.
  • The texture sampler must fall back to basic filtering (NEAREST or LINEAR).
  • If a mipmapped minification filter is applied to a texture lacking a mip chain, WebGL will render the texture as incomplete (often resulting in a black texture or fallback behavior depending on the driver).

Implementation Workflow for Developers

To achieve smooth minification and eliminate texture aliasing with compressed formats in Pixi.js, you must bake mipmaps during your build pipeline:

  • Bake Offline: Use CLI tools like toktx, basisu, or texture compressors from hardware vendors (such as ARM, Imagination, or AMD) with mipmap flags enabled (e.g., --genmipmap).
  • Choose the Right Container: Store the compressed textures in KTX, KTX2, or DDS containers that retain the full mip chain hierarchy.
  • Verify Pixi.js Settings: Ensure your Pixi.js asset configuration enables mipmapping on the resulting base texture, allowing the WebGL context to sample from the pre-uploaded smaller levels as objects move away from the camera.
