Fix PixiJS Stencil Buffer Leaks by Destroying Masks

In PixiJS, complex masking operations rely on the WebGL stencil buffer to restrict rendering to specific geometric bounds. When masked objects are removed from the display list without explicitly detaching and destroying their associated mask instances, references remain trapped within PixiJS's rendering pipeline and the GPU's memory. This guide details why stencil buffer leaks occur and outlines the precise sequence required to unbind, remove, and destroy masks to ensure complete WebGL resource deallocation.

Why Stencil Buffer Leaks Occur

PixiJS uses a dedicated MaskSystem internally to track and push stencil states onto the WebGL context. When you assign a Graphics object to a display object's mask property (target.mask = myMask), PixiJS flags that object for stencil operations.

Simply calling container.removeChild(target) or removing the mask from the scene hierarchy does not tell the MaskSystem that the stencil resource is no longer needed. The target retains a reference to the mask, and the underlying WebGL stencil state and geometry buffers remain allocated in VRAM. Over time, recurring dynamic masks will exhaust available buffer states, causing visual artifacts, frame drops, or context loss.

The Complete Mask Cleanup Sequence

To cleanly free GPU memory and release stencil resources, follow a strict three-step order: detach the mask reference, remove the mask from the scene hierarchy, and destroy the underlying GPU data.

1. Detach the Mask Reference

First, remove the link between the masked display object and the mask object itself. This informs the MaskSystem to bypass the stencil pass for that target:

// Remove the reference from the masked object
target.mask = null;

2. Remove the Mask from the Display Hierarchy

If the mask was added to a Container to ensure it transforms with the target or scene, remove it from its parent:

if (maskGraphics.parent) {
    maskGraphics.parent.removeChild(maskGraphics);
}

3. Destroy the Mask Object and GPU Buffers

Call .destroy() on the mask. Passing options ensures that graphics geometries, WebGL buffers, and textures are purged from the GPU:

// For a Graphics-based mask
maskGraphics.destroy({
    children: true,
    texture: true,
    baseTexture: true
});

If you are using a Sprite as a mask (alpha masking or custom stencil), destroying the sprite requires specifying whether to destroy the texture:

// For a Sprite-based mask
maskSprite.destroy({
    children: true,
    texture: true // Set to false if the texture is shared across other sprites
});

Reusable Cleanup Helper Function

To prevent boilerplate duplication, use a dedicated disposal function that handles both the target and the mask simultaneously:

function disposeMaskedObject(target) {
    if (!target) return;

    // Handle mask cleanup
    if (target.mask) {
        const mask = target.mask;

        // 1. Unlink mask
        target.mask = null;

        // 2. Remove mask from parent if attached
        if (mask.parent) {
            mask.parent.removeChild(mask);
        }

        // 3. Destroy mask resources
        mask.destroy({
            children: true,
            texture: true,
            baseTexture: true
        });
    }

    // Remove and destroy the target display object
    if (target.parent) {
        target.parent.removeChild(target);
    }
    target.destroy({ children: true });
}

Handling Reusable Masks

If your application dynamically switches masks or reuses a single Graphics mask across multiple containers:

  • Do not destroy the mask between switches: Set target.mask = null to detach it, assign it to the new target (newTarget.mask = reusableMask), and only call .destroy() when the entire scene or view is unloaded.
  • Clear graphics data before redrawing: If you modify a mask's shape dynamically, call maskGraphics.clear() before redrawing geometry. This prevents accumulating stale geometry vertices in memory.
