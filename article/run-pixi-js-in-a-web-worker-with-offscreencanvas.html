Run Pixi.js in a Web Worker with OffscreenCanvas

Running Pixi.js inside a Web Worker via the OffscreenCanvas API offloads rendering pipelines and heavy visual computations from the browser's main execution thread. By decoupling rendering from the DOM, your application maintains a smooth 60 or 120 FPS frame rate even when the main thread experiences heavy JavaScript execution or garbage collection pauses. This guide explains how to transfer canvas control to a background worker, initialize Pixi.js within that worker, and handle common requirements like resizing and event handling.

1. Transfer the Canvas on the Main Thread

To render off the main thread, select an HTML <canvas> element and call transferControlToOffscreen(). This transfers ownership of the canvas rendering context, producing an OffscreenCanvas instance that can be transferred to a Web Worker via postMessage.

// main.js
const htmlCanvas = document.getElementById('renderCanvas');
const offscreen = htmlCanvas.transferControlToOffscreen();

const worker = new Worker('worker.js', { type: 'module' });

// Send the offscreen canvas to the worker
worker.postMessage(
  {
    type: 'INIT',
    canvas: offscreen,
    width: window.innerWidth,
    height: window.innerHeight,
    resolution: window.devicePixelRatio || 1,
  },
  [offscreen] // Transferred objects must be included in the transfer list
);

// Forward resize events to the worker
window.addEventListener('resize', () => {
  worker.postMessage({
    type: 'RESIZE',
    width: window.innerWidth,
    height: window.innerHeight,
  });
});

Once transferred, any attempt to obtain a rendering context on the main thread for that canvas will throw an exception.

2. Initialize Pixi.js in the Worker

Inside the worker, import Pixi.js and use the received OffscreenCanvas as the render target. Pixi.js (v7 and v8) supports OffscreenCanvas out of the box.

// worker.js
import { Application, Graphics } from 'pixi.js';

let app;

self.onmessage = async (event) => {
  const { type } = event.data;

  if (type === 'INIT') {
    const { canvas, width, height, resolution } = event.data;

    app = new Application();

    await app.init({
      canvas: canvas,
      width: width,
      height: height,
      resolution: resolution,
      autoDensity: true,
      backgroundColor: 0x1099bb,
    });

    // Create a sample rotating rectangle
    const rect = new Graphics()
      .rect(-50, -50, 100, 100)
      .fill(0xff1010);

    rect.x = app.screen.width / 2;
    rect.y = app.screen.height / 2;
    app.stage.addChild(rect);

    app.ticker.add((ticker) => {
      rect.rotation += 0.02 * ticker.deltaTime;
    });
  }

  if (type === 'RESIZE') {
    const { width, height } = event.data;
    if (app) {
      app.renderer.resize(width, height);
    }
  }
};

3. Handling User Input and Events

Because Web Workers lack direct access to the DOM, Pixi's default event manager cannot directly listen for browser events like pointerdown, pointermove, or keydown. User interaction must be captured on the main thread and serialized across the worker boundary.

Forward input events from the main thread:

// main.js
htmlCanvas.addEventListener('pointerdown', (e) => {
  worker.postMessage({
    type: 'POINTER_DOWN',
    clientX: e.clientX,
    clientY: e.clientY,
    button: e.button,
  });
});

Consume the event inside the worker:

// worker.js
if (type === 'POINTER_DOWN') {
  const { clientX, clientY } = event.data;
  // Map coordinates to your scene or interact with stage elements manually
}

For full interactive support, configure Pixi's EventSystem using an emulation wrapper or map incoming coordinates directly to display objects using app.stage.hitTest(x, y).

4. Asset Loading Considerations

When loading assets like images inside a worker, standard DOM Image objects are unavailable. Use fetch() along with createImageBitmap() to parse textures, or rely directly on Pixi's built-in Assets manager, which handles off-screen environments automatically:

import { Assets, Sprite } from 'pixi.js';

// Works inside Web Workers natively
const texture = await Assets.load('path/to/texture.png');
const sprite = new Sprite(texture);
app.stage.addChild(sprite);
