Pixi.js getBounds in Nested Containers

In Pixi.js, the getBounds method calculates the total axis-aligned bounding box (AABB) of a display object and all of its descendants relative to the world coordinate space. This article explores the underlying mechanics of this calculation, detailing how Pixi.js updates transformation matrices down the display tree, calculates local bounds on leaf nodes, transforms coordinate vertices to world space, and aggregates these points into a single composite bounding rectangle.

1. Updating the World Transform Hierarchy

Before bounds can be calculated across deeply nested containers, Pixi.js must ensure that every object’s spatial position reflects its ancestors' movements. Pixi.js relies on an affine transformation matrix represented by the Matrix class.

When getBounds() is called, it typically triggers a check of the transform hierarchy:

  • Each container maintains a localTransform based on its own position, scale, rotation, pivot, and skew.
  • Each container also stores a worldTransform, which is computed by multiplying the parent's worldTransform by the child’s localTransform:
    \[\text{worldTransform} = \text{parent.worldTransform} \times \text{localTransform}\]
  • In deeply nested trees, Pixi traverses downward from the highest relevant ancestor, updating stale matrices so that every leaf node has an accurate world transform relative to the root canvas.

2. Recursive Traversal of the Scene Graph

Once transformations are verified, Pixi.js executes a recursive traversal through the display hierarchy starting from the container calling getBounds.

  • Non-renderable checks: The engine inspects properties like visible, renderable, and whether a child is active. Containers or objects configured to be ignored during bounds calculations are skipped to optimize performance.
  • Recursion through children: For every valid child, Pixi.js calls the internal bounds calculation method, passing a shared Bounds instance downward.

3. Vertex Extraction at Leaf Nodes

The recursion terminates at leaf nodes—renderable objects such as Sprite, Graphics, Mesh, or Text. These objects know their own intrinsic geometries:

  • A Sprite computes its four corner vertices based on its texture dimensions, anchor point, and trim data.
  • A Graphics object queries its underlying geometry paths and shapes.
  • A Mesh provides access to its raw vertex buffer.

These local coordinates define the untransformed footprint of the element.

4. Transforming Vertices to Global Space

Once a leaf node identifies its local vertices, it does not simply use its width and height. Because ancestors may introduce rotation, scale, or skew, the local vertices must be projected into the target coordinate space.

The leaf object takes each local point \((x, y)\) and multiplies it by its computed worldTransform:

\[x_{\text{world}} = a \cdot x + c \cdot y + tx\] \[y_{\text{world}} = b \cdot x + d \cdot y + ty\]

This operation maps the exact positions of all four corners (or all vertices in a custom mesh) into world coordinates, correctly accounting for all inherited rotations, scaling, and translations from every parent container in the chain.

5. Merging into an Axis-Aligned Bounding Box (AABB)

As the transformed vertices are produced, they are fed into the shared Bounds object. The Bounds class does not store rotated geometry; instead, it expands an axis-aligned bounding box defined by four scalar values: minX, minY, maxX, and maxY.

For every transformed point \((x_{\text{world}}, y_{\text{world}})\):

  • minX = Math.min(minX, x_world)
  • minY = Math.min(minY, y_world)
  • maxX = Math.max(maxX, x_world)
  • maxY = Math.max(maxY, y_world)

This expansion happens continuously as the traversal moves through sibling nodes and across nested container boundaries.

6. Output Generation

After the entire subtree has been visited and all leaf vertices have expanded the Bounds object, Pixi.js constructs a Rectangle object representing the final result:

  • x = minX
  • y = minY
  • width = maxX - minX
  • height = maxY - minY

This returned rectangle encapsulates the entirety of the nested display tree, correctly enclosed within a single global bounding box.
