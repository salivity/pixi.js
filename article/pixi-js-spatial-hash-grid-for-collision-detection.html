Pixi.js Spatial Hash Grid for Collision Detection

This article explains how to build and integrate a 2D spatial hash grid in Pixi.js to accelerate broad-phase collision detection. By partitioning a 2D game world into a uniform grid of cells, you can map display objects to spatial keys, reducing collision check complexity from \(O(n^2)\) to near \(O(n)\). You will learn the mechanics of spatial partitioning, how to write a reusable grid class, and how to query it inside Pixi.js's application ticker to keep your frame rates steady even with thousands of moving sprites.

The Problem with Pairwise Checks

A naive collision detection system compares every object against every other object. With \(n\) objects, this requires \(\frac{n(n - 1)}{2}\) checks per frame. While negligible for 50 objects, 1,000 objects require nearly 500,000 checks, leading to severe frame drops.

A spatial hash grid acts as a broad-phase filter. It assigns objects to spatial cells based on their coordinates. When testing an object for collisions, you only compare it against entities occupying the same or adjacent cells, immediately eliminating distant objects from calculations.

Implementing the SpatialHashGrid Class

The spatial hash grid divides the world into fixed-size square cells. Each cell contains an array or set of references to Pixi.js objects currently overlapping that area.

class SpatialHashGrid {
    constructor(cellSize = 64) {
        this.cellSize = cellSize;
        this.grid = new Map();
    }

    // Convert world coordinates to a unique cell key
    _getKey(x, y) {
        const cellX = Math.floor(x / this.cellSize);
        const cellY = Math.floor(y / this.cellSize);
        return `${cellX}:${cellY}`;
    }

    // Clear the grid at the start of each frame
    clear() {
        this.grid.clear();
    }

    // Insert an object across all cells it overlaps
    insert(object) {
        const bounds = object.getBounds();
        const startX = Math.floor(bounds.x / this.cellSize);
        const endX = Math.floor((bounds.x + bounds.width) / this.cellSize);
        const startY = Math.floor(bounds.y / this.cellSize);
        const endY = Math.floor((bounds.y + bounds.height) / this.cellSize);

        for (let x = startX; x <= endX; x++) {
            for (let y = startY; y <= endY; y++) {
                const key = `${x}:${y}`;
                if (!this.grid.has(key)) {
                    this.grid.set(key, []);
                }
                this.grid.get(key).push(object);
            }
        }
    }

    // Query potential collision candidates for a given object
    query(object) {
        const bounds = object.getBounds();
        const startX = Math.floor(bounds.x / this.cellSize);
        const endX = Math.floor((bounds.x + bounds.width) / this.cellSize);
        const startY = Math.floor(bounds.y / this.cellSize);
        const endY = Math.floor((bounds.y + bounds.height) / this.cellSize);

        const candidates = new Set();

        for (let x = startX; x <= endX; x++) {
            for (let y = startY; y <= endY; y++) {
                const key = `${x}:${y}`;
                const cellObjects = this.grid.get(key);
                if (cellObjects) {
                    for (let i = 0; i < cellObjects.length; i++) {
                        const candidate = cellObjects[i];
                        if (candidate !== object) {
                            candidates.add(candidate);
                        }
                    }
                }
            }
        }

        return candidates;
    }
}

Narrow-Phase Collision Checking

The broad phase identifies candidate pairs that might be colliding. You must then run a precise narrow-phase check, such as an Axis-Aligned Bounding Box (AABB) intersection, to confirm actual contact.

function checkAABB(boundsA, boundsB) {
    return (
        boundsA.x < boundsB.x + boundsB.width &&
        boundsA.x + boundsA.width > boundsB.x &&
        boundsA.y < boundsB.y + boundsB.height &&
        boundsA.y + boundsA.height > boundsB.y
    );
}

Integrating with the Pixi.js Ticker

In the render loop, update your sprite positions, clear the spatial grid, repopulate it, and run your collision routines.

import * as PIXI from 'pixi.js';

const app = new PIXI.Application({ width: 800, height: 600 });
document.body.appendChild(app.view);

const cellSize = 64;
const grid = new SpatialHashGrid(cellSize);
const sprites = [];

// Populate scene with sprites
for (let i = 0; i < 500; i++) {
    const sprite = PIXI.Sprite.from(PIXI.Texture.WHITE);
    sprite.width = 16;
    sprite.height = 16;
    sprite.x = Math.random() * app.screen.width;
    sprite.y = Math.random() * app.screen.height;
    sprite.vx = (Math.random() - 0.5) * 2;
    sprite.vy = (Math.random() - 0.5) * 2;
    
    app.stage.addChild(sprite);
    sprites.push(sprite);
}

app.ticker.add(() => {
    // 1. Move objects
    for (const sprite of sprites) {
        sprite.x += sprite.vx;
        sprite.y += sprite.vy;

        // Wall bounces
        if (sprite.x <= 0 || sprite.x >= app.screen.width - sprite.width) sprite.vx *= -1;
        if (sprite.y <= 0 || sprite.y >= app.screen.height - sprite.height) sprite.vy *= -1;
    }

    // 2. Rebuild spatial grid
    grid.clear();
    for (const sprite of sprites) {
        grid.insert(sprite);
    }

    // 3. Query and resolve collisions
    const checkedPairs = new Set();

    for (const sprite of sprites) {
        const potentialColliders = grid.query(sprite);
        const spriteBounds = sprite.getBounds();

        for (const target of potentialColliders) {
            // Prevent duplicate checks between pairs (A-B vs B-A)
            const pairId = sprite.uid < target.uid 
                ? `${sprite.uid}:${target.uid}` 
                : `${target.uid}:${sprite.uid}`;

            if (checkedPairs.has(pairId)) continue;
            checkedPairs.add(pairId);

            // Narrow-phase check
            if (checkAABB(spriteBounds, target.getBounds())) {
                sprite.tint = 0xff0000;
                target.tint = 0xff0000;
            }
        }
    }
});

Performance Tuning

  1. Cell Size Optimization: The ideal cell size is typically 1.5 to 2 times the size of your average object. If cells are too small, objects span too many cells, increasing insertion costs. If cells are too large, each cell contains too many objects, degrading performance back toward \(O(n^2)\).
  2. Minimize Garbage Collection: Using string keys like ${x}:${y} creates temporary strings every frame. In high-performance games, encode coordinates into a single 32-bit integer: (cellX << 16) | (cellY & 0xFFFF) to bypass string allocation.
  3. Static vs. Dynamic Partitioning: If many objects in your world are static obstacles, maintain two grids. Insert static objects once at level load, and only clear and rebuild the dynamic grid on each tick.
