Screen Shake Decay Formula for Pixi.js Cameras

Implementing natural screen shake in a Pixi.js application requires a mathematical decay function to smoothly return the camera container to its resting position after an impact. Rather than relying on simple linear subtraction, the most effective method combines a trauma-based scalar value with non-linear exponential decay and a power function. This article outlines the exact mathematical formulas needed to calculate trauma decay over time and translate it into fluid camera offsets within a Pixi.js render loop.

The Core Formulas: Trauma and Decay

The most natural-feeling screen shake is calculated using a variable called trauma (\(T\)), a normalized float bounded between \(0.0\) and \(1.0\). Trauma decays over time, and the actual screen offset is proportional to a power of \(T\).

1. Trauma Decay Over Time

Trauma should decrease on each frame. While linear decay works, exponential decay feels more organic because it drops rapidly after the initial hit and gradually settles.

Linear Decay Formula: \[T_{new} = \max(0, T - (\text{decayRate} \times \Delta t))\]

Exponential Decay Formula: \[T_{new} = T \times e^{-\lambda \times \Delta t}\] (Alternatively simplified for frame updates: \(T_{new} = T \times \text{factor}^{\Delta t}\) where \(\text{factor} \approx 0.9\))

  • \(T\): Current trauma (\(0 \le T \le 1\)).
  • \(\Delta t\): Delta time in seconds (or fractional frame time).
  • \(\lambda\) or \(\text{decayRate}\): The speed at which the shake dissipates (typically \(1.0\) to \(3.0\)).

2. The Non-Linear Shake Calculation

Translating trauma directly to pixel offset creates a jarring, linear vibration. Squaring or cubing the trauma value creates a steep ramp: large impacts produce heavy shake, while smaller aftershocks remain subtle.

\[\text{Shake} = T^2 \quad \text{or} \quad \text{Shake} = T^3\]

3. Camera Offset and Angle Formulas

To calculate the new coordinates and rotation for the Pixi.js camera container, multiply the calculated shake value by the maximum allowed displacement and a pseudo-random scalar between \(-1\) and \(1\):

\[\text{Offset}_x = \text{MaxOffset}_x \times \text{Shake} \times \text{random}(-1, 1)\] \[\text{Offset}_y = \text{MaxOffset}_y \times \text{Shake} \times \text{random}(-1, 1)\] \[\text{Angle} = \text{MaxAngle} \times \text{Shake} \times \text{random}(-1, 1)\]

  • \(\text{MaxOffset}_x, \text{MaxOffset}_y\): Maximum translational offset in pixels (e.g., \(16\text{px}\)).
  • \(\text{MaxAngle}\): Maximum rotational shake in radians (e.g., \(0.05\text{ rad}\)).

Pixi.js Implementation Example

In Pixi.js, you apply these formulas to the root PIXI.Container representing your camera or game world inside the app.ticker loop:

let trauma = 0;
const decayRate = 1.5; // Trauma lost per second
const maxOffset = 20;  // Max pixel displacement
const maxAngle = 0.05; // Max rotation in radians

// Call this when an explosion or impact occurs
function addTrauma(amount) {
  trauma = Math.min(1.0, trauma + amount);
}

app.ticker.add((ticker) => {
  const dt = ticker.deltaMS / 1000; // Convert to seconds

  if (trauma > 0) {
    // 1. Decay the trauma linearly (or exponentially)
    trauma = Math.max(0, trauma - decayRate * dt);

    // 2. Square the trauma for a smooth falloff curve
    const shake = trauma * trauma;

    // 3. Apply displacement to the camera container
    cameraContainer.x = (Math.random() * 2 - 1) * maxOffset * shake;
    cameraContainer.y = (Math.random() * 2 - 1) * maxOffset * shake;
    cameraContainer.rotation = (Math.random() * 2 - 1) * maxAngle * shake;
  } else {
    // Reset to resting position
    cameraContainer.x = 0;
    cameraContainer.y = 0;
    cameraContainer.rotation = 0;
  }
});

Using \(\text{Shake} = T^2\) ensures that the camera stabilizes quickly without abrupt stopping, while clamping \(T\) between \(0\) and \(1\) prevents excessive shaking when multiple impacts happen simultaneously.
