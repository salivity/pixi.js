How Pixi.js Handles Rotated Object Masking

This article explores how Pixi.js manages masking when target objects or mask shapes are rotated at arbitrary angles. It breaks down the internal rendering pipeline, covering the automatic fallback from hardware scissoring to stencil buffering, matrix coordinate transformations for sprite-based alpha masks, and key performance considerations when working with rotated display hierarchies.

The Role of the World Transform Matrix

Pixi.js manages all positioning, scaling, skewing, and rotation through a 3x3 affine transformation matrix known as the worldTransform. Every DisplayObject updates its world matrix by multiplying its local transformations with those of its parent container.

When a masked target object or the mask itself is rotated at an arbitrary angle, Pixi.js does not calculate boundary intersections using CPU-bound bounding box geometry. Instead, it pushes the calculated transformation matrices directly to the GPU, allowing the rendering pipeline to resolve orientation at the fragment level.

Automatic Fallback from Scissor to Stencil Masking

Pixi.js utilizes two primary methods for geometry-based masking (PIXI.Graphics): hardware scissor testing and the WebGL stencil buffer.

  1. Scissor Testing: For unrotated, axis-aligned rectangular masks, Pixi.js optimizes rendering by utilizing the WebGL scissor test (gl.scissor). Scissor testing limits rendering to a specified screen-aligned rectangular region without using additional buffers.
  2. Stencil Buffer Fallback: Hardware scissoring cannot handle non-orthogonal geometry or arbitrary rotation angles because standard WebGL scissor boxes must remain parallel to the viewport. When Pixi.js detects that a mask or its target container has an arbitrary rotation (or any non-axis-aligned transformation), it automatically falls back to stencil masking.

During stencil masking, Pixi.js draws the mask's transformed vector geometry directly into the WebGL stencil buffer. The stencil buffer writes a reference value to each pixel covered by the rotated shape. The rotated target object is then drawn, and the GPU discards any fragments that do not pass the stencil test. Because this test operates on individual pixels rather than bounding boxes, the mask remains crisp and accurate regardless of the angle.

Sprite Masking and Matrix Inversion

When using a texture or a sprite as a mask (PIXI.Sprite), Pixi.js applies a specialized filter known as the SpriteMaskFilter. This method uses an alpha mask rather than the stencil buffer.

Handling rotation in sprite masking involves relative coordinate mapping inside the fragment shader:

  1. Pixi.js calculates a relative transformation matrix that maps coordinates from the target object’s local space into the mask’s texture coordinate space.
  2. If either the target or the mask is rotated, the SpriteMaskFilter inverts and multiplies their world transform matrices, sending the resulting matrix to the GPU as a uniform.
  3. The fragment shader uses this matrix to sample the mask’s alpha channel at the correct rotated position for every pixel rendered on the target object.

This allows both the mask and the target to rotate independently at arbitrary angles while maintaining accurate pixel alignment.

Performance Implications of Rotated Masks

Rotating a masked object introduces specific performance shifts within Pixi.js:

  • Draw Call Overhead: The transition from a scissor test to a stencil mask requires clearing, writing to, and testing against the stencil buffer, adding state changes and draw calls to the render pass.
  • Batch Breaking: Standard sprite batching is interrupted when stencil buffer operations or filter passes are applied, which can lower frame rates if numerous rotated masks are used simultaneously.
  • Filter Textures: Using rotated sprite masks invokes filter rendering, which requires allocating temporary framebuffers (render targets) depending on the dimensions of the masked content.
