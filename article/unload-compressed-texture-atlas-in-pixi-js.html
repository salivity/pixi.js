Unload Compressed Texture Atlas in Pixi.js

Managing GPU memory effectively is critical for maintaining high performance in WebGL applications. This article explains how to unload a specific compressed texture atlas from Video RAM (VRAM) in Pixi.js to prevent memory leaks and optimize resource consumption, covering both the modern Assets manager and manual texture destruction techniques.

Using the Assets Manager (Pixi.js v7+)

If you loaded the compressed texture atlas using the modern Assets API, the cleanest way to release it from both system memory (RAM) and GPU memory (VRAM) is calling Assets.unload().

Pass the URL or alias of the atlas manifest file (usually a .json file that references the compressed .ktx2, .dds, or .basis file):

await PIXI.Assets.unload('path/to/atlas.json');

When called on an atlas asset, Assets.unload() recursively removes references from the asset cache, destroys all child textures, and destroys the underlying BaseTexture, which instructs WebGL to release the texture buffer from VRAM via gl.deleteTexture().

Manually Destroying the Spritesheet Instance

If you hold a direct reference to the Spritesheet instance, you can unload it directly by invoking its destroy() method. You must pass true to ensure the base texture residing on the GPU is also destroyed:

// Retrieve your spritesheet reference
const sheet = PIXI.Assets.get('path/to/atlas.json');

// Pass true to destroy the BaseTexture and remove it from VRAM
sheet.destroy(true);

// Remove the entry from the global texture cache if it was manually added
PIXI.utils.clearTextureCache(); // Or PIXI.Texture.removeFromCache(sheet.baseTexture);

The first argument (destroyBase) specifies whether the underlying BaseTexture should be destroyed along with all frame textures. Setting this to true releases the GPU memory allocated for the compressed asset.

Targeting the BaseTexture Directly

In scenarios where you only have access to a specific sub-texture or the raw BaseTexture of the compressed atlas, you can target the base texture directly:

// Access the BaseTexture from any sub-texture of the atlas
const baseTexture = myAtlasSubTexture.baseTexture;

// Destroy the BaseTexture, forcing WebGL to release VRAM
baseTexture.destroy();

When a BaseTexture is destroyed, Pixi.js calls dispose() on its internal GLTexture representations across all active renderers, freeing the hardware texture memory immediately.

Verification of Memory Deallocation

To verify that VRAM has been reclaimed:

  1. Use the Chrome DevTools Memory tab or Task Manager (viewing GPU Memory).
  2. Use WebGL extensions via the browser console to track active WebGL textures by inspecting renderer.gl.getParameter(renderer.gl.TEXTURE_BINDING_2D).
  3. Check renderer.texture.managedTextures (in Pixi.js v7) to confirm the compressed BaseTexture is no longer tracked by the render pipeline.
