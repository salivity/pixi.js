Non-Uniform Scale in PixiJS Scenegraphs

PixiJS handles hierarchical transformations through a chain of 2D affine transformation matrices, propagating non-uniform scaling down deeply nested scenegraphs via recursive matrix multiplication. When a parent container has unequal scaling along its X and Y axes, this distortion naturally compounds with the rotation, skew, and translation of child objects, resulting in affine shear across descending layers. This article explains the internal mechanics of PixiJS's Transform system, the mathematical consequences of nested non-uniform scale, performance handling, and common rendering caveats.

The PixiJS Transformation Pipeline

In PixiJS, every visual node inherits from DisplayObject (or Container), which manages a Transform object. The transformation pipeline relies on two fundamental matrices:

  1. localTransform: A 3x3 affine matrix representing the object's position, scale, rotation, and skew relative to its immediate parent.
  2. worldTransform: A 3x3 affine matrix representing the absolute transformation in screen space, calculated by multiplying the parent's worldTransform with the current node's localTransform.

The 2D affine transform matrix in PixiJS is represented by six values (\(a, b, c, d, tx, ty\)):

\[ \begin{bmatrix} a & c & tx \\ b & d & ty \\ 0 & 0 & 1 \end{bmatrix} \]

Where:

  • \(a\) and \(d\) influence scaling.
  • \(b\) and \(c\) govern skew and rotation.
  • \(tx\) and \(ty\) handle translation.

Matrix Multiplication Down Deep Hierarchies

When updateTransform() runs during the render loop, PixiJS traverses the scene graph from the root downward. The update follows this evaluation order:

Node.worldTransform = Parent.worldTransform * Node.localTransform

Because matrix multiplication is associative, nested transformations accumulate strictly in order from root to leaf. PixiJS does not store separate cumulative scale or cumulative rotation values. Instead, all geometric transformations—including non-uniform scale—collapse directly into the six components of the worldTransform matrix.

Non-Uniform Scale and Shearing

The most significant side effect of non-uniform scale inheritance occurs when a child node is rotated relative to a non-uniformly scaled parent.

In Euclidean geometry, non-uniform scaling stretches space along specific axes. If a parent container has a scale of (2.0, 1.0) and a child container has a rotation of 45°, the child's coordinate space is no longer orthogonal. The matrix multiplication combines the child's rotation with the parent's directional stretch:

  1. The child rotates its local coordinate system.
  2. The parent multiplies this rotated basis by unequal scaling factors.
  3. The resulting transformation creates a shear (skew) distortion.

Because the affine matrix natively supports shear via the off-diagonal entries (\(b\) and \(c\)), PixiJS preserves this mathematical distortion automatically. Every subsequent descendant in the hierarchy will inherit this sheared coordinate system, causing circular shapes to become skewed ellipses and rectangular sprites to render as parallelograms.

Performance and Dirty Flag Propagation

Recomputing matrix chains across deeply nested scenegraphs can become a performance bottleneck. PixiJS optimizes this process using transform IDs and dirty flags:

  • _worldID: An internal integer counter incremented whenever an object's local transform changes.
  • _parentID: Tracks the last known state of the parent's world transform.

During the traversal in updateTransform(), PixiJS compares the parent’s current _worldID with the child's cached _parentID. If neither the child's local properties nor the parent's matrix have changed, the child skips matrix recalculation entirely and passes its existing worldTransform directly to its children.

When a root or intermediate container with non-uniform scale updates, the invalidation cascades down all descendants, forcing each child to re-multiply its local matrix against the new parent matrix.

Practical Implications and Gotchas

  1. Sprite Aspect Ratios: Sprites nested inside non-uniformly scaled containers cannot easily maintain their native aspect ratio if any intermediate ancestor is rotated.
  2. Text Rendering: Text and BitmapText objects inherit the sheared matrix directly on the GPU. This stretches the glyph geometry rather than re-rasterizing the font at a higher resolution, leading to blurred or distorted text edges.
  3. Stroke Weight Distortion: PixiJS Graphics paths rasterize line widths according to the transformation matrix applied at draw time. Non-uniform scale distorts line widths, causing horizontal and vertical strokes to render with different thicknesses.
  4. Hit-Testing and Interaction: Interaction events use worldTransform.applyInverse() to map global pointer coordinates back into the local space of the display object. Because PixiJS uses true affine matrix inversion, hit-testing accounts for non-uniform scaling and shear.
