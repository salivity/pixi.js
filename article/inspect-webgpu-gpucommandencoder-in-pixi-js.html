Inspect WebGPU GPUCommandEncoder in Pixi.js

Inspecting the active WebGPU GPUCommandEncoder in Pixi.js allows developers to debug low-level rendering pipelines, inject custom pass commands, or profile performance. Pixi.js v8 abstracts WebGPU operations behind internal subsystems, but it still exposes the active encoder directly through its renderer systems during the render cycle.

Accessing the Active Command Encoder via renderer.encoder

In Pixi.js v8, the WebGPURenderer delegates low-level command generation to the WebGPUEncoderSystem. The active GPUCommandEncoder is instantiated at the start of a frame and finalized before submission to the device queue.

You can directly access the current command encoder through renderer.encoder.commandEncoder:

const app = new PIXI.Application();
await app.init({ preference: 'webgpu' });

// Ensure the renderer is WebGPU
if (app.renderer.type === PIXI.RendererType.WEBGPU) {
    app.ticker.add(() => {
        // Access during an active render pass
        const commandEncoder = app.renderer.encoder.commandEncoder;
        
        if (commandEncoder) {
            console.log('Active GPUCommandEncoder:', commandEncoder);
        }
    });
}

Because commandEncoder is only active while commands are being recorded, accessing it outside of the render pipeline may return null or an already finished encoder.

Inspecting via Render Lifecycle Hooks

To guarantee the GPUCommandEncoder is captured during active command recording, hook into the renderer’s lifecycle events (prerender and postrender):

app.renderer.on('prerender', () => {
    const encoder = app.renderer.encoder.commandEncoder;
    console.log('Encoder at prerender:', encoder);
});

app.renderer.on('postrender', () => {
    // Inspect right before the queue submits the command buffer
    const encoder = app.renderer.encoder.commandEncoder;
    console.log('Encoder at postrender:', encoder);
});

Intercepting Commands via Prototype Monkey-Patching

Because a GPUCommandEncoder cannot be queried for previously recorded commands natively by WebGPU API design, standard JavaScript property inspection will not show the internal command buffer. To inspect the actual commands being recorded by Pixi.js, intercept the methods on GPUCommandEncoder.prototype:

const originalBeginRenderPass = GPUCommandEncoder.prototype.beginRenderPass;

GPUCommandEncoder.prototype.beginRenderPass = function(descriptor) {
    console.log('Render pass initiated with descriptor:', descriptor);
    return originalBeginRenderPass.apply(this, arguments);
};

const originalFinish = GPUCommandEncoder.prototype.finish;

GPUCommandEncoder.prototype.finish = function(descriptor) {
    console.log('GPUCommandEncoder finished execution:', this);
    return originalFinish.apply(this, arguments);
};

This captures all internal render passes, compute passes, and copy operations executed by Pixi.js during its draw phase.

Using External WebGPU Inspection Tools

For comprehensive frame inspection, monkey-patching can be supplemented with dedicated tooling:

  • Chrome WebGPU Inspector Extension: Captures individual frames, visualizes render and compute passes, and lists the exact encoder commands issued by Pixi.js.
  • Dawn Tracing: If debugging in desktop environments (such as Electron), launching Chromium with the --enable-dawn-features=dump_shaders,record_detailed_timing_in_trace_events flag outputs detailed encoder execution traces to the internal trace viewer.
