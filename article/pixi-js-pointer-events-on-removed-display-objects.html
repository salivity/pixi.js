Pixi.js Pointer Events on Removed Display Objects

When a DisplayObject is removed from the stage in Pixi.js, its attached pointer listeners remain intact in memory, but they immediately stop receiving interaction events because the object is no longer part of the active scene graph. Pixi.js relies on top-down stage traversal to detect pointer hits, meaning detached objects are excluded from the hit-testing pipeline. However, failure to clean up these listeners or properly destroy the object can cause stuck pointer states and prevent garbage collection.

Event Processing and the Scene Graph

Pixi.js processes pointer interactions through its EventSystem (or InteractionManager in older versions). This system listens to native browser pointer events on the canvas and performs hit-testing by traversing the scene graph from the root stage down through its children.

When you call parent.removeChild(displayObject):

  • Hit-Testing Halts: The object is disconnected from the render tree. During pointer movement or clicks, the EventSystem only queries nodes reachable from the stage. Because the detached object is not reached during traversal, pointer events such as pointerdown, pointerup, pointermove, and pointertap will no longer fire.
  • Listeners Persist: Pixi’s DisplayObject inherits from EventEmitter. Calling removeChild() does not invoke removeAllListeners() or detach registered callbacks. The listeners remain registered in the object’s internal event registry.

The Problem of In-Flight Pointer Interactions

If an object is removed while actively being interacted with—such as while a pointer is held down or hovering over it—Pixi.js may not emit the corresponding exit or release events.

  • Missed pointerup and pointerupoutside: If an object is removed between pointerdown and pointerup, it will not receive the terminating pointerup event unless global pointer tracking was explicitly bound to the stage or window.
  • Missed pointerout: If an object is removed while hovered, it may not receive a pointerout event, which can leave custom button states (such as hover tints or scale effects) stuck in their active appearance if re-added later.

Memory Leaks and Proper Cleanup

Because removing a child does not clear its event listeners, keeping a reference to the removed DisplayObject—or creating closures inside the listener callbacks that reference external scopes—prevents the JavaScript garbage collector from reclaiming memory.

To prevent memory leaks and ensure clean removal:

  1. Destroy the Object: If the removed object is no longer needed, call displayObject.destroy({ children: true }). This unregisters all event listeners, clears internal textures/buffers, and cleans up references.
  2. Remove Listeners Manually: If the object will be cached and re-added to the stage later, manually remove active listeners using displayObject.off('pointerdown', handler) or displayObject.removeAllListeners() before disconnecting it from the stage.
