Pixi.js Morph Target Animation with Vertex Buffers

Morph target animation—also known as blend shapes—allows meshes to smoothly deform between different shapes by interpolating between sets of vertex positions. While Pixi.js does not include a dedicated morph target API out of the box, you can achieve this effect by managing custom vertex buffers directly within a PIXI.Mesh and PIXI.Geometry. This article walks through setting up shape key arrays, applying linear interpolation across vertices, and dynamically updating the GPU buffer each frame using the Pixi.js ticker.

1. Requirements for Vertex Buffer Morphing

To implement CPU-driven morph target animation via vertex buffers, you need:

  1. Consistent Topology: Both the base shape and target shape must have the exact same number of vertices and identical index order.
  2. Dynamic Geometry Buffer: A PIXI.Buffer configured to hold the active vertex positions.
  3. Interpolation Loop: A calculation step to compute the intermediate coordinates based on an interpolation weight (typically \(0.0\) to \(1.0\)).

2. Preparing the Vertex Data

Define the vertex positions for both the initial state and the target state. Ensure each array represents pairs of coordinates (\(x, y\)) for a 2D mesh.

// Base shape (e.g., a square)
const baseVertices = new Float32Array([
    -50, -50,
     50, -50,
     50,  50,
    -50,  50
]);

// Target shape (e.g., a diamond/rhombus)
const targetVertices = new Float32Array([
      0, -70,
     70,   0,
      0,  70,
    -70,   0
]);

// The active buffer containing the interpolated values
const currentVertices = new Float32Array(baseVertices.length);
currentVertices.set(baseVertices);

// Triangle indices
const indices = new Uint16Array([
    0, 1, 2,
    0, 2, 3
]);

3. Setting Up the Pixi.js Geometry and Mesh

Wrap the currentVertices array in a dynamic PIXI.Buffer and attach it to a PIXI.Geometry.

// Create the vertex buffer
const vertexBuffer = new PIXI.Buffer(currentVertices, false, false);

// Build geometry
const geometry = new PIXI.Geometry()
    .addAttribute('aVertexPosition', vertexBuffer, 2)
    .addIndex(indices);

// Create the mesh with a basic shader or standard material
const mesh = new PIXI.Mesh(geometry, new PIXI.MeshMaterial(PIXI.Texture.WHITE));
mesh.position.set(app.screen.width / 2, app.screen.height / 2);
mesh.tint = 0x00ffcc;

app.stage.addChild(mesh);

4. Updating the Vertex Buffer in the Render Loop

Linear interpolation (lerp) calculates the position between the base and target vertex positions based on a weight factor t:

\[\text{position} = \text{base} + (\text{target} - \text{base}) \times t\]

Apply this formula across every coordinate in the array inside the app.ticker function, then call the buffer update method to upload the modified data to WebGL.

let progress = 0;
let direction = 1;

app.ticker.add((delta) => {
    // Oscillate progress between 0 and 1
    progress += 0.02 * direction * delta;
    if (progress >= 1) {
        progress = 1;
        direction = -1;
    } else if (progress <= 0) {
        progress = 0;
        direction = 1;
    }

    // Morph vertices
    for (let i = 0; i < currentVertices.length; i++) {
        const base = baseVertices[i];
        const target = targetVertices[i];
        currentVertices[i] = base + (target - base) * progress;
    }

    // Flag the buffer as updated for the GPU
    vertexBuffer.update(currentVertices);
});

Performance Considerations

  • Buffer Allocation: Never instantiate a new Float32Array within the update loop. Mutate the existing array in place to prevent garbage collection spikes.
  • Large Meshes: For meshes with thousands of vertices, executing loops in JavaScript each frame can introduce CPU bottlenecks. For complex geometries, consider moving the interpolation logic into a custom WebGL vertex shader by passing the target positions as a second vertex attribute and adjusting a blend uniform on the GPU.
