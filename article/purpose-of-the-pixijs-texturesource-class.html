Purpose of the PixiJS TextureSource Class

This article provides an overview of the TextureSource class introduced in PixiJS v8, explaining its architectural role in modern 2D rendering. You will learn why PixiJS transitioned away from the legacy BaseTexture system, how TextureSource decouples raw pixel data from UV mapping coordinates, and how it enables seamless support across both WebGL and WebGPU rendering backends.

The Role of TextureSource

In modern PixiJS, TextureSource acts as the foundational wrapper around raw image assets and underlying GPU resources. Whether an asset is an HTMLImageElement, an HTMLCanvasElement, an HTMLVideoElement, or a typed array buffer, it is converted into a TextureSource. Its primary responsibility is to manage the lifecycle, state, dimension metadata, and GPU uploads of the actual pixel data.

Separation of Concerns: Texture vs. TextureSource

PixiJS v8 redesigned its texture architecture to enforce a cleaner separation between pixel data and texture mapping:

  • TextureSource: Represents the physical data. It manages the real width and height, the underlying format, mipmaps, wrap modes, resolution scale, and the binding to WebGL or WebGPU contexts.
  • Texture: Represents a view or sub-rectangle (frame) of a TextureSource. A Texture defines UV coordinates and trimming information, allowing multiple sprite textures—such as frames in a spritesheet—to reference a single TextureSource without duplicating memory on the GPU.

This design completely replaces the older BaseTexture class, simplifying API interactions and aligning the architecture closer to modern graphics standards.

Unification of WebGL and WebGPU

A primary motivation for introducing TextureSource was the integration of WebGPU alongside WebGL in PixiJS v8. Modern graphics APIs handle resource allocation and bindings differently than older pipelines. TextureSource provides a hardware-agnostic interface that:

  1. Standardizes Resource Creation: It abstracts low-level differences between GPUTexture (WebGPU) and WebGLTexture (WebGL).
  2. Optimizes Pipeline Binding: The renderer can create texture groups and bind resources predictably, matching the pipeline-state model required by WebGPU.
  3. Improves Dynamic Updates: Media sources that change over time, such as video streams or interactive canvases, can be flagged as dirty and refreshed using unified update mechanisms that adapt to the active rendering context.

Resource and Lifecycle Management

TextureSource centralizes memory and asset management. When a source is no longer needed, destroying it automatically cleans up the associated textures on the GPU, preventing memory leaks. Additionally, it handles resolution-aware rendering automatically, scaling original assets accurately on high-DPI displays without requiring manual dimension calculations across every dependent Texture instance.
