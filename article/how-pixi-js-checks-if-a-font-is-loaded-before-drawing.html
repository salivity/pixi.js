How Pixi.js Checks If a Font Is Loaded Before Drawing

Rendering custom web fonts accurately in Pixi.js requires verifying that the font glyphs are fully parsed and ready before drawing text to an internal canvas. Pixi.js coordinates between the browser's native CSS Font Loading API, its internal Asset Loader pipeline, and text measurement routines to detect font availability. This article explains the technical steps and detection mechanisms Pixi.js uses to ensure fonts are fully loaded before rendering text.

The Native CSS Font Loading API

In modern versions of Pixi.js, the primary mechanism for loading and verifying font availability is the browser's native CSS Font Loading API (document.fonts).

When loading a web font through the Pixi.js asset loader (Assets.load), Pixi creates a native FontFace object. The loader assigns the font family name and source URL, adds the FontFace to document.fonts, and calls its asynchronous .load() method:

const font = new FontFace(fontFamilyName, `url(${fontUrl})`);
document.fonts.add(font);
await font.load();

By awaiting the resolution of font.load(), Pixi.js guarantees the font data has transitioned from the loading state to the loaded state within the browser's font registry before resolving the asset promise.

Synchronous Verification via document.fonts.check()

When creating a PIXI.Text object with a specified font family outside of the asset loader, Pixi.js does not automatically block rendering. Instead, it queries the font's current availability using document.fonts.check().

The method accepts a CSS font shorthand string (including size and family name):

document.fonts.check(`${fontSize}px "${fontFamily}"`);

If this returns true, the browser confirms the specific font face is loaded and ready for immediate drawing on an HTML5 <canvas>. If it returns false, the browser has not yet completed loading the font, which signals to the rendering pipeline that the font is unavailable.

Canvas Metric Measurement Fallbacks

In environments lacking robust support for document.fonts, or when measuring text baselines and bounding boxes, Pixi.js inspects font metrics using an offscreen canvas (CanvasTextMetrics).

To identify if a custom font has actually taken effect:

  1. Fallback Font Comparison: Text measurement routines render a test string (typically strings containing varied glyph shapes such as BESbswy) using the requested font with a fallback generic family (such as monospace or sans-serif).
  2. Width and Height Probing: The text is measured using CanvasRenderingContext2D.measureText().
  3. Metric Shift Detection: Until the custom web font is ready, the measured dimensions match the default metrics of the fallback family. Once the dimensions deviate to match the custom font's metrics, Pixi.js can confirm that the browser has applied the font to the canvas rendering context.

Text Texture Updates and the Dirty Flag

If a PIXI.Text instance is drawn before its font family is verified as loaded:

  • The 2D canvas context renders the text using the browser's fallback system font to avoid hard crashes.
  • When the font loader finishes loading via document.fonts.ready or the FontFace promise resolves, developers or loader hooks signal the text object by setting text.dirty = true or calling text.updateText().
  • Setting the dirty flag forces Pixi.js to re-measure character dimensions using CanvasTextMetrics, re-render the glyphs to the internal canvas, and re-upload the canvas as an updated GPU texture.
