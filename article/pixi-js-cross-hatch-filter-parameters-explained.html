Pixi.js CrossHatchFilter Parameters Explained

This article provides an overview of the parameters and inner workings of the CrossHatchFilter in PixiJS. It explains the default implementation within the PixiJS filters repository, highlights why the stock filter does not expose direct configuration properties, examines the internal logic driving the visual output, and outlines methods for customizing the effect.

Default Parameters in the Stock Filter

In the official PixiJS filters collection (pixi-filters), the standard CrossHatchFilter does not take any arguments in its constructor and exposes no unique public properties. Instantiating the filter is strictly parameterless:

import { CrossHatchFilter } from 'pixi-filters';

const crossHatch = new CrossHatchFilter();
container.filters = [crossHatch];

Unlike filters such as BlurFilter or ColorMatrixFilter, which provide properties like strength or brightness matrices, the stock CrossHatchFilter relies on hardcoded values in its fragment shader.

The Underlying Shader Logic

The filter works by evaluating the luminance (perceived brightness) of each pixel and drawing diagonal lines across regions depending on how dark they are. The shader evaluates brightness against four predefined threshold levels:

  1. Luminance < 1.00: Draws diagonal lines spaced at 10-pixel intervals in one direction.
  2. Luminance < 0.75: Adds intersecting diagonal lines in the opposing direction to form a basic hatch.
  3. Luminance < 0.50: Adds secondary parallel lines between the existing hatches.
  4. Luminance < 0.30: Fills the darkest regions with dense, tight cross-hatching.

All spacing calculations are based on screen-space coordinates using gl_FragCoord.xy, meaning line width and intervals are locked directly to pixel dimensions.

Controlling and Customizing the Effect

Because the stock class provides no direct uniforms for spacing, angle, or threshold control, you can adjust the effect using the following techniques:

1. Adjusting Filter Resolution

Modifying the filter's resolution property scales the coordinate space used by the fragment shader. Lowering or raising the resolution changes the apparent thickness and frequency of the cross-hatch lines relative to your content:

crossHatch.resolution = 0.5; // Produces thicker, broader hatching

2. Pre-Processing Contrast and Brightness

Preceding CrossHatchFilter with a ColorMatrixFilter allows you to control which parts of your graphic cross the luminance thresholds. By boosting or decreasing brightness and contrast prior to the hatch pass, you dictate where lines appear:

import { ColorMatrixFilter } from 'pixi.js';

const colorMatrix = new ColorMatrixFilter();
colorMatrix.contrast(1.5, false);

container.filters = [colorMatrix, crossHatch];

3. Creating a Custom Hatch Filter

If you need direct parameter control over variables like spacing, line thickness, rotation, or color, the recommended approach is creating a custom Filter with custom GLSL uniforms:

  • Spacing: A uniform float variable replacing the hardcoded modulo step (10.0).
  • Line Thickness: A uniform float determining the threshold width of the drawn line.
  • Hatch Color / Background Color: Uniform vec4 values defining the ink and background colors instead of strict black and white.
