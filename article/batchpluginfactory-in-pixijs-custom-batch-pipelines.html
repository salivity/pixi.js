BatchPluginFactory in PixiJS Custom Batch Pipelines

In Pixi.js, batch rendering minimizes WebGL draw calls by grouping similar objects into a single geometry buffer, but implementing custom shaders or attributes typically requires writing extensive rendering boilerplate. The BatchPluginFactory solves this by automating the creation of specialized batch renderers, handling multi-texture uniform routing, shader template expansion, and buffer management. This article explains the primary role of BatchPluginFactory, the technical problems it resolves, and how it is used to build performant custom batch pipelines.

The Purpose of BatchPluginFactory

By default, Pixi.js routes standard 2D display objects through BatchRenderer, which handles 2D transforms, tinting, UV coordinates, and multi-texture batching. When developers need custom rendering behavior—such as custom vertex attributes, specialized fragment effects, or non-standard blending—they must deviate from the default pipeline.

Building a custom renderer from scratch involves managing complex low-level WebGL operations, including:

  • Dynamic texture unit allocation across different hardware limits.
  • Generating shader code that handles variable numbers of texture samplers.
  • Interleaved buffer uploads and attribute pointer bindings.

BatchPluginFactory acts as a code generator that abstracts these responsibilities. Instead of subclassing BatchRenderer manually, developers pass custom shader code and options into BatchPluginFactory.create(), which outputs a ready-to-use renderer class.

Key Responsibilities

1. Dynamic Multi-Texture Shader Generation

WebGL devices support varying numbers of maximum texture units (typically between 8 and 32). Standard custom shaders cannot hardcode sampler arrays efficiently without limiting hardware compatibility.

BatchPluginFactory automatically processes vertex and fragment shader templates. It dynamically injects the appropriate uniform declarations (such as uniform sampler2D uSamplers[%count%];) and the conditional logic needed to index into the correct active texture on the target GPU.

2. Standardizing Buffer and Geometry Logic

The factory configures the geometry definitions required by the batch pipeline. It ties shader attributes (such as position, texture coordinates, tint colors, and texture indices) to the underlying interleaved float and integer arrays generated by display objects.

3. Reducing Boilerplate

Writing a custom batch pipeline using the factory requires only two primary inputs:

  • A custom vertex shader (or a modified version of the default batch vertex shader).
  • A custom fragment shader containing your specific logic.

The factory bundles these with default batching lifecycles—such as buildDrawCalls, flush, and texture packing—saving hundreds of lines of boilerplate WebGL code.

Implementing a Custom Pipeline

The typical workflow for utilizing BatchPluginFactory follows three steps:

1. Define Custom Shaders

The shader source code utilizes replacement tokens provided by Pixi.js, such as %count%, which the factory replaces with the device-supported texture count:

// Custom fragment shader snippet
varying vec2 vTextureCoord;
varying vec4 vColor;
varying float vTextureId;
uniform sampler2D uSamplers[%count%];

void main(void) {
    vec4 color;
    // %for% loop injected automatically by the batch system
    %for%
    if (vTextureId == %i%.0) {
        color = texture2D(uSamplers[%i%], vTextureCoord);
    }
    %end%
    
    // Apply custom logic (e.g., grayscale effect)
    float gray = dot(color.rgb, vec3(0.299, 0.587, 0.114));
    gl_FragColor = vec4(vec3(gray), color.a) * vColor;
}

2. Generate the Plugin

Pass the shader definitions to the factory:

import { BatchPluginFactory, extensions, ExtensionType } from 'pixi.js';

const CustomBatchRenderer = BatchPluginFactory.create({
    vertex: customVertexShader,
    fragment: customFragmentShader,
    vertexSize: 6 // Number of floats per vertex
});

// Register the custom renderer as a pipeline extension
extensions.add({
    name: 'customBatch',
    type: ExtensionType.RendererPlugin,
    ref: CustomBatchRenderer
});

3. Assign Display Objects to the Pipeline

Any compatible display object (such as a Sprite or custom geometry) is assigned to the newly created pipeline by updating its pluginName property:

const sprite = new Sprite(texture);
sprite.pluginName = 'customBatch';

When the Pixi.js renderer encounters this object, it routes it to the specialized batch pipeline generated by BatchPluginFactory, allowing custom visual effects while retaining optimal multi-texture batching performance.
