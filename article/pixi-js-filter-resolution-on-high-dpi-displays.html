PixiJS Filter Resolution on High-DPI Displays

PixiJS renders visual effects on high-DPI displays by decoupling global canvas scaling from individual post-processing passes through a dedicated resolution property. When rendering on Retina or 4K screens, PixiJS utilizes off-screen framebuffers to compute filter passes. Understanding how the global renderer resolution interacts with the Filter.resolution property is essential to preventing blurry, downsampled effects and balancing GPU performance with visual sharpness.

The High-DPI Rendering Pipeline

High-DPI displays possess a higher physical pixel density than standard displays, typically represented by a window.devicePixelRatio of 2 or higher. In standard operations, the PixiJS Renderer matches this density by multiplying the canvas's internal drawing buffer size by its resolution setting while maintaining the layout dimensions in CSS pixels.

When an object has a filter applied, PixiJS reroutes rendering:

  1. The target display object is drawn to an off-screen render texture instead of directly to the screen.
  2. Fragment shaders execute over this off-screen texture.
  3. The resulting processed texture is composited back into the main scene.

Because this happens off-screen, the visual fidelity of the final output depends entirely on the pixel dimensions of that intermediate render texture.

Filter Resolution vs. Renderer Resolution

Every filter instance in PixiJS has its own resolution property, which defaults to the renderer's global resolution in modern PixiJS versions.

  • Renderer Resolution (renderer.resolution): Determines the scale factor for the primary WebGL context.
  • Filter Resolution (filter.resolution): Controls the pixel density of the intermediate render texture allocated by the FilterSystem.

If a renderer has a resolution of 2 (standard for Retina displays) and a filter attached to an object has a resolution of 1, PixiJS allocates an off-screen texture at standard density. The shader runs on this lower-resolution texture, and the result is upscaled to fit the high-DPI canvas, causing noticeable blurriness, pixelation, or softened edges.

Conversely, setting filter.resolution to match the renderer ensures that the intermediate texture maintains a 1:1 ratio with the physical screen pixels, keeping fine lines, sharp displacements, and text crystal clear.

Dynamic Filter Sizing and Bounds

PixiJS dynamically calculates the bounding box of the display object to determine the size of the temporary render texture. The internal calculation scales the bounding box dimensions by the filter's resolution:

textureWidth = boundsWidth * filter.resolution
textureHeight = boundsHeight * filter.resolution

By clamping the texture size to the precise bounds of the object (plus any specified filter.padding), PixiJS minimizes GPU memory usage on high-DPI viewports. It only allocates the exact pixel area necessary to execute the shader at native density.

Performance Considerations

High-DPI filter rendering quadruples the fragment shader workload when scaling from 1x to 2x resolution (due to width × height scaling). For multi-pass or computationally expensive filters—such as large Gaussian blurs or complex bloom effects—rendering at full native resolution can quickly bottleneck mobile devices and integrated GPUs.

PixiJS allows developers to intentionally downsample expensive filters while keeping the rest of the scene crisp:

  • High-frequency details (ColorMatrix, Outline, Displacement): Keep filter.resolution equal to renderer.resolution (e.g., 2 or window.devicePixelRatio) to preserve sharp edges and pixel precision.
  • Low-frequency details (Blur, Glow, Shadow): Lower filter.resolution to 1 or 0.5. Because blur inherently softens image data, running the shader on a lower-resolution buffer significantly reduces fragment operations with virtually no perceptible loss in visual quality.

Best Practices for Sharp Output

To ensure filters render crisply across all display densities:

  1. Always initialize the Application or Renderer with resolution: window.devicePixelRatio || 1 and autoDensity: true.
  2. Inspect custom or third-party filters to verify that their resolution is dynamically assigned from the renderer rather than hardcoded to 1.
  3. Account for dynamic device ratio changes, such as when a user drags a browser window between standard and high-DPI monitors, by updating the renderer and relevant filter resolutions accordingly.
