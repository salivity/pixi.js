Pixi.js Pivot vs Anchor: Mathematical Differences

In Pixi.js, both pivot and anchor determine the point around which a display object rotates, scales, and positions itself, but they operate on fundamentally different mathematical foundations. While anchor uses normalized ratios to shift the geometry of texture-based objects, pivot uses absolute local pixel values to define the origin of transformation for any container. This article breaks down the mathematical definitions, matrix transformations, and practical calculations governing both properties.

Definitions and Units

The most prominent mathematical difference between the two properties lies in their coordinate systems and unit spaces:

  • pivot (Absolute Pixels): Belongs to the base DisplayObject (or Container). It is defined in unscaled local pixel coordinates \((x, y)\). Setting pivot.set(50, 100) specifies a point exactly 50 units right and 100 units down from the local origin \((0, 0)\).
  • anchor (Normalized Ratio): Belongs specifically to textured objects like Sprite, TilingSprite, and Text. It is a scalar factor, typically ranging from \(0.0\) to \(1.0\). Setting anchor.set(0.5, 0.5) represents 50% of the object's width and 50% of its height.

Mathematical Conversion

Because anchor operates as a normalized scalar, Pixi.js internally translates it into pixel coordinates based on the dimensions of the underlying texture:

\[\text{effective\_anchor}_x = \text{anchor.x} \times \text{texture.width}\] \[\text{effective\_anchor}_y = \text{anchor.y} \times \text{texture.height}\]

If an object has a width of \(200\) and a height of \(100\), an anchor of \((0.5, 1.0)\) mathematically yields:

\[\text{effective\_anchor} = (0.5 \times 200, 1.0 \times 100) = (100, 100)\]

This makes anchor dynamic: if the texture changes size, the offset updates automatically. Conversely, pivot remains fixed at its explicit pixel values regardless of texture dimensions.

Matrix Transformation Mechanics

To understand how both interact during rendering, consider how Pixi.js constructs the local affine transformation matrix (\(M_{local}\)).

The standard local transformation matrix translates the object to its position \((x, y)\), rotates it by angle \(\theta\), scales it by \((s_x, s_y)\), and offsets it by the pivot \((p_x, p_y)\):

\[M_{local} = T(x, y) \cdot R(\theta) \cdot S(s_x, s_y) \cdot T(-p_x, -p_y)\]

Here, the translation by \((-p_x, -p_y)\) is applied before rotation and scaling. Mathematically, this shifts the local coordinate grid so that the point \((p_x, p_y)\) aligns with the origin \((0, 0)\) of rotation and scaling.

Where Anchor Fits in the Pipeline

While pivot directly alters the display object's transform matrix \(M_{local}\), anchor does not modify the transformation matrix itself. Instead, anchor alters the vertex coordinates of the rendered mesh/quad.

For a rectangular sprite of width \(W\) and height \(H\), the quad vertices are calculated directly from the anchor \((a_x, a_y)\):

\[\text{left} = -a_x \times W\] \[\text{right} = (1 - a_x) \times W\] \[\text{top} = -a_y \times H\] \[\text{bottom} = (1 - a_y) \times H\]

These local vertex coordinates are subsequently multiplied by the local transformation matrix \(M_{local}\) (which contains the pivot offset).

Combined Formula

When both properties are used concurrently on a Sprite, the effective transformation applied to the vertex positions is:

\[V_{world} = M_{world} \cdot \left( V_{\text{quad}}(anchor) - \begin{bmatrix} p_x \\ p_y \end{bmatrix} \right)\]

Where:

  • \(V_{\text{quad}}(anchor)\) defines the texture boundaries relative to the origin based on anchor offsets.
  • \(\begin{bmatrix} p_x \\ p_y \end{bmatrix}\) is the pivot vector subtracted prior to rotation and scaling.

In summary, anchor determines how the quad geometry is drawn relative to local \((0,0)\) via texture percentages, while pivot shifts the origin of the coordinate space itself in absolute local units.
