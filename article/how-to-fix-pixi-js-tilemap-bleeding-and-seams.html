How to Fix Pixi.js Tilemap Bleeding and Seams

Tile edge bleeding and visible seams during camera movement in Pixi.js are common rendering artifacts caused by sub-pixel rendering and texture interpolation sampling neighboring texels on a spritesheet. This article breaks down the technical reasons why these flickering lines appear when scrolling tilemaps and provides practical, reliable solutions—including texture extrusion, pixel snapping, texture scale adjustments, and specialized tilemap renderers—to eliminate them entirely.

What Causes Tile Bleeding in Pixi.js?

Tile bleeding typically manifests as thin, flickering gaps or colors from adjacent tiles appearing at the edges of your map while moving or zooming. Two primary factors cause this behavior:

  1. Sub-Pixel Interpolation (Fractional Coordinates):
    When a camera or map container moves using floating-point numbers (such as delta-time-based movement like x += 1.35), the GPU attempts to render tiles at fractional pixel coordinates. WebGL must interpolate the pixels, which shifts the texture sampling coordinates slightly outside the intended tile boundaries.

  2. Bilinear Texture Filtering:
    By default, Pixi.js often uses linear interpolation (PIXI.SCALE_MODES.LINEAR) to smooth textures when scaled. When the GPU samples a pixel near the absolute edge of a tile on a packed texture atlas, the linear filter blends the target tile's edge with the adjacent tile's edge, causing neighboring colors to "bleed" across the boundary.

How to Prevent Tile Bleeding

1. Extrude Tile Textures (The Most Reliable Fix)

The industry-standard solution for eliminating tile seams without sacrificing smooth camera movement is texture extrusion. Extrusion duplicates the outer 1-pixel border of each tile outward into a padding zone. If the GPU slightly over-samples beyond the tile boundary due to floating-point coordinates, it samples the duplicated edge color rather than a neighboring tile.

You can use automated build tools like tile-extruder via npm:

npx tile-extruder --input ./tileset.png --output ./tileset-extruded.png --tileWidth 16 --tileHeight 16 --margin 0 --spacing 0

When loading the extruded tileset, configure your tile-cutting logic or map editor (such as Tiled) with a 1-pixel margin and a 2-pixel spacing.

2. Enable Pixel Snapping

If your project uses pixel art or does not require sub-pixel camera movement, you can force Pixi.js to snap display objects to integer coordinates.

  • Globally via the Renderer: Set roundPixels to true when initializing your application: 
    const app = new PIXI.Application({
    width: 800,
    height: 600,
    roundPixels: true
});
  • Per Container: Enable it directly on the container holding your tilemap or camera: 
    tilemapContainer.roundPixels = true;
  • Manual Coordinate Snapping: Round your camera coordinates in your update loop: 
    camera.x = Math.round(targetX);
camera.y = Math.round(targetY);

3. Change the BaseTexture Scale Mode

If you are building a retro or pixel-art game, switch from linear filtering to nearest-neighbor filtering. Nearest-neighbor stops the GPU from blending adjacent pixels entirely.

// In Pixi.js v7 and earlier:
PIXI.BaseTexture.defaultOptions.scaleMode = PIXI.SCALE_MODES.NEAREST;

// Or on a specific texture:
tilesetTexture.baseTexture.scaleMode = PIXI.SCALE_MODES.NEAREST;

Note: While NEAREST fixes blending artifacts, slight geometric seams can still occur during floating-point camera translation unless combined with extruded tiles or rounded coordinates.

4. Use @pixi/tilemap

Rendering individual PIXI.Sprite objects for a large tilemap is inefficient and prone to coordinate precision issues. The official @pixi/tilemap package packs tiles into shared vertex buffers, significantly improving rendering performance and reducing sampling errors during camera translations.
