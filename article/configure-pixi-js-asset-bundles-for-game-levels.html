Configure Pixi.js Asset Bundles for Game Levels

Pixi.js provides a robust asset management system through its Assets module, allowing developers to group resources into bundles to load content incrementally. Instead of forcing players to download an entire game's assets upfront, you can declare specific bundles for each game level or area. This guide covers how to define manifests, initialize level-based bundles, load them on demand, and unload previous assets to optimize memory usage across game stages.

Defining Assets with a Manifest

The most scalable way to configure level-specific bundles in Pixi.js (v7 and v8) is by creating a manifest. A manifest organizes your assets into named bundles, with each bundle containing an array of asset identifiers and paths.

import { Assets } from 'pixi.js';

const manifest = {
  bundles: [
    {
      name: 'shared',
      assets: [
        { alias: 'ui-button', src: 'assets/ui/button.png' },
        { alias: 'font-main', src: 'assets/fonts/main.woff2' },
      ],
    },
    {
      name: 'level-1',
      assets: [
        { alias: 'background-1', src: 'assets/levels/bg-1.png' },
        { alias: 'boss-1', src: 'assets/sprites/boss-1.json' },
      ],
    },
    {
      name: 'level-2',
      assets: [
        { alias: 'background-2', src: 'assets/levels/bg-2.png' },
        { alias: 'boss-2', src: 'assets/sprites/boss-2.json' },
      ],
    },
  ],
};

Initializing the Manifest

Pass your manifest to Assets.init(). This registers all asset paths without immediately downloading the files, allowing your application to query and fetch bundles when required.

async function setupGameAssets() {
  await Assets.init({ manifest });
}

Alternatively, if you prefer not to use a single manifest object, you can register bundles manually using Assets.addBundle:

Assets.addBundle('level-1', {
  'background-1': 'assets/levels/bg-1.png',
  'boss-1': 'assets/sprites/boss-1.json',
});

Loading Bundles on Demand

When a player enters a specific level, load only that level's assets using Assets.loadBundle(). You can also pass a progress callback to drive loading screens.

async function startLevel(levelName, onProgress) {
  // Show a loading screen before calling loadBundle
  const assets = await Assets.loadBundle(levelName, (progress) => {
    if (onProgress) {
      onProgress(progress); // Returns a float from 0 to 1
    }
  });

  return assets;
}

// Example usage:
await startLevel('level-1', (progress) => {
  console.log(`Loading Level 1: ${Math.round(progress * 100)}%`);
});

Managing Memory Between Levels

Mobile devices and browsers have strict GPU and RAM limitations. When transitioning from one level to the next, unload the previous level's assets to release textures from GPU memory.

async function switchLevels(currentLevelName, nextLevelName) {
  // 1. Unload the previous level's assets
  await Assets.unloadBundle(currentLevelName);

  // 2. Load the new level's assets
  const newAssets = await Assets.loadBundle(nextLevelName);

  // 3. Initialize the new level
  initializeScene(newAssets);
}

Assets.unloadBundle() destroys the cached textures and resources associated with the specified bundle, ensuring clean memory transitions across large game projects.
