Box2D Physics Simulation with Pixi.js Ticker

Integrating a Box2D physics simulation with Pixi.js requires coordinating Pixi's rendering loop with Box2D's numerical integration steps. This guide demonstrates how to synchronize the Box2D physics world inside the PIXI.Ticker lifecycle, handle coordinate system conversions between physics meters and screen pixels, and apply a fixed time-step pattern to ensure deterministic, stable physics behavior across variable display refresh rates.

Understanding the Coordinate System

Box2D operates on the metric system (meters, kilograms, seconds), optimized for objects sized between 0.1 and 10 meters. Pixi.js, however, calculates all transformations in screen pixels.

To bridge the two systems, establish a constant scale factor, often referred to as Pixels Per Meter (PPM):

const PPM = 30; // 30 pixels equal 1 meter in Box2D

const toMeters = (pixels) => pixels / PPM;
const toPixels = (meters) => meters * PPM;

Implementing a Fixed Time Step

Box2D requires a constant time step (typically 1/60th of a second) to remain numerically stable. Rendering loops driven by PIXI.Ticker run at variable refresh rates depending on user hardware and screen frame rates. Coupling the physics step directly to the variable frame delta will cause tunneling and erratic physics behavior.

Use an accumulator loop to consume elapsed time in discrete, fixed steps:

const FIXED_TIMESTEP = 1 / 60; // 60 Hz physics step
const VELOCITY_ITERATIONS = 8;
const POSITION_ITERATIONS = 3;

let accumulator = 0;

app.ticker.add((ticker) => {
    // Convert ticker elapsed MS to seconds
    const deltaSeconds = ticker.deltaMS / 1000;
    
    // Prevent "spiral of death" during lag spikes
    accumulator += Math.min(deltaSeconds, 0.25);

    while (accumulator >= FIXED_TIMESTEP) {
        world.Step(FIXED_TIMESTEP, VELOCITY_ITERATIONS, POSITION_ITERATIONS);
        accumulator -= FIXED_TIMESTEP;
    }

    updateVisuals();
});

Synchronizing Physics Bodies to Pixi Sprites

To render the simulation, map the position and rotation of each Box2D b2Body to its corresponding Pixi.js DisplayObject. Because Box2D calculates positions from the center of mass, ensure your Pixi display objects have their anchors centered.

// Entity structure tracking paired components
const entities = [];

function createBox(x, y, width, height) {
    // 1. Pixi.js visual representation
    const sprite = new PIXI.Graphics();
    sprite.beginFill(0xff0000);
    sprite.drawRect(-width / 2, -height / 2, width, height);
    sprite.endFill();
    app.stage.addChild(sprite);

    // 2. Box2D rigid body definition
    const bodyDef = new Box2D.b2BodyDef();
    bodyDef.set_type(Box2D.b2_dynamicBody);
    bodyDef.set_position(new Box2D.b2Vec2(toMeters(x), toMeters(y)));

    const body = world.CreateBody(bodyDef);

    const shape = new Box2D.b2PolygonShape();
    shape.SetAsBox(toMeters(width / 2), toMeters(height / 2));

    body.CreateFixture(shape, 1.0); // Shape, density

    entities.push({ sprite, body });
}

Updating Transforms

After stepping the physics world, iterate through all paired entities to update the Pixi visual transformations to match the Box2D simulation output:

function updateVisuals() {
    for (let i = 0; i < entities.length; i++) {
        const { sprite, body } = entities[i];
        const pos = body.GetPosition();
        
        // Map meter coordinates back to screen pixels
        sprite.x = toPixels(pos.get_x());
        sprite.y = toPixels(pos.get_y());
        
        // Directly map radian rotation
        sprite.rotation = body.GetAngle();
    }
}

Optional: Transform Interpolation

If the display refresh rate (e.g., 144Hz) exceeds the physics simulation rate (60Hz), visual stutter can occur. Calculate an interpolation alpha using the remaining time in the accumulator to blend between the previous and current physics states:

const alpha = accumulator / FIXED_TIMESTEP;

// Interpolated position update
sprite.x = toPixels(previousX * (1 - alpha) + currentX * alpha);
sprite.y = toPixels(previousY * (1 - alpha) + currentY * alpha);

This pattern decouples the simulation rate entirely from the rendering hardware, providing stable physics calculations while keeping motion smooth across any monitor refresh rate.
