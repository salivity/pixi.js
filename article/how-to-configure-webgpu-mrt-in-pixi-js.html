How to Configure WebGPU MRT in Pixi.js

Multiple Render Targets (MRT) allow a fragment shader to output color data to multiple textures simultaneously in a single render pass, an essential technique for deferred shading, normal mapping, and complex post-processing. In Pixi.js v8, WebGPU support is native, enabling direct use of WGSL shaders and low-level WebGPU render passes. This guide covers how to set up textures, configure a custom RenderTarget with multiple color attachments, write the matching WGSL shader, and execute the multi-target draw call.

1. Creating the Target Textures

To draw to multiple targets, you first need to create the individual RenderTexture instances that will hold each output stream (e.g., base color, normal data, or material properties).

import { RenderTexture } from 'pixi.js';

const width = 800;
const height = 600;

// Create destination textures
const albedoTexture = RenderTexture.create({ width, height });
const normalTexture = RenderTexture.create({ width, height });
const depthOrDataTexture = RenderTexture.create({ width, height });

2. Configuring the RenderTarget

Pixi.js manages framebuffers and color attachments using the RenderTarget class. To configure MRT, initialize a RenderTarget and assign the textures to its colorTextures array. The index of each texture in this array directly corresponds to the @location(n) output index in the WGSL shader.

import { RenderTarget } from 'pixi.js';

const mrtRenderTarget = new RenderTarget({
    colorTextures: [
        albedoTexture,       // Maps to @location(0)
        normalTexture,       // Maps to @location(1)
        depthOrDataTexture   // Maps to @location(2)
    ],
    depth: true,             // Include depth buffer if required
    stencil: false
});

When Pixi.js's WebGPU device compiles the render pipeline for this RenderTarget, it configures the underlying GPURenderPassDescriptor.colorAttachments to match these textures in sequence.

3. Writing the WGSL MRT Shader

A standard WebGPU fragment shader returns a single vec4<f32>. For MRT, define a custom output struct where each member variable is tagged with the @location() attribute matching the indices defined in your RenderTarget.colorTextures.

struct FragmentOutput {
    @location(0) albedo : vec4<f32>,
    @location(1) normal : vec4<f32>,
    @location(2) extraData : vec4<f32>,
};

@fragment
fn mainFragment(
    @location(0) vUV : vec2<f32>
) -> FragmentOutput {
    var output : FragmentOutput;

    // Output diffuse/albedo color
    output.albedo = vec4<f32>(1.0, 0.5, 0.2, 1.0);

    // Output normal vector encoded as color
    output.normal = vec4<f32>(0.0, 1.0, 0.0, 1.0);

    // Output miscellaneous data (e.g., roughness, metallic)
    output.extraData = vec4<f32>(vUV.x, vUV.y, 0.5, 1.0);

    return output;
}

4. Building the Custom Shader Material

Bind the WGSL code into a Pixi.js Shader or create a custom Mesh or Filter to draw your scene objects.

import { Shader, Mesh, Geometry } from 'pixi.js';

const shader = Shader.from({
    gpu: {
        vertex: {
            source: vertexWgslSource,
            entryPoint: 'mainVertex',
        },
        fragment: {
            source: fragmentWgslSource,
            entryPoint: 'mainFragment',
        },
    },
});

const quadMesh = new Mesh({
    geometry: new Geometry(/* geometry definitions */),
    shader: shader
});

5. Rendering to the MRT Target

Direct the Pixi.js WebGPU renderer to draw your container or mesh directly into the configured RenderTarget.

// Instruct the renderer to output to your MRT setup
app.renderer.render({
    container: sceneContainer,
    target: mrtRenderTarget,
    clear: true
});

Once the pass completes, albedoTexture, normalTexture, and depthOrDataTexture are populated with their respective pass outputs and can be bound as standard inputs to subsequent lighting or composition passes.
