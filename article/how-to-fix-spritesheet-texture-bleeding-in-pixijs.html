How to Fix Spritesheet Texture Bleeding in PixiJS

Texture bleeding in PixiJS manifests as thin, flickering lines or ghost edges around sprites rendered from a shared spritesheet or texture atlas. This article covers the core causes of texture bleeding—namely bilinear filtering, subpixel positioning, and mipmapping—and details the exact steps needed to resolve it using sprite padding, border extrusion, and PixiJS rendering configurations.

What Causes Texture Bleeding?

Texture bleeding occurs when the GPU's texture sampling process inadvertently reads pixel data outside the boundary of a specific sub-texture inside a spritesheet.

  1. Bilinear Filtering and Interpolation: By default, PixiJS uses linear interpolation (PIXI.SCALE_MODES.LINEAR) to keep textures smooth when scaled, rotated, or translated. When calculating the color of a fragment near the edge of a sprite's UV coordinates, the GPU samples adjacent texels. If neighboring sprites or transparent borders sit directly next to the edge, the GPU blends those pixels together, causing a visible seam.
  2. Subpixel Positioning and Camera Scaling: When sprites are placed on floating-point coordinates (e.g., x: 10.4, y: 20.7) or when a display container is scaled, the rendered pixels do not align 1:1 with the screen grid. The GPU must interpolate between texels, heavily increasing the likelihood of sampling adjacent sprite data.
  3. Mipmapping: When textures generate downscaled mipmaps, lower-resolution versions blend wider clusters of pixels together. In a tightly packed spritesheet without margins, this blending causes severe bleeding at distances or smaller scales.

How to Prevent Bleeding with Sprite Padding and Extrusion

The most robust solution to texture bleeding is applying proper padding and edge extrusion when generating the spritesheet.

1. Extrude Edge Pixels (Recommended)

Padding alone (adding transparent spacing) prevents bleeding from neighboring sprites, but it can still cause bleeding with transparency, creating dark or semi-transparent outlines. Extrusion fixes this by duplicating the outer edge pixels of each sprite into the surrounding padding area.

  • Using TexturePacker: Set the Extrude value to 1 or 2. TexturePacker will automatically duplicate the border pixels outward while keeping the sprite's UV coordinates mapped to the original boundaries.
  • Using Tile-Extruder: For tilemaps, use the CLI tool tile-extruder to automatically add a 1-pixel extruded border around every tile in your tileset image before importing it into PixiJS.

2. Add Spacing and Inner Padding

If extrusion is not an option, configure your packing software with:

  • Border Padding / Margin: At least 2 pixels of empty space around the edge of the entire spritesheet.
  • Shape Padding / Spacing: At least 2 pixels of transparent space between individual sprites inside the atlas.

PixiJS Configuration Adjustments

In addition to padding the texture source, certain PixiJS settings help eliminate remaining edge artifacts:

Enable Pixel Rounding

Prevent subpixel rendering artifacts by forcing PixiJS to snap coordinates to whole integer pixels:

// Globally for the entire application
const app = new PIXI.Application({
    roundPixels: true
});

// Or per individual sprite
sprite.roundPixels = true;

Switch to Nearest-Neighbor Filtering

For retro or pixel-art games where sharp pixels are desired, disable linear interpolation entirely to prevent the GPU from blending adjacent texels:

// Set globally before loading assets
PIXI.BaseTexture.defaultOptions.scaleMode = PIXI.SCALE_MODES.NEAREST;

// Or apply to an individual loaded texture
texture.baseTexture.scaleMode = PIXI.SCALE_MODES.NEAREST;

Disable Mipmaps for Spritesheets

If a 2D spritesheet does not require 3D perspective or extreme downscaling, turn off mipmaps to prevent downsampled edge bleeding:

texture.baseTexture.mipmap = PIXI.MIPMAP_MODES.OFF;
