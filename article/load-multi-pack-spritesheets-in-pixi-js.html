Load Multi-Pack Spritesheets in Pixi.js

Loading multi-pack spritesheets that span across multiple image files in Pixi.js is a streamlined process thanks to the built-in Assets manager. This guide explains how to properly configure your exported asset data, load the master JSON manifest using modern Pixi.js methods, and access individual frames across your multiple texture pages without manual stitching.

1. Exporting the Multi-Pack Correctly

When dealing with large animation sequences or hundreds of game assets, texture packing tools like TexturePacker allow you to enable multipack support. When exporting:

  • Ensure you export to the PixiJS or JSON (Hash/Array) format.
  • Ensure the multipack option is enabled.
  • The exporter will generate files such as atlas-0.json, atlas-1.json, along with their corresponding image files (atlas-0.png, atlas-1.png).

The main requirement for Pixi.js is the related_multi_packs field. Open atlas-0.json and verify that the meta object contains an array pointing to the sibling files:

"meta": {
  "app": "https://www.codeandweb.com/texturepacker",
  "version": "1.0",
  "image": "atlas-0.png",
  "related_multi_packs": [
    "atlas-1.json"
  ]
}

2. Loading with the Pixi.js Assets API

Pixi.js v7 and v8 automatically resolve and load all sibling assets listed under related_multi_packs. You only need to load the root file (the first JSON file in the set).

import { Application, Assets, Sprite } from 'pixi.js';

async function init() {
  const app = new Application();
  await app.init({ width: 800, height: 600 });
  document.body.appendChild(app.canvas);

  // Load only the primary JSON file
  const sheet = await Assets.load('assets/atlas-0.json');

  // The multi-pack textures are now resolved and ready to use
  createGameScene(sheet);
}

init();

When Assets.load('assets/atlas-0.json') executes, Pixi.js inspects the metadata, automatically downloads atlas-1.json and all associated .png files, and aggregates the textures into a unified collection.

3. Accessing Frames Across Multiple Sheets

Once the initial JSON is loaded, all frames across all linked pages are added directly to the global texture cache and the returned spritesheet instance.

You can instantiate sprites using the frame names directly, regardless of which physical image sheet contains the frame:

function createGameScene(sheet) {
  // Option 1: Accessing directly from the loaded sheet object
  const characterTexture = sheet.textures['character_walk_01.png'];
  const character = new Sprite(characterTexture);

  // Option 2: Using the static Sprite.from method (cached globally)
  const enemy = Sprite.from('enemy_idle_01.png');

  // Multi-pack animations function seamlessly as well
  const runAnimation = new AnimatedSprite(sheet.animations['run']);
  runAnimation.play();
}

Important Considerations

  • Relative Paths: Ensure all JSON files and images remain in the same directory relative to one another. The related_multi_packs entries rely on relative URLs based on the path of the initial JSON file.
  • Resolution Prefixes: If using scaled assets (e.g., @2x.json), ensure your exporter preserves the naming pattern across all multi-pack splits so the loader applies consistent scale factors.
