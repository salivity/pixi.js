Pixi.js Full Stage Filters at 60 FPS

Applying a Pixi.js filter directly to an entire stage while maintaining a solid 60 frames per second (FPS) is technically achievable, but it depends heavily on the device's GPU, screen resolution, and filter complexity. This article explains how Pixi.js handles full-screen filters, why performance bottlenecks like fill-rate limitations occur, and the exact optimization techniques required to keep your application running at 60 FPS.

How Pixi.js Renders Stage Filters

When you attach a filter to app.stage, Pixi.js changes its rendering behavior:

  1. It allocates an off-screen framebuffer (RenderTexture) matching the dimensions of your canvas.
  2. It renders every visual element on the stage into this temporary texture.
  3. It passes the texture through a WebGL fragment shader to apply the visual effect.
  4. It renders the processed texture onto the screen.

Because the entire viewport must be processed per frame, this pipeline becomes bound by GPU memory bandwidth and fill rate rather than CPU draw calls.

Single-Pass vs. Multi-Pass Filters

The type of filter applied to the stage determines whether 60 FPS is realistic:

  • Single-Pass Filters: Simple color adjustments (such as ColorMatrixFilter, basic tints, or custom lightweight fragment shaders) process every pixel only once. On standard desktop hardware and modern mobile devices, a single-pass filter on the full stage will almost always maintain 60 FPS at 1080p.
  • Multi-Pass Filters: Filters like the default BlurFilter execute multiple passes (horizontal and vertical passes repeated across sample iterations). A blur filter with high quality or large kernel size quickly drops frame rates below 30 FPS on high-resolution displays or mobile devices because the GPU must redraw millions of pixels repeatedly within a 16.6ms frame window.

Key Optimizations to Maintain 60 FPS

To guarantee a smooth 60 FPS when filtering the entire stage, apply the following optimizations:

1. Lower the Filter Resolution

Pixi.js allows you to set the rendering resolution of an individual filter independently of the main renderer resolution. Lowering this property drastically reduces the pixel processing load with minimal visual degradation for effects like blurs:

const blurFilter = new PIXI.BlurFilter();
blurFilter.resolution = 0.5; // Processes at half resolution
app.stage.filters = [blurFilter];

2. Restrict the Filter Area

By default, Pixi.js creates a framebuffer covering the entire canvas. If your visual content only occupies a portion of the screen, explicitly define stage.filterArea to prevent the GPU from calculating shader logic on empty pixels:

app.stage.filterArea = app.screen; // Restricts bounds strictly to visible canvas

3. Manage High-DPI (Retina) Displays

On 2x or 3x pixel ratio screens (like modern smartphones and MacBooks), a 1920x1080 canvas actually renders at 3840x2160 or higher. Processing a full-screen filter at 4K resolution in real time will often fail to hit 60 FPS on integrated GPUs. Cap the resolution of the filter or the renderer to 1 on performance-critical scenes:

const app = new PIXI.Application({
    resolution: Math.min(window.devicePixelRatio, 1.5),
    autoDensity: true
});

4. Filter a Master Container Instead of the Stage

Rather than applying filters directly to app.stage, place only the visual elements requiring the effect inside a dedicated PIXI.Container. Keep user interfaces, text, and static overlays outside of this container on a separate layer. This reduces the number of elements drawn to the off-screen framebuffer and prevents UI text from becoming blurry or expensive to compute.
