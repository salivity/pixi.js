WGSL vs GLSL Shaders in Pixi.js: Syntax Differences

Pixi.js v8 introduced a unified graphics pipeline supporting both WebGL and WebGPU, enabling developers to write custom shaders using either legacy OpenGL Shading Language (GLSL) or the modern WebGPU Shading Language (WGSL). While both shading languages achieve the same visual outcomes, WGSL introduces a more modern, Rust-like syntax, stricter type safety, distinct handling of resources, and separated texture sampling. Understanding these structural and syntactic differences is essential when porting existing custom filters and materials or writing high-performance WebGPU shaders in Pixi.js.

Entry Points and Function Declarations

In GLSL, execution begins at an implicit void main() entry point, with input and output values managed globally. WGSL uses explicit function definitions preceded by stage attributes, requiring explicit return types.

  • GLSL: 
    void main() {
    gl_FragColor = vec4(1.0, 0.0, 0.0, 1.0);
}
  • WGSL: 
    @fragment
fn main() -> @location(0) vec4f {
    return vec4f(1.0, 0.0, 0.0, 1.0);
}

Variable Declarations and Immutability

GLSL uses C-style declarations where variables are mutable by default unless declared with const. WGSL enforces clearer intent using let for immutability and var for mutable variables.

  • GLSL: 
    float speed = 2.0;
const vec2 offset = vec2(0.5, 0.5);
speed = speed * 1.5;
  • WGSL: 
    var speed: f32 = 2.0;
let offset: vec2f = vec2f(0.5, 0.5);
speed = speed * 1.5;

Data Types and Strict Type Casting

WGSL features shorter type aliases (such as vec2f for vec2<f32>) and enforces strict typing. Unlike some GLSL configurations, WGSL will not implicitly cast integers to floats, and numeric literals must match their defined types precisely.

Type Description GLSL WGSL (Standard / Alias)
Boolean bool bool
Signed 32-bit Integer int i32
Unsigned 32-bit Integer uint u32
32-bit Floating Point float f32
2D Float Vector vec2 vec2<f32> or vec2f
4D Float Vector vec4 vec4<f32> or vec4f
3x3 Float Matrix mat3 mat3x3<f32> or mat3x3f

In WGSL, writing let x: f32 = 1; will trigger a compilation error. It must explicitly be written as 1.0 or 1.0f.

Uniform Buffers and Structs

GLSL allows individual uniform variables to be declared in the global scope. Pixi.js injects and maps these directly into the WebGL state. WGSL requires uniform data to be wrapped inside structured memory blocks with explicit binding and group decorators.

  • GLSL: 
    uniform vec4 uTint;
uniform float uTime;
  • WGSL: 
    struct Uniforms {
    uTint: vec4f,
    uTime: f32,
};

@group(0) @binding(0) var<uniform> uniforms: Uniforms;
    Accessing these in WGSL requires referencing the struct instance, such as uniforms.uTint.

Texture Sampling

In GLSL, a texture and its filtering configurations are combined into a single sampler2D uniform. In WGSL, following modern graphics hardware architecture, the texture resource and the sampler state are completely separated.

  • GLSL: 
    uniform sampler2D uTexture;
varying vec2 vUv;

void main() {
    vec4 color = texture2D(uTexture, vUv);
    gl_FragColor = color;
}
  • WGSL: 
    @group(1) @binding(0) var uTexture: texture_2d<f32>;
@group(1) @binding(1) var uSampler: sampler;

@fragment
fn main(@location(0) vUv: vec2f) -> @location(0) vec4f {
    return textureSample(uTexture, uSampler, vUv);
}

Vertex Shader Inputs and Outputs

GLSL handles pipeline communication via attribute and varying keywords (or in and out in newer GLSL standards). WGSL handles pipeline data using attributes attached directly to function arguments or wrapped inside structs using @builtin and @location markers.

  • GLSL (Vertex): 
    attribute vec2 aPosition;
attribute vec2 aUv;
varying vec2 vUv;
uniform mat3 uProjectionMatrix;

void main() {
    vUv = aUv;
    gl_Position = vec4((uProjectionMatrix * vec3(aPosition, 1.0)).xy, 0.0, 1.0);
}
  • WGSL (Vertex): 
    struct VertexInput {
    @location(0) aPosition: vec2f,
    @location(1) aUv: vec2f,
};

struct VertexOutput {
    @builtin(position) position: vec4f,
    @location(0) vUv: vec2f,
};

@group(0) @binding(0) var<uniform> uProjectionMatrix: mat3x3f;

@vertex
fn main(input: VertexInput) -> VertexOutput {
    var output: VertexOutput;
    output.vUv = input.aUv;
    output.position = vec4f((uProjectionMatrix * vec3f(input.aPosition, 1.0)).xy, 0.0, 1.0);
    return output;
}
