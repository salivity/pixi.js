How PixiJS Renders Masks with RenderTexture

When rendering a Pixi.js scene to a RenderTexture, masks are processed through the renderer’s internal batching and framebuffer pipeline using either WebGL stencil buffers, scissor rects, or shader-based filter passes. Pixi.js dynamically binds the target RenderTexture as an offscreen framebuffer, converts the mask's local coordinates to the target’s render space, and applies the masking technique specific to the mask object type. This guide explains the step-by-step mechanics of how Pixi.js evaluates, draws, and bakes masks when generating render textures.

Stencil-Based Masking (Graphics Masks)

When you assign a PIXI.Graphics object as a mask, Pixi.js employs the GPU’s hardware stencil buffer.

  1. Framebuffer Attachment: When renderer.render(container, { renderTexture }) is called, Pixi.js binds the RenderTexture's underlying WebGL framebuffer. To support graphics masking, Pixi ensures this framebuffer has an active stencil buffer attachment.
  2. Writing the Stencil: The renderer turns off color drawing (gl.colorMask(false, false, false, false)) and enables the stencil test. The mask geometry is drawn into the stencil buffer, incrementing or setting the stencil bits to mark the visible clipping area.
  3. Drawing Masked Content: Color writing is restored, and the stencil test is configured to pass only where the specific stencil value exists. Pixi.js then renders the masked children directly onto the RenderTexture.
  4. Cleanup: Pixi clears or decrements the stencil buffer area used by the mask to return the stencil state to zero before processing other scene elements.

Sprite and Alpha Masking (Filter Passes)

If you assign a PIXI.Sprite as a mask, Pixi.js bypasses the stencil buffer and routes the operation through its FilterSystem using SpriteMaskFilter.

  1. Intermediate Render Targets: The masked container and its mask cannot be combined immediately onto the destination RenderTexture. Instead, Pixi.js allocates temporary offscreen textures (filter textures) from its internal pool.
  2. Shader Compositing: The container’s contents are rendered into one temporary texture, while the mask sprite is passed as a texture uniform to the SpriteMaskFilter shader.
  3. Alpha Multiplication: The fragment shader samples both the container texture and the mask sprite texture, multiplying the container’s RGBA channels by the alpha (or luminance) value of the mask sprite.
  4. Final Blit: The final calculated pixels are rendered directly into the target RenderTexture.

Scissor Rect Masking

For simple rectangular, non-rotated Graphics masks, Pixi.js optimizes the draw call by using WebGL's built-in scissor testing (gl.scissor). Instead of updating the stencil buffer, Pixi calculates the bounding box of the mask relative to the RenderTexture’s dimensions and clips the drawing area. This minimizes GPU state switches and produces clean rectangular cutouts on the exported texture.

Coordinate Spaces and Transforms

A frequent challenge when exporting masked containers to a RenderTexture is coordinate misalignment.

  • Pixi.js relies on world transformation matrices (worldTransform) to position both objects and masks.
  • If a mask is placed inside the container being rendered, its transform scales and translates predictably relative to the texture's origin (0,0).
  • If a mask resides outside the container’s hierarchy, its transform will be evaluated using the global screen/canvas coordinates rather than the RenderTexture's local coordinate system. This can shift the mask off-target. To resolve this, ensure external masks have their transforms manually updated or use a custom transformation matrix parameter in renderer.render().

Flattening and Export

Once the draw calls finish, the RenderTexture contains the final, composited pixel data with all alpha and stencil operations permanently resolved. When using extraction utilities such as renderer.extract.image(renderTexture) or renderer.extract.canvas(renderTexture), Pixi.js calls gl.readPixels from the bound framebuffer. The exported image contains the final clipped geometry with transparency intact, requiring no additional post-processing.
