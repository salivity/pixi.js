Compute Shaders for Dynamic Vertices in Pixi.js

Pixi.js allows you to modify vertex data dynamically using off-screen compute operations, but your implementation depends heavily on the renderer backend in use. With the introduction of WebGPU in Pixi.js v8, true compute shaders can directly mutate vertex buffers on the GPU without CPU overhead. In WebGL mode, native compute passes are unavailable, requiring workarounds such as GPGPU render-to-texture techniques or custom Transform Feedback passes to achieve dynamic vertex manipulation.

WebGPU Compute Passes (Pixi.js v8)

Pixi.js v8 introduced a unified architecture supporting WebGPU via WebGPURenderer. WebGPU provides native compute pipeline support, making it the most efficient way to mutate vertex data directly on the GPU.

To execute a compute pass that modifies vertex attributes:

  1. Allocate a Shared Buffer: Create a GPUBuffer configured with both compute storage and vertex flags (GPUBufferUsage.STORAGE | GPUBufferUsage.VERTEX).
  2. Write a WGSL Compute Shader: Write a compute shader in WebGPU Shading Language (WGSL) that accepts the buffer as a writable storage buffer and updates position or attribute values.
  3. Dispatch the Compute Pass: Access the underlying device via renderer.gpu.device or integrate the pass using Pixi’s custom rendering extensions. Dispatch the compute pass before the main scene render pass executes.
  4. Bind as Vertex Buffer: Pass the mutated buffer to a custom pixi.js Mesh or Geometry object. The updated positions will render immediately on the screen without reading data back to the JavaScript main thread.

WebGL Alternatives (Pixi.js v7 and Fallback Modes)

WebGL 1 and WebGL 2 do not support standard compute shaders. If your Pixi.js application runs on a WebGL backend, dynamic vertex modification must be handled through alternative patterns:

  • Render-to-Texture (GPGPU): Store vertex coordinates in a floating-point render texture (RenderTexture). Run an off-screen fragment shader pass that computes new vertex coordinates and writes them to the texture. In your render pass, a custom vertex shader samples the positions from this texture using Vertex Texture Fetch (VTF) to position vertices dynamically.
  • Transform Feedback (WebGL 2): WebGL 2 supports Transform Feedback, which captures vertex shader outputs directly into a buffer. While Pixi.js does not expose high-level abstractions for Transform Feedback, you can access the low-level WebGL context (renderer.gl) to execute native Transform Feedback operations and bind the resulting buffer to a Pixi Geometry.
  • CPU-Side Mutation: For simpler meshes or low vertex counts, you can mutate arrays in JavaScript and upload them using geometry.getBuffer('aVertexPosition').update(). While simple, this incurs CPU-to-GPU data transfer overhead each frame.

Best Practices

  • Avoid CPU Readbacks: Never call functions that pull buffer or pixel data back to JavaScript (such as gl.readPixels or mapping GPU buffers for reading) inside your frame loop, as this causes GPU pipeline stalls.
  • Pipeline Synchronization: When using WebGPU, ensure that resource synchronization and execution order between the compute pass and the main render pass are maintained properly within the command encoder.
  • Target Detection: Check renderer.type === RendererType.WEBGPU at runtime to decide whether to run hardware compute passes or fall back to GPGPU texture pipelines for WebGL clients.
