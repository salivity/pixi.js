How to Debug Pixi.js WebGL Stencil Masks

Debugging WebGL stencil buffer issues in Pixi.js requires inspecting both WebGL state and Pixi’s internal masking pipeline, as failed masks often stem from context initialization, stack depth limits, or malformed vector geometries. When graphics masks fail, the stencil buffer either contains unexpected values or is bypassed entirely. This guide outlines how to inspect the stencil buffer directly, leverage WebGL diagnostic tools, and identify common failure points within Pixi.js mask implementations.

1. Verify Context Initialization and Mask Types

Pixi.js handles masking in two distinct ways: Alpha Masks (using shaders and render textures) and Stencil Masks (using PIXI.Graphics and the WebGL stencil buffer). If a PIXI.Graphics mask is invisible or clips everything, ensure the WebGL context actually has a stencil buffer allocated.

When initializing your PIXI.Application, the stencil buffer must be enabled. While Pixi enables this by default, custom configurations or canvas wrapping can disable it:

const app = new PIXI.Application({
    width: 800,
    height: 600,
    antialias: true,
    stencil: true // Ensure the WebGL context requests a stencil buffer
});

Verify that the mask object is assigned correctly to the display object’s .mask property rather than merely added as a child to the container.

2. Inspect the Stencil Buffer with Spector.js

Because the stencil buffer cannot be read natively using standard DOM inspection tools or regular canvas toDataURL() calls, a dedicated WebGL frame capture extension like Spector.js is essential.

  1. Install the Spector.js extension in Chrome or Firefox.
  2. Trigger a frame capture while the broken mask is rendering.
  3. In the capture panel, locate the draw calls associated with the mask geometry (typically a drawArrays or drawElements call preceded by gl.stencilFunc and gl.stencilOp).
  4. Click on the visual state snapshot and open the Stencil tab. Spector displays a grayscale visual representation of the stencil buffer contents at that exact draw call.
  5. Verify whether the shape of your PIXI.Graphics object is actually written to the buffer. If the stencil buffer remains entirely black (value 0), the geometry draw call did not execute or was clipped.

3. Trace Pixi's Internal Mask Stack

Pixi.js maintains a MaskSystem that tracks active masks using an internal stack. Deeply nested masks increment stencil reference values using gl.stencilOp(gl.KEEP, gl.KEEP, gl.INCR). If the nesting exceeds the supported depth of the buffer (typically 8 bits, allowing up to 255 levels, though Pixi optimizes within smaller ranges), masking will fail.

You can monitor the active mask stack at runtime by setting a breakpoint or logging the system state inside your render loop:

// Access the mask system in Pixi v6 / v7 / v8
const maskSystem = app.renderer.mask;

// Check currently applied masks
console.log(maskSystem.maskStack);

If maskStack is empty during a draw call where masking was expected, the display object might be failing Pixi's visibility checks or bounds calculation.

4. Check for Empty or Invalid Geometry

A stencil mask requires closed rasterizable paths to increment or write stencil values. Common issues with PIXI.Graphics include:

  • Unclosed Paths: Polygons must have explicit fills. Lines (lineStyle) without fills often produce zero-area polygons that fail to mark stencil fragments. Call graphics.beginFill(...) before drawing mask shapes.
  • Zero Dimensions or Off-Screen Coordinates: Check mask.getBounds(). If width or height is 0, or if transforms place the mask outside the viewport, Pixi’s culling system may discard the draw call.
  • Transforms: Masks must either be added to the scene graph to inherit transformations or manually have their transforms updated. If a mask is not a child of a rendered container, update its transform manually using mask.updateTransform().

5. Inspect WebGL State Flags Directly

If third-party libraries, custom shaders, or raw WebGL filters run alongside Pixi.js, they can disrupt the global stencil state. Intercept the WebGL state via the console:

const gl = app.renderer.gl;

// Verify stencil test is currently enabled
console.log("Stencil Test Enabled:", gl.isEnabled(gl.STENCIL_TEST));

// Read current stencil configuration
console.log("Stencil Func:", gl.getParameter(gl.STENCIL_FUNC));
console.log("Stencil Value Mask:", gl.getParameter(gl.STENCIL_VALUE_MASK));
console.log("Stencil Write Mask:", gl.getParameter(gl.STENCIL_WRITEMASK));

If gl.isEnabled(gl.STENCIL_TEST) evaluates to false during the masked object's render pass, a filter or custom rendering pass has altered the pipeline state without restoring it via Pixi's StateSystem.

6. Fallback Alternative: Alpha Masking

If hardware constraints or complex blend modes make stencil mask debugging impractical, switch to a texture-based Alpha Mask:

// Convert the graphics object or sprite to an alpha mask
container.mask = spriteMask; // Where spriteMask is a PIXI.Sprite

Alpha masks bypass the stencil buffer entirely, relying on fragment shader calculations and color channel rendering, which can be inspected directly in standard canvas debugging tools.
