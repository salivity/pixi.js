How Pixi.js Maps Accessible Divs Over Canvas

Pixi.js makes interactive canvas content accessible to screen readers by dynamically generating an HTML overlay of standard DOM elements that mirror the visual scene graph. Because the HTML5 <canvas> element functions as an opaque bitmap to assistive technologies, Pixi.js relies on an internal accessibility engine that calculates the global bounding box of visual objects and projects corresponding HTML elements directly over their canvas coordinates.

The Accessibility Container Overlay

When accessibility features are engaged, the Pixi.js AccessibilityManager creates an HTML <div> container styled to sit directly over or under the canvas element. This container shares the same dimensions, scale, and position as the canvas itself. Inside this wrapper, Pixi.js creates standard interactive DOM nodes—primarily <button> and <div> elements—with appropriate ARIA attributes, labels, and roles based on the visual components rendered in the WebGL or 2D context.

Activating the Coordinate System

To maintain performance, Pixi.js does not update accessible DOM elements by default. Instead, the AccessibilityManager listens for a keyboard Tab event. Once a user presses Tab, the manager activates and assumes an assistive technology or keyboard-only user is interacting with the application. Developers can also force the accessibility layer to remain permanently active by setting the manager's isActive property to true.

Bounding Box Calculation and Transformation

To position the invisible DOM nodes accurately over the rendered graphics, Pixi.js performs continuous coordinate transformations:

  1. Local to Global Transformation: Every visual object in Pixi.js (DisplayObject, Container, Sprite) maintains a local transform matrix. Pixi.js traverses the parent hierarchy to compute the object's world transform matrix, accounting for position, rotation, scale, and skew.
  2. Bounds Determination: The engine calls getBounds() on the target DisplayObject. This determines the minimum axis-aligned bounding box (AABB) enclosing the visual asset in world coordinates.
  3. Canvas-to-Viewport Normalization: Pixi.js takes the computed world bounds and maps them through the canvas resolution and CSS scaling factors. If the canvas is rendered at a high DPI resolution (e.g., resolution: 2) or scaled down via CSS width and height, the coordinates are adjusted proportionally.
  4. DOM Styling Application: The resulting values are assigned directly to the inline CSS styles of the corresponding DOM node using position: absolute, left, top, width, and height.

Synchronization and Event Forwarding

During the application's render loop, the AccessibilityManager checks whether an accessible object's transform, visibility, or bounds have changed. If a sprite moves, rotates, or resizes, the overlay DOM element's CSS coordinates update to maintain a 1:1 spatial match.

Because the DOM element matches the size and position of the canvas object, assistive devices can target it naturally. When a screen reader user focuses, clicks, or triggers an action on the DOM node, the AccessibilityManager captures the native browser event and dispatches the equivalent interaction event (such as pointertap or click) back to the underlying Pixi.js DisplayObject. This ensures that logic bound to visual objects executes seamlessly without separate code paths for mouse and assistive inputs.
