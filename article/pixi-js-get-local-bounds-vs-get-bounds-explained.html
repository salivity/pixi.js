Pixi.js: getLocalBounds vs getBounds Explained

In Pixi.js, both getBounds() and getLocalBounds() are used to measure the rectangular dimensions of a display object, but they evaluate that space differently. The fundamental difference lies in the coordinate system used: getBounds() calculates the axis-aligned bounding box of an object in global stage coordinates—factoring in all position, rotation, and scale transforms from the object and its parents—whereas getLocalBounds() calculates the bounding box strictly within the object's own local coordinate space, completely ignoring parent and local transformation matrices.

Understanding getBounds()

The getBounds() method returns a PIXI.Rectangle representing the Axis-Aligned Bounding Box (AABB) of a DisplayObject in the global coordinate space (the root stage).

  • Transforms Applied: It includes the object’s position, scale, rotation, skew, as well as the transforms of every ancestor container up to the stage root.
  • Rotation Impact: Because the returned rectangle is axis-aligned (edges are always parallel to the screen's X and Y axes), rotating an object will cause the width and height returned by getBounds() to expand to encompass the rotated corners.
  • Performance: It is computationally heavier because Pixi.js must multiply the entire world transform matrix down the display tree.
  • Primary Use Cases:
    • Screen-space collision detection and hit-testing.
    • Determining if an object is inside the visible viewport (frustum/viewport culling).
    • Aligning or positioning UI elements relative to the overall screen or stage.

Understanding getLocalBounds()

The getLocalBounds() method returns a PIXI.Rectangle measuring the object relative to its own origin (0, 0).

  • Transforms Applied: It ignores the object's own position, rotation, and scale, as well as any transformations applied to parent containers. It only accounts for the intrinsic geometry of the object (such as drawn graphics or the positions of nested child elements inside it).
  • Rotation Impact: Rotating the object or its parent does not change the dimensions returned by getLocalBounds().
  • Performance: Generally lighter than getBounds() because it does not traverse the global transformation hierarchy.
  • Primary Use Cases:
    • Centering an object's pivot point (e.g., setting object.pivot.x = object.getLocalBounds().width / 2).
    • Creating dynamic backgrounds or borders that wrap an element regardless of its current scale or position.
    • Measuring the intrinsic unscaled size of a composite container.

Summary of Differences
