Custom BatchRenderer Plugin for Pixi.js Primitives

This article explains how to build and register a custom BatchRenderer plugin in Pixi.js to batch user-defined primitives into single draw calls. You will learn how to configure a custom shader, define vertex attributes, extend the BatchRenderer class, and integrate the renderer into a custom display object to achieve maximum rendering performance.

Understanding the Pixi.js Batch System

Pixi.js achieves high performance by batching 2D draw operations. Instead of issuing a WebGL draw call for every individual shape or sprite, the engine packs vertex data from compatible objects into shared vertex buffers.

When creating custom primitives with custom vertex attributes (such as per-vertex colors, thickness, or custom procedural variables), the default batch pipeline cannot process the custom data layout. Implementing a custom BatchRenderer allows you to define your own vertex format, assign custom shaders, and bundle multiple primitive instances into a unified draw call.

1. Define the Custom Shaders

A custom batch renderer requires a vertex shader and a fragment shader capable of handling batched geometry.

const vertexShader = `
    precision highp float;
    attribute vec2 aVertexPosition;
    attribute vec4 aColor;
    attribute float aThickness;

    uniform mat3 translationMatrix;
    uniform mat3 projectionMatrix;

    varying vec4 vColor;
    varying float vThickness;

    void main(void) {
        vColor = aColor;
        vThickness = aThickness;
        gl_Position = vec4((projectionMatrix * translationMatrix * vec3(aVertexPosition, 1.0)).xy, 0.0, 1.0);
    }
`;

const fragmentShader = `
    precision highp float;
    varying vec4 vColor;
    varying float vThickness;

    void main(void) {
        // Render custom primitive styling using passed attributes
        gl_FragColor = vColor;
    }
`;

2. Extend the BatchGeometry

Pixi uses BatchGeometry to manage attribute buffers. If you introduce custom vertex attributes, extend PIXI.BatchGeometry to define their layout.

class CustomPrimitiveGeometry extends PIXI.BatchGeometry {
    constructor(_static = false) {
        super(_static);
        
        // Define custom attribute layout matching the shader
        // Total vertex size = 2 (pos) + 4 (color) + 1 (thickness) = 7 floats (28 bytes)
        this.addAttribute('aVertexPosition', this._buffer, 2, false, PIXI.TYPES.FLOAT)
            .addAttribute('aColor', this._buffer, 4, true, PIXI.TYPES.UNSIGNED_BYTE)
            .addAttribute('aThickness', this._buffer, 1, false, PIXI.TYPES.FLOAT)
            .addIndex(this._indexBuffer);
    }
}

3. Implement the Custom BatchRenderer

Extend PIXI.BatchRenderer. You need to specify the shader, the geometry class, the vertex size (number of 32-bit values per vertex), and how individual display objects feed their geometry into the batch buffers.

class CustomBatchRenderer extends PIXI.BatchRenderer {
    constructor(renderer) {
        super(renderer);
        
        // Number of 32-bit values per vertex (pos: 2, color: 1 [packed uint32], thickness: 1) = 4
        this.vertexSize = 4;
        this.geometryClass = CustomPrimitiveGeometry;
        this.shaderGenerator = new PIXI.BatchShaderGenerator(vertexShader, fragmentShader);
    }

    packInterleavedGeometry(element, attributeBuffer, indexBuffer, aIndex, iIndex) {
        const { uint32View, float32View } = attributeBuffer;
        const packedColor = element.packedColor;
        const thickness = element.thickness;
        const points = element.points; // Array of {x, y}
        
        const startIndex = aIndex / this.vertexSize;

        // Write custom attributes directly to attributeBuffer
        for (let i = 0; i < points.length; i++) {
            float32View[aIndex++] = points[i].x;
            float32View[aIndex++] = points[i].y;
            uint32View[aIndex++] = packedColor;
            float32View[aIndex++] = thickness;
        }

        // Write index buffer data (e.g., triangle strip or list)
        const indices = element.indices;
        for (let i = 0; i < indices.length; i++) {
            indexBuffer[iIndex++] = startIndex + indices[i];
        }
    }
}

4. Register the Plugin with Pixi.js

Register the custom renderer with Pixi’s extension system so the main renderer initializes it upon startup.

PIXI.extensions.add({
    name: 'customPrimitiveBatch',
    type: PIXI.ExtensionType.RendererPlugin,
    ref: CustomBatchRenderer,
});

5. Build the Custom Display Object

Create a custom display object that overrides _render to direct Pixi to use your custom batch plugin.

class CustomPrimitiveObject extends PIXI.Container {
    constructor() {
        super();
        this.pluginName = 'customPrimitiveBatch';
        this.points = [
            { x: 0, y: 0 },
            { x: 100, y: 0 },
            { x: 50, y: 100 }
        ];
        this.indices = [0, 1, 2];
        this.thickness = 2.0;
        this.packedColor = PIXI.utils.rgb2hex([1, 0, 0]); // Packed 32-bit RGBA
        this.vertexCount = 3;
        this.indexCount = 3;
    }

    _render(renderer) {
        // Flush any active batched draws if switching plugins
        renderer.batch.setObjectRenderer(renderer.plugins[this.pluginName]);
        
        // Pass this object to our batch renderer
        renderer.plugins[this.pluginName].render(this);
    }

    _calculateBounds() {
        // Implement bounding box calculations for culling and interaction
        this._bounds.addPoint(new PIXI.Point(0, 0));
        this._bounds.addPoint(new PIXI.Point(100, 100));
    }
}

Execution and Usage

Once registered, instances of CustomPrimitiveObject are added to the stage like standard containers or sprites:

const app = new PIXI.Application({ width: 800, height: 600 });
document.body.appendChild(app.view);

for (let i = 0; i < 1000; i++) {
    const primitive = new CustomPrimitiveObject();
    primitive.position.set(Math.random() * 800, Math.random() * 600);
    app.stage.addChild(primitive);
}

All 1,000 instances will now be aggregated into a single draw call by the CustomBatchRenderer, bypassing individual WebGL state changes and maximizing render throughput.
