How PixiJS Binds Sampler Uniforms in WebGL

This article explains how PixiJS manages the binding of WebGL texture units to sampler uniforms within its rendering pipeline. By decoupling texture allocation through specialized sub-systems—specifically the TextureSystem, ShaderSystem, and BatchRenderer—PixiJS maps GLSL sampler2D uniforms to active GPU texture units sequentially and efficiently. The following sections break down the internal process from texture unit allocation and GLSL uniform updates to multi-texture batching optimizations.

The Role of Texture Units and Uniforms in WebGL

In raw WebGL, rendering a texture requires two distinct operations:

  1. Activating a hardware texture unit (e.g., gl.TEXTURE0, gl.TEXTURE1) and binding a WebGL texture object to that target via gl.bindTexture.
  2. Setting the corresponding shader uniform (sampler2D) to an integer representing the index of that texture unit (e.g., 0, 1) via gl.uniform1i.

PixiJS automates this manual state tracking using internal managers to prevent redundant WebGL state changes and minimize draw calls.

Texture Unit Allocation via TextureSystem

PixiJS manages texture memory and active slots using renderer.texture, an instance of TextureSystem. The system tracks active units through an internal array (boundTextures):

  1. Location Resolution: When a texture must be bound, the TextureSystem checks if the texture is already bound to an active unit.
  2. Assignment: If the texture is not already active, the system finds an empty slot or evicts the least recently used texture slot, assigning an index \(N\) (from 0 up to gl.MAX_TEXTURE_IMAGE_UNITS - 1).
  3. Hardware Activation: The system triggers the native WebGL binding calls: 
    gl.activeTexture(gl.TEXTURE0 + location);
gl.bindTexture(texture.target, glTexture);
  4. State Caching: The internal boundTextures[location] reference is updated to ensure subsequent operations during the same render pass reuse the slot without triggering additional WebGL context calls.

Linking Samplers in ShaderSystem

Custom shaders and filters handle uniforms through the ShaderSystem and the underlying Program abstraction:

  1. Introspection: When a shader is compiled, PixiJS inspects the compiled GLSL program using gl.getActiveUniform to extract uniform names, types, and locations.
  2. Sampler Identification: Uniforms identified as gl.SAMPLER_2D or gl.SAMPLER_CUBE are flagged internally as sampler types.
  3. Execution-Time Binding: During draw preparation, the ShaderSystem invokes a generated uniform sync function. For a single sampler2D:
    • The texture assigned to that uniform property is passed to renderer.texture.bind(texture).
    • The TextureSystem returns the bound unit index (e.g., 1).
    • The shader sync assigns this index directly to the program's uniform location: 
      gl.uniform1i(uniformLocation, unitIndex);

Multi-Texture Batching in BatchRenderer

PixiJS’s performance relies heavily on multi-texture batching, where dozens of sprites sharing different textures are drawn in a single call. In this scenario, sampler assignment operates on an array of samplers rather than a single uniform:

  1. Shader Generation: PixiJS generates a vertex/fragment shader pair that declares an array of samplers based on the device's hardware capacity (for example, uniform sampler2D uSamplers[16];).
  2. Sequential Slot Mapping: The BatchRenderer reserves texture units 0 through MAX_TEXTURES - 1. During initialization, it uploads an integer array directly to the uniform array location once: 
    const samplerIndices = [0, 1, 2, 3, ..., MAX_TEXTURES - 1];
gl.uniform1iv(uSamplersLocation, samplerIndices);
  3. Per-Vertex Texture Indexing: During geometry building, each sprite assigns an attribute indicating which texture unit index (from 0 to 15) holds its texture.
  4. Flush Phase: When a batch is rendered, the BatchRenderer binds all packed textures to their corresponding units (gl.TEXTURE0 + i) in one loop. Because uSamplers is permanently mapped to indices 0 through N, PixiJS does not need to reassign uniform values per draw call, only the bound textures in the active texture units.
