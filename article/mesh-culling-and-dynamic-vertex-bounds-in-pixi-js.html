Mesh Culling and Dynamic Vertex Bounds in Pixi.js

In Pixi.js, culling relies on CPU-side Axis-Aligned Bounding Boxes (AABB) to determine whether a display object is inside the visible viewport. When a Mesh has vertices that animate or displace outside their initial bounds, Pixi.js does not automatically expand the bounding box unless explicitly instructed. Consequently, if the original bounds leave the viewport while the displaced vertices remain in view, Pixi.js assumes the object is off-screen and culls it, causing visual popping and unexpected disappearance.

How Pixi.js Calculates Mesh Bounds

Pixi.js derives a Mesh object's bounds from its underlying Geometry vertex position attributes. During initialization, the CPU calculates a static bounding box based on the minimum and maximum X and Y coordinates in the position buffer.

Because recalculating bounds on complex geometries every frame is computationally expensive, Pixi.js aggressively caches these bounding calculations. The culling system—whether using native container culling via cullable = true or external culling libraries—checks this cached AABB against the camera view.

Behavior During Vertex Displacement

The behavior of culling when vertices move outside their initial bounds depends on where and how the vertex positions are altered:

1. GPU-Side Modification (Vertex Shaders)

If vertices are modified in a custom vertex shader (e.g., waving flags, water ripples, or spine animations), the CPU has no awareness of these GPU-level translations. Pixi.js continues to use the un-displaced vertex positions to calculate bounds.

  • Premature Culling: If the base coordinates of the mesh exit the viewport, the entire mesh is culled, instantly clipping the displaced portions that should still be visible on-screen.
  • Delayed Culling: If the displaced vertices move completely off-screen but the initial rest-pose coordinates remain inside the viewport, Pixi.js will continue to render the mesh, wasting draw calls.

2. CPU-Side Modification (Buffer Updates)

If you dynamically update the vertex coordinates directly in the position buffer via JavaScript, Pixi.js still will not update the bounding box automatically. The internal _boundsID flag prevents re-evaluating bounds on every frame. Unless bounds recalculation is explicitly triggered, the mesh uses its initial bounding limits, leading to the same premature culling issues observed with vertex shaders.

Preventing Culling Artifacts

To prevent dynamic Mesh objects from disappearing prematurely, you must synchronize the CPU bounds with the actual visual space the vertices occupy, or bypass culling entirely:

  • Trigger Bounds Recalculation: When updating vertex buffers on the CPU, notify the geometry that data has changed by updating the position buffer's update ID and calling mesh.geometry.calculateBounds().
  • Expand Bounds Padding: For meshes displaced via shaders, override or expand the bounding box artificially. You can define a custom bounds implementation or extend mesh.calculateBounds to add padding that accounts for the maximum displacement distance expected in the shader.
  • Disable Culling: If the mesh is dynamic or moves unpredictably, set mesh.cullable = false. This ensures Pixi.js skips the visibility evaluation for this object, delegating visibility handling entirely to the GPU's native clipping stage.
