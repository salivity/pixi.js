Pixi.js Filter autoFit: Control Bounding Box

In Pixi.js, visual filters can sometimes clip extended effects or cause unintended coordinate shifts when rendering custom shaders. This article explains how to configure the autoFit property on Pixi.js filters to control bounding box expansion, maintain accurate UV mapping, and determine when to use autoFit versus filter padding to eliminate clipping.

Understanding the autoFit Property

Every instance of PIXI.Filter contains an autoFit boolean property, which defaults to true. When enabled, Pixi.js calculates the tight bounding box of the display object, allocates a temporary render texture matching those dimensions, and restricts the shader pass to that specific area.

When autoFit is set to false, the filter bypasses the local bounds calculation and applies the shader across the entire output render target (typically the full screen or canvas view).

How to Configure autoFit

You configure autoFit by setting it directly on your filter instance before or after attaching it to a display object's filters array:

import * as PIXI from 'pixi.js';

// Create a custom or built-in filter
const customFilter = new PIXI.Filter(vertexShader, fragmentShader, uniforms);

// Disable automatic bounds fitting
customFilter.autoFit = false;

// Attach to your target display object
container.filters = [customFilter];

When to Disable autoFit

Setting autoFit = false is necessary in several specific rendering pipelines:

  1. Screen-Space Shaders: If your shader relies on normalized screen coordinates (like fullscreen post-processing, vignettes, scanlines, or global lighting), keeping autoFit = true will compress the coordinates to the sprite's dimensions. Disabling autoFit ensures vTextureCoord maps correctly across the entire canvas.
  2. Preventing Texture Reallocation: For objects that constantly change dimensions rapidly, an enabled autoFit forces Pixi.js to continually recalculate bounds and reallocate render textures, which can cause frame drops. Setting autoFit = false keeps the render texture size constant at the cost of processing empty pixels.

Controlling Expansion: autoFit vs. Padding

Disabling autoFit is often mistakenly used to fix clipped effects, such as blurs, glows, or outlines that exceed the original sprite geometry. However, turning autoFit off forces the GPU to process the entire screen for that object, which degrades performance.

If you need the filter bounding box to expand outward around the object without rendering to the entire screen, keep autoFit = true and increase the padding property instead:

const glowFilter = new PIXI.Filter(vertexShader, fragmentShader);

// Keep localized bounds calculation
glowFilter.autoFit = true;

// Expand the bounding box outward by 30 pixels on all sides
glowFilter.padding = 30;

sprite.filters = [glowFilter];

The padding value increases the temporary render texture's margins relative to the object's geometry, providing the necessary space for dispersed pixels without the performance cost of a fullscreen shader pass.
