How Pixi.js Parses 9-Slice Spritesheet Data

Pixi.js streamlines UI development by allowing developers to bundle 9-slice (scale-9 grid) definitions directly into spritesheet metadata, eliminating the need to hardcode slice dimensions in application code. This article explains the underlying mechanism Pixi.js uses to extract 9-slice border configurations from a texture atlas JSON, attach that data to instantiated sub-textures, and consume it automatically when creating sliced display objects.

The Spritesheet JSON Structure

Texture atlas generators such as TexturePacker allow you to define 9-slice borders directly on individual sprites before export. When exported to a Pixi.js-compatible JSON format, this slicing information is embedded inside the frame definitions under custom keys—typically borders or scale9Borders.

A standard JSON frame entry containing 9-slice metadata looks like this:

{
  "frames": {
    "button.png": {
      "frame": { "x": 0, "y": 0, "w": 100, "h": 50 },
      "rotated": false,
      "trimmed": false,
      "spriteSourceSize": { "x": 0, "y": 0, "w": 100, "h": 50 },
      "sourceSize": { "w": 100, "h": 50 },
      "borders": { "left": 12, "top": 12, "right": 12, "bottom": 12 }
    }
  },
  "meta": {
    "image": "spritesheet.png",
    "format": "RGBA8888",
    "size": { "w": 512, "h": 512 },
    "scale": "1"
  }
}

Depending on the exporter profile, the coordinates may represent explicit pixel insets (top, bottom, left, right) relative to the un-trimmed frame dimensions.

Loader Pipeline and Spritesheet Parsing

When loading an atlas via Assets.load(), the spritesheetAsset loader parser intercepts the JSON file. It loads the linked base texture image and instantiates a Spritesheet object.

During the internal execution of Spritesheet.parse():

  1. Iterating Frames: The parser walks through each entry in the JSON's frames dictionary.
  2. Sub-Texture Creation: It calculates the rectangular sub-region (pixi.Rectangle) within the base atlas texture.
  3. Metadata Inspection: The parser inspects the frame object for 9-slice border properties (checking keys such as borders or scale9Borders).
  4. Attaching Default Borders: When these keys are present, Pixi.js assigns the defined border offsets directly to the resulting Texture instance, storing them as defaultBorders or borders (e.g., { left, top, right, bottom }).
  5. Texture Cache Population: The configured Texture instance is placed in the global TextureCache under its frame name (e.g., "button.png").

Instantiation via NineSliceSprite

Once the metadata is mapped to the texture, constructing a sliced sprite requires no manual boundary parameters.

In Pixi.js v7 and v8, when you instantiate a NineSliceSprite (or NineSlicePlane) with a texture frame name:

// Texture loaded with embedded borders
const button = new PIXI.NineSliceSprite({
    texture: PIXI.Texture.from('button.png')
});

The NineSliceSprite constructor checks whether the supplied texture has pre-parsed border metadata. If present, it automatically extracts top, right, bottom, and left properties from texture.defaultBorders to generate the internal 3x3 vertex mesh. If the metadata is absent, the constructor defaults the insets to zero or relies on developer-specified fallback values.
