Pixi.js Z-Index Scenegraph Data Structures

Pixi.js maintains its scenegraph and z-index ordering primarily through standard JavaScript arrays combined with a deferred dirty-flag sorting mechanism. Rather than employing complex tree structures like AVL trees or dedicated priority queues for depth ordering, Pixi.js leverages a tree of Container objects where each node holds a flat array of children. When zIndex sorting is enabled, Pixi.js marks containers as dirty and performs an in-place stable sort on their child arrays immediately before rendering.

The Tree of Flat Arrays

At the core of the Pixi.js scenegraph is the Container class, which forms an n-ary tree representing the scene hierarchy. Each Container stores its direct descendants in a contiguous, linear data structure:

  • children Array: A standard JavaScript Array (this.children = []) holding references to child DisplayObject or Container instances.

Pixi.js relies on this standard array structure because it provides fast index-based lookups, optimal iteration speed for WebGL draw calls, and avoids the memory overhead and garbage collection pressure that complex pointer-based node networks create in JavaScript runtimes.

Z-Index Properties and Tracking

Every child object in Pixi.js contains a zIndex numerical property, which defaults to 0. However, the scene is not sorted automatically by default. Z-index ordering is controlled through specific flags:

  • sortableChildren: A boolean flag on the parent Container. When set to false, Pixi.js preserves the default rendering order, which is the exact order in which children were appended via addChild().
  • zIndex: A numerical value assigned to an individual child specifying its relative stacking priority among siblings.
  • sortDirty: An internal boolean flag on the parent container. Whenever a child’s zIndex is updated, or when children are added or removed, Pixi.js sets parent.sortDirty = true.

The Deferred Sorting Mechanism

Pixi.js does not sort the children array immediately when a zIndex property is modified. Immediate insertion sorting would degrade performance when multiple objects update their depths within the same frame (such as in a game loop). Instead, Pixi.js uses deferred evaluation.

During the render or update cycle (typically within updateTransform or prior to the render pass), the engine checks the container's sortDirty flag. If sortableChildren is true and sortDirty is true, Pixi.js invokes its internal sortChildren() method:

  1. In-Place Stable Sort: Pixi.js sorts the underlying children array directly using JavaScript’s native Array.prototype.sort().
  2. Comparator Logic: The comparator evaluates the difference between child zIndex values (a.zIndex - b.zIndex).
  3. Stability Preservation: Modern JavaScript engines implement ECMAScript-compliant stable sorting (such as TimSort in V8). If two children have identical zIndex values, their relative insertion order within the array is preserved.
  4. Flag Reset: Once sorted, sortDirty is toggled back to false, ensuring no redundant sorting occurs on subsequent frames unless depths are altered again.

Tree Traversal and Draw Calls

Once each dirty children array is sorted, the scenegraph's final visual hierarchy is determined via a pre-order depth-first traversal. Because sorting is scoped strictly to siblings within each local Container.children array, z-index values do not globally cross container boundaries. The rendering pipeline traverses down the tree, transforming matrices and executing WebGL batch draw calls in the sequence defined by each container's sorted array.
