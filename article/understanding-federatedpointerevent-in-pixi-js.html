Understanding FederatedPointerEvent in Pixi.js

This article provides a comprehensive overview of the FederatedPointerEvent class in Pixi.js, highlighting its architectural purpose, core capabilities, and how it unifies input handling across interactive 2D scene graphs. By translating standard web platform pointer interactions into Pixi’s hierarchical display tree, this class serves as the backbone of modern Pixi.js event handling.

The Foundation of Pixi's Modern Event System

Pixi.js introduced the Federated Events API to modernize its interaction architecture, replacing the legacy InteractionManager with an implementation aligned closely with the W3C DOM Level 3 Event specification. At the center of this architecture is FederatedPointerEvent, an event object that represents user inputs from mice, touchscreens, and styluses directed at objects within the scene graph.

Instead of handling raw DOM events manually, Pixi’s EventSystem intercepts incoming browser events on the rendering canvas and translates them into federated events. When an interaction occurs, the system creates an instance of FederatedPointerEvent and dispatches it through the appropriate Container or DisplayObject hierarchy.

Normalizing Input Types

The primary role of FederatedPointerEvent is input normalization. Web applications frequently run across hybrid devices that accept mouse clicks, finger taps, and digital pen inputs simultaneously. FederatedPointerEvent abstracts these hardware variations into a single unified interface. Developers can listen for universal pointer events—such as pointerdown, pointermove, and pointerup—without needing separate codebases for touch and mouse interactions.

Key standard pointer properties exposed by the class include:

  • pointerId: A unique identifier for the specific touch or pointer contact.
  • width and height: The physical contact geometry for touch and pen inputs.
  • pressure: The amount of force applied by pressure-sensitive styluses or touch surfaces.
  • pointerType: The device type that generated the event (mouse, pen, or touch).

Scene Graph Propagation: Capturing and Bubbling

Unlike native browser DOM events that traverse HTML elements, FederatedPointerEvent traverses Pixi’s display hierarchy. It supports standard event propagation phases:

  1. Capturing Phase: The event travels down from the root stage to the targeted display object.
  2. Target Phase: The event triggers on the specific interactive object directly under the cursor or contact point.
  3. Bubbling Phase: The event bubbles back up through parent containers to the stage.

FederatedPointerEvent includes standard flow-control methods such as stopPropagation() and stopImmediatePropagation(). These allow developers to prevent parent containers from reacting to interactions meant strictly for child elements, enabling modular UI component design inside the canvas.

Built-in Coordinate Mapping

Transforming screen coordinates to local object coordinates is a frequent performance and implementation hurdle in 2D graphics. FederatedPointerEvent addresses this by calculating and storing multiple coordinate spaces directly on the event instance:

  • global: The point's location relative to the Pixi application's stage coordinates.
  • screen: The point's location relative to the canvas element's viewport.
  • client: The position relative to the browser window.
  • getLocalPosition(): A convenience method that transforms the event's coordinates directly into the local coordinate space of any specified display object.

This eliminates the need for manual matrix multiplication or continuous calls to coordinate conversion utilities when dragging, dropping, or positioning elements.

Bridge to Native Browser Events

While FederatedPointerEvent wraps and enriches the interaction data, it retains a reference to the underlying native DOM event via its nativeEvent property. This ensures developers can access browser-specific properties, keyboard modifier keys (such as shiftKey, altKey, or ctrlKey), and low-level browser interaction details whenever advanced integration is required.
