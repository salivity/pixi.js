Pixi.js WebGPU Texture Samplers and Wrap Modes

Pixi.js leverages the modern WebGPU API to provide high-performance rendering by mapping its internal texture styles directly to native WebGPU sampler configurations. Through Pixi’s texture styling system, developers can configure UV wrap modes such as clamp-to-edge, repeat, and mirror-repeat, alongside magnification and minification filters. This article explains how Pixi.js translates high-level texture settings into native WebGPU GPUSampler descriptors, manages sampler caching, and passes these configurations to the GPU pipeline.

The Role of WebGPU Samplers

In WebGPU, textures and samplers are decoupled. A texture holds the raw texel data, while a sampler (GPUSampler) dictates how that data is read and filtered inside shaders. The sampler defines how coordinates outside the conventional [0.0, 1.0] UV range are handled (addressing modes) and how texels are interpolated across pixels (filtering modes).

When using WebGPU in Pixi.js (introduced natively in Pixi.js v8), the renderer constructs native WebGPU samplers based on the configuration of each texture's source style.

Address Modes: Clamp vs. Mirror-Repeat

Pixi.js textures utilize a TextureStyle object attached to each TextureSource. This style defines how coordinates outside the standard bounds are sampled using the properties addressModeU, addressModeV, and addressModeW.

WebGPU natively supports three primary address modes:

  • clamp-to-edge: Clamps coordinates to the range [0.0, 1.0], causing the edge pixels to stretch infinitely.
  • repeat: Tiles the texture continuously by wrapping coordinates around.
  • mirror-repeat: Tiles the texture by repeating it, but mirrors the image on every integer boundary to create a seamless back-and-forth reflection.

How Pixi.js Maps Address Modes

When a developer sets an addressing mode in Pixi.js, the WebGPU renderer maps the string values directly to the WebGPU GPUAddressMode enum:

// Setting mirror-repeat on a Pixi texture source
texture.source.style.addressModeU = 'mirror-repeat';
texture.source.style.addressModeV = 'mirror-repeat';

// Setting clamp-to-edge (often default for non-repeating assets)
texture.source.style.addressModeU = 'clamp-to-edge';
texture.source.style.addressModeV = 'clamp-to-edge';

Under the hood, the Pixi WebGPU adapter prepares a GPUSamplerDescriptor with corresponding fields:

const samplerDescriptor: GPUSamplerDescriptor = {
    addressModeU: style.addressModeU, // 'clamp-to-edge' | 'repeat' | 'mirror-repeat'
    addressModeV: style.addressModeV,
    addressModeW: style.addressModeW,
    magFilter: style.magFilter,       // 'linear' | 'nearest'
    minFilter: style.minFilter,
    mipmapFilter: style.mipmapFilter,
};

Filter Modes: Linear vs. Nearest

Alongside wrapping modes, texture sampling depends on interpolation filters:

  • Nearest (nearest): Selects the nearest texel value, resulting in pixelated graphics suitable for retro pixel-art styles.
  • Linear (linear): Computes a weighted average of the texels surrounding the sample location, producing smooth blending across scaled surfaces.

Pixi.js maps its scaleMode configurations (e.g., 'linear' or 'nearest') to magFilter and minFilter within the same GPUSamplerDescriptor. When combined with mirror-repeat, linear filtering ensures smooth transitions across the mirrored boundaries without seam artifacts.

Sampler Pooling and Resource Management

Creating a new GPUSampler via device.createSampler() carries overhead if performed continuously. To optimize performance, Pixi.js employs an internal sampler cache:

  1. Hash Generation: Pixi.js generates a unique hash key representing the combined state of addressModeU, addressModeV, addressModeW, magFilter, minFilter, and mipmapFilter.
  2. Lookup and Reuse: Before instantiating a new sampler, the WebGPU system queries its sampler pool. If an identical configuration has already been registered, Pixi reuses the existing GPUSampler instance.
  3. Bind Group Construction: The resolved GPUSampler is packaged into a GPUBindGroup alongside the texture's GPUTextureView.

In the WGSL shader, the sampler is accessed via standard texture sampling functions:

@group(0) @binding(0) var uSampler: sampler;
@group(0) @binding(1) var uTexture: texture_2d<f32>;

@fragment
fn main(@location(0) uv: vec2<f32>) -> @location(0) vec4<f32> {
    return textureSample(uTexture, uSampler, uv);
}

Because the hardware handles the boundary calculations directly through the bound GPUSampler, modes like mirror-repeat and clamp-to-edge execute with zero overhead in the fragment shader.
