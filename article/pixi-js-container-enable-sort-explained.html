PixiJS Container enableSort Explained

This article explains the purpose and mechanics of the enableSort property on a Pixi.js Container. Readers will learn how this property manages child display ordering, how it interacts with the zIndex property, and the performance considerations involved when enabling dynamic depth sorting in 2D WebGL scenes.

Default Child Ordering in Pixi.js

By default, a Pixi.js Container renders its children in the order they are added using the addChild() method. The first object added is drawn first (at the bottom), and subsequent objects are drawn on top of earlier ones. In standard rendering loops, Pixi.js does not automatically check or reorder objects by depth or layers, which keeps rendering performance extremely fast and predictable.

The Purpose of enableSort

The enableSort property (often paired with or referred to as sortableChildren in newer Pixi.js versions) allows a Container to automatically reorder its children based on their individual zIndex values.

When enableSort is set to false (the default state):

  • Setting child.zIndex = 10 has no visual effect.
  • Children remain in their sequential array order regardless of what their zIndex values are.

When enableSort is set to true:

  • Pixi.js actively sorts the container's children array before rendering.
  • Children with lower zIndex values are drawn behind children with higher zIndex values.
  • If two children share the same zIndex, their original insertion order is preserved.

How Sorting Works Internally

When sorting is enabled on a container, changing a child's zIndex flags the container as dirty. Before the next frame renders, Pixi.js calls its internal sortChildren() method, executing a sorting algorithm on the container's children array.

const container = new PIXI.Container();
container.enableSort = true; // Enables zIndex sorting

const background = new PIXI.Sprite(bgTexture);
background.zIndex = 0;

const player = new PIXI.Sprite(playerTexture);
player.zIndex = 10;

const foreground = new PIXI.Sprite(fgTexture);
foreground.zIndex = 20;

// Added in arbitrary order, but rendered according to zIndex
container.addChild(foreground);
container.addChild(background);
container.addChild(player);

Performance Considerations

Dynamic sorting is computationally more expensive than rendering a static array of display objects. Because sorting requires evaluating array positions and reordering elements:

  • Keep it disabled when unnecessary: Only enable sorting on containers where depth ordering changes dynamically, such as in isometric games or Y-sorted top-down RPGs.
  • Limit child count: Avoid enabling dynamic sorting on containers holding thousands of static particles or tiles. Instead, use static layering across separate dedicated containers.
  • Update sparingly: Continuous changes to zIndex trigger continuous re-sorts. Group objects into defined layers when possible to minimize sorting overhead.
