WebGPU Dynamic Uniform Buffer Offsets in Pixi.js

Pixi.js manages uniform buffer dynamic offsets under WebGPU by aggregating distinct draw call data into centralized, pre-allocated uniform buffers aligned to GPU memory constraints, allowing multiple objects to share a single bind group while accessing dedicated data slices via byte offsets during command encoding.

In WebGPU, switching GPUBindGroup instances introduces CPU and GPU overhead. When rendering multiple objects that share the same shader and pipeline but require unique uniform data—such as local transformation matrices, tints, or custom shader parameters—Pixi.js avoids creating individual bind groups for each object. Instead, the engine utilizes dynamic uniform buffers (hasDynamicOffset: true in the bind group layout) to rapidly cycle through data slices within a single buffer.

Pixi.js implements this through its WebGPU uniform buffer system, typically managed by its internal uniform group and buffer adapters. The engine maintains large shared uniform buffers rather than allocating individual GPU buffers for every scene item. As the scene graph traverses and updates objects for rendering, Pixi.js writes the uniform data sequentially into a continuous byte array.

Each individual uniform payload is packed according to strict alignment requirements. WebGPU enforces a hardware limitation defined by minUniformBufferOffsetAlignment, which is typically 256 bytes. Pixi.js calculates the byte size of the uniform block and rounds each subsequent offset up to the nearest multiple of this alignment threshold. The engine tracks these calculated byte offsets in an array mapped to each respective draw call.

During the render pass execution, Pixi.js binds the shared GPUBindGroup to the render pass encoder using passEncoder.setBindGroup(index, bindGroup, dynamicOffsets). For consecutive draw calls sharing the same pipeline, Pixi.js does not rebinding the group layout. Instead, it re-invokes setBindGroup passing an array containing the precomputed dynamic byte offset for that specific object, or executes a direct draw call utilizing the offset index.

This approach works in tandem with Pixi's 2D batching system. While standard 2D elements like basic sprites are batched into a single large vertex buffer using vertex attributes for per-item data, complex objects such as custom meshes, graphics with unique materials, and filtered containers rely on uniform buffers. By leveraging dynamic offsets, Pixi.js eliminates buffer re-allocations and bind group recreation, allowing WebGPU to execute sequential draws with minimal state churn.
