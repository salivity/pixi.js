How PixiJS Chooses Scissor or Stencil Masking

PixiJS dynamically optimizes render performance by automatically selecting between scissor masking and stencil masking based on the geometry and transform properties of the masking object. Scissor masking leverages hardware-level viewport clipping to restrict rendering to an axis-aligned rectangular area with virtually zero performance overhead. When a mask cannot satisfy strict rectangular and alignment criteria, PixiJS falls back to stencil masking, which utilizes the WebGL stencil buffer to handle complex, arbitrary shapes at the cost of additional draw operations.

The Automatic Selection Mechanism

PixiJS evaluates masks through its internal MaskSystem. When you assign a mask to a display container, the engine checks whether the mask candidate can be mapped to a native WebGL scissor test (gl.scissor). The automatic decision comes down to two primary evaluations: geometric structure and screen-space alignment.

1. Geometry Verification

PixiJS inspects the underlying data of the mask object:

  • Simple Rectangles: If the mask is a standard PIXI.Rectangle instance or a PIXI.Graphics object composed strictly of a single rectangular draw call (drawRect), it qualifies as a candidate for scissor masking.
  • Complex Shapes: If the mask contains curves, polygons, circles, rounded rectangles (drawRoundedRect), multiple path instructions, or holes, scissor masking is instantly ruled out. PixiJS assigns stencil masking to preserve the irregular contours using the stencil buffer.

2. World Transform and Axis Alignment

Even if a mask is a flat rectangle, it must remain strictly axis-aligned to the screen viewport:

  • Translation and Scale: Operations that only move or resize the rectangle along the X and Y axes preserve axis alignment. Under these transforms, the edges remain parallel to the viewport edges, and PixiJS utilizes scissor masking.
  • Rotation and Skew: If the mask or any of its parent containers apply a rotation (that is not an exact orthogonal 90-degree increment) or a skew, the rectangle's edges tilt relative to the screen grid. WebGL scissor rectangles can only be aligned to the screen coordinates; they cannot rotate. Therefore, any angular distortion forces PixiJS to automatically elevate the mask to a stencil mask.

WebGL Execution Differences

The decision determines how PixiJS configures the GPU pipeline:

  • Scissor Masking (MASK_TYPES.SCISSOR): PixiJS calculates the screen-space bounding box of the rectangular mask and executes gl.enable(gl.SCISSOR_TEST) along with gl.scissor(x, y, width, height). The GPU discards pixels outside this box prior to pixel processing. No auxiliary framebuffers or stencil buffers are cleared or written to, resulting in optimal speed.
  • Stencil Masking (MASK_TYPES.STENCIL): PixiJS enables the stencil test (gl.enable(gl.STENCIL_TEST)), clears the stencil buffer, and renders the mask geometry to define pixel visibility. The masked object is then drawn where the stencil values permit. While robust and capable of rendering intricate vector silhouettes, this path requires multiple draw passes and state changes.

Overriding the Automatic System

PixiJS exposes explicit control via the MaskData class. While the automatic system handles most use cases reliably, developers can explicitly set maskData.type to force scissor or stencil behavior when building custom rendering pipelines. If a non-conforming shape is forced to use scissor masking, PixiJS clips using that shape's rectangular bounding box rather than its actual visual perimeter.
