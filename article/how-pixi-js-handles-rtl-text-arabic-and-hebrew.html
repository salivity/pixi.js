How Pixi.js Handles RTL Text: Arabic and Hebrew

Pixi.js does not provide native, out-of-the-box support for right-to-left (RTL) languages like Arabic and Hebrew, primarily because standard canvas-based text rendering struggles with bidirectional text (BiDi) and complex character shaping. While basic RTL rendering can work in limited scenarios via the underlying HTML5 Canvas 2D API, complex scripts and features like word wrapping require specific workarounds. To achieve accurate RTL text in Pixi.js, developers typically rely on HTML-based text components or external preprocessing libraries.

The Underlying Rendering Pipeline

Standard text in Pixi.js is handled via the PIXI.Text class. Under the hood, Pixi.js creates a hidden HTML5 <canvas> element, draws the text using the browser's CanvasRenderingContext2D.fillText() method, and converts the resulting canvas into a WebGL texture.

Because of this approach, text display depends entirely on the browser's native canvas capabilities. Modern browsers natively support basic RTL text rendering to some degree when proper Unicode characters are detected, but the implementation in Canvas 2D lacks the comprehensive layout engines found in standard HTML/CSS DOM environments.

The Problem with Pixi.js and RTL Scripts

RTL languages present two primary challenges in Pixi.js:

  1. Broken Word Wrapping: Pixi.js implements its own custom text-wrapping algorithm to measure string widths and break lines. This algorithm expects text to flow left-to-right (LTR). When text wrapping is enabled in Pixi.js, it slices strings based on spaces or character counts without accounting for the Unicode Bidirectional Algorithm. This causes lines to break in incorrect orders and reverses character sequences.
  2. Contextual Ligatures and Shaping (Arabic): Arabic is a cursive script where character glyphs change depending on their position in a word (isolated, initial, medial, or final). While the browser's fillText can often shape basic continuous strings, any manual manipulation, splitting, or word-wrapping by Pixi.js breaks the text-shaping context, resulting in detached, reversed, or improperly formed letters.
  3. Bidirectional Mixing: When text contains both RTL (Hebrew/Arabic) and LTR (English or numbers) scripts, Pixi.js cannot independently calculate the visual layout order, leading to numbers and punctuation rendering at the wrong end of phrases.

How to Properly Display RTL in Pixi.js

Developers use two primary methods to resolve RTL rendering issues in Pixi.js applications:

1. Using HTMLText (@pixi/text-html)

The most robust solution is to use Pixi.js's HTMLText plugin (included natively in Pixi.js v7 and v8 via @pixi/text-html).

HTMLText renders text using an SVG foreignObject containing actual HTML and CSS before rasterizing it to a canvas. This delegates text layout, bidirectional ordering, and ligature shaping entirely to the browser’s full layout engine (such as Blink, WebKit, or Gecko). By setting the CSS direction: rtl; style on an HTMLText element, Arabic and Hebrew text—along with complex line wrapping and mixed-script strings—will render accurately.

2. Pre-processing Strings with BiDi and Shaping Libraries

If performance constraints prevent using HTMLText (which can be slower to generate than native PIXI.Text), developers preprocess strings before passing them to PIXI.Text. This pipeline involves:

  • Arabic Reshaping: Libraries like arabic-persian-reshaper convert generic Arabic Unicode characters into their context-dependent glyph variants (initial, medial, final).
  • BiDi Reordering: A library like bidi-js applies the Unicode Bidirectional Algorithm to reorder the characters from logical order (how they are typed) into visual order (how they appear on the screen from left to right).

Once the string is converted to visual LTR order with mapped glyphs, native PIXI.Text can render it correctly without requiring browser-level bidirectional parsing. However, Pixi's built-in word wrapping must remain disabled; line breaks must be calculated and applied manually prior to shaping.

What About BitmapText?

Pixi.js BitmapText relies on pre-rendered font atlases mapping individual character codes to texture coordinates. Because BitmapText cannot dynamically generate ligatures, context-dependent glyphs, or complex script shaping, it cannot be used for Arabic without extensive pre-computed ligature mapping. For Hebrew, BitmapText can theoretically work, provided the text is pre-processed into visual order using a BiDi library.
