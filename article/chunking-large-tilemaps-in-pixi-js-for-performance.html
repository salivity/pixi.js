Chunking Large Tilemaps in Pixi.js for Performance

Rendering massive tilemaps in Pixi.js can quickly degrade performance and consume excessive memory if handled as a single, monolithic structure. This guide explains how to divide large tilemaps into a grid of manageable chunks, dynamically load and unload them based on camera position, and leverage object pooling and specialized rendering techniques to maintain stable 60+ FPS gameplay with minimal memory overhead.

Understanding the Chunking Architecture

Instead of instantiating hundreds of thousands of tiles across a giant map, chunking subdivides the world into a uniform grid of smaller segments (e.g., 16x16 or 32x32 tiles). Each chunk acts as an independent entity containing its own display objects.

By splitting the world into these discrete boundaries, you only need to process, update, and render chunks that intersect with the active camera viewport, leaving the rest unloaded or dormant in memory.

Step 1: Define Chunk Dimensions and Coordinates

First, establish fixed chunk parameters in both tile and world pixel dimensions:

const TILE_SIZE = 32;
const CHUNK_SIZE = 16; // 16x16 tiles per chunk
const CHUNK_PIXEL_SIZE = CHUNK_SIZE * TILE_SIZE; // 512px

function getChunkCoord(worldX, worldY) {
  return {
    x: Math.floor(worldX / CHUNK_PIXEL_SIZE),
    y: Math.floor(worldY / CHUNK_PIXEL_SIZE)
  };
}

function getChunkKey(chunkX, chunkY) {
  return `${chunkX},${chunkY}`;
}

Step 2: Implement Viewport Culling

To determine which chunks to display, monitor the camera's bounding box. Expand this bounding box slightly by adding a margin buffer (e.g., 1 chunk in every direction) to prevent pop-in artifacts when the player moves quickly.

function getVisibleChunkRange(camera, screenWidth, screenHeight, buffer = 1) {
  const minX = Math.floor((camera.x - screenWidth / 2) / CHUNK_PIXEL_SIZE) - buffer;
  const maxX = Math.floor((camera.x + screenWidth / 2) / CHUNK_PIXEL_SIZE) + buffer;
  const minY = Math.floor((camera.y - screenHeight / 2) / CHUNK_PIXEL_SIZE) - buffer;
  const maxY = Math.floor((camera.y + screenHeight / 2) / CHUNK_PIXEL_SIZE) + buffer;

  return { minX, maxX, minY, maxY };
}

Step 3: Manage Active Chunks and Pooling

Avoid creating and destroying PIXI.Container or sprite instances dynamically, as this causes garbage collection hitches. Instead, maintain an active chunk map and recycle chunk containers using an object pool.

const activeChunks = new Map();
const chunkPool = [];

function getChunkContainer() {
  return chunkPool.pop() || new PIXI.Container();
}

function releaseChunkContainer(container) {
  container.removeChildren();
  chunkPool.push(container);
}

On every camera update:

  1. Calculate the currently visible chunk range.
  2. Build a set of chunk keys that should be active.
  3. Remove and pool active chunks that fall outside this set.
  4. Instantiate or fetch new chunks entering the visible set.
function updateChunks(camera, worldData, worldContainer) {
  const { minX, maxX, minY, maxY } = getVisibleChunkRange(camera, 800, 600);
  const requiredKeys = new Set();

  for (let cx = minX; cx <= maxX; cx++) {
    for (let cy = minY; cy <= maxY; cy++) {
      const key = getChunkKey(cx, cy);
      requiredKeys.add(key);

      if (!activeChunks.has(key)) {
        const chunkContainer = getChunkContainer();
        chunkContainer.position.set(cx * CHUNK_PIXEL_SIZE, cy * CHUNK_PIXEL_SIZE);
        
        buildChunkTiles(chunkContainer, cx, cy, worldData);
        worldContainer.addChild(chunkContainer);
        activeChunks.set(key, chunkContainer);
      }
    }
  }

  for (const [key, container] of activeChunks.entries()) {
    if (!requiredKeys.has(key)) {
      worldContainer.removeChild(container);
      releaseChunkContainer(container);
      activeChunks.delete(key);
    }
  }
}

Step 4: Optimize Chunk Rendering

Standard PIXI.Sprite instances can quickly flood the WebGL pipeline with draw calls. To maximize rendering performance inside each chunk:

  • Use @pixi/tilemap: The @pixi/tilemap extension batches tiles using shared textures, allowing thousands of tiles per chunk to be rendered in a single draw call.
  • Render to Texture (Baking): For static environments, bake each chunk into a single PIXI.RenderTexture when generated. The chunk is then displayed as a single flat sprite, eliminating tile-level rendering overhead entirely.
  • Texture Atlasing: Ensure all tile graphics are packaged into a single spritesheet to avoid breaking batch operations.

Step 5: Data Streaming and Memory Eviction

For exceptionally large worlds, store raw tile data in compact structures (such as Uint8Array or Uint16Array) rather than nested JavaScript objects. When dealing with maps that exceed system RAM, dynamically stream chunk data from a backend server or IndexedDB, keeping only adjacent and visible chunk data cached locally.
